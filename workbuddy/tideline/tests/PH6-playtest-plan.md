## 0. 待验证的假设（先写死，再跑，避免事后改口径）

| # | 假设 | 来源 | 若不成立的影响 |
|---|---|---|---|
| **H1** | `p_beach`（每次冲浪返程的搁浅率）随熟练度从 **0.15 降到 0.03** | R1 §1.3 | 支柱四"两分钟精通"失去数值支撑；C1 可能失败 |
| **H2** | `p_beach` 是**可练的技巧项**（专家/新手比 ≥ 3×） | R1 §3.4 | 冲浪路线变成"运气"而非"技巧"，支柱四的胜任感轴崩塌 |
| **H3** | C1：`k=1` 时 冲浪/深水 期望收益比 **≥ 1.5**（新手 1.53 / 专家 1.75） | R1 §3.3 | 冲浪路线沦为死内容，支柱二抉择瓦解 |
| **H4** | 最优押注 **k=2**；Bank 后仍有相当比例玩家选择 Push | R1 §3.4 / C3 | Bank-or-Push 形同虚设 |

> ⚠️ **统计前提**：5–8 人是**方向性样本**，不做显著性检验（n 太小，p 值无意义）。
> 本方案只回答"量级对不对"，不回答"差异是否显著"。**阈值必须在招募前锁定**（见 §5），跑完不许改。

## 1. 被试与分组（客观、行为指标，禁止自我报告）

### 1.1 样本
- 目标 **6 人**（最低 5，最高 8）：3 名"少玩街机/动作游戏"、3 名"常玩动作/反应类"。
- 招募时**只按"近一年每周玩动作/街机类游戏小时数"做初始配额**（<2h vs >5h），
  这只是为了保证样本**覆盖两端**，**不作为最终分析分组依据**。
- 明确告知：这是原型测试，考的是**游戏**不是人；可以随时退出；记录匿名。

### 1.2 最终分组 —— 用行为指标，不用自评
每名被试先跑 **3 局校准局**（不计入正式统计），用下面的行为指标分组：

| 组别 | 判定（取前 3 局的**中位数**） |
|---|---|
| **低技巧组（新手代理）** | 前 3 局**搁浅次数**中位数 **≥ 2** 次/局 |
| **高技巧组（专家代理）** | 前 3 局**搁浅次数**中位数 **≤ 0.5** 次/局（即 3 局合计 ≤1 次） |
| 中技巧组 | 其余（样本足够时单列，不足时并入低技巧组并标注） |

> **为什么不用自评**：玩家对自己水平的自评与客观表现的相关性很低，且会被"我是硬核玩家"的
> 自我形象污染。搁浅次数是**行为**，且正好是我们要测的那个量，用它分组与因变量同源，最干净。
>
> **补充客观轴（用于交叉验证）**：若两组在"冲浪返程成功率"上的排序与搁浅次数分组**不一致**，
> 说明分组不稳，报告时必须标注该被试为"边界样本"。

## 2. 采集指标（因变量）

每局自动记录、逐局落盘。**核心是先给每个指标下可执行的定义**，否则数据没法比。

### 2.1 操作定义（必须写进埋点）
| 指标 | 操作定义 |
|---|---|
| **搁浅事件** | `enterBeached()` 被调用的次数（进入 QTE 即算一次，无论 QTE 成败） |
| **冲浪返程** | 一次「鲨鱼进入 SURF 区 → 之后到达 DEEP 区」的行程 |
| **冲浪返程成功** | 该行程中途**未**搁浅且未死亡 |
| **冲浪尝试** | 进入 SURF 区的次数（含未完成的） |
| `p_beach_hat` | `Σ搁浅事件 / Σ冲浪返程`（**主指标**，逐人算，再在组内取中位数） |
| **ALARM 峰值** | 单局内 `G.alarm` 的最大值 |
| **ALARM>75 时长占比** | 单局内 `alarm ≥ 75` 的秒数 / 单局时长 |
| **Bank 次数 / Push 次数** | 结算的次数 / Bank 之后**再次离开深海去捕食**的次数 |
| **押注量 k 分布** | 每次**死亡**时身上的 `carryK`；每次 **Bank** 时的 `carryK` |
| **单局时长** | 从可操作到死亡的秒数 |
| **死因分布** | `deathReason` 计数（beached / tether / harpoon / other） |

### 2.2 指标清单（按优先级）
1. `p_beach_hat`（新手/专家两组）← **主判据**
2. 搁浅次数 / 冲浪尝试 / 冲浪返程成功
3. ALARM 峰值、ALARM>75 时长占比
4. Bank vs Push 分布、押注量 k 分布
5. 单局时长分布
6. 死因分布

## 3. 埋点方案 `?playtest=1`（**仅设计，本次不实现**；实现由主理人负责）

> 约束：纯前端、无后端。**不联网、不采集 PII、不上传**。数据先落 `localStorage`，由被试/主测手动导出。

### 3.1 开关
- `?playtest=1` —— 启用埋点记录与"导出数据"按钮。
- `?playtest=1&pid=P03` —— 打被试编号（匿名代号，不用真名）。
- `?playtest=1&pid=P03&seed=12345` —— 固定 `U.srand` 种子，用于**复现**某一局（可选）。
- 未带 `playtest` 参数时行为完全不变（零影响、零开销）。

### 3.2 记录粒度（性能优先）
- **不做逐帧记录**（60fps 写盘会掉帧污染数据）。只在**事件发生时**追加一条记录，
  并在每局结束时写一条 `run_summary`。
- 事件类型：`grab`（type, x, alarm_before/after）、`bank`（k, score, combo）、
  `strand`（alarm_at, 是否脱困）、`surf_enter`、`surf_return`（success/fail）、
  `death`（reason, k, pendingScore）、`dash`（hit/未命中）。
- 单局聚合：`duration_s`、`alarm_max`、`alarm_over75_s`、`strand_count`、`bank_count`、
  `push_count`、`k_at_bank[]`、`k_at_death`、`grabs_by_type`。

### 3.3 存储与导出
- 键：`tideline.playtest.v1`，值为 **NDJSON**（一行一条 JSON，便于追加与人工检查）。
- 每次 `reset()` 递增 `runId`。
- 主测页面角落一个「导出 JSON」按钮（`Blob` + `a[download]`）+ 一个「复制到剪贴板」。
- 首行写入 `{"schema":"tideline.playtest.v1","pid":...,"startedAt":...}`，便于版本管理。

### 3.4 隐私与告知
- 记录里**不含**任何自由文本、按键内容或个人信息；只有游戏内数值。
- 开始前口头告知并在页面顶部显示一行：`本局记录游戏内数据用于平衡性测试，不含个人信息`。

### 3.5 验收埋点本身（防止埋点坏了还以为是游戏坏了）
跑测前，主测先用 3 局人工对拍：手动数搁浅次数，与导出 JSON 的 `strand_count` 对照，一致才开测。

## 4. 流程与时长控制（单局 90–150 秒，防疲劳污染）

### 4.1 单场结构（每人 ≈ 60 分钟）
| 时段 | 内容 | 时长 |
|---|---|---|
| 0–5 min | 知情同意 + 光敏警告 + 无文字墙操作说明（"冲、叼、逃"三个图标） | 5 min |
| 5–15 min | **校准局 ×3**（用于行为分组，不计入统计） | 10 min |
| 15–20 min | 强制休息 | 5 min |
| 20–50 min | **正式采集**：约 12–16 局（每局 90–150s + 结算/重试 ~20s） | 30 min |
| 30 min 处 | **强制 60s 休息**（每 4 局也强制一次 60s 停顿） | 含在内 |
| 50–60 min | 半结构化访谈（见 §6） | 10 min |

- **总计**：约 **60 min/人**；6 人分 2 天 × 3 人，或 3 天 × 2 人。**同一时段**开测，避免早晚状态差。

### 4.2 抗疲劳设计（因为要测"后段是否被疲劳污染"）
1. 单局天然短（90–150s），本身不易疲劳。
2. **每 4 局强制 60s 离屏休息**；中段 30 min 处强制 5 min 休息。
3. **疲劳哨兵**：把每人的正式局按时间**三等分**，比较前 1/3 与后 1/3 的 `p_beach_hat`。
   - 若后 1/3 显著变差（`p_beach_hat` 上升 ≥ 50% **且** 单局时长明显变短），
     判定为疲劳污染 → **该被试后 1/3 数据剔除**并在报告标注。
   - 若后 1/3 反而更好，说明存在学习效应 → **不剔除**，但要说明 H2 可能被学习曲线推高。
4. 被试间**随机化顺序**：动作游戏组与新手组交替安排，避免"都是新手连测导致后半场全是新手状态"。

## 5. 判定阈值（**本方案最重要的部分** —— 招募前锁定）

主判据：分组后的 `p_beach_hat` 中位数。参考基线：R1 假设 新手 **0.15** / 专家 **0.03**。

### 5.1 A 区 · 假设成立（不必回跑沙盘）
- 专家组 `p_beach_hat` **≤ 0.06**，且
- 新手组 `p_beach_hat` 落在 **[0.10, 0.22]**，且
- 组间比 **新手/专家 ≥ 3×**（即 H2 成立）。
- → **结论**：0.15→0.03 的技巧曲线在**量级上**成立，R1 的 C1/C2/C3 无需重算，进入内容扩展。

### 5.2 B 区 · 警戒（微调，不必推翻结构）
- 新手组 `p_beach_hat` ∈ **(0.22, 0.25]**，或 专家组 ∈ (0.06, 0.10]，但组间比仍 ≥ 2×。
- → **动作**：微调**弱杠杆**（沙盘 §5 已证 `A_grab`、死亡曲线指数是弱杠杆），
  并在下一轮 playtest 复测；**不必**回跑沙盘重推 C1。

### 5.3 C 区 · **必须回跑 R1 沙盘**（红线）
只要出现**任一条**，即触发回跑（跑 `design/gdd/tools/r1_sandbox.py`，并重走 C1/C2/C3）：

| # | 触发条件 | 为什么必须回跑 |
|---|---|---|
| **C-a** | **新手组 `p_beach_hat` > 0.25** | 冲浪路线对新手劝退。按沙盘模型估算：`p_beach` 从 0.15 抬到 0.25，新手 k=1 的冲浪速率从 8.69 降到 ≈7.65，**C1 比值从 1.53 掉到 ≈1.35 < 1.5 → C1 失败**，支柱二抉择受损 |
| **C-b** | **专家组 `p_beach_hat` ≥ 0.10**（>0.03 的 3 倍） | 技巧天花板没兑现 → 支柱四"两分钟精通"存疑；需回跑并检查 QTE/搁浅预警的**可学性** |
| **C-c** | **组间比 < 1.5×**（专家 ≈ 新手） | `p_beach` **不是技巧项** → R1 把它当"可练的技巧轴"的前提作废，必须重构（可能改 `m_surf`/`A_grab` 或给冲浪路线加可学辅助） |
| **C-d** | **搁浅死因占全部死亡 > 25%** | 风险过度集中在单一机制；需回跑评估该机制权重 |

> **C-a 的具体回跑动作**：重跑沙盘 → 若 C1 失败，优先动 **`m_surf`（最强杠杆，线性 ±0.35）**
> 或 **冲浪 ALARM 斜率（次强）**；也可先试"降低新手搁浅惩罚"（延长 T_WARN / QTE 窗口）再复测。

### 5.4 其他辅助判据（不单独触发回跑，但写进报告）
| 指标 | 期望 | 异常含义 |
|---|---|---|
| 单局时长中位数 | 90–150s | 偏离 → 支柱四时长假设要改 |
| ALARM>75 时长占比 | < 30% | 过高 → 围剿档过久，节奏压迫 |
| Bank 后 Push 比例 | **≥ 20%** | 过低 → 押注结构未被激活，C3 存疑 |
| 押注量 k 众数 | **2** | 若是 1 → "押注没有牙齿" |

## 6. 访谈提纲（只用行为锚定问题，不问"你觉得好玩吗"）
