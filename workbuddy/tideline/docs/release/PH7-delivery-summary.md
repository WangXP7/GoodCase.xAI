### 2.1 三个值得记录的验证方法

1. **像素级资产取证**（`smoke-mvp.js` 新增 8 项）
   把测试桩从"只计数"升级为**按 `add()` 分组的栅格化**，于是可以直接对产物断言：
   §4.1.3 配色的三个色阶齐备、**不含**旧深藏青（防回退）、
   外扩 3 层环全为 `#0A0E17`（P-06），且第 4 层已越出描边（证明厚度**恰好** 3px 而非更厚）。

2. **验证基准必须选对**
   首版断言失败，我一度以为描边没画出来。实测 dump 像素后发现描边正常（915 个黑像素）——
   错的是**验证逻辑**：拿"全部不透明像素"做膨胀基准，而描边本身就是不透明像素，
   环自然落在了描边之外的空区。改为以**体色像素**为基准后成立。
   → 教训：断言失败先怀疑断言，别急着改代码。

3. **真实帧缓冲 > 常量推导**
   `art-deep-verify.js` 直接 `readPixels` 最终画布，因此结论包含雾效、后期去饱和、
   CRT 扫描线的全部影响——这是常量侧推导**给不出**的。它也直接量出了修复前的病征：
   鲨鱼灰度 17.4% < 背景 24.7%，即"比背景还暗"。

## 3. 关键决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 硬红线① 的修法 | **统一闸门**（`triggerFlash` 唯一出口限频），而非给档位闪单独打补丁 | 新增任何闪光源都自动受约束，不会再出现同源回归 |
| 限频范围 | **只限视觉**，音效与 toast 照播 | 若连音效一起限，"闪烁 ≤2Hz"就会削减玩家的信息通道，反而违反可访问性目标 |
| 鲨鱼图集尺寸变化 | 画布 84×40 → 100×56，同时按 `DRAW_PAD` 补偿渲染尺寸 | 外描边需要 3px 余量（且鳍尖本就溢出）。补偿后**本体视觉尺寸 168×80 保持不变**，不破坏已有视觉调校 |
| 描边实现 | **外扩 3 层**（真描边），非内描边 | 内描边在深海（背景 8%）几乎不可见；外描边在浅滩/冲浪区/沙滩提供轮廓分离 |
| 救生员作为猎物（设计不一致） | **保留实现**，记为已知差异 | 它构成"高风险高价值猎物"的合理玩法扩展；硬红线① 修复后不再有安全风险。改设计需同步 GDD-03 + R1 沙盘 + 重跑沙盘脚本，成本高于收益，交 playtest 裁决 |
| 单文件 vs 多文件 | **两者都交付**，且用同一套 41 项断言验证 | 单文件方便分发试玩；多文件方便后续迭代 |
