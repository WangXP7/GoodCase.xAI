## 裁决 1 · 渲染方案：批准 WebGL2，否决方案 F

### 背景

程基岩给出两条路径：

| 方案 | 技术 | CRT 效果 | 工期 |
|---|---|---|---|
| **主方案** | WebGL2 + 自研薄渲染层（~1.2k LOC） | 完整（弯曲 + 色差 + 余晖 + 调色板切换） | +1~2 周 |
| **方案 F** | Canvas2D | 退化为「扫描线滤镜」 | 省约 2 周 |

程基岩标注方案 F 是「唯一一个降低美术目标换工期的选项，我不能替你做这个决定」。

### 裁决：**主方案（WebGL2），否决方案 F**

### 理由

**① 「复古街机风」是用户在 Phase 1 明确锁定的方向，CRT 弯曲与色差是这个风格的物理签名，不是可选装饰。**

扫描线滤镜只能模拟「隔行扫描」，模拟不了「球面显像管」——而后者才是街机厅的记忆锚点。玩家说不出「少了桶形畸变」，但会说「不像街机」。这正是那种**说不出哪里不对、但就是不对**的差别。

**② 程基岩那句论证是对的：「本作的视觉身份就是渲染器」。**

硬边像素、有序抖动、整屏调色板切换——三件最独特的事**全是渲染层行为**。砍掉渲染层，这三件一起消失，美术圣经 175KB 里定义的视觉身份会塌掉一半。我们已经在设计阶段投入巨大，不能在实现时砍掉它的立身之本。

**③ 色差一项就足以定案。** WebGL 里是一次全屏 pass 的 3 次纹理采样；Canvas2D 是每帧 2.24 亿像素写入。**20 倍差距**，不是"贵一点"，是"可行/不可行"。

**④ 用户在 Phase 0 选择了「完整工作室流程」，这是品质优先的明确信号。** 若为省两周牺牲视觉签名，与这个选择自相矛盾。

**⑤ 风险已被 5 天 Spike 闸门兜住**（见裁决 2），不是裸奔。

### 附带批准：HUD 走 DOM

程基岩这条建议的价值被他自己低估了。**可访问性从「要做很多工作」变成「基本免费」**——文本是真实文本，屏幕阅读器可读、浏览器缩放可用、字体替换可用。这不是优化，是质变。

且它顺带解决了中文字集问题（不需要位图字体图集，省 200+ 字形资产）。

## 裁决 2 · 批准 5 天 Spike 闸门

程基岩为「自研渲染层未经验证」设计的闸门：

- 6 项验收**全过** → 执行主方案
- 过 3–5 项 → 修 3 天
- **≤2 项** → 立即转 PixiJS 备选方案 B

**批准。** 这是一个诚实的风险管理设计——他没有把未验证的方案包装成确定可行，而是预设了撤退线。**有撤退线的冒险是决策，没撤退线的冒险是赌博。**

## 裁决 3 · 关于「21 项待会签」

程基岩列出 21 项待会签，其中标注「用户/主理人」的项，我按以下原则处理：

**凡是涉及「降低美术目标换工期」的，一律不批。** 本项目当前阶段不缺时间承诺，缺的是视觉身份的完整性。

**凡是涉及架构灵活性（如 RNG 种子化、固定步长、回放支持）的，一律批准。** 程基岩那句论证成立：

> 「这两件事的共同点：**现在做几乎免费，以后做要返工**。特别是回放——它要求全项目 RNG 种子化与固定步长，**必须在 MVP 之前决定**，否则后期无法补。」

这类「现在免费、以后昂贵」的决策，应当无条件批准。

## 裁决 4 · 进入 Phase 5 的批准

设计资产已齐备：

| 阶段 | 产出 |
|---|---|
| Phase 1 | 概念文档 + 美术圣经 + R1 数值沙盘 |
| Phase 2 | 3 份系统 GDD（移动 / ALARM敌人 / 捕食携带） |
| Phase 3 | 架构 + 6 条 ADR + 阻塞项解决方案 |
| Phase 4 | 资产清单 + 诱饵 VFX + 验收清单 |

**批准进入 Phase 5 实现，采用垂直切片策略**——先做一个能在浏览器打开、可操作、能看到核心循环跑通的版本，而不是铺开全部系统。

垂直切片范围：

1. 渲染层（WebGL2 批处理器 + 图集加载 + CRT 后处理）
2. 四层水体场景（深海 / 浅滩 / 冲浪区 / 沙滩）
3. 鲨鱼移动与状态机（巡游 / 冲刺 / 咬合 / 携带 / 搁浅）
4. ALARM 累积与衰减
5. 捕食 → 携带 → 逃回深海 → Bank 结算
6. 搁浅 QTE（招牌机制）

暂缓：经济升级、多区域、元系统、完整关卡。
