## 1. 系统概述

**一句话职责**：把玩家的方向意图转换成鲨鱼在水体中的位置、朝向与速率，并定义「鲨鱼永不停止」这一手感基石。

**在核心循环中的位置**：移动系统是循环的**载体层**，不直接产生产出，但主循环五步（潜行 → 冲刺 → 捕食 → 逃生 → 结算）全部跑在它之上。它是唯一一个**每帧都在被调用**的系统——ALARM 按区结算、捕食按冲刺判定、搁浅按地形判定，三者的输入都来自本系统的输出（位置 + 状态 + 速率）。

**本系统的四个输出量**（其他系统只依赖这四个）：

| 输出 | 类型 | 消费方 |
|---|---|---|
| `pos` 位置 `(x, y)` | 连续量，px | GDD-02（区域判定 → ALARM 斜率）、GDD-04（收集物碰撞） |
| `state` 状态枚举 | 枚举 | 全部系统 |
| `vec` 速度矢量 | 连续量，px/s | GDD-03（冲刺判定）、GDD-04（冲浪速率） |
| `carry_k` 携带数 | 整数 0–4 | GDD-02（暴露斜率）、GDD-03（惩罚曲线） |

## 3. 核心机制

### 3.1 运动模型：方向玩家给，速率状态定

这是本系统最重要的一条规则，它精确定义了「鲨鱼永不停止」：

```
速率 v  = v_state(状态, carry_k)      ← 玩家不可控，由状态机决定
方向 θ  = 由玩家输入的目标角，经角速度 ω 平滑追随  ← 玩家唯一可控的量
速度矢量 = v × (cos θ, sin θ)
```

> **推论**：玩家**永远不能让鲨鱼停下来**。他只能改变它往哪儿走。
> 这正是概念文档 §7.2「玩家只控制『往哪』，不控制『走不走』」的机制化表述，也是移动端能把输入压缩到 1.5 个自由度的前提。

| 输入 | 自由度计算 | 说明 |
|---|---|---|
| 方向（二维连续） | **1.0** | 单指拖拽 = 一个连续的方向矢量，不是两个独立轴 |
| 冲刺（离散点按） | **0.5** | 可选、低频、非持续 |
| **合计** | **1.5** | ✅ 与概念文档 §7.2、美术圣经 §5.0 一致 |

### 3.2 方向追随（转向惯性 / 重量感）

概念文档 §9 把「鲨鱼手感（重量感、转向惯性、冲刺曲线）」列为 P0 关键待解问题。裁决如下：

```
θ_target = atan2(input_dy, input_dx)          // 玩家输入的目标角，无输入时保持上一帧
Δ = 最短角差(θ_target − θ)                     // 归一化到 (−180°, 180°]
θ += clamp(Δ, −ω·dt, +ω·dt)                    // 每帧最多转 ω·dt
```

- `ω` = 当前状态的最大角速度（见 §4.2）
- **不引入加速度/惯性积分**——只用「最大角速度」限制。理由：像素街机游戏里，二阶惯性会让操作显得"糊"，与美术圣经 §6.7 的「硬边、量化、干脆」直接冲突
- **转向惯性体现在 ω 的数值上，不体现在物理模型上**。这是一个刻意的简化：它给出重量感，又不损失输入响应

**四个允许速率为 0 的例外状态**（其余时刻速率恒 > 0，见 §3.1）：

| 状态 | 速率 | 玩家输入 | 时长 |
|---|---|---|---|
| `Stunned` 眩晕 | 0 | 完全失效 | 1.5 s |
| `Snared` 束缚（渔网） | 0 | 方向仍可输入，束缚结束立即生效 | 1.5 s |
| `Beached` 搁浅 | 0 | 仅 QTE 连打有效 | 2.5 s（QTE 窗口） |
| `Dead` 死亡 | 0 | 失效 | 0.8 s 动画 |

> ⚠️ **这四者是全部例外**。任何新出现的"速率为 0"需求都必须显式登记在此表，否则会破坏「永不停止」并重新打开龟缩漏洞。

### 3.4 冲刺（Dash）

| 阶段 | 时长 | 速率 | 说明 |
|---|---|---|---|
| **起手** | 0.00–0.08 s | 300 → 700 px/s 线性 | 8 帧爆发感。起手即扣体力（见 §4.3） |
| **巡航** | 0.08–0.65 s | 700 px/s 恒定 | 冲刺主体，位移约 400 px |
| **衰减** | 0.65–0.80 s | 700 → 300 px/s 线性 | 收尾段，给冲刺一个"用完"的物理感，避免戛然而止 |
| **冷却** | 冲刺结束后 1.2 s | — | 冷却期间不可再次冲刺 |

**冲刺期间的三条约束**（它们是"冲刺是承诺"的机制保证）：

1. **转向受限**：`ω` 降至 90°/s，且 `θ` 被限制在**起手方向 ±25°** 内
2. **不可取消**：冲刺一旦起手，必须跑完 0.8s（除非被强制打断态打断）
3. **穿出水面即触发 DECOY BREACH**（GDD-03 §3.5）——这是冲刺的副产品，不是独立技能

**冲刺与咬合的关系**：**咬合只在冲刺状态下判定**（概念文档 §3.1 动词表：`咬 / Bite | 冲刺命中自动触发`）。
> 裁决理由：若非冲刺也能咬到，冲刺就失去了作为进攻工具的独占价值，且潜行阶段会因"蹭到就吃"而破裂——玩家无法安全地靠近目标观察，支柱二的「估值时间」被剥夺。

### 3.5 冲浪模式（Surf）· 副循环入口

**进入条件**（三条同时成立）：

| 条件 | 阈值 |
|---|---|
| 位于冲浪区 | `x ∈ [x_surf, x_beach)` |
| 贴近浪面 | `|y_shark_center − y_wave(x)| ≤ 40 px` |
| 速率足够 | `|v| ≥ 0.8 × v_cruise = 240 px/s` |

**效果**：速率 ×1.25，体力回复 +0.6 格/s，鲨鱼侧身（视觉规格见美术圣经 §4.1.5 `surf` 帧）。
**退出**：任一条件不成立即退出，无过渡动画（保持街机的干脆）。

> ⚠️ **本系统只负责 Surf 的进出与速率加成**。收集物生成规则、COMBO 窗口与倍率曲线归 **GDD-04（冲浪收集与 COMBO 系统）**，本文档不越界。

### 3.6 搁浅判定（Beached）

> **设计说明**：原型当前的「鲨鱼卡在沙滩上」是一个物理/碰撞 Bug。用户决策 **D4** 已拍板：**设计化为招牌机制**（概念文档 §3.1）。本节给出它的触发条件、逃脱方式与后果的机制定义；演出规格见美术圣经 §6.8。

**触发条件**（两条必须同时成立，且**持续 1.2 s**）：

| 条件 | 定义 |
|---|---|
| **触地** | 鲨鱼底部 `y ≥ y_sand(x) − 8 px`（沙滩地形线） |
| **低速** | 水平速率 `|v_x| < 210 px/s`（= 0.7 × v_cruise） |

```
if (触地 && 低速)  beach_timer += dt
else              beach_timer −= 2.0 × dt      // 回落速度是累积速度的 2×

if (beach_timer ≥ 1.2 s)  → 进入 Beached
if (beach_timer ≤ 0)      → beach_timer = 0
```

**为什么用「低速」而不是纯「停留时间」**：这样**高速掠过沙滩不会搁浅**——一个极限贴地掠过的操作是**技巧**而不是失误。这直接创造了概念文档 §3.2 预判的涌现玩法「**贴浪极限**」：在搁浅阈值边缘反复试探，换最高速的冲浪连击，风险自找、收益自担。

**为什么携带时更容易搁浅（无需额外公式）**：
- 空手速率 300 px/s > 阈值 210 → 正常游动不搁浅，**只有撞轮胎/减速后才会**
- 携带 k=2 速率 210 px/s = 阈值 → **处于临界，必须靠冲刺维持**
- 携带 k=4 速率 138 px/s < 阈值 → **不冲刺就必搁浅**

> 携带惩罚（速率下降）自动推导出"越贪越容易搁浅"，不需要为搁浅单独写一套 k 曲线。这是支柱一「你的战利品就是你的通缉令」的自洽闭环。

**逃脱窗口**：`beach_timer` 累积期间玩家仍可操作。只要把速率拉回 ≥210 px/s（冲刺 / 冲向下坡）或离开沙滩地形，就逃脱。**1.2 s 是明确的、可感知的求生窗口**，不是突然死亡。

**QTE**：进入 Beached 后 2.5 s 内需 6 次有效输入（概念文档 §3.1）。成功 → 弹回水中（复用 `breach` 动画 + L1 水花 + 顿帧 0.08s + 震屏 6px）；失败 → 死亡。完整演出见美术圣经 §6.8.4–6.8.5。

> ⚠️ **体力消耗不随 k 递增**（恒为 2 格）。理由：速率与转向已随 k 递减，若体力也递减，k=3 起冲刺将完全不可用于逃生段，那会让 k≥3 直接变成死策略——而沙盘明确建模了 k=3 / k=4 的收益区间（🔒）。**不得让 k≥3 变成不可玩状态。**

> **⚠️ 主导策略自检 · 深海龟缩**：深海回复 0.4 格/s（7.5 s 回满），但深海区零分数产出，ALARM 衰减的同时收益速率为 0 → 概念文档 §3.1 的「龟缩 = 零收益」自然惩罚成立。✅

### 5.1 输入方案

| 操作 | 键盘 | 触屏 | 说明 |
|---|---|---|---|
| 方向（二维） | 方向键 / WASD | **单指拖拽**（相对位移控制方向矢量） | 概念文档 §7.2 |
| 冲刺 | 空格 / J | **另一指点按**（或双指点按） | |

**触屏拖拽的方向映射**：

```
θ_target = atan2(pointer.y − anchor.y, pointer.x − anchor.x)
输入强度 = clamp(dist(pointer, anchor) / 60 px, 0, 1)
```
- 拖拽距离 < 12 px 视为无输入（防误触），保持上一帧 `θ_target`
- `anchor` 在 `pointerdown` 时设定，拖拽中位置固定（**相对位移**，非跟随手指）

### 5.2 响应时序（输入延迟预算）

| 事件 | 响应延迟 | 说明 |
|---|---|---|
| 方向输入 → θ 开始变化 | **≤ 1 帧（16.7 ms）** | 硬要求。§3.2 不做惯性积分正是为此 |
| 冲刺输入 → 起手帧播放 | ≤ 2 帧 | 需校验体力，允许 1 帧判定 |
| 冲刺起手 → 体力格闪灭 | 同帧 | 美术圣经 §6.1 |
| 搁浅 QTE 有效输入 → `thrash` 播一次 | ≤ 1 帧 | 美术圣经 §6.8.4：「必须让玩家感到每一次点击都推动了什么」 |

> ⚠️ **顿帧禁令**（美术圣经 §6.6 / 概念文档 §6）：**受击、被追击时绝不触发顿帧**。逃生段顿帧会被感知成卡顿与输入延迟。本系统所有强制打断态（Stunned / Snared / Slowed）**一律不给顿帧**。

## 6. 边缘情况

### E1 · 冲刺途中进入强制打断态（Stunned / Snared / Beached）

**情形**：玩家起手冲刺（0.8 s）后第 0.3 s 被救生员浮标命中，进入 Stunned。
**裁决**：
1. 冲刺**立即中止**，剩余 0.5 s 不保留、不返还体力（体力已在起手时扣除）
2. 冷却计时**从打断时刻起算** 1.2 s（不是从原定结束时刻）
3. `θ` 保持被打断时的朝向，Stunned 结束后以该朝向继续
4. **不给顿帧**（§5.2 禁令）

**理由**：若冷却从"原定结束"起算，等于眩晕时冷却也在走，玩家会觉得眩晕的代价变轻了；若返还体力，则"被打断"反而有收益，会催生主动碰瓷的策略。

---

### E2 · 冲刺结束瞬间恰好贴着浪面且速率达标

**情形**：冲刺衰减段结束时，鲨鱼位置满足 Surf 三条进入条件。
**裁决**：**允许进入 Surf**，且速率按 `状态速率 ×1.25` 计算。冲刺衰减段的终速 300 px/s × 1.25 = 375 px/s，随后平滑回落到 Surf 巡航速率。

**理由**：这是「冲刺切入冲浪」的正向技巧，玩家应该被奖励而不是被系统拦下。它与概念文档 §3.2 预判的涌现玩法「**连击搭桥**」（先冲浪攒 COMBO 再叼人）方向一致。

---

### E3 · 搁浅计时未满时，鲨鱼被强制打断态打断（如渔网束缚刚好落在沙滩上）

**情形**：`beach_timer` 已累积 0.9 s（未达 1.2 s），此时被渔网命中进入 Snared 1.5 s。
**裁决**：
1. **`beach_timer` 冻结**（暂停累积，不回零、不清零）
2. Snared 结束后，`beach_timer` 从 0.9 s 继续累积
3. 若 Snared 期间鲨鱼仍触地且低速，仍**不**累积（避免"束缚 = 必死"的组合技）

**理由**：组合技（束缚 + 搁浅）若叠加为必死，会摧毁玩家对渔网作为「**非致命阻碍**」的定位认知（概念文档 §3.1 明确把渔网归为非致命）。冻结而非清零，既保留压迫感，又不制造不可反抗的死亡。

---

### E4 · 玩家在 Beached 状态中再次被敌人命中 / 直升机锁定计时到达

**情形**：搁浅 QTE 进行到第 1.8 s，直升机锁定计时器恰好满 3.0 s。
**裁决**：**Beached 状态期间，所有外部致命计时（直升机锁定、捕鲨队装填、T2 撞击判定）全部暂停**；ALARM 仍按 §GDD-02 的搁浅斜率飙升。

**QTE 成功后**：暂停的计时**恢复到进入 Beached 时的数值**（冻结，不是清零）。

> ⚠️ **这是一条防主导策略的关键裁决。** 若 QTE 成功后锁定计时**归零**，则「被直升机锁定时故意冲上沙滩搁浅 → 打过 QTE → 锁定清零」会成为一个**万能解围技**——玩家只需付出 1.2 s 的时间代价就能买断最高危的致命威胁。这是教科书式的主导策略，且直接架空 ALARM 75–100「围剿」档的全部张力。
> **必须冻结，不得清零。** 搁浅暴露已通过「ALARM 飙升 + 战利品全损（GDD-03 E1）」付出代价，不需要再加一条死亡。

**QTE 失败**：死亡，优先级见 GDD-02 E5。

---

### E5 · 转向追随中的角度回绕（±180° 边界）

**情形**：`θ = 170°`，玩家输入 `θ_target = −170°`。朴素实现会让鲨鱼转 340°，而玩家意图是转 20°。
**裁决**：`Δ` 必须归一化到 `(−180°, 180°]`：

```js
let d = target - current;
while (d >  180) d -= 360;
while (d <= -180) d += 360;
```

**理由**：这是原型阶段最常见的转向抖动 Bug。若不处理，玩家在正左/正右方向的微小输入抖动会导致鲨鱼"抽风式"旋转，直接摧毁手感，并被误读为输入延迟。

---

### E6 · 触屏拖拽时另一根手指按下（冲刺）导致 anchor 跳变

**情形**：玩家单指拖拽控制方向，第二根手指点按冲刺，`pointerdown` 事件可能重新锚定 `anchor`。
**裁决**：
1. `anchor` **只在第一根手指（`pointerId` 最小者）按下时设定**，后续手指不改变它
2. 冲刺点按走**独立的 `pointerdown` 监听**，不参与方向拖拽的位移计算
3. 第一根手指抬起时，`anchor` 清空；若此时第二根手指仍在屏幕上，**不自动接管**（避免方向突变），改为保持上一帧 `θ_target` 直至新的 `pointerdown`

**理由**：移动端多点触控的手指身份管理是原型高频 Bug 源。不锁 `anchor` 会出现"想冲刺却突然转向"的失控感。

---

### E7 · 鲨鱼抵达航道边界（x < 0 或 x > 3000）

**情形**：玩家一直往左（深海方向）或往右（沙滩方向）推。
**裁决**：
1. **硬边界**，`x` 被 clamp 到 `[0, 3000]`，速率不降（鲨鱼顶着边界游，视觉上是"顶住"）
2. `x = 0` 处强制进入 Bank 判定区（GDD-03 §3.6）
3. `x = 3000` 处即沙滩最远端，**不额外惩罚**（该处已经是明度 82% 的最暴露区，惩罚已足够）
4. 顶住边界**不累积 `beach_timer`**（边界处不算触地）

**理由**：不做软墙反弹——反弹会破坏「永不停止」的连续感，且玩家可能利用反弹做高速折返（ unintended tech）。硬 clamp 最可预测。

---

### E8 · 帧率骤降时的位移积分（低性能设备）

**情形**：移动端掉帧到 25 fps，`dt` 达 40 ms，冲刺 700 px/s 单帧位移 28 px。
**裁决**：
1. **`dt` 上限 clamp 到 50 ms**（低于 20 fps 时宁可慢放，也不要大位移穿透）
2. 冲刺期间启用**分步碰撞检测**：单帧位移 > 40 px 时，把该帧拆成 `ceil(dist / 40)` 个子步做扫掠检测
3. 咬合判定与搁浅判定**同样走子步**，不得只在帧末采样

**理由**：原型期"鲨鱼穿墙/穿人"的经典根因。低性能移动设备是本作的主要平台之一，必须在设计层就写死。
