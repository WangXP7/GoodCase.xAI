03技术要点

全部由脚本生成，无任何外部资产。以下几条是这轮里真正决定成败的地方。

  • 俯视 diorama 时，物理正确的天空渐变在画面里根本看不见。相机俯角 22.5°、垂直 FOV 只有 27.6°，整幅画面都落在地平线以上，于是「上冷下暖」的渐变整条跑到画外。v1 的天变成一片暖橙就是这个原因。
  • 修法是换掉坐标源，而且要先用彩虹图标定。TexCoord.Generated 在 World 里返回常量（天空直接变单色），必须改用 NewGeometry.Incoming → SeparateXYZ.Z → MapRange(-1..1 → 0..1) → ColorRamp。但映射关系不直观：先渲一张 8 段 CONSTANT 彩虹 ramp 的 640×480 标定图，反推出「画面高度 ↔ ramp 位置」的对应（本机相机下可见区间约 0.55–0.80），再据此摆暖色余晖带。
  • 不能靠查 enum 判断引擎能力。RenderSettings.engine 的 enum_items 在本机 5.2.2 的 --factory-startup 下只返回 ['BLENDER_EEVEE']，但 render.engine = 'CYCLES' 实际是成功的。view_settings.view_transform 同样只报 NONE，而 AgX / Filmic / Standard 都能设。一律实测赋值，别信 enum。
  • 合成器 API 在 5.x 变了。Scene.node_tree 已移除，改用 Scene.compositing_node_group（需自建 bpy.data.node_groups.new(name, "CompositorNodeTree") 并用 interface.new_socket 定义进出 socket）；CompositorNodeComposite / MixRGB 已不存在；Glare 节点的全部参数都改成了 input socket（Type、Threshold、Strength、Size、Tint 这些都是 inputs[...] 下的条目），旧属性名一律 AttributeError。
  • 辉光在这个场景里救不回来，最后关掉了。雪面在强光下的 HDR 亮度与窗光发光体是同一量级，任何「能让窗户发光」的阈值都会连带把整片雪原点亮、把画面整体染暖。代码里保留了 setup_compositor() 并设 USE_BLOOM = False，需要时可以打开。
  • EEVEE 阴影池有 2048 tile 硬上限。shadow_pool_size 的枚举最大就是 2048，400+ 对象的场景必然报 "Shadow buffer full"。实测 visible_shadow = False 与 shadow_ray_count = 1 都不能降低这个计数——只能合并对象，或者接受它（实际视觉影响极小）。
  • 屋顶积雪是细分位移雪壳，不是贴片。snow_slab_grid() 把四边形细分成 9×9 网格，沿法线按「檐口薄、屋脊厚」的厚度函数抬高，再叠一层带边界衰减的噪声；边缘自动收口到 0，所以檐口不会翘边、屋脊自然堆高。
  • Blender 4.1+ 没有 mesh.use_auto_smooth。平滑着色 + 保留硬边要用「polygon.use_smooth = True + 按面夹角标 edge.use_edge_sharp」这个组合，不要再调 shade_smooth_by_angle 算子（它在 background 模式下还要依赖 context）。
