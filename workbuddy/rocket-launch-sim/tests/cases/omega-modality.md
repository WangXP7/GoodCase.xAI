## 对既有 A7-2 断言方法的审查（本任务重点）

`verify-prototype.mjs` 的连续性断言是：

```js
jumpSeen = sim.omega.get().switchJump * 100;    // ← 读被测模块自己算的 switchJump
ok('切换跳变 ≤ 0.5%', jumpSeen <= 0.5, ...);
```

**问题：`switchJump` 由 `omega.js:97` 在切换帧赋值为该帧的 |Δs|，它衡量的是"普通单步增量"，不是" discontinuity"。**

独立验证证明（TC-OMEGA-04）：切换帧的 ΔΩ = 0.018%，而**全体帧**的 p99.9 = 0.079% —— 切换帧的变化**比普通帧还小**（比值 0.23×）。也就是说：

- 该断言测的指标**任何一帧都会通过**，没有针对"切换"这一事件做任何检验；
- 从数学上，`s = max(h_eq,h_p)ᵞ` 是 `h_disp` 的连续函数，而 `h_disp` 取 `max` 保证单调 —— **不连续根本不可能发生**，所以该断言"必然通过"是结构性冗余，而非"验证通过"。

**建议**：把 A7-2 的判据改为「全程 max 逐帧 |ΔΩ| ≤ 阈值」（本套件 TC-OMEGA-03 已实现），它才是真正能在回归中捕获 discontinuity 的断言。

## ⚠️ TC-OMEGA-11 备注：分离度余量脆弱

S7 §6.5 标称样本给的是"入轨 ≥97.8% vs 失败 ≤96.2%"（余量 1.6%）。在**玩家真实输入**的 50 组弹道里，余量收窄到 **99.4% vs 98.9%（0.5%）**：例如 `hTurn=10500/p=2.0` 的未入轨弹道 Ω 终值达 **98.9%**。即 A7-6 形式上通过，但"满条却未入轨"的边缘案例已非常接近。建议在 Phase 5 用真实弹道重跑并考虑重标定 `Ω_CRIT`。

> **提示风险（非缺陷）**：这也是 S7 §3.1 第 5 道防线（模态 A 成功标记恒为灰）必须成立的原因——否则玩家看到 98.9% 的满条会误以为已入轨。该防线的验收 A7-17 目前**无自动化**，需浏览器截图核查。
