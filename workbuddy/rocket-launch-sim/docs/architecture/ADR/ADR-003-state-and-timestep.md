# ADR-003 · 状态管理与时步

- **状态**：已接受（Accepted）
- **日期**：Phase 3
- **决策者**：程基岩（技术/引擎）
- **关联**：ARCH-1 §2/§3/§5 · GDD S1 §3.1 · S3 §6.2

## 背景（Context）

物理必须在不同渲染帧率下产生**相同弹道**（确定性），且要处理：卡顿后的追帧、分离顿帧（S3，物理暂停但视觉继续）、焦点丢失。同时 HUD 与渲染需读状态但**绝不能回写**物理。

## 决策（Decision）

1. **单一可变状态容器** = `Simulation` 实例（含 `fm/atmo/orbit/omega/seq/staging/judge/failure`）。由 `Game` 单例在渲染宿主中持有；无头脚本各自 new 一个。
2. **固定步长累加器**：物理锁 120 Hz；`acc += clamp(realDt,0,MAX_FRAME_DT)`；`while(acc>=DT && steps<5) step(DT)`。保留 `renderAlpha=acc/DT` 供插值。
3. **单向数据流**：输入 → `setInput()` → 物理步 → `hudModel()` 只读快照 → 渲染/HUD。**快照对象每帧复用只读缓冲，render 层无写权限。**
4. **顿帧不喂时间**：分离顿帧期间不向 `acc` 累加，避免补跑。
5. **每帧最多追 5 步**（`MAX_STEPS`）防死亡螺旋。

## 备选方案（Alternatives）

| 方案 | 为何不选 |
|---|---|
| **可变步长（跟 rAF delta）** | 弹道随帧率漂移，确定性丧失，无头无法复现浏览器结果 |
| **把物理对象塞进 Phaser Scene（用其 update）** | 物理与渲染耦合，无法无头运行，破坏 core/render 边界 |
| **每步全量重建快照（分配型）** | 120Hz × 每次新对象 → 热路径 GC 压力。采用复用缓冲（见 control-manifest 零分配规则） |
| **事件总线反向通知物理** | 引入隐式耦合与非确定性顺序，违背"物理只被时间推进" |

## 后果（Consequences）

**正向**
- 确定性：30fps 与 144fps 下弹道**逐位相同**（`verify-prototype` 中"倒计时期间无位移/不耗油"与帧率无关测试佐证）。
- render 层不可能误改物理 → 架构上杜绝一类 bug。
- 顿帧、追帧、失焦均被显式策略覆盖。

**负向 / 代价**
- 需手动实现累加器/夹紧/插值（已在 core 完成）。
- `renderAlpha` 插值要求绘制层正确处理"上一帧 vs 当前帧"，箭体位置/角度需双缓冲（已实现）。

**触发重评的条件**
- 若引入联网对战（需 lockstep/回滚）→ 时步策略需升级为定步 + 状态快照回滚。
