# ADR-004 · 轨道解算的调用时机

- **状态**：已接受（Accepted）
- **日期**：Phase 3
- **决策者**：程基岩（技术/引擎）
- **关联**：ARCH-1 §2.2 · GDD S5 §2 · S7 §6.4

## 背景（Context）

每步需要知道轨道根数（偏心/半长轴/近远地点/制度），用于：① 判近地点是否越 15 km（Ω 模态切换 + 评级）② 失败归因（ESCAPE/DEGENERATE 识别）③ HUD 双模态显示。问题：**每物理步（120Hz）解算，还是事件驱动（仅需时解算）？**

## 决策（Decision）

**每个物理步都解算（120 Hz），用解析式 + 复用输出对象。**
- 解算仅含闭式表达式（比角动量、能量、e、a、h_p、h_a），无迭代求解。
- `OrbitSolver` 持有 `this.out` 复用对象，`solve()` 原地写入，**热路径零分配**。
- `DEGENERATE`/非有限结果 → 沿用上一有效帧；从未有效 → `peri=−R`（强制模态 A，S7 §6.4）。

## 备选方案（Alternatives）

| 方案 | 为何不选 |
|---|---|
| **事件驱动（仅在特定 h/p 阈值变化时解算）** | 需维护"何时该重算"的判断，逻辑复杂且易漏触发；Ω 是**连续**量，阈值法在临界处会产生延迟/抖动，破坏"模态切换视觉连续、不跳变"的硬要求 |
| **每 N 帧解算（降频）** | 同样引入临界处抖动；且 120Hz 下解析解算成本本就很低，降频收益不抵风险 |
| **GPU/Worker 并行解算** | 过度工程；单帧解算仅数十次浮点运算 |

## 后果（Consequences）

**正向**
- Ω 与近地点**逐帧连续**，模态切换无跳变（实测 `switchJumpPct ≤ 0.019%`，远小于感知阈值）。
- 逻辑简单：每步无条件解算，无"何时重算"分支。
- 复用对象 + 闭式表达式 → 120Hz 下开销可忽略。

**负向 / 代价**
- 每步都算，即便在不需要的早期阶段（成本极低，可接受）。
- 依赖"解析式足够廉价"这一前提；若未来解算变重（如摄动项），需回头改为惰性/缓存。

**触发重评的条件**
- 若引入高阶引力摄动/J2 → 解算变重，改为惰性求值 + 脏标记。
