> **本文档的五条硬约束（贯穿全篇）**
> 1. **P1 过程即内容**：不设计"播放一段音效让你听"的被动表演。每一个音频都必须**挂在玩家操作或物理状态变化上**，且**改变玩家的下一次输入**。
> 2. **P3 一次发射，六十秒**：无长前奏、无慢起音、无 30 s 以上的乐句。所有音效**起音 ≤ 120 ms**（爆炸除外，其起音 ≤ 5 ms）。

> 5. **音频不得驱动任何视觉**（硬边界，对齐美术 §9.2 **T2**「禁止音乐可视化式特效」）：**音频永不驱动发光 / 跳动 / 波形 / 缩放；视觉也永不依赖音频**。本作**所有发光由物理事件驱动**（喷口、补光、辉光弧），**不由时间或音量驱动**。此条为双向承诺，亦见 §1.3 与 §8.1。

## §1 音频基调

### 1.1 一句话定调

> **用模拟合成器与机械继电器，把每一个物理量翻译成一声可辨认的响动——1960 年代任务控制中心的冷静，不是太空歌剧的宏大。**

### 1.2 五个风格关键词（对齐美术 §1.2 的 K1–K5）

| # | 关键词 | 含义 | 落地判据（可验收） |
|---|---|---|---|
| **A1** | **Analog-Instrument 模拟仪表** | 主体音色来自**减法合成**（振荡器 + 滤波 + 包络），非管弦、非采样乐器库 | 全作**零个**原声乐器采样；旋律性组件仅允许正弦 / 三角波振荡器 |
| **A2** | **Mechanical Relay 机械继电器** | 状态切换用**继电器的咔哒**而非"UI 音效包"的电子"叮" | 每一次状态机跃迁（子阶段推进、模态切换、按钮）都伴随一个**继电器咔哒**，且不同跃迁**咔哒音高不同** |
| **A3** | **Radio Telemetry 无线电遥测** | 人类声音缺席，只有**带限（300–3000 Hz）的载波噪声**作为"有人在听"的存在感 | 任何"告警 / 确认"类音必须经**带通 300–3000 Hz**处理，模拟无线电链路 |
| **A4** | **Tape Grain 磁带颗粒** | 一切长音均有**轻微不稳（wow/flutter, ±5 cent）+ 底噪**，对抗"数字塑料感" | 停顿静默段不是**数字零**，而是**−60 dBFS 的磁带噪声**（除 §3.8 指定的两处**绝对静默**） |
| **A5** | **Information-Carrier 信息载体** | 每个音首先是一条**可读信息**（对齐美术 K4），删掉它玩家会**少知道一件事** | 任何音频若被删掉而"玩家仍能在 1 s 内读懂该状态"，即为装饰音 → 打回 |

### 1.3 为什么"模拟合成器 + 继电器"是对的（与视觉定调的对齐论证）

美术 §1.1 定的视觉基调是 **1960s 任务控制中心仪表美学**，其四条可验收判据是：等宽数字、物理开关、印刷温度、仪表可读性。音频与它们逐条对齐：

| 视觉锚点（美术 v1.1） | 音频侧对齐手段 |
|---|---|
| **K1 Analog-Futura**（模拟仪表、物理开关） | 减法合成音色 + 继电器咔哒 + **9 个"仪器音"而非"音乐音"** |
| **K2 Hard-Edge Geometric**（硬边、无柔边） | **短包络、零混响尾巴**（爆炸、爆螺栓均**无 reverb tail**，S6 §5.3 原文）；禁止长衰减 pad 覆盖事件 |
| **K3 Print-Texture Warmth**（颗粒、网点） | 磁带底噪 + 轻度 wow/flutter（A4 关键词）；点阵打印机式"遥测走纸"音（§3.9） |
| **K4 Instrument Readability**（元素首先可读） | **A5 关键词**：每个音必须携带信息，删则信息缺失 |
| **K5 Vertical Grandeur**（构图锁纵向） | **频率侧锁纵向隐喻**：上升 = 频率/亮度上行（点火、越线、锁相确认）；下降 = 残骸 tumble、失败 |

> **与美术 §9.2 T2 的关系（重要）**：美术禁止"音乐可视化式特效"，即**音频不得驱动任何发光 / 跳动 / 波形**。本文档**完全接受**该禁令，并在 §8 反向承诺：**音频永远不驱动视觉，视觉也永远不依赖音频**（这也是可访问性的前提，见 §8）。S2 §5.4 已把"哔声不得驱动发光"写死为禁忌，本文档与之逐字一致。

### 1.4 明确不做（Anti-Audio）

| 不做 | 理由 |
|---|---|
| ❌ 管弦配乐 / 史诗铜管 | 违反 A1；太空歌剧腔与"飞行员的驾驶考试"定位冲突（概念 D1） |
| ❌ 电子"叮"式 UI 音效包 | 违反 A2；通用素材感，违反美术 T8 的音频版 |
| ❌ 语音播报（"Three, two, one..."）/ VO | MVP 无 VO（概念 §7.1 未列）；且**倒计时的仪式感应由"数字 + 继电器 + 静默"承担**，人声会把它变成电影 |
| ❌ 失败时的惩罚性下行音阶 / "失败"齐奏 | S6 §5.3 原文禁止；P4 要求"失败是内容不是惩罚" |
| ❌ 长混响 / 大空间感 | 违反 K2 硬边；且发射场是户外，混响会瞬间变成"室内演出感" |
| ❌ 音频驱动的任何视觉 | 美术 §9.2 T2 硬禁止 |

## §2 音乐方向

### 2.1 先回答"要不要音乐"

**概念文档给的边界是清楚的**：
- 概念 §7.1「✅ 进 MVP」只写了 **「基础音效：引擎、爆炸、分离」**——**MVP 不含音乐**。
- 概念 §7.2「核心体验层」才写 **「音效与音乐分层（引擎噪声随速度 / 节流动态变化）」**——音乐分层是**下一层**的内容。
- 概念 §3.3 Aesthetics 只把 **Sensation（感官）** 列为主美学，且其具体表现写的是 **"引擎噪声随速度变化的音效分层"**，**未提音乐**。

**因此我的判断分两层**：

1. **MVP 不引入"旋律音乐"**（不写主旋律、不做主题动机、不做配乐段落）。
2. **但 MVP 需要一层"承担音乐功能的声音"**——即一条**控制室环境床**（Ambience Bed）。它不是音乐，但它填补了"完全没有持续声底"会造成的空洞感，并让失败 / 入轨的静默有对比。

### 2.2 两方案对比

| 维度 | **方案 A · 克制（环境床，无旋律）** | **方案 B · 靠近高潮（自适应模块化配乐）** |
|---|---|---|
| 内容 | 一条非旋律 analog drone（2–3 个慢速失谐正弦 + 带限噪声 + 磁带嘶声），分为 4 个"相位变体"，随飞行阶段交叉淡化 | 4–6 个可叠加的 8–16 s 模块（脉冲 / 低音 / 琶音），按阶段叠层进场 |
| 单局 60–90 s 适配 | ✅ 相位变体交叉淡化，**无循环接缝** | ⚠️ 模块需精确对齐相位，60 s 局与 90 s 局的**接缝位置不可控**；易被听出"循环了" |
| 与"仪表美学"一致性 | ✅ 高（A1/A3 关键词天然契合） | ⚠️ 低（有旋律即"配乐"，瞬间滑向太空歌剧） |
| Achiever 高频重玩疲劳（概念 §2.2，日均 15–30 min） | ✅ 低（drone 会自动退到背景） | ❌ 高（旋律是"听第二遍就腻"的东西） |
| P4（失败不惩罚） | ✅ 环境床**在失败时继续存在**，中性、非惩罚 | ⚠️ 音乐在失败时"停 / 落"天然读作惩罚 |
| P1（过程即内容） | ⚠️ 中性（环境床是被动的，但优先级最低，不抢戏） | ❌ 弱（旋律是典型的"播放给你听"的被动表演，与 P1 直接冲突） |
| 实现成本 / 体积 | ✅ 极低（合成，**0 KB 资产**） | ❌ 高（需要作曲、编排、多模块资产） |
| 是否符合概念 §7.1 MVP 边界 | ✅ 是（可论证为音效而非音乐） | ❌ 否（属 §7.2 核心体验层） |

### 2.3 推荐：**方案 A** —— ✅ **已裁决（AQ1）：批准，MVP 不做旋律音乐**

> **✅ 裁决结论（主理人 游承峰）**：**采纳方案 A。** 理由被明确肯定为"**符合 P1** —— 环境床服务氛围，而不是『播一段音乐让你听』"。78–90 s 单局 + 高频重玩下，旋律要么太短听不出主题、要么循环露馅；且概念 §7.1 的 MVP 边界本就不含音乐。
> **方案 B（自适应模块化配乐）转入"核心体验层"备选**，MVP 不实现（对齐概念 §7.2「音效与音乐分层」的下层归属）。

**一句话理由**：单局只有 78–90 秒、且玩家会高频重玩同一局，**旋律音乐在这个时长下只有两种命运——要么太短听不出主题，要么循环痕迹明显；而仪表美学本身不需要旋律，它需要的是"机器在工作"的持续声底。**

**方案 A 的具体规格**：

| 项 | 规格 |
|---|---|
| 名称 | `bed_control_room`（控制室环境床） |
| 层次 | ① 次低音 drone（55 Hz 正弦，缓慢 ±3 cent 漂移）② 失谐对（110 / 111.5 Hz 三角波，产生 1.5 Hz 拍频）③ 带限噪声（300–3000 Hz，−42 dBFS，模拟无线电链路本底）④ 磁带嘶声（−48 dBFS，全频） |
| 相位变体 | 4 个：`IDLE` / `ASCENT` / `VACUUM` / `TERMINAL`，**交叉淡化 1.5 s**，由飞行阶段驱动 |
| 音量 | **−20 dB**（最低优先级总线，见 §6） |
| 起音 | **无**（全程存在，从进入关卡即淡入 2 s） |
| 独立开关 | ✅ 设置项 `audioBed`（默认开），可单独静音 —— 见 §8 |
| 体积 | **0 KB**（全程序合成） |

> **相位变体与事件的对齐**（这让"非音乐"也能承载叙事）：
> - `IDLE`（T-10 前 / 待机）：仅 ① + ④，最稀薄。
> - `ASCENT`（松绑 → 大气顶）：叠入 ②，bass 拍频给"力量感"。
> - `VACUUM`（T+47.6 → tJudge）：撤掉 ③（无线电本底），只留 ① + ② 更纯净——**听觉上的"世界安静了"与 S4 §5.3、美术 §6.6 的"用静表达"同构**。
> - `TERMINAL`（结算 / 归因面板）：回到 ① + ④，加一个极缓慢的上行谐波（仅 +0.2 dB/2 s），是**"这条链路还在运行"**而非"庆祝"。
>
> **失败路径特例**：失败时环境床**不停**，只把 ② 的拍频**拉慢到 0.4 Hz**（"心跳变慢"而非"音乐停了"）——这是 P4「失败是内容不是惩罚」的音频兑现。

## §3 音效设计清单

> **通用规格**：采样率 44.1 kHz；采样件单声道（除爆炸为立体声）；所有一发声件的**起音 ≤ 120 ms**（爆炸、爆螺栓例外，见条目）；声像（pan）默认居中，仅残骸 / 爆炸使用轻声道偏移以制造宽度。
> **所有音效的对齐锚点**：S2 §5.4、S3 §5.3、S4 §5.3、S5 §5.4、S6 §5.3、S7 §5.5 / §7.2 已给出的事件音规格，本文档**逐条落实并补全**，不与之冲突。

### 3.1 发射前序列（T-10 → T+0.40）

| 事件 | 时刻 | 声音设计 | 时长 | 合成/采样 |
|---|---|---|---|---|

## §4 动态分层音频系统（本项目音频的核心价值）

> **概念 §7.2 原文要求**：「音效与音乐分层（**引擎噪声随速度 / 节流动态变化**）」。
> **概念 §3.3 主美学 Sensation 的具体表现**：「引擎噪声**随速度变化**的音效分层」。
> §4 是这两条的**唯一落地章节**。这是本文档最高价值的部分。

### 4.1 为什么必须"合成"而不是"采样"

| 需求 | 采样方案的失败点 | 合成方案 |
|---|---|---|
| 节流 τ ∈ [0.30, 1.00] 连续变化 | 需要**每一档一个采样**（或交叉淡化多档，仍有"档位感"） | 一个振荡器 + `GainNode` 连续映射，**零档位感** |
| 动压 q 从 0 → 16.5 kPa → 0 连续 | 无法在一个采样里表达"气动分量随 q 起落" | 独立噪声层，**增益直接 ∝ q** |
| 大气密度 ρ 在 T+47.6 断崖归零 | 需要额外的"切段"素材 | 用 `rho` 直接门控气动层，**天然无缝** |
| 级间音色切换（5 喷口 → 1 喷口） | 需要两套长循环 + 精确对齐 | 两套振荡器簇，**0.10 s 换组** |
| 体积 | 长循环引擎噪声若采样：10 s × 44.1 kHz 立体声 Opus ≈ **160 KB/条**，多档叠加破 1 MB | **0 KB** |
| 循环接缝 | 长循环长音**接缝永远存在**，在 78–90 s 局里会被听出 | 无接缝（连续合成） |

**结论：引擎系统 100% 程序合成。** ✅ **已裁决（AQ3）：批准。** 主理人肯定理由为"这是唯一同时满足『连续参数化 + 0 KB + 无接缝』的方案，且概念 §7.2 明确要求『引擎噪声随速度 / 节流动态变化』——**采样做不到无级连续，合成才能**"。

```
                    │  gain = clamp((q − 8 kPa) / 8 kPa, 0, 1) × 0.8            │
                    └─────────────────────────────────────────────────────────┘
                                        ┌──────────────────────────────┐
                                        │ L6 侧滑噪声 Sideslip Noise    │
                                        │ 500–4k Hz 噪声, gain ∝ |α|    │
                                        │ （玩家操作反馈，不属环境）     │
                                        └──────────────────────────────┘
```

> **L1–L4 是"环境 / 机器"层；L5 是"结构载荷"层；L6 是"玩家操作"层。** L5 独立总线的原因见 §6：**它必须能在引擎声之上被听见**（R3 专项的关键）。

### 4.3 参数映射表（可直接实现）

| 输入（来自 `sim.hudModel()`，**只读**） | 影响层 | 映射 | 平滑 |
|---|---|---|---|
| `throttle` τ ∈ [0.30, 1.00] | L1 增益 | `gain = −22 dB + 16 dB × (τ − 0.3)/0.7`（0.3 → −22 dB，1.0 → −6 dB） | `setTargetAtTime`, τ = 30 ms |
| `throttle` τ | L2 增益 | `gain = −26 dB + 18 dB × (τ − 0.3)/0.7` | τ = 30 ms |
| `throttle` τ | L3 音高 | `freq = 90 + 130 × (τ − 0.3)/0.7` Hz（90 → 220 Hz） | τ = 40 ms |
| `speedMs` v | L3 音高（微调） | `freq ×= 1 + 0.06 × (v / 2087)`（最多 +6%） | τ = 120 ms |
| `speedMs` v | L2 频谱斜率 | 低通 `cutoff = 400 + 700 × (v / 2087)` Hz（越快越"亮"） | τ = 120 ms |
| `qPa` q | **L4 增益** | `gain = −40 dB + 34 dB × clamp(q / 16.5 kPa, 0, 1)` | τ = 60 ms |
| `rho` ρ（或 `qState`） | **L4 门控** | `gate = ρ > 0 ? 1 : 0`，配合 0.35 s 淡出（T+47.61 的"世界安静了"） | 0.35 s ramp |
| `qPa` q | **L5 增益** | `gain = clamp((q − 8 kPa)/8 kPa, 0, 1) × 0.8`（8 kPa 以下**完全无声**） | τ = 80 ms |
| `alphaDeg` \|α\| | L6 增益 | `gain = clamp((\|α\| − 5°) / 25°, 0, 1) × 0.7` | τ = 60 ms |
| `stage` 1 / 2 | **音色换组** | stage 1 → 5 振荡器簇（±0.8% 失谐）；stage 2 → 单振荡器 | **0.10 s crossfade** |
| `phase` | 环境床相位 | `IDLE/ASCENT/VACUUM/TERMINAL` 交叉淡化 1.5 s | 1.5 s crossfade |

> **映射原则**：**每一个映射都必须能回答"这个声音告诉玩家什么"**（A5 关键词）。
> - τ → 音量/音高：**"我给多少油门，就有多大劲"**（V2 的即时反馈，P1）
> - q → L4：**"大气在拦我"**（S4 §3.3 的听觉表达）
> - q → L5：**"箭体在被压"**（R3 专项的关键，见 §9）
> - \|α\| → L6：**"我在侧滑"**（S4 §5.4 的听觉对应）
> - stage → 音色：**"换级了"**（S3 §5.2 的"换挡演出"听觉版）
> - ρ → 门控：**"我出大气了"**（S4 §5.3）

### 4.4 交叉淡化策略

| 场景 | 淡化方式 | 时长 | 理由 |
|---|---|---|---|
| 节流连续变化 | `setTargetAtTime`（指数逼近，非线性 ramp） | τ = 30 ms | **线性 ramp 会产生"拉链噪声"**。30 ms 时间常数在 120 Hz 物理步下无感知延迟，也无 zipper |
| 大气顶气动层消失 | 独立 `GainNode` ramp | 0.35 s | 与美术 §2.2 的 0.8 s 色带淡入**错峰**（音频先落，视觉后淡），避免"声画同步的机械感"（美术 §6.8-4 错拍原则的音频版） |
| 级间换组 | 两个 gain 交叉 | 0.10 s | 比 S3 的 `SEP_DELAY = 0.15 s` 预热**更短**，让"换声"发生在预热之后、点火之时 |
| 环境床相位 | 两条 bed 轨交叉 | 1.5 s | 慢到不会被听成"切歌" |
| 失败静默 | **硬切到 −∞** | 0 ms（瞬时） | S6 §5.3 要求"完全无声"，**任何淡化都会破坏这 0.6 s** |
| 入轨静默 | 硬切到 −∞ | 0 ms | S5 §5.4 的 0.8 s 静默同理 |

### 4.5 性能预算

| 指标 | 预算 | 说明 |
|---|---|---|
| 同时活跃 `AudioNode` 数 | **≤ 40** | 环境床 4 + 引擎 5（含簇内节点估计）+ 事件音峰值 ~10 + 混音总线 6 |
| 音频参数更新频率 | **rAF（≈60 Hz）**，**不在 core 的 120 Hz 步进内** | 热路径零分配（control-manifest Z1–Z3）；音频参数用 `setTargetAtTime`，不需 120 Hz |
| 音频线程 CPU | **≤ 3% 单核**（桌面） | 合成节点数远低于 Web Audio 可承载量级 |
| 单次 `setTargetAtTime` 调用 | ≤ 12 / 帧 | 只更新发生变化的层（带脏标记） |

### 6.2 相对音量建议（dB，相对 Master 0 dB 参考）

| 总线 | 标称 | 动态峰值 | 说明 |
|---|---|---|---|
| **Master** | 0 dB | 真实峰值 **−1.0 dBTP** | 留 1 dB 给编码与系统混音；加**峰值限制器**（阈 −1.0 dBTP，释放 50 ms） |
| **IMPACT（冲击/爆炸）** | **0 dB** | **−1.0 dBTP** | **全作最响的东西**（P4：失败也好看）。触发时 duck 其余总线 **−12 dB / 600 ms** |
| **TELEMETRY ALARM（遥测告警）** | −3 dB | −3 dBTP 瞬时 | **必须永远高于引擎**（见 6.3）。S4 §5.1 / S5 §5.4 要求"告警不可被遮盖" |
| **ENGINE（引擎）** | −6 dB | −8 dBTP | 持续声底，是"手感"的主体，但不能盖过告警 |
| **AERO / STRUCT（气动·结构）** | −10 dB | **Max-Q 时 −4 dB** | R3 专项：结构应力声必须能在 Max-Q 时**顶出到接近引擎音量**（见 §9） |
| **COCKPIT / UI（座舱·UI）** | −12 dB | −14 dBTP | 提示性，不抢戏 |
| **AMBIENCE（环境床/环境音）** | **−20 dB** | −20 dB | 最低。可被玩家单独调至 0（§8） |

### 6.3 三条混音铁律（可验收）

| # | 铁律 | 手段 | 验收 |
|---|---|---|---|
| **M1** | **遥测告警不能被引擎声盖住** | ① **频段分离**：告警集中在 **1.5–4 kHz**，引擎 L1/L2 主要在 **< 800 Hz**（物理上不重叠）；② **侧链 duck**：任一 P1 告警活跃时，ENGINE 总线 **−3 dB**；③ 告警总线标称 **−3 dB > 引擎 −6 dB** | 在基准弹道 T+16.5–22.0 的 Max-Q 段，告警音（742 Hz 带通）与引擎声同时播放，**告警的可听度（A-weighted 相对电平）须比引擎高 ≥ 6 dB** |
| **M2** | **失败爆炸能"压住"其他所有声源** | 爆炸触发时对**除 IMPACT 外的全部总线 duck −12 dB / 600 ms**，且爆炸本身 0 dB、起音 ≤ 5 ms | 爆炸瞬间，其余总线的瞬时电平须低于爆炸 **≥ 12 dB** |
| **M3** | **两处静默必须是绝对 −∞** | 失败 `0.50–1.10 s`、入轨 `tJudge+0.6–1.4 s`：**mute 全部总线（含环境床）** | 该时段音频输出采样值恒为 0（真静默，非 −60 dB 底噪） |

> **M3 为什么"绝对"而不是"−60 dB 底噪"**：这是全作仅有的两个**"静"作为演出**的时刻（美术 §6.6/§6.7 原文"完全静止/完全无声"）。磁带底噪（A4 关键词）在这两处会**破坏演出的说服力**。**其余所有时刻保留 −60 dBFS 底噪。**

### 6.4 整局动态范围（Loudness 编排）

| 阶段 | 目标响度（相对） | 说明 |
|---|---|---|
| 待机 / 简报（IDLE） | **最低（−24 LUFS 级）** | 只有环境床 + 磁带嘶声。压抑段（对齐美术 §1.3 情绪曲线的"压抑"） |
| 倒计时 T-10→T-0 | **很低** | 只有哔声 + 泵声 + 环境床。**粒子 = 0、音量也几乎 = 0 延续** |
| 点火 → 大气顶 | **中高（引擎 −6 dB）** | 爆发段 |
| Max-Q 段 | **中高 + 告警点缀** | 结构应力声顶出（见 §9） |
| 真空段 | **中** | 气动层消失，只剩引擎 + 更干净的 bed |
| 近地点爬升 | **渐强**（Ω 里程碑逐级 +18 dB 提示音是"刻度"） | 收敛焦虑 |
| 越线 / 判定 | 确认音 → 静默 → 环境床 | 释放 |
| 爆炸 | **最高（0 dB / −1 dBTP）** | P4 的兑现 |

**整局目标**：积分响度 **≈ −20 LUFS**，真实峰值 **≤ −1.0 dBTP**。**没有一处超过 −1.0 dBTP**（含爆炸）。

## §7 技术实现策略（关键约束）

### 7.1 Phaser 3 音频选型：**双层方案**

Phaser 3.80.1 提供 `WebAudioSoundManager`（默认）与 `HTML5AudioSoundManager`（回退）。但 **Phaser 的 Sound API 只能播放已解码的音频缓冲**，**不暴露振荡器、滤波器、增益自动化**——而本项目的核心价值（§4 的五层动态引擎）**必须**用这些原语。

**因此选型是"双层"，而非二选一**：

| 层 | 用途 | 技术 | 理由 |
|---|---|---|---|
| **合成层（主）** | 引擎 L1–L4、结构 L5、侧滑 L6、倒计时哔声、继电器、RCS、告警音、环境床 | **直接使用 Web Audio API**：`OscillatorNode` / `AudioBufferSourceNode`（噪声）/ `BiquadFilterNode` / `GainNode` / `ConstantSourceNode` | Phaser 不暴露这些；合成让 22/32 个音效**零资产** |
| **采样层** | 爆炸、爆螺栓、撞地/坠海、弹离、碎片、打印、大气顶事件线 | **复用 Phaser `sound`（`game.sound.add()`）** 或 `AudioBufferSourceNode`，二选一由工程定 | 一次播放、无需参数化，用 Phaser 省事且自带统一 unlock / 音量 / 暂停管理 |

> **建议实现**（交程基岩核对）：**复用 Phaser 的 `AudioContext`**（`game.sound.context`），不要新建第二个 `AudioContext`。浏览器对每页 `AudioContext` 数量有限制，且 Phaser 的 `WebAudioSoundManager` 已负责**首次用户手势解锁**。理由与风险见 7.2。

### 7.2 音频必须挂在 render 层（**硬约束 · control-manifest B1**）

**规则**：`src/core/**` 只 import 其它 core（**B1**），core 内**禁止** `window`（**D4**）。因此：

```
❌ 禁止                                     ✅ 正确
────────────────────────────────────────────┼──────────────────────────────────────────
src/core/flight-model.js 里 new AudioContext │ src/core/** 里**零音频代码**
core 里 import ../render/audio/**            │ core 通过既有事件接口**发出纯数据**
core 里读 window.AudioContext                │ src/render/audio/** 订阅事件 → 播放/合成
core 里 setTimeout(() => beep())             │ src/render/audio/** 处理浏览器解锁与调度
```

**事件契约（已被 GDD/ARCH 定义，本文档直接消费，无需 core 改动）**：

| core 事件 | 来源 | 音频用途 |
|---|---|---|
| `onMaxQPassed {qMax,tQMax,hQMax}` | S4 §7.1 | #18 `sfx_q_passed` |
| `onQWarning` / `onQWarningEnd {q}` | S4 §7.1 | #16 `sfx_q_warn` + #17 结构应力层 |
| `onAtmosphereExit {t,h,v}` | S4 §7.1 | #19/#20 大气顶 |
| `onSeparate {dvWasted,fuel1AtSep,qSep}` | S3 §7.1 | #21/#22/#23 分离三连 |
| `onSepHighQ {qSep}` | S3 §7.1 | #25 高动压分离告警 |
| `onPeriapsisCross {t,periapsis}` | S5 §7.1 | #29 越线确认音 |
| `onJudge {judgement,snapshot}` | S5 §7.1 | #30 关机淡出 + 结算 |
| `onOmegaMilestone(pct)` | S7 §7.2 | #27 里程碑咔 |
| `onFailure(record)` | S6 §7.2 | #32–#37 失败演出 |
| `hudModel()` 只读快照 | S7 §4.1 | §4.3 的全部参数映射（§4 的动态层**只读**，不回写） |

> **实现要求**：render 层维护一个**事件队列**（core 每步 push 纯数据，音频层在 rAF 消费），**不在事件回调里直接创建音频节点**（避免在 120 Hz 步进中分配，违反 Z1–Z3）。音频参数**统一在 rAF（≈60 Hz）更新**。

**三个风险（标注存疑，交程基岩确认）**：

| # | 风险 | 建议 | 需谁确认 |
|---|---|---|---|
| **AR-1** | `game.sound.context` 在 Phaser 初始化早期可能为 `null` / suspended；音频层若在 `create()` 前取 context 会崩 | 音频层**延迟到第一次用户手势**（`Space` 按下 / 点击）时初始化 context 并 `resume()`；监听 `Phaser.Sound.Events.UNLOCKED` | 程基岩 |
| **AR-2** | 两个 `AudioContext`（Phaser 的 + 自建）会**各自独立解锁**，且数量受限 | **复用 Phaser 的 context**；若 Phaser 的 Sound API 限制了对 context 的直接访问，退路是**自建单例 context 并在同一手势内 resume** | 程基岩 |
| **AR-3** | 顿帧（S3 `HITSTOP = 0.35 s`）期间"物理暂停但渲染继续"——**音频必须继续**（否则 0.35 s 无声会读作"音频卡了"） | 音频层**不订阅顿帧**，只按 rAF 更新参数；顿帧期间保持引擎层输出（可轻微降低 1 dB 制造"时间停住"的微妙感） | 程基岩 |

### 7.3 首屏包红线（≤1.2 MB）：音频必须计在红线之外 —— ✅ **已裁决（AQ4）：批准「首屏音频 0 字节」**

> **✅ 裁决结论（主理人 游承峰）**：**批准**。主理人特别肯定加载策略中的一个关键洞察：**「倒计时是纯合成段，不依赖采样，所以拿它当预载窗口是零风险的。」**

**现实**（ARCH-1 §6.1 原文）：`phaser.min.js` 单文件 **1.18 MB**，**已逼近 1.2 MB 红线**。
**推论**：**音频在首屏的贡献必须是恰好 0 字节。** 这不是"优化目标"，是**硬性物理约束**。

**加载时机策略（四阶段，全部不阻塞首屏）**：

| 阶段 | 时刻 | 加载内容 | 体积 | 阻塞 |
|---|---|---|---|---|
| **Stage 0** | 打包期 | **音频零字节入包** | **0 KB** | — |
| **Stage 1** | 首个用户手势后（`requestIdleCallback`） | **核心采样集**：`explosion` + `bolt_release` + `impact` | **≈ 60 KB** | ❌ 不阻塞（异步） |
| **Stage 2** | **倒计时期间后台预载**（T-10 → T-0 有 10 s 空闲） | 其余采样：`abort_escape`、`debris×5`、`printout`、`atmo_exit` | **≈ 60 KB** | ❌ 不阻塞（倒计时是全合成段，无采样依赖） |
| **Stage 3** | 运行中按需 | 失败演出所需的额外变体（若首局即失败但预载未完成，**降级**为合成兜底音，见 7.5） | 0 | ❌ |

**为什么这样切分是"免费"的**：
1. **倒计时 10 秒是纯合成段**（哔声 + 泵声 + 环境床，全部程序生成），**不需要任何采样资产**。这 10 秒天然是完美的预载窗口。
2. **玩家必须按 Space 才能发射**（S2 §4.1-1）——**这个手势本身就是浏览器的解锁手势**，一举两得：解锁 + 触发 Stage 1 加载。
3. 若玩家在首次加载完成前就触发了需要采样的音（几乎不可能，因 Stage 1 在首个手势后立即完成），**降级为合成兜底**（见 7.5），**不阻塞、不报错**。

**与美术 §6.0 三阶段加载的对接**：美术的 `boot`(<200 KB) → `core`(<1.0 MB) → `orbit`(<2.3 MB) 是**视觉资产**的阶段。**音频的 Stage 1/2 与美术的 `orbit` 阶段并行**（都在升空前后），互不阻塞。

### 7.4 总音频体积预算

| 项 | 预算 | 说明 |
|---|---|---|
| **首屏音频** | **0 KB** | 硬性（见 7.3） |
| **采样资产·传输体积** | **≤ 250 KB**（目标 **120 KB**） | 10 个采样，Opus/Vorbis 高压缩，单声道为主 |
| **合成代码** | **≈ 15 KB**（min 前，JS） | 计入自研源码（ARCH-1 已计 ~90 KB min 前） |
| **运行内存（解码后 PCM）** | **≤ 4 MB** | 见 7.5 的逐项估算；**不占**美术的 48 MB 纹理内存（独立预算） |
| **全量下载（含音频）** | 增量 **≤ 250 KB** | 相对美术 §6.0 的 3.5 MB 总下载红线，音频占比 **≤ 7%** |

|---|---|---|---|

### 7.5 Web Audio 合成 vs 采样资产的取舍

| 判据 | 选**合成** | 选**采样** |
|---|---|---|
| 需要**连续参数化**（音量/音高随物理量变化） | ✅ 必须 | ❌ 做不了 |
| 需要**超长循环**（引擎 78–90 s） | ✅ 0 KB、无接缝 | ❌ 体积爆炸 + 接缝 |
| 需要**极高瞬态密度**（爆炸、撞击） | ⚠️ 合成可以做，但"像不像"成本高 | ✅ **必须采样** |
| 需要**真实金属瞬态**（爆螺栓） | ❌ 难做像 | ✅ 采样 |
| 需要**音量极小、区别度低**（UI 咔、继电器） | ✅ 合成更省、可控 | ⚠️ 不划算 |
| **体积敏感**（首屏 0 KB） | ✅ **0 KB** | ❌ 计入传输 |

**逐条决策结论（32 条音效 ID）**：

| 类别 | 音效 | 决策 | 理由 |
|---|---|---|---|
| **引擎系统（4 层 + 侧滑 + 结构应力）** | `eng_dynamic_L1..L4` / `eng_sideslip_L6` / `struct_creak_L5` | **合成** | 参数化 + 长循环 + 0 KB |
| **环境床（4 相位）** | `bed_control_room` | **合成** | 长循环、无接缝、0 KB |
| **倒计时 / 子阶段 / 充能** | `cd_tick` / `cd_chill` / `cd_press` / `cd_igniter` / `charge_*` | **合成** | 短、需频率变化（升调）、0 KB |
| **继电器系（UI / 模态 / 里程碑 / 锁定）** | `ui_*` / `mode_switch` / `omega_milestone` / `unlock` / `seq_fault` | **合成** | 极短、高复用，**必须变调**（A2 关键词要求不同跃迁不同音高） |
| **告警系** | `q_warn` / `sep_highq_alarm` / `peri_cross` | **合成** | 需带限 + 变调 + 精确包络 |
| **RCS / 节流伺服** | `rcs_puff` / `throttle_servo` | **合成** | 高频触发（限流 12/s），采样池反而更重 |
| **游戏收尾与终结** | `eng_spool` / `eng_shutdown` / `sep_preheat` / `sep_ignite` | **合成** | 与动态层无缝衔接 |
| **爆炸** | `explosion` | **采样** | 瞬态密度是核心；合成做不像（且这是 P4 的门面） |
| **金属瞬态** | `bolt_release` | **采样** | 真实金属瞬态难合成 |
| **撞击 / 坠海** | `impact` | **采样** | 需要物体材质感 |
| **弹离 / 逃逸** | `abort_escape` | **采样 + 合成** | 爆燃采样 + 警示音合成 |
| **碎片池** | `debris_impact` ×5 | **采样** | 需要变体随机化避免"机关枪" |
| **遥测打印** | `printout` / `telemetry_print` | **采样** | 点阵打印机质感（美术 K3 印刷温度） |
| **大气顶事件线** | `atmo_exit_tick` | **采样** | 与美术事件线同帧的"记录"音 |

**降级兜底（若采样未及时加载）**：任一采样件缺位时，**合成兜底**——如 `explosion` 缺位则用"低频噪声爆发 + 快速衰减"合成（力度弱但**不静音、不报错**）。**验收：任何加载状态下音频输出不得出现空播放异常或静音失败。**

### 7.6 浏览器自动播放策略（必须处理）

| 挑战 | 策略 |
|---|---|
| 浏览器禁止未交互的自动播放 | **音频层在首个用户手势时初始化+`resume()`**。本项目天然满足：**玩家必须按 Space 才能发射**（S2 §4.1-1） |
| 若玩家只悬停不按键（简报屏） | 简报屏的 `Space` 提示本身即手势；且 Stage 1 加载绑定 `pointerdown` **或** `keydown` 任一 |

| iOS / Safari 特有问题 | **非目标平台**（桌面优先），但实现不依赖任一平台专有 API，天然可移植 |

**验收方法**：**「静音测试」——把音频总音量拉到 0 后，玩家必须仍能在 1 s 内读懂全部状态**（这正是美术给视觉定的标准）。

### 8.2 音量与静音策略 —— ✅ **已裁决（AQ5）：批准「独立环境床音量滑块」**

> **✅ 裁决结论（主理人 游承峰）**：**批准。** 主理人肯定理由为"成本极低，且让『不要音乐』与『要氛围』两类玩家共存——这正是**可访问性的正确做法**"。

| 设置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| **总音量（Master）** | **70%** | 0–100% | 乘在 Master 总线；**0% = 完全静音** |
| **环境床 / 音乐** | **70%** | 0–100% | ✅ **独立滑块**（§2.3 的 `audioBed`），可单独关掉。**关掉后不再有任何"音乐"**（因 MVP 只有环境床）。**已裁决 AQ5：批准** |
| **音效（SFX）** | 80% | 0–100% | 独立于环境床 |
| **静音快捷键** | — | 切换 | **`Ctrl+M`**（可重映射，纳入 S8 §3.5 的键位重映射表）。⚠️ **不是 `M`** —— `M` 已被占用为**「减少动效」**（S8 §3.6），且该键直接关系**光敏性癫痫安全**（美术 §9.3 硬红线），**优先级高于静音快捷**。详见下方注 ① |
| **快速静音提示** | — | — | 首次启动伴随光敏提示条，给出一个"音频开关"（对齐美术 §9.3 的"首次启动一次性提示"） |
| **动态范围压缩** | **关** | 开 / 关 | 供听力敏感或在嘈杂环境中的玩家；开启后爆炸峰值压到 −6 dBTP，整体动态范围减半 |

> **注 ① · 静音键为何是 `Ctrl+M` 而非 `M`（✅ 已裁决）**
> 本文档初稿曾建议用 `M` 作静音键。**主理人裁决：改用 `Ctrl+M`。** 三条理由：
> 1. `M` 已被占用为**「减少动效」**（S8 §3.6），且该功能直接关系**光敏性癫痫安全**（美术 §9.3 硬红线，按 Comprehensive 处理），**其优先级高于静音快捷**——安全项不可为便捷性让路。
> 2. 该键**代码已实现、HUD 提示行已印出**，改代码成本高于改一个尚未实现的音频键位。
> 3. `Ctrl+M` 是常见约定，且**不与现有任何键位冲突**（现有绑定见注 ②）。
>
> **注 ② · 音频侧键位自查（v1.1，对照 `control-manifest.md` + UX-spec 现有绑定）**
> 现有绑定：`Space`（点火/充能）· `W/S`（节流）· `A/D`（配平）· `Shift`（分离）· `Esc`（中止）· `R`（重开）· `M`（减少动效）· `P`（暂停）。
>
> | 本文档涉及的键 | 用途 | 与现有绑定是否冲突 |
> |---|---|---|
> | `Ctrl+M` | 静音 | ✅ 无冲突（新增，已裁决） |
> | `Space` | 首个用户手势触发音频解锁（§7.2 AR-1 / §7.6） | ✅ **复用**同一次按键，不新增绑定 |
> | `P` | 暂停时环境床降 8 dB + 低通（§3.9 / 事件表 #46） | ✅ 无冲突（对齐 S8 §3.1.4 的 `P` 暂停） |
> | `Esc` | 点火前中止的继电器断音（§3.4 V5 条目） | ✅ 无冲突（对齐 S2 §3.5 的 `Esc` 中止） |
> | `R` / `Shift` / `W` / `S` / `A` / `D` | **本文档不涉及**（音频只对结果配音，不定义输入） | ✅ 无冲突 |
>
> **自查结论：除已裁决的 `M`→`Ctrl+M` 外，本文档无其它键位冲突。**

> **与「减少动效」模式的关系**：美术 §9.3 的「减少动效」只管视觉（震屏/闪烁/粒子），**不影响音频**（音频不涉及光敏风险）。若玩家希望"减少听觉刺激"，通过**总音量 + 动态范围压缩**实现，**不新增一个"减少音频"模式**（避免设置项膨胀）。

### 8.3 响度安全

## §9 RT-1 R3 专项：Max-Q 戏剧性削弱的音频侧处理

> **问题（RT-1 §7 R3 原文）**：「大气顶 12 km 意味着 Max-Q 出现在极早期（T+14 s 附近，14 kPa），原设计的『Max-Q 窒息时刻』戏剧性削弱」。
> **实测修正（S4 §3.4）**：Max-Q 在 **T+19.16 s**，峰值 **16.47 kPa**（比 RT-1 估计略晚、略高），高度 2.609 km，速度 279 m/s。相对 `Q_STRUCT = 30 kPa` 有 **82% 余量**。
> **问题本质**：这个"坎"落在飞行的**前 24%**，此时玩家还在学按键；而它相对解体阈值只有 16.5/30 的压迫感——**它在物理上是小坎，在情绪上被放错了位置**。

### 9.1 音频能否补救？——**能，但方式不是"把它做成高潮"**

**我的结论分三句**：
1. **音频可以显著提升 Max-Q 的"可感知度"，但无法把它变成"中段高潮"**——因为高潮是**时间位置**的函数，音频改变不了时间轴。
2. **音频正确的补救方向是"诚实放大 + 教学化"**：把"16.5 kPa"翻译成**玩家身体能听懂的东西**（结构在响），并让玩家**因为听到它而做出操作**（收油门）。
3. **真正的中段峰值应由设计侧重新编排**（我不改 GDD，只提建议，见 §9.4）—— ✅ **已裁决（R3-1）：主理人已批准将该建议落地。**

### 9.2 音频侧的三个具体手段（**全部诚实，不撒谎**）—— ✅ **已裁决（AQ2）：批准"诚实放大 + 教学化"**

> **✅ 裁决结论（主理人 游承峰）**：**批准。**「明确不做人为放大音量 / 紧张音乐层 / 声音驱动视觉——这个克制是对的，**符合 P1 的诚实原则**。」

| # | 手段 | 规格 | 为什么它不同于"伪造高潮" |
|---|---|---|---|
| **① 结构应力声 `struct_creak_L5`** | 200–600 Hz 带通噪声 + 0.6 Hz 慢速 AM，增益 `= clamp((q − 8 kPa)/8 kPa, 0, 1) × 0.8`，走**独立的 AERO/STRUCT 总线**（标称 −10 dB，Max-Q 时顶到 −4 dB） | 它**忠实地随 q 起落**：q 越大，响度越大。这是**物理量的听觉镜像**（P2），不是"这里该激动了所以加音乐"。玩家听到的是**真实的载荷**，不是编造的紧张 |
| **② 环控告警弧（Q_WARN → Max-Q → Passed）** | T+16.5 两声带限警戒音（742 Hz，间隔 180 ms，**非上行非下行**）→ T+16.5–22.0 结构应力持续 → T+22.3 一声"松弛"（应力衰减 + 极轻继电器咔）→ **不做解除音** | 这是一条**有起有落的听觉弧**，把散在 5.5 s 里的三个事件串成"一次坎"。它是"仪表的读数弧"，不是"配乐的情绪弧" |
| **③ 让玩家"听见自己的解法"** | 玩家收油门（V2）→ L1/L2 音量与 L3 音高**立即下降**（τ = 30 ms）→ 玩家**立刻听到自己压住了那股劲** | 这是 **P1（过程即内容）的完美兑现**：Max-Q 不是一段"你要看的表演"，而是**"你做了什么 → 你听到什么"** 的闭环。S4 §4.1 已定量证明"收油门到 0.6 可把峰值从 16.0 降到 11.4 kPa"——**音频让这个因果链变得可听** |

> **明确不做（避免撒谎 / 违反美术 §9.2 T2）**：
> - ❌ 不因为"这里本该是高潮"而人为放大音量 / 加低频冲击——**那会让 16.5 kPa 听起来像 30 kPa，直接击穿 P2**。
> - ❌ 不加"紧张音乐"层 / 不加脉冲节奏——**这是配乐思维，违反 A1 关键词与 P1**。
> - ❌ 不让声音驱动视觉（美术 §9.2 T2 硬禁止）。
