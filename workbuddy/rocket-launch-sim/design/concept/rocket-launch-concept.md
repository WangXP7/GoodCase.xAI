## 0. 设计前提与差异化定位

### 0.1 已被验证的核心交互链

用户前期观察到多例 AI「复刻火箭发射模拟器」作品，其中被反复验证、能留住玩家的交互链是：

```
玩家按下按钮 → 系统依次触发倒计时 → 点火 → 火箭升空
```

这条链条的爽点**不在"点击的结果"，而在"阶段推进的仪式感"与"状态变化的可见反馈"**。玩家想看的不是"火箭飞了"，而是"我按下之后，这枚机器一步步活过来的过程"。

这是我们设计的起点，也是必须守住的东西。

### 0.2 为什么不能直接复刻

同类作品的通病是：**交互深度止于"按下按钮"**。玩家看完一遍升空表演，新鲜感在 30 秒内耗尽，没有第二个理由再按一次。一次性表演不具备可重复游玩的价值。

### 0.3 我们的三条差异化

| # | 差异化 | 说明 |
|---|---|---|
| **D1** | **从"看发射"到"开发射"** | 玩家不是观众，是飞行员。点火只是开始，之后全程手动操纵。 |
| **D2** | **从"一次表演"到"可精进的技能"** | 核心技能锚定在**重力转弯（Gravity Turn）**——一个真实、可教学、有明确技巧上限的动作。 |
| **D3** | **从"结果反馈"到"过程反馈"** | 每一个物理量都有对应的可视化表达。失败不是黑屏，而是一次可归因的数据复盘。 |

**一句话概括差异化**：别人做"火箭发射的过场动画"，我们做"火箭发射的驾驶考试"。

## 1. 游戏支柱（Design Pillars）

四条支柱，用于在所有后续阶段做决策取舍。任何特性提案若无法挂靠到至少一条支柱，默认不进。

### P1 · 过程即内容（The Process Is the Content）

> 每一个游戏阶段都必须有可交互的状态推进，绝不出现"播放一段动画让你看"。

- **解释**：倒计时的每一秒、增压的每一格压力、分离的每一个动作，玩家都应能看到并能干预。
- **取舍用法**：砍掉所有自动化过场、一键跳过、过场 CG。宁可让流程慢 3 秒，也不让流程"不可打断"。

### P2 · 可解读的深度（Legible Depth）

> 系统可以硬核，但每一个数值、每一次失败，玩家都必须能看懂"为什么"。

- **解释**：硬核不等于劝退。任何进入游戏的物理量，必须有对应的视觉 / 听觉表达，并在失败后给出可归因的数据。
- **取舍用法**：**无法可视化的系统不进 MVP**。若某个机制很酷但玩家看不懂它如何影响结果，推迟到它有了可视化方案为止。

### P3 · 一次发射，六十秒（One Launch, One Minute）

> 单局时长控制在 60–90 秒，失败后 3 秒内可以重来。

- **解释**：高频迭代是技能型游戏的心跳。短局让"再来一次"成为本能而非决策。
- **取舍用法**：任何延长单局时长的内容（长过场、繁杂的发射前流程、慢速爬升）都是成本，不是内容。
- **目标值说明**：**基准单局 ~70 秒**。60 秒为激进/熟练打法（可跳过倒计时 + 高效弹道），90 秒为保守/生疏打法（完整倒计时 + 末段救场）。**时长本身应当是技能的信号——飞得越好，这一局越短。**

### P4 · 失败也好看（Failure Is Spectacular）

> 失败是内容的一部分，不是需要被缓冲的惩罚。

- **解释**：火箭解体是这个题材最有感染力的时刻之一。我们要为失败投入演出资源，并确保玩家在爆炸后想的是"我知道错在哪了，再来"，而不是"烦"。
- **取舍用法**：爆炸演出、残骸物理、失败数据回放，优先级等同于成功流程。不做"安慰性"的失败缓冲设计。

## 2. 电梯陈述与目标受众

### 2.1 电梯陈述

> **按下点火，然后亲手把这枚火箭开进轨道。**
> 一款 2D 硬核火箭发射模拟器——从 T-10 倒计时到重力转弯，每一秒都由你操纵，每一次失败都告诉你错在哪。

### 2.2 目标受众画像

**平台语境**：TapTap 网页版用户对"小而精、上手即玩、视觉有品质"有明确偏好。设计需同时满足短时高频游玩与"截图有面子"两个诉求。

> **（v0.2 决策）** 虽然 TapTap 存在移动端访问的可能性，但 MVP **锁定桌面键鼠优先**，移动端触屏后置到核心体验层。因此本章的输入、HUD 布局与节奏设计均按桌面端推导。

#### 核心受众 A —「轨道工程师」（主要服务对象）

| 维度 | 描述 |
|---|---|
| 画像 | 20–32 岁，看过 KSP / SpaceX 发射直播内容，玩过《坎巴拉太空计划》《Spaceflight Simulator》一类作品 |
| 动机 | 想要**弄懂系统**，而非被投喂内容。享受"我搞明白了"的时刻 |
| 行为 | 日均 15–30 分钟碎片游玩；会主动查数据、看回放、优化方案 |
| 付费 | 愿为解锁内容与外观付费，强烈反感数值付费与体力系统 |
| 设计指向 | 技能上限、可量化进步、系统透明度是本作的生命线 |

#### 次级受众 B —「奇观观众」（首 30 秒不能流失的对象）

| 维度 | 描述 |
|---|---|
| 画像 | 被火箭发射 / 爆炸短视频吸引而来，想要"酷"，耐心有限 |
| 动机 | 感官刺激 + 社交货币（截图 / 录屏） |
| 行为 | 找不到爽点 3 分钟内离开；但一旦被"第一次成功入轨"击中，会转化为核心受众 |
| 设计指向 | 首局必须有强反馈演出（哪怕失败也要炸得漂亮），教学必须隐形 |

#### 明确不服务的对象

- **Socializer（社交型）**：MVP 不做任何社交 / 聊天系统。
- **强 Killer（竞争型）**：MVP 不做 PvP。排行榜为异步间接竞争，不做对抗。

> **受众取舍声明**：我们用前 30 秒的演出留住 B，用后续 2 小时的技能曲线留住 A。**A 的留存优先级高于 B 的转化数量**——为 B 牺牲系统深度会同时失去两者。

## 3. MDA 分析

### 3.1 Mechanics（机制 — 系统给玩家的规则与可操作对象）

游戏世界为**侧视 2D 剖面**：X 轴为水平航程（downrange），Y 轴为高度（altitude）。火箭在低空贴地垂直爬升，随高度上升逐渐倾倒，最终以接近水平的姿态进入轨道——重力转弯在侧视 2D 中天然可视。

| 机制 | 说明 | 备注 |
|---|---|---|
| **分级发射序列** | T-10 → 预冷 → 增压 → 点火 → 松绑 → 升空的状态机 | 支柱 P1 的核心载体 |
| **推力与质量耦合** | 燃料消耗 → 总质量下降 → 相同推力下加速度上升 | 齐奥尔科夫斯基方程简化实现 |
| **姿态控制（Pitch）** | 玩家控制俯仰角 θ（相对当地水平面，90° 为垂直） | **核心技能动词** |
| **重力转弯（Gravity Turn）** | 在正确高度开始倾倒，用重力自然塑造弹道，以最小燃料换取水平速度 | **本作的核心玩法** |
| **节流（Throttle）** | 推力输出 τ ∈ [0,1]，用于穿越 Max-Q 与精细控制 | 风险/效率权衡旋钮 |
| **分级分离（Staging）** | 抛弃耗尽级，瞬间减重换取加速度跃升 | 时机赌博 |
| **大气阻力与 Max-Q** | 阻力 D = ½·ρ(h)·v²·Cd·A，随高度递减；低空高速存在结构风险峰值 | **制造早期的第一个"可管理取舍点"（非情绪峰值）**，见 §3.2-2 |
| **入轨判定** | 近地点高度 ≥ 目标高度，且速度矢量接近水平 | 明确的成功条件；判定过程必须可视化，见 §7.1「轨道预测标记条」 |

> 所有数值（g₀、Isp、Cd、ρ(h) 曲线等）在此阶段仅定性，**具体标定在后续系统 GDD 完成**。

### 3.2 Dynamics（动态 — 玩家与机制互动中涌现的运行时行为）

机制是死的，动态是玩家实际玩出来的东西。以下是我们**期待涌现**的关键动态：

1. **燃料 vs 稳定的权衡**：过早倾倒省燃料但可能撞回稠密大气；过晚倾倒稳当却拖着无用的垂直动量白白烧油。没有唯一正解。
2. **穿越动压峰值（Max-Q）—— 单局的第一次考题，不是高潮**：`q = ½ρ(h)v²` 在 **T+19.1 s** 前后达到峰值（基准 **16.5 kPa**，相对 `Q_STRUCT = 30 kPa` 解体阈值有 **82% 余量**）。它不要求玩家"窒息"，而要求玩家学会**第一次取舍**：收油门可压低峰值（收到 0.6 可把峰值降到约 11.4 kPa，代价约 65 m/s 重力损失），不收也能过。**这是"节流"这个动词的教学时刻，不是情绪峰值。** 单局的情绪峰值位于**大气顶（T+47.6 s）与近地点爬升（T+61.7 → 81 s）**，见 §5.2。
   > **历史注记（v0.4）**：本条原为「Max-Q 的窒息时刻……单局的第一个情绪峰值」，与 RT-1 实测不符——该"坎"落在飞行**前 24%**（此时玩家还在学按键），且相对解体阈值有 **82% 余量**，物理上不构成压迫感。情绪峰值已由 §5.2 重新编排。
3. **分级时机的赌博**：早分离轻快但可能燃料不够，晚分离稳妥但全程拖着死重。
4. **失败归因学习环**：爆炸 → 看回放数据 → 形成假设 → 下一次验证。这是本作真正的长期驱动力。
5. **"再来一次"的高频迭代**：60 秒一局 + 3 秒重开，使"再试一把"成为肌肉记忆而非理性决策。

> **✅ 待验证假设已关闭（v0.4）**：原假设「重力转弯是否能在 2D 侧视 + 键鼠输入下形成『易于上手、难于精通』的技能曲线？若否，需回退到更简化的姿态目标制（玩家设定目标角，系统自动配平）」——**假设成立，不需回退。** 原型闭环验证结果：**闭环判据 9/9 通过**（正常玩家能入轨 `PRECISE` / 时长 81.02 s / 近地点 15.03 km / 全部弹道 Ω 回退 = 0 / 切换跳变 ≤ 0.5% / 安全窗口内分离质量恒为 16500 kg / **多路径成立（低抛 & 高抛均入轨）** / 新手失败路径可触发）；**端口一致性 9/9**；**原型验证 41/41**。证据：`tests/prototype/_verify.txt`、`tests/prototype/closed-loop-results.json`。
>
> *（v0.2 注：触屏版本不在 MVP 验证范围，该假设在核心体验层做触屏适配时需重新验证一次。）*

### 3.3 Aesthetics（美学 — 我们想让玩家产生什么体验）

采用 MDA 八种美学分类，明确主次：

| 优先级 | 美学类型 | 在本作中的具体表现 |
|---|---|---|
| **主** | **Challenge（挑战）** | 掌握重力转弯本身的乐趣；"我终于稳定入轨了" |
| **主** | **Sensation（感官）** | 尾焰、屏幕震动、烟雾粒子、引擎噪声随速度变化的音效分层 |
| **次** | **Narrative（叙事）** | 航天任务的仪式感与宏大感；任务编号命名（"你的第 47 次发射"） |
| **次** | **Discovery（发现）** | 理解系统运作原理的"啊哈"时刻——原来 Max-Q 是这么回事 |
| **弱** | **Expression（表达）** | 火箭涂装自定义（延展层，非 MVP） |
| **弱** | **Fellowship（伙伴）** | 异步排行榜 / 分享卡（核心体验层，非 MVP） |

> 明确**不追求**的美学：Fantasy（幻想）、Submission（消遣）。本作是清醒的、有目标的体验。

## 4. 玩家核心动词清单（动词优先法）

先定义玩家**想做什么**，再倒推机制与输入。动词是设计的原子单位——如果一个动词无法被清晰表达和反馈，它对应的机制就不该存在。

### 4.1 MVP 必需动词（5 个）

| # | 动词 | 玩家意图 | 输入映射 | 反馈 | 对应支柱 |
|---|---|---|---|---|---|
| **V1** | **点火 Ignite** | "开始这次发射" | 空格 | 分级倒计时逐项点亮、引擎轰鸣渐强、屏幕开始震 | P1 |
| **V2** | **节流 Throttle** | "控制这股力量" | W/S / 上下箭头 | 尾焰长度变化、加速度指针摆动、引擎音高变化 | P1, P3 |
| **V3** | **配平 Pitch** | "让火箭按我想要的角度飞" | A/D / 左右箭头 | 姿态指示器转动、地平线相对旋转、箭体倾斜 | P1, P2 |
| **V4** | **分离 Stage** | "丢掉没用的死重" | Shift / 专用按钮 | 爆螺栓闪光、分离级翻滚坠落、速度读数脉冲跃升 | P1, P4 |
| **V5** | **中止 Abort** | "这次要炸，我撤" | Esc / 专用按钮 | 逃逸塔点火、乘员舱弹离、警示灯全亮 | P1, P4 |

> **输入基线（v0.2 决策）**：MVP 输入**锁定键鼠**，移动端触屏降级到核心体验层再评估。上表因此不列触屏映射。届时需为触屏重新设计 V3「配平」的输入方案，并重新验证其手感。

> **（v0.3 澄清）V3 配平是全飞行段动词，不是"一级专用动词"。**
> 从松绑升空到上级入轨收敛，**姿态控制权始终在玩家手上，全程不存在任何自动驾驶 / 自动导航段**。
> 澄清一条极易被误读的推论：**「圆化 Circularize」被列为非 MVP 动词，指的是不做独立的机动节点规划系统（不要求玩家设定燃烧点、计算点火窗口），绝不意味着玩家在上级段交出姿态控制权。** 上级段的操作内容由 V3 配平与 V2 节流在全飞行段内承担——玩家持续把速度矢量压向水平、把近地点推过 100km 目标线，这本身就是圆化动作，只是不以"独立动词"的形式暴露给玩家。详见 §5.2。

### 4.2 隐性必需动词（1 个，容易被忽略但是 MVP 的生死线）

| # | 动词 | 玩家意图 | 输入映射 | 反馈 | 对应支柱 |
|---|---|---|---|---|---|
| **V6** | **读取 Read** | "我现在状态怎么样？该做什么？" | 视线移动 | HUD 遥测：高度 / 速度 / 燃料 / 姿态 / **Δv 余量（轨道预测标记条，形态见 §7.1）** | **P2** |

> **警告**：V6 不是"把数值摆在屏幕上"就完事。它要求**玩家能在 1 秒内从 HUD 读出"我现在该往哪打杆"**。这是 P2「可解读的深度」落地与否的唯一检验点。若 MVP 测试中出现"玩家不知道自己为什么炸了"，优先怀疑 V6 而非玩家。

### 4.3 核心体验层动词（非 MVP）

| 动词 | 玩家意图 | 说明 |
|---|---|---|
| **分析 Analyse** | "我刚才错在哪？" | 飞行数据回放，失败归因可视化 |
| **圆化 Circularize** | "把椭圆轨道压圆" | 远地点变轨机动，入轨的最后一步。**「非 MVP」仅指不做独立机动节点系统**——该动作由 V3 配平在全飞行段承担（见 §4.1 澄清），玩家从未交出姿态控制权 |
| **抛罩 Deploy** | "去掉整流罩减重" | 出大气后的分离动作 |
| **重开 Retry** | "再来一次" | 3 秒内回到可操作状态（P3 的硬性指标） |
| **解锁 Unlock** | "我能飞更远的目标了" | 目标轨道分档递进 |

### 4.4 延展 / 野心层动词

| 动词 | 层级 | 说明 |
|---|---|---|
| **组装 Build** | 延展 | VAB 式火箭装配：自选发动机 / 燃料箱 / 级间段 |
| **涂装 Customize** | 延展 | 外观自定义 |

## 5. 玩家心理学分析

### 5.1 自我决定论（Self-Determination Theory）

自我决定论认为，持久的内在动机来自自主、胜任、关联三要素的同时满足。以下逐项说明本作的落地方案。

#### 自主（Autonomy）— 玩家感到"是我在决定"

- **设计保障 1**：任何时刻玩家至少有 **2 个有意义的选择**。点火不用说是手动的，倾斜时机、节流曲线、分离时机全部由玩家决定。
- **设计保障 2**：**达成入轨存在多条可行路径**。低抛（早倾倒、省燃料、容错窄）与高抛（晚倾倒、费燃料、容错宽）都应可通关。杜绝主导策略（Dominant Strategy）。
- **设计保障 3**：不提供"最优解提示"。可以显示数据，不显示答案。

> **设计理论红线**：一旦出现唯一最优打法，自主性立刻归零。这是本作最需要警惕的失衡点，需在系统 GDD 阶段用平衡检查专项验证。

#### 胜任（Competence）— 玩家感到"我在变强"

- **设计保障 1**：**技能曲线可见**。评级分三档（未完成 / 入轨 / 高效入轨），评级标准**明示给玩家**，不是黑箱。
- **设计保障 2**：**失败可归因**。每次失败给出明确的数据归因（"你在 32km 时俯仰角偏低 12°，导致远地点不足"），而非模糊的"任务失败"。
- **设计保障 3**：**进步可量化**。Δv 余量、燃料剩余、入轨精度三项数据在结算界面呈现，并在跨局之间保留趋势。

#### 关联（Relatedness）— 玩家感到"我不是一个人在飞"

- **MVP 阶段**：仅通过**内容化叙事**满足——任务编号计数器（"你的第 47 次发射"）、发射档案室（历史飞行记录）。低成本，不依赖后端。
- **核心体验层**：异步排行榜 + 分享卡（成绩截图生成）。
- **明确不在 MVP 做**：社交系统、好友、聊天。

> **（v0.3 结构性变更）取消「上级燃烧 / 圆化」独立分段。**
> v0.2 把「重力转弯」与「上级燃烧」切成两段，是沿袭 KSP 的划分习惯——那里上级需要玩家规划机动节点，**分段有信息价值**。**本作 MVP 为单构型、单 LEO 目标，上级段没有机动规划可言，独立分段不提供任何新信息，只在玩家脑中制造一次"下一段是不是要换操作"的切换成本。** 因此合并为「重力转弯 → 入轨收敛」单一连续技能窗口。

> **分离（V4）降级为段内节拍**：它仍是玩家手动触发的动词，仍是爆螺栓 + 速度读数脉冲的强反馈，但**不再切断玩家的操作连续性**——分离前后，玩家手上是同一套键位（A/D 配平），眼睛盯的是同一条读数（轨道预测标记条）。**段内节拍 ≠ 段边界。**
>
> **曲线形状说明（v0.4 重画）**：单局有**两个峰值 + 一个教学坎**——
>
> - **第一个教学坎（非峰值）**：**Max-Q，T+19.2 s**。落在飞行前 24%，相对解体征兆有 82% 余量，**刻意做成一个小鼓包**——玩家第一次"要不要收油门"的取舍，读完即平。
> - **峰值①（情感高点）**：**大气顶事件，T+47.6 s**。气动层 0.35 s 淡出、环境床撤走无线电本底——"世界安静了"。这是**呼吸式的释放**，不是压迫，也是"我上天了"的物理证据。
> - **峰值②（心流通道最窄）**：**近地点爬升，T+61.7 → 81 s（19 s 持续渐强）**。玩家持续把速度矢量压向水平、把近地点推过目标线，条在末段加速——**前 25 秒的每一次配平都在这里结账**。
> - **情绪空档（T+33.4 → 47.6）**：倾倒程序结束到大气顶之间的 14 s 由**侧滑噪声**（音量 ∝ |α|）补位，不新增资产、不新增读数。
>
> 左侧 T-10 → T+12 s 的平缓爬升段为倒计时 + 垂直上升；分离（V4）之后**强度不归零**，紧张来源从"大气 + 姿态"换挡为"近地点爬不爬得过目标线"——是**同一个窗口内的情绪换挡，不是进入新阶段**。

#### 合并逻辑：为什么砍的是「分段」，不是「秒数」

**v0.2 的刀法被推翻了一半。** 原主刀口是「上级燃烧 / 圆化」30s → 15s，理由是"该段交互密度最低"。但这个判断的前提是：上级段玩家只有"看燃料表"一件事可做。**而 v0.2 从未写过上级自动驾驶——V3 配平是全飞行段动词（见 §4.1 澄清）。** 所谓"交互密度低"，是文档没写清楚造成的误读，不是设计事实。

**v0.3 的事实**：上级段玩家全程持有 V3 配平，持续做两件互相拉扯的事——

1. **把速度矢量压向水平**：换取水平速度，把**近地点**抬起来（近地点 ≥ 100km 是入轨判定门，见 §3.1）；
2. **同时让远地点一路爬升**，并在燃料耗尽前完成收官。

压得太早太狠 → 近地点抬不起来，飞得出大气但落得回来；压得太晚太保守 → Δv 白白烧在重力损失上，燃料见底。**这恰恰是重力转弯判卷的时刻——前 25 秒的每一次配平，都要在这 11 秒里结账。**

因此 v0.3 的刀法改为：**不砍时长，砍边界。**

- **砍边界**：两段合并为一个连续窗口。分离（V4）降级为段内节拍——它仍是玩家手动触发的动词，仍有爆螺栓 + 加速度跃升的强反馈，但**不再切断操作连续性**：分离前后玩家手上是同一套键位（A/D 配平），眼睛盯的是同一条读数（轨道预测标记条）。
- **时长**：40s → 38s（−2s）。省下的 2 秒来自取消段间切换后的节奏收紧，**不分给任何新机制**。
- **入轨确认 +2s（8s → 10s）**：把合并省下的缓冲还给成就时刻。这是本作唯一的截图窗口与支柱 P4 的高光，8 秒偏紧。
- **仍绝不砍一级重力转弯的 25 秒**：它是核心技能窗口，砍它就是砍掉差异化本身。

**一处诚实的减法**：**上级段的节流（V2）是假选择。** 固定构型 + 单 LEO 目标下，上级满油门近乎恒优（收油门只会增加重力损失），把它当旋钮等于塞一个玩家不该关心的动作。因此 v0.3 明确：**上级段节流键位保留可用（不锁死输入），但设计上不作为该段主要旋钮，不围绕它做权衡。** 宁可这段短，也不塞假动作。

#### 60 / 70 / 90 秒三个数怎么来的

时长不是随机波动，而是**由玩家的技能水平决定**：

- **60s（激进 / 熟练）**：跳过倒计时（−10s），其余保持基准分配 → 12 + 38 + 10 = 60s。注意：**飞得干净不等于上级收敛变快**——上级燃烧时长由 Δv 缺口决定，飞得好只是让这段**不必拉长救场**。
- **70s（基准）**：上表分配，完整倒计时 + 标准弹道。
- **90s（保守 / 生疏）**：完整倒计时 ~10s + 垂直上升拖到 ~15s（节流保守）+ 合并窗口被迫拉长到 ~53s（倾倒偏差 → 分离拖晚 → 上级烧满救场）+ 入轨确认 ~12s。

> **设计意图**：让**单局时长本身成为技能的可读信号**。基准 70s 是分水岭——压到 60s 说明你没浪费一秒仪式感；拖到 90s 说明你在合并窗口里为前面的失误还了债。

> ✅ **Q7 已裁决（v0.3）**：上级段在 MVP 是否给玩家交互？——**保留控制权，不补新动词。** 玩家用 V3 配平把近地点推过 100km 目标线；「圆化」作为独立动词仍不进 MVP（不做机动节点系统），其操作内容由 V3 在全飞行段承担。详见 §4.1 澄清与附录 B。

#### 心流通道的调节手段

**不靠数值难度旋钮，靠容错窗口宽度**：

- **主旋钮**：目标轨道高度。目标越高，Δv 预算越紧，重力转弯的容错窗口越窄。
- **副旋钮**：天气 / 风切变（核心体验层）。风切变在低空制造额外扰动，增加操作负荷。
- **减压阀**：**辅助线（Guidance Line）**——为新手显示建议弹道曲线，可关闭。关闭辅助线后评级加成。这是让 A 和 B 两类受众共存于同一局的关键设计。

| 类型 | 适配度 | 说明 |
|---|---|---|
| **Achiever（成就者）** | ★★★ 主要 | 追求掌握与优化：最少燃料入轨、最高轨道、最短时间。是我们的核心服务对象。 |

### 6.2 循环要点说明

- **单次循环时长**：60–90 秒（成功）／ 20–50 秒（失败）。
- **失败支路的地位等同于成功支路**（支柱 P4）。失败不是"回到起点"，而是"带着一条信息回到起点"。
- **重开成本**：从失败演出结束到玩家可再次操作，硬上限 **3 秒**（支柱 P3 的可检验指标）。
- **长线驱动**：评级优化（三档评级 + Δv 余量 / 燃料 / 入轨精度三项数据）构成 MVP 内的跨局进步感；目标轨道分档递进 + 解锁属核心体验层。
- **合并窗口的操作连续性（v0.3）**：分离（V4）是窗口内的一个节拍，不是阶段边界。从一级重力转弯到上级入轨收敛，玩家的键位（A/D 配平）与视线目标（轨道预测标记条）保持不变——这是「过程即内容」（P1）在末段的兑现方式。

## 7. 范围分层

### 7.1 MVP — 可验证的最小闭环

> **MVP 的唯一目标**：证明「重力转弯」这个核心技能在 2D 侧视 + 网页端输入下成立且好玩。
> 任何不为这个目标服务的东西，一律不进 MVP。

**✅ 进 MVP**

- 单枚**固定构型**两级火箭（参数不可修改）
- 完整发射序列：T-10 倒计时 → 预冷 → 增压 → 点火 → 松绑 → 升空
- 四个玩家动词：**节流 / 配平 / 分离 / 中止**（+ 点火 = 5）
- 简化物理：重力、推力、燃料消耗与质量变化、大气阻力（简化模型）
- **一个**目标轨道（LEO，约 100km）
- 入轨判定 + **三档评级**
- 失败演出：解体爆炸、坠海、中止逃逸
- 核心 HUD（**5 读数，无增减**）：高度 / 速度 / 燃料 / 姿态 / **Δv 余量（MVP 内必须可视化，形态见下）**
- 单局 60–90 秒（基准 ~70s），一键 3 秒重开
- **键鼠输入**（键位见 §4.1；触屏不在 MVP 范围）
- 基础音效：引擎、爆炸、分离

> **（v0.3 确定化）第 5 个读数「Δv 余量」的图形形态已锁定 —— 不留"若可"的余地。**
> **形态**：HUD 上的一条**轨道预测标记条**——实时显示预测**远地点 / 近地点高度**（双游标或双端条），并叠加一条**目标线（100km）**；预测值越过目标线时，标记条由警示色转为通过色。
> **为什么必须在 MVP 内可视化**：它是「入轨判定」（§3.1）唯一的可见载体，也是支柱 P2「可解读的深度」的验收点——**玩家必须能在 1 秒内读出"我该往哪打杆"**。带"若可稳定可视化"的条目无法作为验收标准，故确定化。
> **不新增读数**：标记条占用的是第 5 个读数「Δv 余量」的槽位（同一物理量的图形表达），**5 动词 + 5 读数的认知过载红线未破**。

**❌ 不进 MVP**

- 火箭组装 / 参数自定义
- 多目标轨道 / 任务选择
- **移动端触屏适配（已决议：桌面优先，触屏后置到核心体验层）**
- 天气与风切变
- 排行榜 / 分享 / 任何后端依赖
- 剧情叙事 / 角色
- 涂装 / 商店 / 货币
- 教学关（**改为在首局中用 HUD 高亮与辅助线做隐形引导**）
- 存档系统（除本地最佳成绩外）

### 7.2 核心体验（Core Experience）— 让 MVP 的技能曲线撑起 1–2 小时内容

## 8. 视觉锚点（Visual Anchors）

以下 5 个关键词供美术方向（art-bible）对齐使用。每条含"要什么"与"不要什么"。

### A1 · 硬核工程蓝调（Industrial Blueprint）

> ✅ **已由用户拍板确认（v0.2）——视觉基调锁定「硬核写实工程风」，美术圣经需对齐此方向。**

- **要**：冷灰蓝金属质感、工程网格底纹、单色描边、结构清晰可读。仪表与机械结构是主角，不是装饰。
- **不要**：Q 版、卡通化、高饱和糖果色、无功能性的装饰细节、适度风格化路线（低多边形 / 像素等）。

### A2 · 冷霜金属 · 暖橙烈焰（Cryo-Cool vs Combustion-Warm）

- **要**：箭体冷色（钢蓝 #3A4A5A 系 / 霜白），尾焰从亮白 → 橙 → 暗红衰减。**全画面唯一的高饱和暖色留给火焰与爆炸**。
- **不要**：箭体本身色彩斑斓、尾焰与背景争抢注意力。

### A3 · 遥测可读性优先（Legible Telemetry）

- **要**：HUD 采用等宽字体 + 矢量线条，像真实遥测屏幕而非游戏 UI。**任何数值变化都必须有对应的图形动画**（数字跳动的同时指针要动、条要涨）。
- **不要**：拟物化过度导致读不清、纯数字无图形、UI 元素遮挡飞行视野。

### A4 · 剪影与尺度（Scale Through Silhouette）

- **要**：用剪影与相对尺度传达巨大感——发射塔旁的人影、随高度缩小的云层、从天蓝到深空黑的天色渐变、高层大气出现的星点。
- **不要**：靠贴图细节堆体积感、固定不变的背景。

### A5 · 颗粒与震动（Grain & Vibration）

- **要**：屏幕震动、胶片颗粒、烟雾粒子、尾迹拖影。物理感来自"这个东西真的很有力量"。
- **不要**：干净无菌的画面、无反馈的平滑运动。

## 附录 A · Phaser 3（2D 网页引擎）可实现性备注

> 供技术方向（程基岩）在架构阶段参考。以下为设计侧的技术预期，**不构成技术承诺**，需由技术侧确认。

| 设计需求 | 设计侧预期实现路径 | 风险等级 |
|---|---|---|
| 侧视 2D 飞行 + 相机跟随 | 相机随高度 zoom-out，地面随高度呈现弧形 | 低 |
| 尾焰 / 烟雾 / 爆炸 | Phaser 3 ParticleEmitter | 低 |
| 屏幕震动 | Phaser Camera.shake | 低 |
| 天空渐变 / 星空 | Graphics 渐变填充 + 星点图层 | 低 |
| 飞行物理积分 | **建议自写半隐式欧拉积分器**，而非 Arcade Physics（后者为游戏手感设计，不适合弹道精度） | **中 — 需技术侧定夺** |
| HUD 遥测 | DOM 覆盖层 或 Phaser Text + Graphics，取决于性能与排版需求 | 中 |
| 输入 | MVP 仅键鼠，双套输入映射推迟到核心体验层 | 低 |

**原最高风险项已解除（v0.2 决策）**：v0.1 阶段设计侧最担心的技术风险是「触屏设备上的配平（Pitch）操作手感」。用户已拍板**桌面优先、触屏后置**，MVP 输入锁定键鼠，该风险因此**在 MVP 阶段解除**，不再占用原型验证窗口。

**但风险只是被推迟，不是被消除**，需在进入核心体验层规划时重新评估：

1. 触屏版**必须**重新设计 V3「配平」的输入方案——键鼠的 A/D 离散输入无法直接映射到触屏。
2. 届时的**回退方案仍然保留**：「设定目标角度 + 系统自动配平」。该方案会削弱 V3 的操作深度（把持续操纵降级为一次性设定），因此只在触屏手感验证失败时启用。
3. 若启用回退方案，**需同步重新评估 §3.2 的待验证假设**与心流峰值的设计——自动配平会显著削平重力转弯段的心流曲线。

## 附录 C · 设计理论红线自检

在后续系统 GDD 阶段必须持续回归检验的四条红线：

| 红线 | 本作的具体风险点 | 检验方式 |
|---|---|---|
| **主导策略** | 若某种倾倒曲线在所有目标轨道下都最优，自主性归零 | 系统 GDD 阶段做多解验证：至少 2 条可行入轨路径 |
| **经济失衡** | Δv 预算过松（随便飞都能入轨）或过紧（只有一种打法能过） | 平衡检查：容错窗口宽度随目标轨道单调收窄 |
| **认知过载** | MVP 只暴露 5 动词 + 5 读数，加一个就得减一个 | HUD 元素数量硬上限，新增需评审 |
| **支柱漂移** | 任何新特性提案必须挂靠至少一条支柱 | 特性提案模板中强制填写"对应支柱"字段 |
