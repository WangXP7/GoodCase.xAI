## §0 方法声明与基线

### 0.1 本文档的取信顺序（**实现 > GDD > 概念**）

本规格的**唯一事实来源是已实现的代码**。凡代码实现与 S7/S2/S6 GDD 文字不一致处，本文档以代码为准描述「现在是什么」，并单列 §8「规格与实现的偏差」记录「GDD 说应该是什么」与「建议」。

**我不改代码。** 所有偏差交由主理人裁决（谁改 GDD / 谁改代码）。

### 0.2 认知过载红线（硬约束）

MVP 只暴露：

- **5 个动词**：点火 Ignite · 节流 Throttle · 配平 Pitch · 分离 Stage · 中止 Abort
- **5 个读数**：高度 Altitude · 速度 Speed · 燃料 Fuel · 姿态 Attitude · 入轨指示（Ω 双模态）

**加一个就必须减一个。** §8-D11 / D12 已识别实现层出现的"第 6 个信息簇"风险，处置建议见该节。

### 0.3 术语

| 术语 | 含义 | 代码锚点 |
|---|---|---|
| 状态 phase | 发射序列相位 | `SeqPhase`：`IDLE / CHARGING / COUNTDOWN / RELEASE / FLIGHT / ABORTED / FAILED` |
| 结局 outcome | 局终结果（叠加在相位之上） | `simulation.outcome`：`null / 'SUCCESS' / 'FAILURE'` |
| 模态 A / B | Ω 双模态 | `omega.source`：`'A'` 上升段估算 / `'B'` 近地点实测 |
| Ω | 入轨进度复合指标 [0,100]% | `omega.omega` |
| 飞行时钟 | 松绑起算的 T+ | `fm.t` |

> **注意**：`SeqPhase` 中**没有独立 `IGNITION` 相位**。GDD S2 §2.1 的 `IGNITION` 已被折叠为 `COUNTDOWN` 的子阶段 `IGNITE`（T−1.6 → T−0）。HUD 阶段名因此显示「点火 IGNITION」而非独立相位。

## §1 完整用户流程

### 1.1 流程总览（节点 / 时长 / 进入与退出条件）

>
> ⚠️ **P3 时长口径待裁决**：完整倒计时 + 81 s = **91 s**，超 P3 的 90 s 上限。S2 §9-C2 建议方案 B（把 60/81/90 重新解释为"二级提前关机 / 基准 / 节流降档"，并把 60–90 s 口径定义为 T-0 → 判定）。本文档按方案 B 叙述（倒计时计为局外），并沿用 S2 的待裁决标注。

## §2 各流程节点的交互规格

> 格式：**玩家做什么 → 系统给什么反馈 → 时序**。所有时序取常量真值（`src/core/constants.js`）。

### N1 · 待机 IDLE

- **玩家做什么**：按住 `Space`。
- **系统反馈**：主发射按钮文案 `HOLD SPACE TO LAUNCH`；按下后按钮由底向上充能（`launchLabel` → `CHARGING…`）；阶段名 `待机 STANDBY` → `充能 CHARGING`。
- **时序**：`CHARGING_DELAY = 0.6 s`。**点按（按下即松）永远发不出去**——这是刻意的"重量感"。
- **可用输入**：`Space`（点火）、`Esc`（无效果）、`M`（减少动效）。`A/D/W/S/Shift` 此时无任何物理效果（`fm.step` 不运行）。

### N2 · 充能 CHARGING

- **玩家做什么**：继续按住 `Space`。
- **系统反馈**：按钮内琥珀充能条（`g.fillRect(760, 986 + 88*(1-ch), 400, 88*ch)`）自底向上填充。
- **时序**：`ch ≥ 1` → 进入 `COUNTDOWN`；`ch` 在按住期间线性增长。
- **退出**：中途松手 → 立刻回 `IDLE`，充能条清零（`CHARGING_ABORT`）。

### N3 · 倒计时 COUNTDOWN（含三子阶段）

- **玩家做什么**：（未解锁跳过）按住 `Space` 保持；（已解锁跳过）按住 `Space` 时倒计时自动压缩为 3.0 s。
- **系统反馈**：
  - 任务带右侧 64px 倒计时大数字，`fmt(max(0,-t),1)`，`A1 琥珀`。
  - 阶段名随子阶段切换：`预冷 CHILL` → `增压 PRESS` → `点火 IGNITION`。
  - 控制台左侧/右侧 12 段序列指示器按 `_seqProgress()` 逐段点亮（倒计时占进度 0.10 → 0.30）。
  - 告警行 `warningText` 仅在动压异常时出现（倒计时期间为空）。
- **时序**（未跳过）：`wChill=4.0 / wPress=4.4 / wSpool=1.2`；子阶段严格串行（`press` 须 `chill≥0.98` 才累计；`spool` 须 `press≥0.98`）。
- **退出**：
  - 三条件满足（`chill≥0.98 ∧ press≥0.98 ∧ spool≥0.995`）→ `RELEASE`。
  - `CHILL`/`PRESS` 阶段松手 → 回 `IDLE`（`COUNTDOWN_ABORT`，**不计失败**）。
  - `IGNITE` 阶段松手 → **无效果**（不可逆段）。
  - `Esc` → 回 `IDLE`（`ABORT_SEQ`，**不计失败**，0.3 s 内可重按）。
- **跳过模式**：`skippable = 累计成功入轨 ≥ 3 OR 累计发射 ≥ 10`（`game-state.skippable()`）。压缩为 3.0/1.2/1.32/0.48 s，**三个子阶段与全部视觉事件不裁剪**，仅按比例压缩时长。松绑延迟 0.40 s **不压缩**。

### N4 · 松绑 RELEASE（0.40 s）

- **玩家做什么**：无（单帧事件 + 0.40 s 机械延迟）。
- **系统反馈**：阶段名 `松绑 RELEASE`；震屏事件 `T_ZERO`（10 px / 0.4 s，减少动效时 ×0）；倒计时数字让位为飞行时钟 `T+0.0`。
- **时序**：`T_RELEASE_DELAY = 0.40 s`，期间 `t = releaseT`，物理仍锁定。到期 → `RELEASE` 事件，`FLIGHT`，`fm.t = 0`。
- **可用输入**：`Esc`（→ `ABORT`）。

### N5 · 垂直上升（T+0 → ~T+4.7 s）

- **玩家做什么**：保持垂直；可 `W/S` 调油门（`THROTTLE_MIN=0.30`）。
- **系统反馈**：尾焰随节流变长（`_drawFlame`，base = 360·throttle）；高度带三角游标上移；速度、燃料更新；高度带 `ALT km` 刻度。
- **时序**：`fm.t < 0.5 s` 时**配平输入被强制为 0**（首帧防抖，`simulation._physicsStep`）；`t ≥ 0.5 s` 起 `A/D` 生效。
- **退出**：高度达 `PROGRAM.H_START = 150 m`（≈ T+4.7 s），倾倒程序启动。

### N6 · 重力转弯 → 入轨收敛（合并窗口，~76.3 s）

> **本节点是核心技能窗口。分离（V4）是窗口内的节拍，不是阶段边界**——分离前后键位（A/D）与视线目标（Ω/近地点）不变。

- **玩家做什么**：`A/D`（或 `←/→`）持续配平俯仰角 θ，把速度矢量压向水平；`W/S` 管理节流；在 q ≤ 5 kPa 后按 `Shift` 分离。
- **系统反馈**：
  - 姿态表盘：琥珀实际指针 θ vs 灰色参考指针（`refThetaDeg`，辅助线）；配平代价条随 |α| 变色（`A2` → `A1` → `Danger`）。
  - Ω 标记条：模态 A 单一爬升填充（`A2` 冰蓝实心块 + `EST` 角标 + `%`）；近地点追上等效近地点后一次性切模态 B（`近地点 PERIAPSIS` + `MEA` + km 游标）。
  - 动压副行：`q X / 30 kPa`，超 12 kPa 转 `WARN` 色（`A1`），超 30 kPa 转 `Danger`；`h > 12 km` 且真空气压持续 1.2 s 后折叠隐藏（`qVisible`）。
  - 分离：`SEPARATE` 事件触发 0.35 s 顿帧 + 震颤，加速度跃升，燃料条一级转灰、二级点亮。
  - 节流提示：动压进警戒且油门 > 0.8 时，控制台节流条**呼吸式高亮**（减少动效时改静态）。
- **时序（基准）**：
  - T+4.7 s：倾倒起始（150 m）。
  - Ω 模态 A→B：基准 **T+61.66 s**（7 条入轨弹道区间 59.7 – 66.1 s）。
  - 分离：建议在 **T+40 s 后**（q 降到 5 kPa 以下）；HUD 在 q 超限时禁用分离按钮着色。
- **退出**：入轨判定触发（见 N7）。

### N7 · 入轨确认（冻结 1.4 s）

- **玩家做什么**：无（判定已锁）。
- **系统反馈**：`judgeFreezeT` 期间**仍显示飞行 HUD**；Ω 条在模态 B 越 15 km 时填充转 `Success` 绿、成功标记实心点亮。结算面板**延迟到 `judgeFreezeT ≥ 1.4 s` 才弹出**（给玩家 1.4 s 的"我做到了"呼吸）。
- **时序**：判定时机 = ① `SECO`（`stage2 ∧ fuel2 ≤ 0`）或 ② 主动关机（`stage2 ∧ fuel2 > 0 ∧ throttle ≤ 0.30` 持续 1.0 s）。判定后 `outcome='SUCCESS'`，物理冻结。
- **裁定口径**：`regime ∈ {ELLIPTIC, CIRCULAR} ∧ periapsis ≥ 13500+1 m ∧ apoapsis 有限`；`|periapsis − 15000| ≤ 750 m` ⇒ `PRECISE`，否则 `ORBITAL`。

### N8 · 结算面板

- **玩家做什么**：读取数据；按 `R` 或 `Space` 重开。
- **系统反馈**：全屏 dim（alpha 0.85）+ 居中面板。
  - 标题：`● PRECISE ORBIT` 或 `● ORBITAL`（`Success` 绿）。
  - 正文：入轨精度 / Δv 余量·燃料剩余 / 单局时长 / 近地点·远地点。
  - 图例：`入轨门槛  近地点 ≥ 13.5 km       精确入轨  近地点 14.25 – 15.75 km`。
  - 重开提示：`RETRY (R)`（`A1`）。
- **时序**：`R`/`Space` 生效条件 = `outcome==='SUCCESS' ∧ judgeFreezeT > 1.4`。

### N9 · 失败演出 → 归因面板

- **玩家做什么**：演出期（0 → 1.70 s）**无操作**（输入锁定）；面板期读证据链、按 `R`/`Space` 重开。
- **系统反馈**：
  - **0.00–1.70 s 演出**：全屏炽白闪 1 帧 → 碎片/烟环/震屏 10 px → **0.50–1.10 s 完全静止**（静默段）→ 所有遥测数字转 `Danger` 并归零。
  - **1.70 s 面板**：标题 `▲ <失败码标题>`（`Danger`）；主因一句话；证据链（`▲/◆/■` 判定标记 + `T+XX.Xs 量名 数值 单位`）；`建议：<fixHint>`。
- **时序**：面板与重开并存（1.70 s 起 `canRestart=true`）。**演出期 `R`/`Space`/`Esc` 全部无效**（`canRestart=false` 且 `seq.update` 不被调用）。
- **`ABORT` 特例**：不播爆炸演出，播逃逸塔点火（1.20 s），**不计失败统计**。

### N10 · 重开（3 秒红线）

- **玩家做什么**：按 `R`（任意），或按 `Space`（仅当 `canRestart`）。
- **系统反馈**：`Game.restart()` → `sim.reset(skippable)` → `_resetVisuals()`（清天空/尾焰/残骸/相机 FX）；`restartLock = 0.3 s` 去抖，`missionNo` 递增。
- **时序落地（P3 可检验）**：
  ```
  t_fail            : 失败发生，演出开始
  t_fail + 1.70 s   : 面板弹出，R/Space 生效（≤ 3.0 s 红线内）
  t_fail + ≤3.00 s  : 玩家若立即按键，已回到可操作的 IDLE
  ```
  **硬指标实现**：`canRestart = (outcome==='FAILURE') ∧ (timeSinceFailure ≥ 1.70)`，1.70 < 3.00 ⇒ 红线满足。面板**不自动关闭**（尊重阅读节奏，"想快就能快"）。

## §3 HUD 元素规格

> **基准分辨率 1920×1080**，坐标/尺寸为基准像素（`Scale.FIT` 自适应）。层级：**L1** 主视线落点 / **L2** 核心读数 / **L3** 辅助读数 / **L4** 状态与图例。
> **数据来源**：全部来自 `sim.hudModel()` 的只读快照（HUD 禁止回写物理）。

### 3.3 Ω 标记条的双模态呈现（P2 成败点）

| 模态 | 触发 | 填充 | 颜色 | 数值行 | 角标 |
|---|---|---|---|---|---|
| **A（估算）** | `h_p ≤ h_eq` | 自底向上整块填充（高 = `BAR.h·pct/100`） | `A2` 0.85 | `XX.X %` | `EST` |
| **B（实测）** | `h_p > h_eq` 首次（一次性闩锁） | 12 px 高游标（`-6-overshoot` 偏移） | 未越线 `A2` / 越线 `Success` | `X.XX km` | `MEA` |

- **单调闩锁**：`Ω₀`、`h_disp` 双闩锁，回退量恒 0。
- **连续性**：切换发生在 `h_p` 追上 `h_eq` 的交点，跳变恒 0（实测 max 0.130%）。
- **过冲**：`overshoot = sin(e·π)·0.08·10`（位移，非缩放），`T_TRANSITION = 0.60 s`。
- **成功标记**：模态 A 恒空心灰（第 5 道防线——**"条满 ≠ 成功"**）；模态 B 越线实心绿。

1. **倒计时中按 `Shift`（分离）** → 🚫 静默忽略。因为 `fm.step` 不运行、`staging.update` 只在 `FLIGHT` 的物理步内被调用，分离边沿无处消费。

## §7 隐形引导规格（MVP 明确不做教学关）

> **前提**：MVP 不含教学关、不含文字墙、不含"播放动画教你"。引导 = **HUD 高亮 + 辅助线**，全程可被玩家忽略。本节定义触发条件、强度衰减、以及可关闭性与评级加成。
>
> ⚠️ **实现现状**：当前代码只实现了**引导机制的一个子集**（灰色参考指针、节流呼吸高亮、分离按钮 Disabled 着色、告警行）。**"强度衰减"与"可关闭 + 评级加成"尚未实现**，本节为待落地设计，偏差记录于 §8-D8。

### 7.1 引导载体清单

| 引导载体 | 现状 | 引导的"该往哪打杆"语义 |
|---|---|---|
| **G1 姿态参考指针**（灰色） | ✅ 已实现 | 表盘上灰针对齐琥珀针 = 你的俯仰角接近"教科书弹道"。指向"抬杆还是压杆" |
| **G2 参考角数值行** `参考 R°   Cd ×X.XX` | ✅ 已实现 | 把 G1 量化；Cd× 让"压过头"的代价可见 |
| **G3 配平代价条** | ✅ 已实现 | \|α\| 越大条越红 = "你压偏了，正在付费" |
| **G4 节流条呼吸高亮** | ✅ 已实现 | 动压警戒 + 油门 > 0.8 ⇒ "该收油门了" |
| **G5 分离按钮 Disabled 着色** | ✅ 已实现 | q > 5 kPa 时 `SEPARATE` 转灰 = "现在别分" |
| **G6 中止标签高亮** | ✅ 已实现 | 仅 `FLIGHT`/`RELEASE` 亮 = "现在按才有用" |
| **G7 告警行** `warningText` | ✅ 已实现 | `动压警戒`/`结构超限`/`分离禁用` |
| **G8 世界空间建议弹道曲线（Guidance Line）** | ❌ **未实现** | 概念 §5.2 的"减压阀"本体：在场景层画出参考弹道 |
| **G9 首局开环演示（autoProgram）** | ⚠️ 代码有开关，默认关 | 首局让系统代打一段，展示正确姿态 |

### 7.2 触发条件

| 级别 | 触发条件（建议） | 引导内容 |
|---|---|---|
| **L0 关闭** | 玩家手动关闭 / 达到熟练档 | 无 G1–G9（**保留 G5/G6/G7 安全提示**——它们是"事实"不是"建议"） |
| **L1 弱** | 默认飞行态 | G5 + G6 + G7 + G3（**只提示"错"，不提示"对"**） |
| **L2 中** | 连续 2 次失败，或本局偏离参考弹道 > 阈值 | 增开 G1 + G2（参考指针） |
| **L3 强** | 首局，或连续 3 次失败，或近地点连续 5 s 无增长 | 增开 G4 + G8（世界空间建议弹道曲线）+ G9 开环演示段 |

> **隐形原则**：L1 是**默认档位**——新手看到的引导不比老手多"很多"，避免"新手体验被降级"。加档只发生在**连续失败**这个明确信号之后。

### 7.3 强度衰减

- **单局内**：引导强度在**成功入轨后回落一档**（如 L3→L2）。
- **跨局**：`累计成功入轨次数` 每 +1，基线档位 **−1**（最低 L1）；`累计发射次数` 每 +5，基线档位 **−1**（最低 L1）。
- **熟练解锁**：当 `successes ≥ 3`（与跳过倒计时同门槛）时，**默认基线降至 L1**；玩家可手动再开高。
- **硬下限**：**永远保留 G5/G6/G7**（安全/可用性提示）——它们不是"答案"，关掉会造成误操作。

### 7.4 玩家的可关闭性 + 评级加成（**核心设计**）

> 这是让核心受众 A（轨道工程师）与次级受众 B（奇观观众）**共存于同一局**的关键设计（概念 §5.2 减压阀）。

| 项 | 规格 |
|---|---|
| **开关** | 玩家可关闭**建议性引导**（G1/G2/G3/G4/G8/G9），一键切换；**Safety 提示（G5/G6/G7）不可关** |
| **默认值** | 首次进入默认 **L2**（弱+参考指针）；一旦玩家手动关闭，**记忆为 L0 并跨局保持** |
| **评级加成** | **辅助线关闭后评级加成**：结算面板显示 `GUIDANCE OFF · +1 档`（或独立徽记）。加成规则建议：**关闭引导入轨 ⇒ 至少评到 `ORBITAL`，若近地点精度达标则该局记入 `PRECISE` 并额外标记"无辅助"**。加成**只影响结算呈现与跨局统计，不影响物理与判定门槛** |
| **可检验表述** | 关闭引导的局，结算面板必须出现"无辅助"徽记；该局在 `Game.stats` 中独立计数（`successesNoAssist`） |

> **红线提醒**：评级加成**不得**改变入轨判定门槛（13.5 km）本身——否则就是"难度旋钮"，会与 §5.1 自主保障（不显示答案、多条路径）冲突。

### 7.5 P2 的 1 秒可读性——落成可检验表述

> **S7 §1.1 / 概念 §4.2 要求**：玩家必须能在 **1 秒内**从 HUD 读出"我现在该往哪打杆"。这是 P2 的**唯一检验点**。

**可检验表述（验收判据 U-1）**：

> 在 `FLIGHT` 段的**任意随机帧**上，向未受试者展示一帧 1920×1080 HUD 截图 **1.0 秒**（随后隐藏），要求其只回答一个二选一问题：**"为了让弹道更接近入轨，此刻应该[抬杆 A / 压杆 D]？"**
> **通过门槛**：≥ 8/10 帧的正确率 ≥ 90%，且**受影响者无需把视线移出火箭通道（x 720–1200）**。

**支撑该判据的三个 HUD 事实**：

1. **同屏并列**：姿态表盘的琥珀针（实际 θ）与灰针（参考 θ）**在同一半圆内**，偏移方向 = 打杆方向。玩家只需比较两个夹角。
2. **辅助线可关**：关闭后（§7.4）判据仍须通过——此时靠**配平代价条（G3）+ 飞行副行 θ/α**支撑，考验"无可视答案"下的可达读性。
3. **不依赖数值**：判据不要求读出具体度数，只要求读出**方向**——这正是"该往哪打杆"的最小信息量。

**当前风险的诚实标注**：姿态指示器位于 **x=1216**（右侧空域），而箭体在 **x=960**。二者相距 **256 px**，**视线需要横移**——这与 S7 §5.4 C11-b 的设计理由（"攻角需看着箭体读"）不符。**U-1 的"无需移出火箭通道"子条件当前不满足。** 建议裁决见 §8-D3。

## §8 规格与实现的偏差（**供主理人裁决**）

> **我不改代码。** 以下每条给出：① 偏差位置 ② GDD 怎么说 ③ 代码怎么做 ④ 我的建议。**阻塞级 = 影响 P2 验收**。

### 🔴 阻塞级

#### D7 · Ω「成功标记」阈值（15 km）与判定门槛（13.5 km）不一致 【阻塞 · P2】

- **位置**：`src/render/hud.js` `_updateOmega()`：`const crossed = m.periapsisM >= WORLD.H;`（`WORLD.H = 15000`）
- **GDD**：S7 §3.3「目标线位于 G=1.00（条顶）…**条满 = 达标**」；S7 §3.1 防线⑤「近地点游标越过目标线（15 km）⇒ ● 点亮」。**但 S5 判定门槛 `JUDGE.H_PASS = 13500`。**
- **代码结果**：近地点 ∈ **[13.5, 15.0) km** 时，**判定为入轨成功**（结算面板弹 `ORBITAL`），但 Ω 条的填充仍为 `A2` 冰蓝、成功标记仍为**空心灰**。
- **后果**：违反"不撒谎"防线的设计意图——S7 把"条满"设计为"达标"的视觉同义词，但实际达标在 13.5 km，**条满 = 15 km**。玩家在 13.5–15 km 区间会看到"系统说我入轨了，但条没满、灯没亮"，这是 P2 的直接自相矛盾。
- **建议**（二选一，需裁决）：
  - **(a)** 把 `crossed` 改为 `periapsisM >= JUDGE.H_PASS`（13.5 km），并在条上 G 对应位置画出 **13.5 km 门槛线**（区别于 15 km 目标线）。语义变为"越门槛 = 达标，越目标线 = 精确"。
  - **(b)** 维持 15 km，但把判定门槛也抬到 15 km（**否决**——会击穿 RT-1 的 13.5 km 入轨解与 S7 §8.1 的成功/失败分离度标定）。

#### D3 · 姿态指示器位置（x=1216）与 S7「紧贴箭体（x≈960）」不符 【阻塞 · P2】

- **位置**：`src/render/hud.js` `this.attC = { x: 1216, y: 474 };`
- **GDD**：S7 §5.4 C11-b 要求「姿态指示器移到**火箭通道内、紧贴箭体的浮动位置**」，理由是「攻角 `α = θ − γ` 是箭体指向与速度方向的夹角——玩家必须在看到箭体的同时看到这个数」，否则「视线在箭体（x≈960）与仪表（x≈1740）之间往返 780 px，违反 A3 与 P2」。
- **代码**：`attC.x = 1216` —— 处于**右侧空域**（分区 x 1216–1568），距箭体中轴 **256 px**。
- **后果**：§7.5 的 U-1 判据（无需移出火箭通道）**不成立**。虽比 780 px 好，但仍需视线横移。
- **建议**：裁决 —— ① 移到箭体旁（如 x ≈ 860 或 1060，紧贴箭体但避开遮挡）；② 或保持 1216 但**在 UX 规格中把 U-1 的"移出通道"子条件放宽为 ≤ 300 px**（诚实标注这是妥协）。

### §8.5 V-MAXQ · 「越过动压峰值」的视觉形态（应答音频侧 B3-②）

> **目标**：让静音玩家也能在 1 s 内读出"峰值已过"这个**正向事件**，且**不把 16.5 kPa 伪装成高潮**（P2 红线），**不新增读数槽**（认知过载红线）。

| 项 | 规格 |
|---|---|
| **载体** | **复用现有动压量规**（`hud.js` T13，位置 `(1616,702)` 256×7，警戒线在 12 kPa）与其数值副行（T12，`q X / 30 kPa`）。**不新增 widget、不新增读数槽。** |
| **① 峰值刻线（持续）** | 从飞行开始，量规上维护一条 **1 px `A1` 峰值刻线**，位置 = `qMax/Q_STRUCT`（基准 16.5/30 ≈ 55% 宽）。**它标出"本局最高到过哪"**，随 `qMax` 刷新而右移，**只增不减**。 |
| **② 越峰瞬间（T+22.3，事件当帧）** | 刻线**由 `A1` 转 `A2`、alpha 1.0 → 0.6**（0.3 s 过渡）——读作"峰值已定，记录在案"。同时 T12 副行临时改文案：<br>`峰值 16.5 kPa · 已越过 ▲`（`A2`），持续 **1.2 s**，随后**折叠收回**为常规的 `q X / 30 kPa`（不是消失，是收回）。 |
| **③ 大气段结束** | `qVisible` 变 `false`（真空气压持续 1.2 s）时，刻线与副行**一起折叠隐藏**——与现有动压退场机制（S4 §6.5 / S7 §5.6）共用同一出口，不新增退场逻辑。 |
| **④ 不做** | 不加全屏闪、不加新的告警条、不加"解除音"式的庆祝、刻线**不呼吸不闪烁**（"事实记录"不催促玩家）。「减少动效」模式下与常规完全一致（本方案零动效风险）。 |
| **⑤ A1 计数** | 越峰前刻线为 `A1`（可能是本屏第 N 个 `A1`）；越峰后即转 `A2`。**须复核 `A1-BOUND`（单屏 ≤ 5 处）**——若超限，把刻线常色改为 `P1` 陶瓷白。 |
| **⑥ 教学联动** | 玩家看到 ①的刻线随自己收油门而**停在更低处** ⇒ 直接看见 S4 §4.1 的教学点（收到 0.6 峰值仅约 11.4 kPa）。**这是"显示数据不显示答案"（概念 §5.1 自主保障 3）的合规实现。** |
