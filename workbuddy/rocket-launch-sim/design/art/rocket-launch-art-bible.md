## §1 视觉基调

### 1.1 一句话定调

> **用 1960 年代任务控制中心的冷静仪表美学，去拍一部垂直向上的升空史诗——每一帧都像一张能贴在墙上的发射日纪念海报。**

### 1.2 五个风格关键词

| # | 关键词 | 含义 | 落地判据（可验收） |
|---|--------|------|------------------|
| K1 | **Analog-Futura 模拟未来** | 60s 任务控制的机械感与仪式感：模拟仪表、纸质标签、物理开关 | 所有 UI 读数必须是**等宽数字**；所有操作必须有「预备→动作→回弹」三段 |
| K2 | **Hard-Edge Geometric 硬边几何** | 一切形体由清晰可辨的直边与规整圆弧构成，无模糊过渡 | 全画面**零个**模糊阴影、零个柔边投影；圆角半径只允许 `{0, 2, 4, 8}` 四档 |
| K3 | **Print-Texture Warmth 印刷温度** | 颗粒、网点、微错位带来的物质感，对抗"数字塑料感" | 全屏叠加 1 层 4% alpha 的噪点纹理；所有渐变必须是**色带（banding）** |
| K4 | **Instrument Readability 仪表可读性** | 每个视觉元素首先是可读的信息，其次才是装饰 | 去掉任何一个装饰元素都不影响信息传达；反之则不合格 |
| K5 | **Vertical Grandeur 垂直崇高** | 构图永远服务于"向上"这一个动作 | 火箭恒居**火箭通道**内（横屏基准下为 **x 720–1200**，480px 带，中轴 x=960）；**箭体中心在画面中随高度单调下沉**（§5.1.3 C2）；所有引导线与环境 UI 运动方向**锁为纵向**，禁止横向流动 |

### 1.3 情绪曲线

一条发射的视觉情绪不应该是单调上升的，而是**压抑 → 爆发 → 穿透 → 静默**：

```
张力                                            ╭── 静默（入轨，粒子=0，去饱和）
 ▲                                             ╱
 │                                    ╭───────╯  穿透（连续穿越 8 条大气色带）
 │                              ╭────╯
 │                    ╭─────────╯  爆发（点火，全屏粒子峰值 + 底部补光）
 │        ╭───────────╯
 │   ╭────╯  压抑（倒计时 10s，粒子数 = 0，只有数字与充能条）
 └──┴──────────────────────────────────────────────────────────→ 时间
   T-10   T-0    T+3s      T+20s       T+50s          T+81s（入轨）
   （倒计时）（点火）（爆发峰值）（重力转弯）（穿大气顶）（去饱和静默）
```

**关键**：T-10 到 T-0 这 10 秒**一个粒子都不许有**。克制本身就是张力。把预算全押在 T-0 之后。

> #### ⚠️ A1 偏离声明（v1.1 新增 · 有意偏离视觉锚点 A2 · 主理人已裁决**采纳**）
>
> **① 偏离了 A2 的哪一句**
> 视觉锚点 **A2「冷霜金属 · 暖橙烈焰」** 原文要求：
> > "**全画面唯一的高饱和暖色留给火焰与爆炸。**"
>
> 本文档将 `A1 #FFB627` 同时用于**火焰核心**（场景层，§4.2 中层焰）与**主 CTA 按钮 / 倒计时数字 / 充能条**（UI 层，§5.3 / §5.4 / §6.1）。即：高饱和暖色**不止**出现在火焰与爆炸，也出现在 UI 上。**这是一次有意识的偏离，不是疏漏。**
>
> **② 为什么这样更好**
> 琥珀 = **能量与注意**。玩家按住发射按钮时，琥珀从按钮底部向上充能；松手点火，琥珀从喷口向下爆发。
> **让"按钮里憋着的能量"和"喷口爆发的能量"在视觉上是同一件事**——玩家不必学习两套色彩语义，升空的因果链在色彩层就闭合了。机械执行锚点会让"能量"在 UI 与场景之间**断开一次**，而断开的地方恰恰是全作最需要连贯的那一秒（T-0）。
>
> **③ 边界约束 · 规则 `A1-BOUND`（可验收）**
>
> | 项 | 内容 |
> |---|---|
> | **白名单**<br>（允许） | `A1` 只允许出现在满足以下**任一**语义条件的位置：<br>• **能量流** —— 火焰 / 尾焰三层、底部补光（§4.6）、充能条填充、发动机点火、燃料临界阈值段（§5.4）<br>• **注意指令** —— 主 CTA（发射按钮）及其 Hover / Pressed 态、倒计时数字、临界告警（§2.7 警告态） |
> | **黑名单**<br>（禁止） | 禁止用于：一般性文字强调、次要 / 三级按钮、图标描边、面板背景、分隔线、角标（corner ticks）、进度条的**常态**填充、装饰性高光、环境物件。<br>这些位置的默认强调色是 **`A2` 冰蓝**，不是 `A1`。 |
> | **验收判据**<br>（三条全过） | **① 语义问句**：截取任意一屏，逐个 `A1` 元素问"这处是能量，还是要我看它？"——**有任一处答案为否，即违规。**<br>**② 计数上限**：单屏 `A1` 元素 **≤ 5 处**（火焰系统计 1、充能条计 1、倒计时计 1、主 CTA 计 1、告警计 1）。超出即说明已发生泛化。<br>**③ 替换测试**：把某处 `A1` 换成 `A2 冰蓝`，若**信息传达不受影响**，则该处即为违规泛化（因为 `A2` 才是"信息 / 遥测"的默认强调色，`A1` 必须**不可替代**）。 |
> | **与既有约束的关系** | §2.6 第 2 条的 `A1` 屏占比 ≤ 12% 仍然有效。本规则是**语义层**约束，与屏占比是**并列且取严**的关系，不互相替代。 |

### 2.2 天空色阶（Sky Ladder · Planet-C）—— 本作最重要的色彩资产

天空**不是一条连续渐变**，而是 **8 条离散色带**。每带之间做 0.8s 交叉淡入。这样既有"穿越层"的事件感，又规避了平滑渐变的廉价感，同时性能更好（只需 2 个 TileSprite / 2 组矩形轮换）。

> **v1.2 重算说明**：旧表按地球尺度 0–400 km 铺开（9 条，含卡门线）。Planet-C 全飞行仅覆盖 **0–19.409 km**，故色带区间**按 `src/core/constants.js` 的 `SKY_BANDS` 逐值重算**。8 条色带的**顶部 / 底部 HEX 与旧表完全一致**（色值未变，只有区间与条数变了）。**代码 id 保留旧编号（L0–L4、L6–L8，跳过 L5）**，本表为便于阅读顺延为 **L0–L7**；两列对照见"代码 id"列。

| 本表编号 | 代码 id | 名称 | 高度区间 | 顶部 HEX | 底部 HEX | 视觉事件 |
|---|---|---|---|---|---|---|
| **L0** | `L0` | 地面 GROUND | 0 – 150 m | `#8FB8D9` | `#E8D9BE` | 地平线暖雾、发射塔、地表细节 |

### 2.5 无彩使用规则（反"灰色技术演示风"）

**全画面禁止出现未定义用途的中性灰 `#808080` 系。** 所有"灰"必须来自：
- `P2 铁灰 #5A6472`（偏蓝的冷灰，属结构色）
- `P3 墨蓝 #121A33`（深色底）
- `#8A8D93`（水泥，唯一中性灰，仅用于地面水泥且必须带 P2 阴影）

### 2.6 色板纪律

1. 单屏**同时出现的色相 ≤ 6**（含背景）。超了就说明信息分层失败。
2. 强调色 A1/A2 屏占比合计 **≤ 20%**（其中 `A1` ≤ 12%）。它们只在"看这里"的地方出现。
3. 任何新颜色加入色板前，必须先在 §2.1 表里登记并说明用途，否则视为违规资产。
4. **`A1` 琥珀另受 §2.1 的 `A1-BOUND` 边界规则约束**（v1.1 新增）：除屏占比外，还须通过**语义问句 / 计数上限（单屏 ≤ 5 处）/ 替换测试**三条验收判据。`A2` 冰蓝是默认强调色，`A1` 只在"**能量 / 注意**"语义处才可顶替它——**禁止泛化到一般性强调**。

### 2.7 色盲模式（Colorblind Mode）—— 颜色永不作为唯一通道

**双通道铁律**：每一个状态色必须配对（a）一个**形态/图案**通道 +（b）一个**图标形状**通道。

| 语义 | 标准模式 | 色盲模式（Deuteran / Protan 安全） | 图案通道 | 图标形状 |
|------|---------|--------------------------------|---------|---------|
| 危险 | `#FF4B3E` | **`#FF9D2E` 橙** | 45° 斜纹 | ▲ 三角 |
| 警告 | `#FFB627` | **`#FFE066` 亮黄** | 对角条纹 | ◆ 菱形 |
| 成功 | `#4FE0A8` | **`#4F9BE0` 天蓝** | 实心填充 | ● 圆形 |
| 信息 | `#5FD8E8` | **`#E6EDF7` 近白** | 点阵 | ■ 方形 |

色盲模式四色在**明度上也拉开梯度**（近白 > 亮黄 > 橙 > 天蓝），因此灰度打印下依然可辨。

**验收项**：全屏截图转灰度后，危险态与成功态必须仍能被区分（靠图案与形状，不靠明度巧合）。

## §3 形状语言

### 3.1 火箭（Rocket）

- **母题**：圆柱 + 圆锥 + **水平环带**。
- **比例**：箭体直径 **96px**，全长 **768px**（@1x 基准），**细长比 1:8**。细长比是"向上感"的物理来源，不得随意加粗。
- **头锥角**：22°（锐利但不失真）。
- **对称铁律**：火箭本体**严格左右对称**。唯一允许不对称的时机：级间分离之后的坠落段、以及失败时的碎片。对称 = 秩序 = 可发射状态；不对称 = 失控。这个语法要让玩家无意识读懂。
- **装饰语法**：所有装饰是**水平环带**，宽度取自 `{4, 8, 16, 32}` px（2 的幂）。水平环带强化垂直轴，是当前最省力的"向上"暗示。
- **尾翼**：4 片**直角三角形**，硬角无倒角，高 96px、底宽 56px。
- **强制细节**：箭体侧面必须有**一条贯穿全身的 2px 管线**（燃料管，色 `P2`），以及**等间距 32px 的 2px 铆钉点阵**。这两样是"这东西是人造的、会坏的"的视觉证据。

### 3.2 场景（Scene）

- **母题**：**水平分层 + 垂直塔架 + 弧线**。
- 大气 = 水平带（§2.2 的 **8 带**）；塔架/桅杆/电缆 = 垂直线；行星边缘（Planet-C limb）/地平线 = 弧。
- 地面设备一律由 **矩形块 + 圆柱 + 三角支撑** 三种基本体拼装，**无有机曲线**。
- **云不是柔和圆**：是**扁平椭圆团**，硬边单色（`#F4EFE4` / `#C9D6E4`），宽高比 3:1 到 5:1，2 层错位堆叠（错开 8px、明度差 6%）。这是丝网印刷的云，不是天气 App 的云。

### 3.3 UI

- **母题**：直角矩形框 + **1px 硬描边** + 等宽数字 + 角标（corner ticks）。
- **圆角半径只允许 `{0, 2, 4, 8}` px 四档**。按钮固定 4px。**禁止药丸形（大圆角）、禁止半圆。**
- **角标语法**：每个面板四角有 L 形角标（长 12px，1px，`A2` 或 `P2`）。角标 = "这是一块仪器面板"。
- **进度条**：**分段式**（segmented），8–12 段硬边矩形，段间间隙 2px。段数即精度上限，天然传达"刻度感"。禁止连续流体条（太现代、太软）。
- **仪表**：半圆刻度盘（9 个主刻度、每主刻度间 4 个次刻度）+ 单个三角指针。

### 3.4 通用几何规律

1. **网格**：所有精灵尺寸为 **4 的倍数**，关键元素吸附 8px 网格。
2. **描边**：全局统一 **1px（@1x）**，色 `P3 #121A33` 或对应填充色的 60% 明度版。禁止 2px 以上的粗描边（会脏）。
3. **间距**：面板内边距取值 `{8, 16, 24, 32}` px。
4. **圆角/斜切**：斜切角统一 **45°**，切角尺寸 `{4, 8}` px。

## §4 材质与光影（2D 实现方案）

### 4.0 总原则：色带，不是渐变

**本作禁止把平滑渐变当作主体填充。** 平滑渐变在 2D 里几乎总是读作"廉价"。替代方案是**色带化（banding）**：把渐变烘焙成 **5 档离散色阶**写进贴图。同样的过渡，观感从"PPT 默认背景"变成"丝网印刷"。

### 4.1 金属

```
┌─────────────────────────┐  ← 1px 高光线（填充色 +25% 明度）
│  主体平色（无渐变）        │  占宽度 60%
│                         │
├─────────────────────────┤
│  阴影带（填充色 -30% 明度）│  占宽度 30%，位于右下
└─────────────────────────┘
  + 竖向 1px 拉丝纹（alpha 8%，间距 8px）
  + 2px 铆钉点阵（间距 32px）
```

- **三段平铺**，不使用径向渐变。
- 火箭箭体用 P1 陶瓷白，阴影色 `#C4BCAA`，高光线 `#FFFFFF`（alpha 70%）。

### 4.2 火焰

**三层层叠 + `BlendMode.ADD`**，主力是 **5 帧 sprite 序列 + 随机缩放**，不是粒子。

| 层 | 颜色 | 形状 | 缩放范围 |
|---|------|------|---------|
| 核心 Core | `#FFF3D0`（近白） | 细长锥，长度为满焰 55% | X 0.9–1.1，Y 0.95–1.05 |
| 中层 Mid | `#FFB627`（A1 琥珀） | 锥，长度 100% | X 0.85–1.15，Y 0.9–1.1 |
| 外层 Outer | `#E2603C`（S1 砖橙） | 锥，长度 115%，边缘**锯齿缺口** | X 0.8–1.2，Y 0.85–1.15 |

- 帧循环周期 **0.083s**（12fps），三层**错拍**（核心 0.083 / 中层 0.091 / 外层 0.077），避免机械同步。
- 锯齿缺口用**硬边切角**实现（每帧 3–5 个三角形缺口），不用柔化。
- **真空段例外**：高空时外层消失，只剩核心 + 中层的**羽毛状扩散**（sprite 换组，长度 ×1.6、宽度 ×2.4、alpha ×0.7）。这是真实火箭在真空中的样子，也是免费的"我上天了"信号。

### 4.3 烟雾

**扁平硬边椭圆块，不是柔和圆形粒子。** 这是全作最容易做丑的一项，务必执行。

- 颗粒数：**地面扩散 12–20 个 / 尾迹 40–60 个**（桌面），移动端 ×0.55。
- 单颗粒半径 **24–64px**，alpha **0.55–0.85**（不做低透明度堆叠——那正是"廉价粒子云"的成因）。
- 颜色：`#C9D6E4`（亮部）→ `#8A8D93`（暗部），点火最初 0.6s 内被底部补光染成 `#FFB627`（alpha 30% 叠加）。
- 运动：上浮 + 缓慢放大（1.0 → 1.6×）+ 缓慢旋转（±12°/s），存活 1.2s。
- **地面扩散阶段（T-0 → T+1.5s）是招牌画面**：3 个宽椭圆（宽 640 / 800 / 560px，高 48 / 64 / 40px）从喷口两侧**横向**铺开，0.9s 铺满发射台。真实发射最有识别度的就是这股贴地横向卷云，不要做成向上冒的蘑菇云。

### 4.4 大气辉光 / 光晕

- 使用**预烘焙的径向渐变纹理**：单张 **256×256**，`#5FD8E8` → 透明（5 档色带化），`BlendMode.ADD`，靠缩放复用。
- **禁止实时模糊 / 实时高斯**。
- 全屏同时 **≤ 3 个 glow 实例**（喷口 1、底部补光 1、行星边缘 1）。

### 4.5 玻璃 / 舷窗

- 平色 `#0E1229` + 一条 **2px 45° 斜向高光**（白 alpha 40%）。就这两样，够了。

### 4.6 光影统一规则

- **常态单一光源**：来自**上方偏左 15°**（模拟日光），所有硬边投影向右下，投射角固定 75°，阴影色为 `P3 #121A33` alpha 35%。
- **点火后叠加底部补光（Bottom Rim Light）**：点火瞬间起，箭体底部 1/3 出现琥珀色边缘光（`#FFB627`，ADD，alpha 峰值 0.55），随高度上升按 `alpha = 0.55 × e^(-altitude/8km)` 衰减。**这是"有生命感"的核心手法**——光会随事件改变，而不是永远烘焙在贴图上。
- **入轨后补光转色**：底部补光由琥珀 `#FFB627` → 冰蓝 `#5FD8E8`（行星反照），1.2s 过渡。冷光 = 到了另一个世界。

## §5 UI 视觉风格

### 5.1 设计基准与自适应

> **v1.1 全节重写。** 主设计基准由 1080 × 1440（3:4 竖屏）改为 **1920 × 1080（16:9 横屏）**，以对齐 **Q2「桌面优先，触屏后置」**。原竖屏布局**保留**于 §5.1.4，但明确**不属于 MVP 交付范围**。

#### 5.1.1 基准取舍

**主设计基准：1920 × 1080（16:9）**，Phaser `Scale.FIT` + `autoCenter: CENTER_BOTH`。

| 候选 | 结论 | 理由 |
|------|------|------|
| **1920 × 1080（16:9）** | ✅ **选定** | 桌面占比最高的原生分辨率；16:10 屏 FIT 后上下各留约 10%（由**环境框边**填充，非黑边）；纵向 1080px 是"垂直升空"叙事的硬通货 |
| 1600 × 900（16:9） | ❌ | 纵向仅 900px。扣掉 HUD 后，发射塔（880px）与火箭（768px）几乎顶格，**买不到"火箭上方的未至空域"**——而这正是横改竖之后最贵的那件东西（§5.1.3） |
| 1280 × 720（16:9） | ❌ | 纵向 720px < 火箭全长 768px，火箭根本装不下；强行缩小会崩掉 §3.4 的 1px 描边与 8px 网格系统 |
| 1920 × 1200（16:10） | ❌ | 在 16:9 屏上左右各留约 9% 黑边。**横向是遥测柱与控制台的主战场**，横向留边的代价比纵向大 |

**浮层规则（两条，可验收）**：

1. **半透明，不是实心**：浮层底 = `P3 #121A33` **alpha 0.78** + 1px `A2` 内描边（alpha 0.5）+ 四角 L 角标（§3.3）。**必须能看见后面的天空**，否则横屏的全出血优势被浪费。
2. **对比度保护**：浅色天空带（L0 `#8FB8D9` / L1 `#7FA8D4`）下，浮层须保证 §2.3 的对比度结论仍成立。核算：alpha 0.78 `P3` 叠在 `#8FB8D9` 上 ≈ `#2D3D58`，`#F4EFE4` 其上 ≈ **9.5 : 1 ✅ AAA**。**验收判据**：截取 L0/L1 段的 HUD 区域，实测对比度须 ≥ 4.5:1，否则提高浮层 alpha（不得降低文字亮度）。

**构图核算基准（供布局校验）**：满焰长度取箭体全长的 **35%**（硬边几何焰，非堆砌，§4.2）。**升空段的尾迹允许并鼓励冲出画面底边**——那是"正在离开地面"的证据；唯 T-0 点火瞬间需要在画内落地。

#### 5.1.3 横屏的代价与补偿：「垂直崇高」五件套

> **先承认损失**：3:4 竖屏天然是"向上"的画框，16:9 横屏天然是"向两边"的画框。改成横屏后，**画面本身的纵向张力确实变弱了**——这是真实损失，不粉饰。
> **补偿思路**：不去否认它，而是把"向上"从**画框属性**翻译成**镜头语言 + 仪表语言**。画面给不了的东西，让镜头和仪表给。

| # | 手段 | 规格 | 补回了什么 |
|---|------|------|-----------|
| **C1** | **离散拉远 rails<br>（Dolly Out Rails）** | 相机 zoom ∈ **{1.0 → 0.75 → 0.5}** 三档**硬切**，节点为：塔架脱离后（≈ T+0.6s，被烟与震屏掩盖）、到达**大气顶 12 km**（§2.2 L4/L5 边界，被天空色带 0.8s 交叉淡入掩盖）。**禁止连续 lerp** | 火箭屏上高度 768 → 576 → 384 px。**拉远 = 世界在变大 = 还有多少天要爬** |
| **C2** | **下沉锚点<br>（Sinking Anchor）** | 箭体中心在画面中的纵向锚位：**Z1 y=516（47.8%）→ Z2 y=648（60%）→ Z3 y=702（65%）**，**随高度单调下沉**。上方"未至空域"因此 **132 → 360 → 510 px** 单调增长 | **"火箭越飞越高，在画面里却越来越低。"** 用**构图的下沉量编码高度**——竖屏靠画框给 headroom，横屏靠这条规则给。这是五件套里的主件 |
| **C3** | **高度带<br>（Altitude Tape）** | 80 × 800 垂直标尺，**倒序刻度（0 km 在下、20 km 在上）**；标注 **8 条色带边界 L0–L7**、**大气顶（12 km，`A2` 1px 横线 + "ATMOSPHERE TOP"）**与**目标轨道线（15 km）**；当前高度指针为 **`A1` 三角**，随高度**自下而上**推移；已通过区间填 `A2` alpha 0.12 | 把纵向位移翻译成一个**可读的仪表**。横屏损失的是"画面在往上走"，高度带补回的是"**数字也在往上走**"——而且它是全作最"任务控制中心"的一件东西 |
| **C4** | **垂直速度线<br>（Vertical Streaks）** | 高空段（**> 8 km**，即 L3 近似真空段起）在火箭通道两侧出现**竖直细线**：1–2px 宽、长 60–160 px、`P1` alpha 0.25、`BlendMode.ADD`，长度与密度随速度增长。**方向严格锁死为竖直，禁止任何倾斜** | 全作唯一被允许的"速度感"特效，且方向锁死为竖直——**把"向上"直接画进画面** |
| **C5** | **环境 UI 纵向锁** | 左侧环境框边内的示波器波形改为**纵向走纸**（自下而上，而非自左向右）；状态灯阵**竖排**；远山剪影**竖向分层**。全画面**禁止任何横向跑马灯 / 横向流动进度条 / 横向扫光** | 横屏最怕"两侧 UI 把视线拉向左右"。所有环境 UI 的运动矢量一律锁为**纵向**，把溢出的横向空间反过来用作向上的引导 |

**为什么 zoom 必须离散（技术论证，三条）**：

1. **保 1px 描边**：非整数连续缩放会糊掉 §3.4 的 1px 硬描边，直接违反 K2 硬边几何。
2. **采样比全部 ≥ 1.0**：@2x 资产在 zoom `{1.0, 0.75, 0.5}` 下的采样比为 **{2.0, 1.5, 1.0}**——**无上采样模糊**；而任意中间值（如 0.68）会出现 1.36 这类非整数比，反而最糊。
3. **同一套哲学**：离散拉远与 §4.0「色带不是渐变」是同一个决定——**离散优于连续**。

**横屏构图红线（可验收）**：

| 段 | 火箭包围盒顶边 → 画面顶边（y=0） |
|---|---|
| **Z1**（T-10 → T+0.6s） | **豁免**。该段刻意让火箭顶天立地（箭体 y 132–900，塔架 880px 更高、塔尖允许被任务带半透明压住） |
| **Z2**（T+0.6s → 12 km） | **≥ 324 px（30% 画高）** |
| **Z3**（12 km → 入轨 15 km） | **≥ 480 px（44% 画高）** |

> **判定方式**：截取该段任意一帧，量 `火箭包围盒顶边 → y = 0` 的像素距离。低于阈值即为构图违规。

### 5.2 字体气质

**"等宽数字 + 无衬线大写标签" —— 这是仪表感的核心，不可妥协。**

| 用途 | 字体 | 处理 |
|------|------|------|
| 所有数字 / 遥测读数 | **IBM Plex Mono**（fallback: Roboto Mono → `ui-monospace`） | 强制 `font-variant-numeric: tabular-nums`；**中文数字遥测一律用阿拉伯数字** |
| 标签 / 按钮文字 / 正文 | **Inter**（fallback: Noto Sans SC → 思源黑体） | 大写 + `letter-spacing: 0.08em`（印刷标签感） |
| 中文 | **思源黑体 Source Han Sans** Medium / Bold | **禁止宋体 / 楷体 / 圆体**（破坏工业感） |
| 标题 / 阶段名 | Inter Bold 或 IBM Plex Mono Bold | 字重不超过 Bold（不用 Black，太潮） |

**网页字体预算（首屏关键）**：
- 家族 ≤ 2 个，字重 ≤ 4 个（Mono Regular/Bold + Sans Medium/Bold）
- 总 woff2 **≤ 120KB**，子集化（仅拉丁 + 常用汉字 3500）
- `font-display: swap` + 系统字体栈 fallback，**首屏不得因字体阻塞渲染**
- 数字字形可用 **base64 内联的位图数字集**（0-9 + 单位符号，约 8KB）在字体加载完成前顶上——保证遥测数字**永不闪白**

### 5.3 按钮反馈（4 态 + 1 充能态）

| 状态 | 表现 |
|------|------|
| **Idle** | 平色填充 + 1px 描边 |
| **Hover**（仅桌面） | 填充提亮 12% + 描边转 `A1 #FFB627` |
| **Pressed** | **下沉 2px（位移，非缩放）** + 填充压暗 15% + 1 帧白色闪（4 帧内衰减） |
| **Disabled** | 填充去饱和至 40% + 描边转 `P2` + 45° 斜纹叠加 |
| **Charging**（主发射按钮专属） | 按住时 `A1` 琥珀色**从底部向上填充**（0→100%），同时描边亮度随之提升。**仪式感的核心交互**——松手即中止并回落 |

> **禁止用 scale 做反馈**。位图缩放会糊，且"缩放 = 变大了"是廉价游戏 UI 的标志。用**位移 + 明度**。

### 5.4 仪表盘与进度条

- **分段式**，8–12 段硬边矩形，段间间隙 2px。填充方向：垂直条从下往上，水平条从左往右。
- 临界值段（如燃料 < 20%）：段内填 `A1 #FFB627` + 45° 斜纹；耗尽段填 `P2` 空心。
- 指针式仪表：半圆刻度（9 主刻度 × 4 次刻度）+ 单三角指针。
- **指针移动带 8% 过冲回弹**（`Back.easeOut`，200ms）。**仪表指针不许线性移动**——线性 = 死。

### 5.5 HUD 信息层级

| 层级 | 内容 | 视觉权重 |
|------|------|---------|
| **L1 主导** | 倒计时数字、主发射按钮 | 最大字号 + `A1` 强调色 + 唯一允许的全屏动效 |
| **L2 状态** | 当前阶段名、速度 / 高度读数 | 等宽数字 + `A2`，中字号 |
| **L3 背景** | 燃料 / 温度 / 次要遥测 | `P2` 灰 + 小字号，仅在需要时高亮 |
| **L4 环境** | 任务名、装饰性示波器 | 低对比度，可被忽略 |

## §6 动效与 VFX 基调

### 6.0 性能预算（硬红线，超出即违规）

| 指标 | 桌面 | 移动端 | 备注 |
|------|------|--------|------|
| **活跃粒子总数** | **≤ 420** | **≤ 220** | 全场景合计，非每发射器。用 `maxParticles` 硬性封顶 |
| 并发发射器实例 | ≤ 6 | ≤ 4 | — |
| 后处理 FX pass | ≤ 3（Bloom / 色差 / 暗角） | **≤ 1**（暗角） | **移动端默认关闭 Bloom**，用 §4.4 预烘焙 glow 贴图替代 |
| Draw call | ≤ 90（含 UI） | ≤ 70 | — |
| 纹理内存 | ≤ 48 MB | ≤ 32 MB | — |
| 图集 | 单张 ≤ 2048×2048，最多 3 张 | 同左 | `padding: 2`，`trim: true` |
| 震屏幅度 | ≤ 12 px | ≤ 8 px | 仅 `Camera.shake`，禁止整个场景容器位移 |
| 震屏频率 | ≤ 2 Hz 主体 | ≤ 2 Hz | 光敏安全（§9） |

**纹理与加载**：
- 格式：**WebP（有损 q=82）** 为主；纯色 UI 元素用 PNG-8；**禁止未压缩 PNG-32 作精灵图**。
- 图集 `padding: 2`（不是 16，省内存）、`trim: true`、`extrude: 0`。
- 分 3 个加载阶段：`boot`（<200KB，Logo + 进度条）→ `core`（<1.0MB，火箭 + 发射场 + UI）→ `orbit`（<2.3MB，太空段资源，在火箭升空时后台预载）。
- **天空不需要大图**：色带用 **8 × 512** 的垂直渐变 PNG 拉伸（每张 < 2KB），**8 条色带合计 < 20KB**。

### 6.1 关键动效：倒计时（T-10 → T-0）

> **本阶段粒子数 = 0。** 克制即张力。

- 每次跳数：数字缩放 1.0 → 0.92 + alpha 1 → 0.6，**120ms**，`Back.easeOut` 回弹。
- 同步：任务带底部一条 `A1` 琥珀色**充能进度条**从左向右分段填满（10 段，每秒 1 段）。
- T-3 起：每次跳数伴随 **2px / 80ms** 的极轻相机位移（预告性颤动）。
- T-0：数字替换为 `LIFTOFF`，字重 Regular → Bold，**12px / 400ms** 大震，充能条满格后整条闪白 2 帧。

### 6.2 关键动效：点火（T-0 → T+1.2s）

| 时间 | 事件 |
|------|------|
| 0.00s | 喷口出现白点（4px → 12px） |
| 0.25s | 拉长为 40% 长度的火舌（3 层同时出现，外层略滞后 0.05s） |
| 0.40s | 达到满焰长度并进入稳定循环 |
| 0.00–0.50s | 全屏底部琥珀 ADD 层 alpha 0 → 0.35 → 0.18 |
| 0.10–0.90s | 3 个宽椭圆贴地横向铺开（见 §4.3） |
| 0.00–0.80s | 震屏 **12px / 0.8s**（2Hz 主体 + 高频抖动叠加） |
| 0.30s | 塔顶摆杆摆开 60°（0.5s，缓出）；鸟群惊飞（3–5 个 `v` 形，抛物线飞出） |
| — | 粒子：烟 **40**（桌面）/ **24**（移动）；火星 **0**（全用 sprite 序列） |

### 6.3 关键动效：升空（T+1.2s → 塔架脱离）

- 上升加速度：**0 → 8 px/s²，ease-in**。前 1.5s 位移 **< 40px**——"沉重感"来自起步的慢，不是来自抖动。
- 尾焰拉长至静止长度的 **2.2×**，帧循环提速至 1.6×。
- 相机跟随：`deadzone 200px`，`lerp 0.12`。
- 持续微震：**2px → 5px**，随速度线性增加。
- 粒子：尾迹烟 **60**（桌面）/ **32**（移动），存活 1.2s。

### 6.4 关键动效：级间分离（Stage Separation）

- **0.35s 顿帧（hit-stop）**。顿帧属于**时序层**，与震屏正交，**不占用震屏名额**。
- 分离面出现 2px 白色闪光线，横向贯穿箭体，**持续 3 帧**。
- 下级箭体：立即失去动力 → 火焰 0.2s 内 alpha→0 → 继续上升 0.3s → 开始翻转下落（**旋转 45°/s + 轻微 tumble**）。
- 上级发动机：**0.15s 预热闪烁**（3 次明暗，2Hz）→ 点火。**有预热才有"机械感"**，直接点火读作"开关"。
- 震屏：8px / 0.25s。
- 粒子：分离碎片 **12**（小矩形硬边，带独立旋转）。**不用柔和粒子**。

### 6.5 关键动效：整流罩抛离（Fairing Jettison）

- 两片整流罩**左右对称分开**：水平速度 260px/s，旋转 ±25°/s，0.8s 后淡出。
- 震屏 6px / 0.2s。
- 视觉语法：这是全作唯一一次"完美对称的分离"，与 §6.4 的"不对称坠落"形成对照。**对称分离 = 计划内；不对称 = 意外。**

### 6.6 关键动效：入轨（Orbit Insertion）—— 用"静"表达成功

> **本阶段粒子数 = 0。** 真空里没有烟，这是物理，也是最好的设计决策。

- 全屏**去饱和渐变 1.2s**：场景饱和度 → 15%，**只有遥测 UI 保持全彩**。（技术上是叠一层 `P3` 色的低 alpha 层 + 降 UI 之外的对比，比真做饱和度后处理便宜得多。）
- **行星大气辉光弧（Planet-C limb）** 从屏幕底部升起，成为唯一光源；底部补光由琥珀转冰蓝（§4.6）。**触发条件（v1.2）**：按**入轨判定事件**触发（近地点 ≥ **15 km** 门限），**非固定高度**——Planet-C 在 12 km 以上 ρ 已截断为 0，15 km 处确为真空，静默方案成立。
- 一圈 `#5FD8E8` 1px 细环（ADD）从火箭中心缓慢扩散，**只出现 1 次**，1.8s。
- 尾焰熄灭过程 **0.6s**（不是瞬间消失），熄灭后画面**完全静止 0.8s**，然后 UI 才弹出成功面板。**静默 0.8 秒比任何庆祝特效都有力。**

### 6.7 关键动效：失败 / 爆炸

> **禁止**：大团橙色柔和粒子云、慢镜头碎片雨、反复闪白。这三条是廉价爆炸的三大件。

| 时间 | 事件 |
|------|------|
| 0.00s | 全屏炽白闪（alpha 0.9，**1 帧**） |
| 0.02–1.20s | 火箭碎成 **8–14 个硬边几何块**（保持箭体配色，边缘是切面不是柔边），每块独立旋转 + 抛物线，1.2s 内飞出屏幕 |
| 0.05–0.95s | **3 个硬边烟环**（环形，非实心圆），快速扩大 + 淡出 |
| 0.00–0.50s | 震屏 10px / 0.5s |
| **0.50–1.10s** | **画面完全静止**（0.6s 静默） |
| 0.00–0.40s | 所有遥测数字转 `Danger` 色，等宽数字快速归零，最后停在 `0` |
| — | 粒子：仅 **30**（桌面）/ **18**（移动）余烬点；碎片与烟环全用 sprite |

### 6.8 通用动效原则（"生命感"的来源）

1. **三段式**：所有状态切换必须有 **Anticipation（预备）→ Action（动作）→ Settle（回弹）**，最短总时长 **240ms**。没有预备的动作读作"跳变"。
2. **缓动**：进入用 `Back.easeOut`（过冲 8%），退出用 `Cubic.easeIn`（快出）。
3. **禁止线性运动**。唯一例外：遥测数值滚动（线性的数字流动才有"仪表在读数"的感觉）。
4. **错拍**：所有循环动效周期取**非整数倍关系**——火焰帧循环 0.083s / 烟上浮 1.7s / 待机摆动 3.2s / 蒸汽阀闪烁 2.3s。同步的循环 = 机械感。
5. **静止时也要呼吸**：待机火箭有 **0.6px 幅度、周期 3.2s** 的极缓慢摆动；塔架蒸汽阀持续 1 帧闪烁；旗帜缓慢飘动；地面车辆有 0.3px 的怠速抖动。**画面中不允许存在完全静止的元素。**
6. **状态姿态差异**：火箭在「待机 / 上升 / 真空」三态必须有**可辨的姿态差异**（待机：垂直静止 + 微摆；上升：尾焰拉长 + 轻微仰角摆；真空：无尾焰 + 缓慢自转）。

### 8.2 地面弧曲率 LOD（四级）

随高度推进，地面从"水平条"渐变为"大弧"。用 **4 张预烘焙弧线贴图**交叉淡入（不用实时变形）：

| 级别 | 高度区间 | 表现 |
|------|---------|------|
| **G0** | 0 – 1 km | 水平地面条，无曲率 |
| **G1** | 1 – 5 km | 轻微下弯，地面条压缩至 60% 高度 |
| **G2** | 5 – 9 km | 明显弧线，压缩至 35%，大气辉光带贴弧生成 |
| **G3** | 9 km+ | 大弧，占屏幕底部 1/4，4 层辉光弧完整（§2.2）；行星弧 alpha 随 `(alt−9km)/9km` 渐入 |

### 8.3 视差层（5 层，垂直滚动系数）

| 层 | 内容 | 系数 |
|---|------|------|
| 远景 | 远山剪影 `P3` | 0.08 |
| 云层 A | 高空薄云 | 0.25 |
| **主体** | 火箭 + 发射塔 + 地面 | **1.00** |
| 云层 B | 低空厚云（穿云层时用） | 0.45 |
| 前景 | 尘埃 / 气流线 | 1.60 |

### 8.4 大气层过渡机制

- **离散色带 swap**，不是连续 lerp。每个色带边界做 **0.8s 交叉淡入**。
- 实现：2 个 `TileSprite`（当前带 + 下一带）轮换，纹理为 **8 × 512 色带化渐变 PNG** 横向拉伸。
- 好处三重：性能（2 个 draw call）、观感（色带不是廉价渐变）、**事件感**（"穿过了一层"是可感知的进度）。

### 8.5 穿云层（L1–L2 段 · ≈5 km 以下）的额外处理

- 火箭穿过云层 B 时，云层 B 的云在穿过的瞬间**被气浪推开**（云向两侧水平位移 40px + 快速淡出，0.4s）。
- 这是给低空段（最容易无聊的一段）的**事件补偿**。

### 9.2 视觉禁忌（Anti-Patterns）—— 硬性，违规即打回

> **授权例外登记（v1.1）**：本节十条禁忌全数有效。目前全作**仅 1 项已登记的授权例外** —— §2.1 的「A1 琥珀偏离声明」（高饱和暖色 `A1` 用于 UI 的"能量 / 注意"语义处，偏离文策渊锚点 A2 原句），由主理人裁决采纳，并受 `A1-BOUND` 三条验收判据约束。**除此之外，任何对锚点 A2 的偏离都必须先经主理人裁决并登记于此，不得自行改判。**

> **T1 · 禁止粒子堆砌**
> 任何时刻屏幕活跃粒子 ≤ 420（桌面）/ 220（移动）。粒子是**点缀**，不是表现手段。火焰、烟、碎片的主力表现必须是 **sprite 序列与硬边形体**。
> **验收判据**：把粒子系统整体关掉后，画面**仍然成立**（点火看得出点火、爆炸看得出爆炸）。若关掉就塌了，即为堆砌。

> **T2 · 禁止音乐可视化式特效**
> 禁止与音频频谱联动的发光 / 跳动 / 波形；禁止无信息量的呼吸式全屏 glow 脉动；禁止彩虹 / 霓虹渐变循环；禁止频谱柱状装饰。
> 本作所有发光必须**由物理事件驱动**（喷口、补光、辉光弧），不由时间或音量驱动。

> **T3 · 禁止静态雕塑感**
> 画面中**没有任何元素允许完全静止**。待机时至少保留 1 个低频呼吸动效（火箭微摆 3.2s / 蒸汽阀闪烁 2.3s / 旗帜飘动 2.4s）。
> 火箭在「待机 / 上升 / 真空」三态必须有可辨的姿态差异。

> **T4 · 禁止灰色技术演示风**
> 不允许出现未定义用途的灰色（`#808080` 系）几何体、**网格地面、线框模型、坐标轴**。
> 所有"灰"必须是 `P2 铁灰 #5A6472`、`P3 墨蓝 #121A33`、或水泥色 `#8A8D93`（仅地面且必须带 P2 阴影）。

> **T5 · 禁止廉价渐变**
> 不允许把大面积平滑线性 / 径向渐变作为主体填充。天空用**离散色带**（**8 带**），金属用**三段平铺**，glow 用**色带化预烘焙贴图**。
> 允许平滑渐变的唯一场景：§4.4 的 glow 贴图与 §2.2 的**行星辉光弧**（且必须是色带化的）。

> **T6 · 禁止模糊阴影 / 柔边投影**
> 所有阴影为**硬边色块**，同角度（75°）同色（`P3` alpha 35%）。
> 模糊 = 需实时 filter = 性能与风格双输。

> **T7 · 禁止颜色作为唯一信息通道**
> 每个状态色必须配对一个形态 / 图案 / 图标通道（§2.7）。
> **验收项**：灰度截图下，危险态与成功态仍可区分。

> **T8 · 禁止通用素材感**
> 不允许直接套用通用 UI kit、通用按钮、通用爆炸素材包、通用图标集。
> 所有元素必须能被指认出"属于这个世界"（判据：把元素单独抠出来，能否一眼认出是本作的）。

> **T9 · 禁止缩放动画作为主要反馈**
> 按钮 / 面板的 hover / press 不使用 `scale`（位图会糊，且是廉价 UI 标志）。改用**位移 + 明度 + 描边**。

> **T10 · 禁止常驻装饰性屏幕效果**
> 屏幕常驻扫描线、暗角边框、CRT 曲率、噪点动画——一律禁止（光敏安全 + 克制双重原因）。
> 例外：噪点可以是**静态**的 4% alpha 层（§4 K3）；扫描线仅在**故障状态**下短时出现（≤ 1.5s，且可关闭）。

### 9.3 光敏性癫痫安全（按 Comprehensive 处理）

本作震屏与闪光密集，属高风险品类，安全规格按最高档执行：

| 项 | 规格 |
|---|------|
| 震屏 / 闪烁 / 扫描线抖动 | **三者独立开关**，默认震屏开、闪烁开、扫描线关 |
| 闪烁频率 | **≤ 2 Hz**（硬上限，非 3Hz） |
| 闪烁形式 | **禁止硬 on/off**，一律用**呼吸式明暗渐变**（正弦，非方波） |
| 大面积（> 屏 25%）红色闪烁 | **禁止** |
| 首次启动 | 弹出一次性光敏提示，提供"减少动效"快捷开关 |
| 减少动效模式 | 震屏幅度 ×0（改 1px 位移提示）、粒子 ×0.3、闪烁改静态高亮 |

- 打包参数：`padding: 2`、`trim: true`、`extrude: 0`、格式 **WebP q=82**（UI 纯色件用 PNG-8）。

### 10.4 Phaser 3 实现要点（交程基岩核对）

| 需求 | 建议实现 | 备注 |
|------|---------|------|
| 火焰 / 辉光混合 | `setBlendMode(Phaser.BlendModes.ADD)` | — |
| 天空色带 | 2 × `TileSprite`，纹理 8×512 横向拉伸 | 交叉淡入，不用大图 |
| 星星 | 1 张 512×512 预烘焙 `TileSprite` | **禁止逐颗生成对象** |
| 粒子硬上限 | emitter config 中设 `maxParticles`，并做**全局粒子计数器**在 `update` 中做总数熔断 | 单靠各发射器的 `maxParticles` 加不满上限时会超 |
| 震屏 | `this.cameras.main.shake(duration, intensity)` | **禁止**位移场景容器 |
| 后处理 | Phaser 3.60+ FX pipeline；移动端 `isMobile` 分支关闭 Bloom | 需引擎层做开关 |
| 缩放 | `Scale.FIT` + `autoCenter: CENTER_BOTH` | 见 §5.1。基准 **1920 × 1080**；< 1600 × 900 切紧凑模式（两档，非连续） |
| 相机 zoom rails | `camera.setZoom()` 三档 **{1.0 / 0.75 / 0.5}**，事件节点硬切 | 见 §5.1.3 C1。**禁止每帧 lerp**；切档须与天空色带交叉淡入对齐（RA-5） |
| Graphics | **仅用于 debug**，禁止每帧重绘 | 每帧重绘 Graphics 是性能杀手 |
| 去饱和（入轨） | 叠一层 `P3` 低 alpha 全屏矩形 + 隐藏非 UI 层的饱和度 | 比真做饱和度后处理便宜 |
