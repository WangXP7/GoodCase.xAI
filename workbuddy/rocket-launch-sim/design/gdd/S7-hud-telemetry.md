## 1. 系统职责与支柱挂靠

### 1.1 一句话职责

> **让玩家在任意一帧都能用 1 秒回答两个问题：「我现在状态怎么样？」「我该往哪打杆？」** S7 是概念 §4.2 隐性必需动词 **V6「读取 Read」** 的唯一载体。

### 1.2 支柱闸门校验

| 支柱 | 本系统如何服务 | 判定 |
|---|---|---|
| **P1 · 过程即内容** | 无。HUD 是呈现层，不是过程本身 | ⚠️ **无挂靠** |
| **P2 · 可解读的深度** | **本系统是 P2 的第一验收点，也是唯一验收点。** 概念 §4.2 原文：「V6 是 P2『可解读的深度』落地与否的唯一检验点。若 MVP 测试中出现『玩家不知道自己为什么炸了』，优先怀疑 V6 而非玩家。」**Ω 的成功与否直接决定 P2 成立与否** | ✅ **挂靠（唯一载体）** |
| **P3 · 一次发射，六十秒** | 读数退场机制（§5.6）保证真空段不出现"死读数"占用注意力，间接服务 P3 | ✅ 弱挂靠 |
| **P4 · 失败也好看** | HUD 在失败时转 `Danger` 色并归零（美术 §6.7），是失败演出的组成部分 | ✅ 弱挂靠 |

**闸门结论：S7 是 P2 的唯一载体。P1 无挂靠是结构性的（呈现层不产生过程），这不是砍系统的理由——S7 是 MVP 的硬性组成（概念 §7.1 核心 HUD）。**

### 1.3 明确不属于 S7

- 失败演出的画面（碎片 / 烟环）→ S6
- 结算面板的数据**计算** → S5（S7 只呈现）
- 跨局趋势与档案室 → S8

## 2. Ω 复合指标（RT-1 遗留风险 **R1** 的解答）

> **本节是全份 GDD 的核心交付物。所有系数均已用 RT-1 的 7 条入轨弹道 + 8 条含失败弹道实测标定，不留"待调"。**

### 2.1 问题重述与一个前置纠错

**RT-1 §6 的原始前提**：「近地点游标在飞行前 87% 是死的（T+70.8 s 前恒为 −300 km），属 SUBORBITAL，物理本质无法调参解决。」

**实测证伪（见 `tests/c1/omega-calib.mjs` §2）**：真实近地点的**数值**并非钉死：

| T+s | 0 | 20 | 30 | 40 | 50 | 55 | 60 | 65 | 70 | 71 | 75 | 81 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 近地点 km | −300.00 | −299.76 | −296.44 | −282.30 | −247.58 | −215.72 | −166.18 | −89.29 | −4.98 | +1.23 | +10.89 | +15.09 |

「钉死在 −300 km」的观感来自**两重夹紧**，而不是物理：
1. `orbit-solver.ref.mjs` 的 `toDisplay()` 把负近地点**夹紧到 0**；
2. `regime === SUBORBITAL` 的**分类判定**把整个阶段标记为"无效"。

**这个纠错很重要**：它意味着真实近地点**可以被用作指示量**，只是需要一个**能容纳 −300 km 的压缩标尺**，而不是全程依赖合成指标。本设计正是基于这一点——**Ω 与真实近地点跑在同一条标尺上，因此天然连续。**

### 2.2 Ω 完整公式（可直接实现）

#### ① 分量

```
A = h / H                      高度项，量纲 1。**不夹紧**，可 > 1（SECO 时 = 19.409/15 = 1.294）
B = (v_h / V_C)²               水平速度项，量纲 1 = 水平动能 / 圆轨道所需动能
```

| 符号 | 值 | 量纲 | 说明 |
|---|---|---|---|
| `h` | 当前高度 | m | S1 |
| `H` | 15000 | m | 目标轨道高度 |
| `v_h` | 当地水平（切向）速度分量 | m/s | S1（`vh`） |
| `V_C` | 1512 | m/s | 目标高度圆轨道速度 |

#### ② 复合指标

```
Ω₀ = 0.45 · A + 0.55 · B                        ∈ [0, ~1.62]
Ω₀ ← max(Ω₀, Ω₀_prev)                           单调闩锁（高水位标记）
```

**权重来源**：`tests/c1/omega-calib.mjs` 在 5 个候选函数族 × 权重 × 阈值 × 伽马上做网格寻优，目标函数 = **最大化「任意 8 秒窗口内的最小进度增量」**（7 条弹道取最差）。冠军即 `wA = 0.45, wB = 0.55`。

#### ③ 等效近地点（把 Ω₀ 翻译成与真实近地点同轴的量）

```
h_eq = −R · (1 − min(Ω₀ / Ω_CRIT, 1))            ∈ [−300000, 0] m
Ω_CRIT = 1.60
```
`h_eq` 从 −300 km（毫无进展）单调升到 0（轨道与地表相切）。

#### ④ 融合（**本设计的核心机制**）

```
h_disp_raw = max( h_eq , h_p )                   h_p = 真实近地点高度 m（可为负）
h_disp     = max( h_disp_raw , h_disp_prev )     单调闩锁
```

> **为什么用 `max`**：
> 1. **天然单调**：两个单调递增量的 `max` 仍单调，再加一道闩锁，回退在数学上不可能发生。
> 2. **天然连续**：切换发生在 `h_p` 追上 `h_eq` 的**交点**，交点处二者相等 ⇒ **切换跳变恒为 0，与系数取值无关**。这是结构性保证，不依赖标定精度。
> 3. **自标定**：`Ω_CRIT` 取 1.2 还是 2.2 只影响交点落在哪里，**不影响连续性**。实测 `Ω_CRIT = 1.60` 时切换落在 T+59.7 – T+66.1 s（7 条弹道），模态 B 总有 **14.9 – 21.3 s** 可读。

#### ⑤ 折线压缩标尺（把 −300 km 到 +15 km 压进一条 0–100% 的条）

```
G(h) = 0.60 · (1 + h / R)                , −R ≤ h < 0      [h=−300km → 0.00 ; h=0 → 0.60]
G(h) = min(1, 0.60 + 0.40 · (h / H))     ,  0 ≤ h          [h=0 → 0.60 ; h=15km → 1.00]
```

| 区段 | 占条宽 | 含义 |
|---|---|---|
| `G ∈ [0, 0.60)` | 60% | **亚轨道区**：`h_disp` 从 −300 km 爬到 0 km |
| `G ∈ [0.60, 1.00]` | 40% | **轨道区**：真实近地点从 0 km 爬到 15 km |

> **40% 给最后 13 秒是刻意的**：条在末段**加速**——玩家看到游标在最紧张的时候动得最快，这正符合概念 §5.2 的「收敛焦虑 → 释放」情绪设计。

#### ⑥ 感知伽马

```
s = G(h_disp) ^ 0.55                              ∈ [0, 1]
```
补偿 `G` 在早期的极度缓慢（不补偿时 T+30 s 时条只走 7%，伽马后走 24%）。

#### ⑦ 显示值

```
Ω = 100 · s                                       ∈ [0, 100] %
```

### 2.3 公式汇总（一屏可抄）

```js
const H = 15000, R = 300000, VC = 1512;
const W_A = 0.45, W_B = 0.55, OMEGA_CRIT = 1.60, GAMMA = 0.55;

function computeOmega(st, orbit, prev) {
  // ① 分量
  const A = st.h / H;
  const B = (st.vh / VC) ** 2;

  // ② 复合 + 闩锁
  const o0 = Math.max(W_A * A + W_B * B, prev.o0);

  // ③ 等效近地点
  const hEq = -R * (1 - Math.min(o0 / OMEGA_CRIT, 1));

  // ④ 融合 + 闩锁（轨道解算退化时 h_p 沿用上帧）
  const hP = orbit.valid ? orbit.periapsis : prev.hP;
  const hDisp = Math.max(Math.max(hEq, hP), prev.hDisp);

  // ⑤⑥⑦ 标尺 → 伽马 → 百分比
  const G = (hDisp < 0)
    ? 0.60 * (1 + hDisp / R)
    : Math.min(1, 0.60 + 0.40 * (hDisp / H));
  const s = Math.pow(Math.max(0, G), GAMMA);

  return { o0, hEq, hP, hDisp, s, omega: 100 * s,
           source: (hP > hEq) ? 'B' : 'A' };   // 模态判定
}
```

### 2.4 双模态切换判据

```
模态 A（Ω 估算）  : h_p <= h_eq        → 显示 Ω 百分比，实心填充条
模态 B（近地点实测）: h_p >  h_eq 首次成立 → 显示真实近地点，游标 + 数字

切换为**一次性闩锁**：一旦进入模态 B，本局不再回到模态 A（防 h_p 抖动导致来回跳）。
```

**基准弹道实测**：切换于 **T+61.66 s**（全程 81 s 的 **76%**），模态 B 有 **19.4 s** 可读。

## 3. 「不撒谎」约束的 UI 实现（违反即击穿 P2）

> **RT-1 §6 设计要点 1 原文**：「上升段显示的 Ω 是复合指标，不是『伪近地点』。UI 标签必须区分（进度条 vs 双游标），**不得让玩家误以为近地点已达标**。」

### 3.1 五道防线

| # | 防线 | 模态 A | 模态 B |
|---|---|---|---|
| **1** | **单位** | 条上、数字上**永不出现 `km`**。只有 `%` | 出现 `km` 与数值（等宽、`tabular-nums`） |
| **2** | **标签** | `入轨进度 ORBITAL PROGRESS Ω` + **`EST` 估算角标** | `近地点 PERIAPSIS` + **`MEA` 实测角标** |
| **3** | **颜色语义** | 填充用 **`A2 冰蓝 #5FD8E8`**（信息 / 遥测语义） | 未达目标线保持 `A2`；**越线才转 Success `#4FE0A8`** |
| **4** | **图形语义** | **实心填充块**（连续的一整条，读作"进度"） | **实心游标 + 目标线**（读作"读数 vs 门槛"） |
| **5** | **成功标记** | 条顶的 ● 成功标记保持**空心 `P2` 灰**——**Ω = 100% 也不点亮** | 近地点游标越过目标线（15 km）⇒ ● 点亮为 `#4FE0A8` |

> **第 5 条是最重要的一条。** 它保证了「Ω 到 100%」与「入轨成功」在视觉上是**两个不同的事件**。玩家在模态 A 看到条满了，成功标记仍是灰的——他会立刻意识到"这还不是成功"。

### 3.2 双通道（色盲）合规

美术 §2.7 铁律：颜色永不作为唯一通道。

| 语义 | 标准色 | 色盲色 | 图案通道 | 图标 |
|---|---|---|---|---|
| 模态 A（估算 / 信息） | `A2 #5FD8E8` | `#E6EDF7` 近白 | 点阵 | ■ 方形 |
| 模态 B 未达标 | `A2 #5FD8E8` | `#E6EDF7` 近白 | 点阵 | ■ 方形 |
| 模态 B 已达标 | `#4FE0A8` | `#4F9BE0` 天蓝 | 实心填充 | ● 圆形 |
| 目标线 | `A2` 1px 横线 | 同 | 虚线 + `15.0 KM TARGET` 文字标签 | — |

**验收**：灰度截图下，模态 A 的填充（点阵）与模态 B 达标的填充（实心）必须可区分；成功标记的空心与实心必须可区分。

### 3.3 目标线的位置

```
目标线位于 G = 1.00（条顶），2px `A2` 横线 + 标签 `15.0 KM TARGET`
```
**理由**：条的量程上界就是目标高度 15 km，因此"条满"="达标"，无需在条中间再画一条线——中间线会让玩家以为"过中间线就算成功一半"，这是新的误解源。

### 3.4 远地点游标的处理（对 v0.3 §7.1「双游标」的偏离说明）

**基准弹道远地点 = 8746 km**，7 条弹道区间 **4431 – 10127 km**。而条的量程只有 0 – 15 km。

**结论：远地点无法与近地点共存于一条线性标尺。**

**处理**：远地点以**数字 + 越界标记**呈现，不占条的像素：
```
远地点 APOAPSIS   8746 km ▲
```
当远地点 < 20 km 时（理论上 MVP 内不会发生），游标正常落在条内显示。

> **这是我对概念 v0.3 §7.1「双游标或双端条」的偏离，需主理人确认。** 理由是物理的：远地点比近地点大 3 个数量级，线性双游标在数学上不可能。若坚持"双游标"形态，唯一替代是把条改为**对数标尺**（0.1 – 20000 km），代价是近地点的末段精度（13.5 → 15.1 km 只占对数轴的 2%）几乎不可读——**那就等于把 P2 的核心读数做坏了**。我建议维持上述方案。

### 5.2 五个读数的槽位分配与 Ω 的占位论证

> **任务要求**：「Ω 若占用新槽位，必须说明它挤掉哪一个，或论证它是『Δv 余量』读数的图形化表达。」

**答案：Ω 不新增槽位。** 概念 v0.3 §7.1 已把第 5 读数确定化为「**Δv 余量（轨道预测标记条）**」，并明确「标记条占用的是第 5 个读数『Δv 余量』的槽位（同一物理量的图形表达），**5 动词 + 5 读数的认知过载红线未破**」。

**Ω 就是这条标记条在模态 A 的填充量。** 具体地说，第 5 槽这一个 widget 内含三层，共享同一像素轴、同一视线落点：

| 层 | 模态 A | 模态 B | 层级 |
|---|---|---|---|
| **主游标** | Ω 实心填充（`s = G(h_eq)^0.55`） | 真实近地点游标（`s = G(h_p)^0.55`） | L2 |
| **副游标** | 隐藏 | 远地点数字 + ▲ 越界标记 | L3 |
| **数值行** | `Ω 52.5 %` | `近地点 −144.7 km`（夹紧显示 `0`） | L2 |
| **底注** | 例（基准 T+61.66）：`Δv 余量 861 m/s · 4144 kg`（**两种单位同一数据**，见 §9-C13） | 同左 | L3 |

**「我离入轨还差多少」是这四层的唯一语义**——Ω 与 Δv 余量不是两个量，是同一个问题的两种表达（前者是"你已经完成了多少"，后者是"你手里还剩多少"）。**因此第 5 槽是 1 个读数，不是 3 个。**

### 5.4 姿态指示器为什么放在箭体旁（对美术 §5.1.2 的偏离）

美术 §5.1.2 的遥测柱原定 4 格：高度 / 速度 / 燃料 / **温度**。而 MVP 的 5 读数是 高度 / 速度 / 燃料 / **姿态** / Δv 余量。

**两个偏离，均需林绘澄确认**：

| # | 偏离 | 理由 |
|---|---|---|
| **C11-a** | **删掉「温度」格** | MVP 无气动加热模型（S4 §1.3），温度是**假读数**。放一个恒定的假数字违反 P2 |
| **C11-b** | **姿态指示器移到火箭通道内、紧贴箭体的浮动位置** | 攻角 `α = θ − γ` 是"箭体指向"与"速度方向"的夹角——**玩家必须在看到箭体的同时看到这个数**。放在右侧遥测柱会迫使视线在"箭体（x≈960）"与"仪表（x≈1740）"之间往返 780 px，直接违反锚点 **A3 遥测可读性优先**与 P2 的「1 秒内读出该往哪打杆」 |

**遥测柱因此变为 3 格**：标记条（2 格 324 px）+ 速度（156）+ 燃料（156）= 660 px，正好填满。

## 6. 边缘情况（≥3 条，含数值退化与除零防护）

### 6.1 `V_C` 的除零与 `B = (v_h/V_C)²`

`V_C = 1512 m/s` 是编译期常量，永不为 0。但**若未来支持多目标轨道**，`V_C` 由 `sqrt(MU/R_TGT)` 计算，`R_TGT = 0` 会除零。

**防护**：`B` 计算前断言 `V_C > 1`；否则 `B = 0` 并记一条 `console.error`。**MVP 内 `V_C` 为硬编码常量，该分支不可达，但断言必须存在。**

### 6.2 `A = h / H` 在 `h < 0` 时

理论上 `h ≥ 0`（起飞点）。但 `h` 因浮点可能取到 `−1e-9`。

**防护**：`A = Math.max(0, st.h) / H`。`A` 为负会让 `Ω₀` 下降，触发闩锁把它"粘"住——**症状是条卡住不动，比条倒退更难排查**。

### 6.3 `G(h_disp)` 的负底数求幂

`s = G(h_disp)^0.55`。若 `G(h_disp) < 0`（`h_disp < −R`，理论上不可能但浮点可达），`Math.pow(负数, 0.55) = NaN`。

**防护**：`s = Math.pow(Math.max(0, G), GAMMA)`。**这是本系统最重要的一行防御**——`NaN` 会沿 `omegaPct` 污染整个 HUD，直接违反美术 §5.2「遥测数字永不闪白」。

### 6.4 轨道解算退化时的 `h_p`

`regime === DEGENERATE`（起飞瞬间 `r × v ≈ 0`）时 `periapsis` 可能是 `NaN`。

**防护**：`const hP = orbit.valid ? orbit.periapsis : prev.hP;`（见 §2.3 代码）。若从未有过有效值，`prev.hP` 初始化为 `−R`（−300000），使 `max(h_eq, h_p)` 必然取 `h_eq` ⇒ 模态 A。**起飞阶段强制模态 A，这是正确的。**

### 6.5 失败弹道下 Ω 的上限（不撒谎的边界）

8 条弹道实测（含失败）：

| 弹道 | 结局 | Ω 峰值 |
|---|---|---|
| 基准 50%/0.8 | 入轨 | 100.0 % |
| 低抛 35%/0.5 | 入轨 | 97.8 % |
| 高抛 85%/1.2 | 入轨 | 99.5 % |
| 极早倾倒 10%/0.3 | MAXQ 解体（T+61.4） | **46.3 %** |
| 急抛 20%/0.2 | 未入轨 | **92.7 %** |
| 极晚倾倒 130%/2.0 | 未入轨 | **96.2 %** |
| 不倾倒 200%/3.0 | 未入轨 | **89.6 %** |
| 超高抛 150%/2.5 | 未入轨 | **95.9 %** |

**观察：入轨者 Ω ≥ 97.8 %，未入轨者 Ω ≤ 96.2 %，无重叠。**

> ⚠️ **这不是承诺，是观察**。**Ω 高 ≠ 一定入轨**（96.2 % 也会失败）。这正是 §3.1 第 5 道防线（成功标记在模态 A 恒为灰）存在的理由。
>
> **验收判据**：在 8 条标称弹道上，入轨组与未入轨组的 Ω 终值区间不得重叠。**Phase 5 闭环验证时必须用玩家实际输入的弹道重跑该判据**——若出现重叠，需重新标定 `Ω_CRIT`。

### 6.6 单调闩锁与"条卡住"

闩锁保证不回退，代价是：若玩家在末段把火箭压下去，`h_p` 下降但条不动。

**这是刻意的取舍**：条卡住 ≠ 撒谎（玩家没有变好，条也不该涨），且 S6 会在 1 s 内接管 HUD。**验收**：失败弹道下 Ω 单调不减，且在失败后 1 s 内 HUD 切换为失败面板。

### 6.7 重开时的闩锁残留

`prev.o0` / `prev.hDisp` 若未在 `reset()` 清零，第二局 Ω 会从上一局的终值（100 %）起算 ⇒ **开局即满条**。

**防护**：`reset()` 无条件将 `prev = { o0: 0, hDisp: -R, hP: -R }`。**验收**：连续重开 20 次，每局 T+0 时 `Ω === 0.0 %`。

## 9. 冲突与待裁决项

### C12【重要 · 需裁决】Ω 的函数形式偏离了 RT-1 §6 的字面建议

**RT-1 §6 建议**：`Ω = f(水平速度占比, 高度/H)`，即 `B = v_h / v`。

**实测否决理由**：`B = v_h / v` 在 **T+40 s 即达到 0.845、T+50 s 达到 0.954、T+58 s 达到 0.99**，而 `A = h/H` 在 **T+61 s 达到 1.0**。二者**同时饱和**，任何线性加权组合都会在 **T+58 s 触顶**——即**最后 23 % 的飞行（19 s）进度条完全不动**。

我在 `omega-calib.mjs` 中跑了 5 个候选函数族 × 权重 × 阈值 × 伽马的网格寻优（目标：最大化任意 8 s 窗口的最小进度增量）。结果：

| 函数族 | 最优「最小 8s 增量」 | 是否进入前 14 名 |
|---|---|---|
| F1 加权和（`A` 夹紧） | 进度条在 T+58 后**完全钉死** | ❌ 未进入 |
| F2 加权和（`A` 不夹） | 同上（饱和主导） | ❌ 未进入 |
| F3 乘积 `A^p·B^q` | 早期动态范围过窄 | ❌ 未进入 |
| **F4 `0.45·(h/H) + 0.55·(v_h/V_C)²`** | **5.01 %** | ✅ **冠军** |
| F5 `0.45·(h/H) + 0.55·(v_h/V_C)` | 4.75 – 5.01 % | ✅ 次席 |

**我的选择：F4。** 它与 RT-1 的精神一致（仍是"水平速度 + 高度"两个已验证的单调量），只是把"水平速度占比"**从「占总速度的比例」改为「占圆轨道速度的比例的平方」**——后者在整个飞行区间内不饱和，且有清晰的物理语义：

| 项 | 模态 | 物理含义 | 不饱和范围 |
|---|---|---|---|
| `A = h / H` | 高度 | **你到了多高 / 目标多高** | 0 → 1.294 |
| `B = (v_h / V_C)²` | 水平速度 | **你有多少水平动能 / 圆轨道需要多少** | 0 → 1.880 |

**裁决请求**：请确认是否接受 F4 作为 Ω 的定义。若坚持 `B = v_h / v` 的字面形式，则必须接受「末段 19 s 进度条不动」——那将直接击穿 P2（玩家在最关键的末段失去唯一的进度反馈）。

### C1【阻塞级】美术圣经高度轴与新标定差 20 倍 —— **高度带刻度必须重标**

见 S4 §9-C1 的完整分析。落到 S7 的具体影响：

| 美术条款 | 影响 |
|---|---|
| §5.1.2 高度带（`0 – 400 km` 倒序刻度） | **95 % 的刻度永不使用**。需改为 `0 – 20 km`，并把 9 条色带边界重标（见 S4 §9-C1 的建议映射表） |
| §2.2 L5 卡门线 `100 KM` | **永不触发**。需改为大气顶 `12 KM` 事件线，标签 `ATMOSPHERE TOP` |
| §5.1.3 C1 zoom rails（50 km 节点） | **永不触发**。建议改为 `{松绑+0.6s, 7.5 km, 12 km}` 三档 |
| §5.1.3 C4 垂直速度线（`> 20 km`） | **永不触发**（最高 19.41 km）。建议改为 `> 6 km` |

**S7 的应对**：高度带的刻度数值由 S7 从常量表读取，**不硬编码**。我已把全部高度相关的物理锚点列入 S4 §9-C1 的映射表，供林绘澄直接取用。

### C11【中】遥测柱的「温度」格与「姿态」读数错位

见 §5.4。美术 §5.1.2 的遥测柱原定 4 格（高度 / 速度 / 燃料 / 温度），MVP 的 5 读数是（高度 / 速度 / 燃料 / **姿态** / Δv 余量）。

**两个建议**：① 删除温度格（MVP 无热模型，温度是假读数）；② 姿态指示器移到箭体旁浮动位置（攻角需要"看着箭体读"）。

### C13【低】「Δv 余量」与「燃料剩余」在固定构型下冗余

见 S5 §3.5。`dvRemain = 2900 · ln((m_dry + fuelRemain) / m_dry)`，二者一一对应。S7 的应对是**把两者并排显示为同一数据卡的两种单位**（`1514 m/s · 27 900 kg`），而不是两个独立卡片。
