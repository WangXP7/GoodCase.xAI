## 1. 系统职责与支柱挂靠

### 1.1 一句话职责

> **把玩家的按键变成一条可归因的弹道。** S1 拥有火箭的全部运动学状态、姿态动力学、推进与质量流，是所有其他系统的唯一真值源（single source of truth）。

### 1.2 支柱闸门校验

| 支柱 | 本系统如何服务 | 判定 |
|---|---|---|
| **P1 · 过程即内容** | 姿态与节流是**逐帧连续**的玩家操作，全程无自动驾驶、无自动导航段。飞行中不存在"播放动画"的时刻——引擎每一帧都在读玩家输入 | ✅ 挂靠 |
| **P2 · 可解读的深度** | 每一个物理量（θ、θ_cmd、τ、m、q、v_h）都有 HUD 表达（见 S7）。**物理量的数量被刻意压到玩家能归因的规模**：只有推力、重力、阻力三项加速度源 | ✅ 挂靠 |
| **P3 · 一次发射，六十秒** | 积分步长与燃时直接决定单局时长。S1 保证满油门动力飞行 **81.0 s**（RT-1 实测），节流降档会拉长燃时——这是 90 s 上限的唯一来源 | ✅ 挂靠 |
| **P4 · 失败也好看** | S1 负责产出失败**原因码**（MAXQ / IMPACT / TUMBLE / DESTRUCT），S6 只消费不重算 | ✅ 挂靠 |

**闸门结论：S1 挂靠全部四根支柱，无"无挂靠"子系统。**

### 1.3 明确不属于 S1

- 大气密度模型与动压 → **S4**（S1 只调用 `rho(h)` 与 `q` 两个接口）
- 轨道根数解算 → **S5**（S1 只提供 `r, v` 状态向量）
- 发射前状态机（预冷/增压/松绑）→ **S2**（松绑前 S1 的积分器不推进）
- 分离事件本身 → **S3**（S1 只执行质量跳变与级参数切换）
- HUD 数值格式化与降级 → **S7**

### 2.3 运行时状态（每帧）

```ts
interface FlightState {
  // ── 运动学（惯性系，原点 = 行星质心）──
  rx, ry:     number;   // 位置 m（rx = downrange，ry = 高度方向）
  vx, vy:     number;   // 速度 m/s

  // ── 质量 ──
  m:          number;   // 当前总质量 kg
  fuel1:      number;   // 一级剩余燃料 kg
  fuel2:      number;   // 二级剩余燃料 kg
  stage:      1 | 2;    // 当前级

  // ── 姿态 ──
  theta:      number;   // 实际俯仰角 rad（相对当地水平面，π/2 = 垂直向上）
  theta_cmd:  number;   // 目标俯仰角 rad（玩家输入 / 引导程序的输出）
  alpha:      number;   // 攻角 rad = theta − gamma
  gamma:      number;   // 速度矢量俯仰角 rad（航迹角）

  // ── 推进 ──
  throttle:   number;   // 节流 τ ∈ [0.30, 1.00]
  thrust:     number;   // 当前推力 N = throttle · T_stage

  // ── 派生（每帧由 S1 计算，供 S4/S5/S7 读取，不重复计算）──
  r:          number;   // 到质心距离 m
  h:          number;   // 高度 m = r − R
  v:          number;   // 速度模长 m/s
  vr:         number;   // 径向（垂直）分量 m/s
  vh:         number;   // 当地水平（切向）分量 m/s
  q:          number;   // 动压 Pa（由 S4 提供）
  dvRemain:   number;   // Δv 余量 m/s（剩余推进剂可提供的 Δv）
  dvSpent:    number;   // 已消耗 Δv m/s

  // ── 时序 ──
  t:          number;   // 局内时间 s（T-0 起算，松绑前为负）
  tPowered:   number;   // 动力飞行时长 s
}
```

### 2.4 单位与坐标系约定

- **SI 制**，长度 m、质量 kg、时间 s、力 N、角度 **rad**（HUD 显示时转 °，见 S7）。
- 惯性系原点 = 行星质心，`+y` 为起飞点天顶方向，`+x` 为 downrange 方向。
- 当地坐标系单位向量：径向 `û = (rx, ry)/r`，切向 `l̂ = (uy, −ux)`（指向 downrange 前方的"水平"）。
- **角度定义**：`theta = π/2` 为垂直向上，`theta = 0` 为当地水平（沿 `l̂`）。这一定义与 RT-1 的积分器逐字一致，**不得改为"相对竖直"**，否则全部标定失效。

## 3. 规则与公式

### 3.1 积分器

**半隐式欧拉（Semi-Implicit Euler），固定步长，带累加器与渲染插值。**

```
DT        = 1/120 s            // 固定物理步长（RT-1 验证脚本同值）
MAX_STEPS = 5                  // 单帧最多追帧数，防死亡螺旋
```

```ts
// update(frameDt: number)
accumulator += Math.min(frameDt, MAX_STEPS * DT);   // 夹紧，防切后台回来爆炸
while (accumulator >= DT) { step(DT); accumulator -= DT; }
alpha = accumulator / DT;                            // 渲染插值系数
renderX = lerp(prevRx, rx, alpha);                   // 仅用于绘制，不回写状态
```

> **为什么半隐式欧拉而非 RK4**：能量误差在 81 s 窗口内可忽略（RT-1 全弹道扫描已用同积分器复现 7 条入轨弹道），而 RK4 每帧 4 次力评估对本作的实时预算是浪费。**不得改用 Phaser Arcade Physics**（附录 A 已判定其为游戏手感设计，不适合弹道精度）。

### 3.2 单步推演（`step(DT)`）

**顺序固定，不得调换**（质量 → 推力 → 加速度 → 速度 → 位置 → 质量）。

#### ① 重力加速度（矢量，指向质心）

```
ag = −MU / r²                        // 量纲 m/s²，符号表示指向质心
ax_g = ag · ux        ay_g = ag · uy
```

#### ② 推力

```
thrust = throttle · T_stage          // N；T_stage ∈ {T1, T2}
ax_T = (thrust / m) · cos(theta) · lx  +  (thrust / m) · sin(theta) · ux
ay_T = (thrust / m) · cos(theta) · ly  +  (thrust / m) · sin(theta) · uy
```

即推力沿箭体轴向 `n̂ = cos(θ)·l̂ + sin(θ)·û`。

> **真空推力补偿（MVP 不做）**：RT-1 标定中 `ISP_G0` 为常数，未建模海平面比冲损失。**S1 明确不引入高度相关的 Isp 曲线**——引入会改变 Δv 总量，击穿 RT-1 全部验收数据。若要引入，必须回 RT-1 重新标定。

#### ③ 大气阻力（由 S4 提供 `rho(h)` 与 `q`）

```
D  = 0.5 · rho(h) · v² · Cd(α) · A_REF            // N
Cd(α) = CD0 + CD_ALPHA · sin(α)²                  // α = theta − gamma
ax_D = −(D/m) · (vx/v)        ay_D = −(D/m) · (vy/v)
```
**仅当 `v > V_DRAG_EPS = 0.5 m/s` 时计算**（除零防护，见 §6.1）。

#### ④ 半隐式欧拉更新

```
vx += (ax_g + ax_T + ax_D) · DT
vy += (ay_g + ay_T + ay_D) · DT
rx += vx · DT                                     // 注意：用**已更新**的速度
ry += vy · DT
```

#### ⑤ 质量流与燃料

```
if (stage === 1 && fuel1 > 0) { mdot = throttle · MDOT1; fuel1 = max(0, fuel1 − mdot·DT); }
else if (stage === 2 && fuel2 > 0) { mdot = throttle · MDOT2; fuel2 = max(0, fuel2 − mdot·DT); }
else mdot = 0;
m −= mdot · DT;
```

#### ⑥ Δv 记账（供 S7「Δv 余量」读数）

**Δv 余量 = 剩余推进剂还可提供的 Δv（含两级各自的齐奥尔科夫斯基项）。**

引入三个常量：

| 常量 | 值 | 组成 |
|---|---|---|
| `M_AFTER_S1` | 23500 kg | 一级燃料烧尽**但尚未分离**：`S1_DRY + S2_DRY + S2_FUEL + M_PAYLOAD` |
| `M_S2_START` | 16500 kg | 分离后二级起始：`S2_DRY + S2_FUEL + M_PAYLOAD` |
| `M_DRY_FINAL` | 12000 kg | 二级燃料烧尽：`S2_DRY + M_PAYLOAD` |

```
dvRemain = (stage === 1)
  ? ISP_G0 · ln( m / M_AFTER_S1 )            // 一级剩余可用 Δv
  + ISP_G0 · ln( M_S2_START / M_DRY_FINAL )  // ＋ 二级满油 Δv（923 m/s，常量）
  : ISP_G0 · ln( m / M_DRY_FINAL )           // 二级剩余可用 Δv
```

**自洽性校核**：
- `t = 0`：`2900·ln(42400/23500) + 923 = 1711 + 923 = 2635 m/s` ✅ 等于 `DV_TOTAL`
- `t = 60⁻`（一级燃尽未分离）：`2900·ln(23500/23500) + 923 = 923 m/s`
- `t = 60⁺`（刚分离，m = 16500）：`2900·ln(16500/12000) = 923 m/s` ✅ **与分离前连续，跳变 0**
- `t = 81`（二级燃尽，m = 12000）：`0 m/s` ✅

> ⚠️ **常见的错误写法**：`dvRemain = ISP_G0 · ln(m / M_DRY_FINAL)`（把一级段也除以 12000）。
> 该式在 `t = 0` 给出 `2900·ln(42400/12000) = 3662 m/s`，比真实 Δv 2635 高出 1027 m/s——
> 因为它把"分离抛掉 7000 kg 一级干重"白送的 Δv 算成了推进剂提供的。**必须按上式分段计算。**

**边界**：`m > m_dry` 时公式有效；`m ≤ m_dry` 时返回 0（防 `ln` 负数 / 除零，见 §6.2）。

### 3.3 姿态动力学（核心技能载体）

**玩家控制的是目标俯仰角 `theta_cmd`，实际俯仰角 `theta` 通过一阶滞后 + 气动恢复力矩追踪。** 这一定义与 RT-1 验证脚本逐字一致，保证开环标定可直接闭环复用。

```
// 1) 玩家输入 → theta_cmd
theta_cmd += input_pitch · PITCH_CMD_RATE · DT         // input_pitch ∈ {−1, 0, +1}
theta_cmd  = clamp(theta_cmd, THETA_MIN, THETA_MAX)

// 2) 追踪律
dTheta = (theta_cmd − theta) / TAU_PITCH
       + K_AERO · q · (gamma − theta)                  // 气动恢复力矩（攻角归零趋势）

// 3) 角速度限幅
dTheta = clamp(dTheta, −PITCH_RATE_MAX, +PITCH_RATE_MAX)

theta += dTheta · DT
```

| 常量 | 值 | 量纲 | 说明 |
|---|---|---|---|
| `PITCH_CMD_RATE` | 0.262 | rad/s | **15 °/s**，玩家按 A/D 时目标角的移动速率 |
| `TAU_PITCH` | 0.30 | s | 一阶滞后时间常数（RT-1 值） |
| `K_AERO` | **1.5e-5** | rad/(Pa·s) | 气动恢复力矩系数 —— **RT-1 R5 标注为占位值，见 §9-C7** |
| `PITCH_RATE_MAX` | 0.209 | rad/s | **12 °/s** 角速度硬限幅（RT-1 值） |
| `THETA_MAX` | π/2 (1.5708) | rad | 90°，垂直向上（起飞姿态，也是上限） |
| `THETA_MIN` | −0.349 | rad | **−20°**，允许少量下压用于末段救场 |

> **设计说明（为什么玩家控制目标角而非角速度）**：
> 直接控制角速度（`dTheta = input`）会让箭体像"游标"一样漂移，玩家难以稳定停在某个角度，且**气动恢复力矩在低空会与玩家输入打架**，手感随高度漂移。控制目标角则把"玩家意图"与"箭体响应"分离：`TAU_PITCH` 提供稳定的手感，`K_AERO · q` 提供"稠密大气里箭体自己想摆正"的真实感，两者叠加不需要玩家额外学习。
> **这也让辅助线（S8）有明确语义**：辅助线画的是建议的 `theta_cmd(h)` 曲线，而不是"箭体该在哪"。

### 3.4 航迹角与攻角

```
gamma = (v > V_GAMMA_EPS) ? atan2(v·û, v·l̂) : π/2      // 低速时定义为垂直，防 atan2(0,0)
alpha = theta − gamma                                   // 攻角 rad
```

`V_GAMMA_EPS = 1.0 m/s`。

### 3.5 参考重力转弯程序（辅助线 / 自动驾驶对照用，**不是玩家默认控制**）

RT-1 基准弹道所用的程序，**MVP 内仅用于绘制辅助线（S8）与首局隐形引导，不得代替玩家输入**：

```
hStart = 150 m      (= 1% H)
hTurn  = 7500 m     (= 50% H)
p      = 0.8

theta_cmd_ref(h) = (h < hStart) ? π/2
                 : (π/2) · [ 1 − clamp( (h − hStart)/(hTurn − hStart), 0, 1 ) ]^p
```

| 事件 | 基准弹道实测时刻 |
|---|---|
| 到达 `hStart` 150 m | **T+4.71 s**（v = 65 m/s） |
| 到达 `hTurn` 7.5 km（倾倒完成，θ_cmd → 0） | **T+33.36 s**（v = 486 m/s，q = 7.05 kPa） |

### 3.6 节流

```
throttle ∈ [0.30, 1.00]，默认 1.00
throttle += input_throttle · THROTTLE_RATE · DT
```
- `THROTTLE_RATE = 1.0 /s`（0.7 s 走完全程）
- 下限 0.30 为**防熄火下限**，不是设计选择空间
- 节流**不改变 Isp**，只改变推力与质量流 ⇒ **总 Δv 恒定，只改变重力损失与燃时**

> **v0.3 §5.2「诚实的减法」落地**：上级（二级）段节流键位**保留可用，不锁死**，但 S1 不围绕它设计任何权衡，S7 也不在二级段高亮节流读数。满油门在二级段近乎恒优（收油门只会增加重力损失）。

## 4. 玩家输入映射（键鼠 · MVP 已锁）

| 动词 | 键位 | 输入量 | 映射公式 |
|---|---|---|---|
| **V1 点火 Ignite** | `Space` | — | 属 S2（松绑前不进入 S1 积分） |
| **V2 节流 Throttle** | `W` / `↑` 增<br>`S` / `↓` 减 | `input_throttle ∈ {−1,0,+1}` | `throttle += input_throttle · 1.0 · DT` |
| **V3 配平 Pitch** | `A` / `←` **抬头**（θ_cmd 增大）<br>`D` / `→` **低头**（θ_cmd 减小） | `input_pitch ∈ {−1,0,+1}` | `theta_cmd += input_pitch · 0.262 · DT` |
| **V4 分离 Stage** | `Shift`（左或右） | — | 属 S3 |
| **V5 中止 Abort** | `Esc` | — | 属 S6 |

### 4.1 输入处理细则

1. **同时按下取和**：`A` 与 `D` 同按 ⇒ `input_pitch = 0`（不报错、不抖动）。`W`/`S` 同理。
2. **键位可重映射**：美术 §9.4 已将「按键/输入重映射（桌面键盘）」列为 ✅ 必做。S1 只读 `input_pitch` / `input_throttle` 两个抽象量，**不直接读键码**，重映射表由 S8 管理。
3. **焦点丢失**：`window.blur` 时两个输入量强制归零并锁定 0.2 s，防止"切窗口回来火箭已经翻了"。
4. **首帧防抖**：松绑后前 0.5 s 内 `input_pitch` 强制为 0（起飞段不允许配平，物理上也无意义——v ≈ 0 时气动恢复力矩为 0，配平只会有害）。

### 4.2 输入 → 反馈的延迟预算

| 环节 | 预算 | 说明 |
|---|---|---|
| 按键 → `theta_cmd` 变化 | 同帧 | 直接改状态 |
| `theta_cmd` → `theta` 可见变化 | **≤ 0.30 s**（τ） | 一阶滞后，这是**刻意的质感**，不是延迟缺陷 |

| **总感知延迟** | **≤ 0.32 s** | 验收判据见 §8 |

## 6. 边缘情况（≥3 条，含数值退化与除零防护）

### 6.1 `v → 0` 时的除零（起飞瞬间 / 悬停）

`vx/v` 与 `vy/v` 在 `v = 0` 时无定义。

**防护**：阻力计算整体跳过（`v > V_DRAG_EPS = 0.5` 才计算）；`gamma` 在 `v < 1.0` 时**定义为 π/2**（垂直），而非 `atan2(0,0)`（后者在 IEEE-754 下返回 0，会让起飞瞬间的攻角从 0 跳到 π/2，进而让 `Cd(α)` 在首帧从 0.25 跳到 2.25，产生一个假的阻力尖峰）。

**验收**：T+0 前 3 帧内 `q` 必须恒为 0，`alpha` 必须恒为 0。

### 6.2 `ln(m/m_dry)` 的退化（燃料耗尽）

`m` 因浮点累积可能略小于 `m_dry`，使 `ln` 参数为负 ⇒ NaN，NaN 会沿 `dvRemain` 污染 HUD 第 5 读数（美术 §5.2「遥测数字永不闪白」直接被违反）。

**防护**：
```
m_eff  = max(m, m_dry + 1e-6)
dvRemain = (m_eff <= m_dry) ? 0 : ISP_G0 · ln(m_eff / m_dry)
```
且 `dvRemain` 输出前统一过 `Number.isFinite() ? x : 0`。

### 6.3 分离瞬间的质量跳变与速度连续性

分离使 `m` 瞬间 −7000 kg（42.5% → 取决于时刻）。若在同一帧内既改质量又用新质量算加速度，会产生一帧的加速度尖峰。

**防护**：分离事件在 `step()` 的**末尾**（位置更新之后、下一帧力计算之前）执行质量跳变；且分离当帧强制 `dt_effective = DT`（不追帧），避免累加器在一帧内跑多步放大该尖峰。

### 6.4 长时间挂起后的累加器爆炸

切后台 / 断点调试后 `frameDt` 可能达到数十秒。

**防护**：`accumulator += Math.min(frameDt, MAX_STEPS · DT)`（`MAX_STEPS = 5`，即单帧最多追 41.7 ms）。**丢弃**超出部分而非补算——补算会让火箭"瞬移"，比慢放更糟。

### 6.5 姿态数值发散（tumble）

若玩家在稠密大气中大角度配平，`K_AERO · q · (gamma − theta)` 项可能被限幅前的 `dTheta` 拉爆。

**防护**：`dTheta` 在**使用前**必须过 `clamp(±PITCH_RATE_MAX)`（RT-1 已如此）。此外增加：
```
若 |alpha| > ALPHA_STRUCT (0.35 rad ≈ 20°) 且 q > Q_STRUCT (30 kPa)
  ⇒ 触发 S6 的 DESTRUCT（结构解体）
```
> **MVP 声明**：本作**没有连续的结构应力模型**。上述判据是唯一的"结构"表达，且它只在极端情况下触发（基准弹道全程 `|alpha| < 0.05 rad`，永不触发）。**不引入应力累积条**——那会是第 6 个读数，违反认知过载红线。

### 6.6 高度下穿 0（坠毁 / 发射台回落）

`h ≤ 0` 且 `t > 1 s` ⇒ 触发 S6 的 IMPACT。松绑后 1 s 内的 `h ≤ 0` 忽略（火箭尚未完全离塔，几何上箭尾仍可能低于 `h = 0` 参考点）。

### 6.7 推力方向与速度反向（极端下压）

`THETA_MIN = −20°` 已限制下压幅度；但若二级段长时间下压，`vh` 仍为正而 `vr` 为负，`gamma` 为负，`alpha` 可能超过 90°。此时 `sin(α)²` 仍 ≤ 1，`Cd` 有界，**不会数值爆炸**；物理上表现为大阻力惩罚，是正确行为。

## 9. 与 RT-1 标定的冲突 / 待裁决项

> 详见各 GDD 末尾的汇总；此处仅列 **S1 直接相关**的三项。

### C3【中】垂直上升段与重力转弯段的边界与概念文档不符

概念 §5.2 的阶段表写「垂直上升 ~12 s → 重力转弯 T+12 → T+50」。但 RT-1 的 `hStart = 150 m (1% H)` 在**基准弹道 T+4.71 s** 即到达，倾倒程序从那时就启动；`hTurn = 7.5 km` 于 **T+33.36 s** 完成倾倒；一级燃尽/分离在 **T+60.00 s**（概念表写 ~47 s）。

**建议（待裁决）**：阶段表按实测重排为「垂直上升 0 → T+4.7 s / 重力转弯 T+4.7 → T+60 / 分离 T+60 / 上级收敛 T+60 → T+81」。这不改变 MVP 边界（5 动词不变），只修正文档与实测的错位。

### C7【中】`K_AERO = 1.5e-5` 为占位值（RT-1 R5）

**S1 不擅自标定。** 建议的标定方法（交 Phase 5 原型执行）：
1. 固定 `theta_cmd` 阶跃（90° → 45°），在 `h = 2 km`（q ≈ 16 kPa，接近 Max-Q）测量 `theta` 的实际收敛时间 `t_63`。
2. 目标手感：`t_63 ∈ [0.25, 0.40] s`——明显快于真空的 τ = 0.30 s，但不会快到"箭体自己抢方向盘"。
3. 由 `1/t_63 ≈ 1/TAU_PITCH + K_AERO · q` 反解 `K_AERO`。
4. 在 `q = 0`（真空）复测，`t_63` 必须回到 0.30 s ± 10%。

**在标定完成前，S1 保留 RT-1 的 1.5e-5 作为默认值，且该值必须写成具名常量而非字面量。**

### C8【低】`orbit-solver.ref.mjs` 的 `PLANET_C` 常量未同步 RT-1

`tests/c1/orbit-solver.ref.mjs` 第 22 行导出 `{mu: 1.08e12, R: 3.0e5}`，对应 `g0 = 12.0`，而 RT-1 已改判 `g0 = 8.0 / μ = 7.2e11`。**Phase 3 若直接复用该常量会引入错误标定。** 需程基岩更新为 `{mu: 7.2e11, R: 3.0e5}`。
