## 1. 系统职责与支柱挂靠

### 1.1 一句话职责

> **把"按下按钮"这 0.2 秒，拉成一段 10 秒可干预、可中断、可跳过的仪式。** S2 拥有从进入关卡到松绑之间的全部时序，是玩家接触本作的前 10 秒。

### 1.2 支柱闸门校验

| 支柱 | 本系统如何服务 | 判定 |
|---|---|---|
| **P1 · 过程即内容** | **本系统是 P1 的头号载体。** 倒计时的每一秒都是可感知、可干预的状态推进：预冷、增压、点火、松绑各自有独立的视觉/听觉/仪表反馈。且**任意时刻可按 Esc 中止**，序列回到待机 | ✅ 挂靠（主载体） |
| **P2 · 可解读的深度** | 每一段序列失败（预冷不足 / 增压未到位 / 点火失败）都有明确的仪表指示与原因文案，不是"发射失败"四个字 | ✅ 挂靠 |
| **P3 · 一次发射，六十秒** | **本系统是 P3 的最大风险源**。倒计时 10 s + 动力飞行 81 s = 91 s，已超 90 s 上限。见 §9-C2 的裁决建议 | ⚠️ **条件挂靠** |
| **P4 · 失败也好看** | 发射台上的失败（点火后未松绑 / 中止逃逸）属于 S6 的演出范围，S2 只负责产生正确的失败码与时序 | ✅ 挂靠 |

**闸门结论：S2 挂靠 P1（主）、P2、P4；对 P3 为条件挂靠，取决于 §9-C2 的裁决。**

### 1.3 明确不属于 S2

- 松绑之后的任何飞行逻辑 → S1/S3/S4/S5
- 失败演出的画面实现（爆炸粒子、碎片）→ S6
- 结算与重开 → S8（重开在 3 s 内回到本系统的 `IDLE`）

## 2. 核心状态与数据结构

### 2.1 状态机枚举

```ts
export const LaunchPhase = Object.freeze({
  IDLE:        'IDLE',        // 进入关卡，火箭在塔上待机，等待玩家按下发射
  COUNTDOWN:   'COUNTDOWN',   // T-10 → T-0，含预冷/增压/点火三个子阶段
  IGNITION:    'IGNITION',    // 引擎点着、达到满推力、尚未松绑（T-0 → T+0）
  RELEASE:     'RELEASE',     // 松绑瞬间（单帧事件）
  FLIGHT:      'FLIGHT',      // 已松绑，交给 S1 推进（S2 退居监听）
  ABORTED:     'ABORTED',     // 中止，移交 S6
  FAILED:      'FAILED',      // 发射台失败，移交 S6
});
```

### 2.2 状态数据结构

```ts
interface LaunchSeqState {
  phase:        LaunchPhase;
  t:            number;    // 局内时钟 s。IDLE 时为 null；COUNTDOWN 期间为负（−10 → 0）
  subPhase:     'CHILL' | 'PRESS' | 'IGNITE' | null;   // COUNTDOWN 内部的子阶段
  chill:        number;    // 预冷完成度 [0,1]
  press:        number;    // 增压完成度 [0,1]
  engineSpool:  number;    // 引擎推力爬升 [0,1]（IGNITION 期间 0→1，1.2 s）
  holdCount:    number;    // 本次倒计时被 Hold 的次数（MVP 内玩家不可主动 Hold，仅系统记录）
  skipped:      boolean;   // 是否由熟练玩家跳过
  abortArmed:   boolean;   // 中止是否已触发
}
```

### 2.3 时间常量

| 常量 | 值 | 量纲 | 说明 |
|---|---|---|---|
| `T_COUNT` | 10.0 | s | 完整倒计时时长（T-10 → T-0） |
| `T_CHILL_START` | −10.0 | s | 预冷开始（= 倒计时开始） |
| `T_CHILL_DUR` | 4.0 | s | 预冷持续（T-10 → T-6） |
| `T_PRESS_START` | −6.0 | s | 增压开始 |
| `T_PRESS_DUR` | 4.4 | s | 增压持续（T-6 → T-1.6） |
| `T_IGNITE` | −1.6 | s | 点火指令（引擎开始爬推） |
| `T_ZERO` | 0.0 | s | T-0：满推力判定点 |
| `T_HOLD_CHECK` | 0.0 | s | 满推力保持检测窗口 |
| `T_RELEASE` | +0.0 ~ +0.4 | s | 松绑延迟（`T_RELEASE_DELAY`） |
| `T_RELEASE_DELAY` | 0.40 | s | 满推力后到松绑的机械延迟 |
| `T_SPOOL` | 1.20 | s | 引擎推力爬升时间（T-1.6 → T-0.4 实际 1.2 s，与 T-0 判定对齐） |
| `T_SKIP_MIN` | 3.0 | s | **最短可跳过倒计时**：熟练玩家可压缩到 3 s |

> **松绑时刻定义**：`t = 0.00 s` 为 T-0（满推力达成）；松绑在 `t = +0.40 s`。**S1 的局内时钟 `t` 从松绑起算为 0**，即 S1 的 `t = 0` 对应 S2 的 `t = +0.40`。两者相差 0.40 s 的常量偏移，S7 显示的倒计时以 S2 时钟为准，飞行时间以 S1 时钟为准。

## 3. 规则与公式

### 3.1 状态转移图

```
                    ┌─────────────────────────────────────┐
                    │                                     │
   ┌────────┐  Space │                                     │
   │  IDLE  │───────►│           COUNTDOWN                │
   └────────┘        │  T-10 ──► T-6 ──► T-1.6 ──► T-0    │
        ▲            │   CHILL   PRESS    IGNITE    │     │
        │            └──────────────────────────────┼─────┘
        │                       ▲                   │
        │            Esc        │                   ▼  满推力 & chill≥0.98 & press≥0.98
        │                       │            ┌────────────┐
        │                       │            │  IGNITION  │  engineSpool 0→1，1.2s
        │                       │            └─────┬──────┘
        │                       │                  │ engineSpool ≥ 0.995
        │                       │                  ▼
        │                       │            ┌────────────┐
        └───────────────────────┴────────────│  RELEASE   │ 单帧：解锁 + 移交 S1
                    Esc                      └─────┬──────┘
                                                   │
                                                   ▼
                                             ┌──────────┐
                                             │  FLIGHT  │  S2 退居监听（仅响应 Esc→S6）
                                             └──────────┘

   任意状态 + Esc  ──────────────────────────►  ABORTED / FAILED（交 S6）
```

### 3.2 子阶段推进公式

#### ① 预冷 CHILL（T-10 → T-6，4.0 s）

```
chill = clamp( (t − T_CHILL_START) / T_CHILL_DUR, 0, 1 )
```
- 线性推进，**无随机性**（MVP 不做设备故障随机事件——那属于核心体验层的天气/风切变）。
- 完成判据：`chill ≥ 0.98`。

#### ② 增压 PRESS（T-6 → T-1.6，4.4 s）

```
press = clamp( (t − T_PRESS_START) / T_PRESS_DUR, 0, 1 )
```
- 完成判据：`press ≥ 0.98`。
- **增压必须在预冷完成后才开始累计**（若 `chill < 0.98` 则 `press` 冻结）——这是 P2 的归因链条：增压慢，玩家能回头看到是预冷没完成。

#### ③ 点火 IGNITE（T-1.6 → T-0，1.6 s）

```
engineSpool = clamp( (t − T_IGNITE) / T_SPOOL, 0, 1 )
```
- `T_SPOOL = 1.2 s`，故 `engineSpool` 在 `t = −0.4 s` 达到 1.0，T-0 时已满推并稳定 0.4 s。
- 这 0.4 s 的"满推力悬停"是**仪式感的物理来源**：火箭在塔上憋着劲，束缚螺栓还锁着。
- **引擎推力**在此阶段已作用到 S1，但 S1 位置被约束（见 §3.4）。

#### ④ T-0 判定与松绑

```
IF t ≥ T_ZERO AND chill ≥ 0.98 AND press ≥ 0.98 AND engineSpool ≥ 0.995
  THEN 进入 RELEASE 倒计时（T_RELEASE_DELAY = 0.40 s）
ELSE IF t ≥ T_ZERO AND 任一条件不满足
  THEN 触发 HOLD（见 §6.3）
```

松绑瞬间（单帧）：
1. `phase = RELEASE`
2. 解除 S1 的位置约束
3. S1 时钟 `t` 置 0
4. 通知 S3（一级燃料开始消耗）、S4（动压开始累计）、S5（开始解算）
5. 下一帧 `phase = FLIGHT`

### 3.3 跳过倒计时（熟练玩家）

> **动机（P3）**：倒计时是 P1 的载体，但对第 20 次发射的玩家，它是 10 秒的纯等待。概念 §5.2 已写「熟练玩家可加速 / 跳过」，此处将其确定化。

**解锁条件**（由 S8 判定并持久化）：
```
skippable = (累计成功入轨次数 ≥ 3) OR (累计发射次数 ≥ 10)
```

**跳过行为**：
- 按住 `Space` 时，`T_COUNT` 从 10.0 s 压缩至 `T_SKIP_MIN = 3.0 s`；
- 三个子阶段**按比例压缩**，不裁剪任何一段：
  ```
  scale   = T_SKIP_MIN / T_COUNT = 0.30
  CHILL:  4.0 → 1.20 s   (T-3.0 → T-1.80)
  PRESS:  4.4 → 1.32 s   (T-1.80 → T-0.48)
  IGNITE: 1.6 → 0.48 s   (T-0.48 → T-0)
  ```
- **保留全部视觉与听觉事件**，只压缩时长（倒计时数字仍逐秒跳 3 → 2 → 1）。
- 松绑延迟 `T_RELEASE_DELAY = 0.40 s` **不压缩**（这是物理，不是仪式）。

> **红线校验（P1）**：跳过不等于"一键发射"。玩家**仍然必须按住 Space 完成充能**（美术 §5.3 Charging 态），仍能看到三个子阶段的仪表推进。**跳过的是等待，不是过程。**

### 3.4 松绑前 S1 的行为约束

松绑前（`phase ∈ {IDLE, COUNTDOWN, IGNITION}`），S1 的积分器：
- **不推进位置**（`rx, ry` 锁定为 `(0, R)`）
- **不推进速度**（`vx, vy` 锁定为 `(0, 0)`）
- **不消耗燃料**
- 但**推进 `theta` / `theta_cmd`**（允许玩家在塔上预置配平？——**MVP 内禁止**，见下）

> **MVP 决策**：松绑前 `input_pitch` 与 `input_throttle` **强制为 0**。理由：塔上预置配平会让"松绑瞬间箭体已在倾斜"，既不合物理（塔架约束），也给玩家一个无反馈的操作窗口，违反 P1「每一秒都有可感知反馈」。

### 3.5 中止（Esc）的时序

| 触发时刻 | 行为 | 失败码 |
|---|---|---|
| `IDLE` / `COUNTDOWN`（T-10 → T-1.6） | 序列直接回 `IDLE`，**无演出**，0.3 s 内可重按 Space 重来 | 无（不算失败） |
| `IGNITION`（T-1.6 → T-0） | 引擎紧急关机，推力 0.3 s 内归零，回 `IDLE` | 无 |
| `RELEASE` / `FLIGHT` | 移交 **S6** 的逃逸塔演出 | `ABORT` |

> **设计说明**：点火前的中止**不计入失败统计、不播放失败演出**。理由：玩家只是"我改主意了"，不是"我搞砸了"。把它算成失败会惩罚探索，且与 P4「失败也好看」无关——它没有值得看的内容。

## 4. 玩家输入映射（键鼠）

| 输入 | 状态 | 行为 |
|---|---|---|
| **`Space` 按下并保持** | `IDLE` | 进入 `COUNTDOWN`（若已解锁跳过，则同时启动压缩倒计时） |
| **`Space` 松开** | `COUNTDOWN` | **中止倒计时**，序列回 `IDLE`，充能条回落（美术 §5.3 Charging：「松手即中止并回落」） |
| **`Space` 松开** | `IGNITION` / `FLIGHT` | 无效果（此时 Space 不再是发射键） |
| **`Esc`** | `IDLE`/`COUNTDOWN`/`IGNITION` | 回 `IDLE`（§3.5） |
| **`Esc`** | `RELEASE`/`FLIGHT` | 触发 S6 中止逃逸（V5） |
| **`R`** | `ABORTED`/`FAILED` | 重开（S8，3 s 硬上限） |

### 4.1 输入细则

1. **`Space` 必须"按住"而非"点按"**：这是美术 §5.3 Charging 态的交互前提——琥珀色从按钮底部向上充能，松手即回落。**点按 = 立即松开 = 永远发不出去**，这是刻意的：它让"发射"这个动作有重量。
2. **充能完成 ≠ 立即发射**：`Space` 按住后充能条走完（0.6 s）才真正进入 `COUNTDOWN`；之后松开 Space **不再中止**（已进入不可逆的推进剂加注阶段）。
   - **例外**：`T > −1.6 s`（点火后）松开 Space 无效，必须走 `Esc`。
3. **`Esc` 与 `Space` 同时按**：`Esc` 优先（中止语义强于发射）。
4. **重映射**：`Space` / `Esc` / `R` 三个键均可重映射（美术 §9.4），S2 只读抽象动作 `launchHeld` / `abortPressed` / `restartPressed`。

## 6. 边缘情况（≥3 条，含数值退化与除零防护）

### 6.1 倒计时时钟的浮点累积

`chill / press / engineSpool` 均由 `(t − T_start)/T_dur` 计算。若 `t` 由逐帧 `+= DT` 累积，长时间运行会漂移，导致 `t = 0` 时 `engineSpool` 不等于 1。

**防护**：三个进度量一律用**绝对时间差**计算（如上式），不做 `+= `增量累加。且 `t` 在进入 `COUNTDOWN` 时记录 `t0 = performance.now()`，每帧 `t = T_COUNT_remaining − (now − t0)/1000`，不依赖帧数。

**验收**：倒计时结束时刻与真实经过时间的偏差 < 50 ms。

### 6.2 `T_dur = 0` 的除零（跳过功能启用时）

若某子阶段时长被压缩为 0（配置错误或未来的"极速模式"），`(t − T_start)/0 = Infinity`。

**防护**：
```
progress = (T_dur <= 1e-6) ? 1 : clamp((t − T_start) / T_dur, 0, 1)
```

### 6.3 T-0 时条件不满足 → HOLD

若 `chill < 0.98` 或 `press < 0.98` 或 `engineSpool < 0.995`（浮点边界导致），T-0 不放行。

**防护（两层）**：
1. **比较用宽松阈值**：`≥ 0.98` 而非 `≥ 1.0`，吸收浮点误差。
2. **HOLD 行为**：时钟冻结在 `t = 0`，任务带显示 `HOLD` 琥珀闪烁（≤ 2 Hz，呼吸式，符合 §9.3 光敏规格），进度量继续补齐；补齐后自动放行。若 3 s 内仍未补齐 ⇒ 判定为序列故障，交 S6 `FAILED`（失败码 `SEQUENCE_FAULT`）。

> **MVP 声明**：基准流程下 HOLD **永不触发**（三个进度量都是确定性线性推进）。它是纯防御性分支，但必须存在——否则浮点边界会造出一个"卡在 T-0 不动"的死锁，那是最难排查的一类 bug。

### 6.4 松开 Space 的时序竞态

玩家在 `t = −1.599 s`（点火前一帧）松开 Space：是中止，还是已进入不可逆段？

**防护**：状态机转移只在 `update()` 开头判定一次，不响应同帧内的多次输入。且点火判定用 `t ≥ T_IGNITE`（`−1.6`），松手判定用 `phase === COUNTDOWN`——**以 phase 为准，不以 t 为准**。同一帧内 `Esc` 优先于一切。

### 6.5 重开时的状态残留

失败后 3 s 内重开，若 `engineSpool`、`chill` 等未清零，第二次发射会"秒点火"。

**防护**：`resetToIdle()` 必须显式清零 `LaunchSeqState` 的**全部**可变字段，且 S1/S3/S4/S5 各自持有独立的 `reset()`。**验收**：连续重开 20 次，第 20 次的 T-0 时刻与前 19 次的偏差 < 50 ms。

### 6.6 光敏安全：HOLD 闪烁

HOLD 的琥珀闪烁必须满足美术 §9.3：
- 频率 **≤ 2 Hz**
- **禁止硬 on/off**，用正弦呼吸式明暗渐变
- 大面积（> 屏 25%）红色闪烁 **禁止**（HOLD 用琥珀 `A1`，非危险红 `#FF4B3E`）
- 「减少动效」模式下改为**静态高亮**

### 7.3 时序铁律

```
S2.update() 必须先于 S1.step()
```
理由：松绑是单帧事件，若 S1 先跑，松绑当帧的推力会被吃掉一帧，导致起飞 TWR 与 RT-1 的 2.693 产生 1/120 s 的偏差——虽然微小，但会让 A1-1 的复现断言出现非确定性。

## 9. 与 RT-1 / 概念文档的冲突（待裁决）

### C2【阻塞级】倒计时 10 s + 动力飞行 81 s = 91 s，**超出 P3 的 90 s 上限**

RT-1 实测动力飞行 **81.0 s**（一级 60 s + 二级 21 s，满油门）。概念 §5.2 的阶段表总计 70 s（T-10 10 + 垂直 12 + 合并窗口 38 + 入轨确认 10），与实测错位。

**三种解法（待主理人裁决，我倾向 B）**：

| 方案 | 内容 | 代价 |
|---|---|---|
| **A** | P3 的 60–90 s **重新定义为「T-0 → 入轨判定」**，倒计时与结算计为局外时间。实测 81.0 s ✅ 达标 | 概念 §5.2「60 s = 跳过倒计时」的表述需改写；但**零实现成本、零物理改动** |
| **B** | 同 A，且**同时**把 60/81/90 三个数重新解释为：<br>• **60 s** = 二级提前关机（近地点达标即停，最多省下全部 21 s 二级燃时）<br>• **81 s** = 基准（两级烧满）<br>• **90 s** = 一级节流降档导致燃时拉长（代价是重力损失上升、Δv 余量下降） | 需要 S5 支持"提前关机也算入轨"，但那是 S5 本就要做的；**时长因此成为技能信号，与概念 §5.2 的设计意图完全一致** |
| **C** | 压缩火箭燃时（一级 60 → 50 s，二级 21 → 18 s） | **否决**：需重跑 RT-1 全部标定，且 T* = 61 s 已是最优动力时长，压缩会推高 Δv 需求 |

**我的建议：B。** 它把 RT-1 的硬约束（81 s）变成了 P3 的设计资产（时长即技能信号），且不需要动任何一个物理参数。

### C3【中】松绑前的"垂直上升 12 s"不存在

概念 §5.2 的「垂直上升 ~12 s」在 RT-1 标定下不成立：`hStart = 150 m` 在 **T+4.71 s** 即到达，倾倒程序从那时启动。垂直段实际只有 4.7 s。详见 S1 §9-C3。S2 不受影响（S2 的时序在松绑即结束），但**任务带的阶段名序列需同步修正**。
