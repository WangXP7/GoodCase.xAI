## 1. 系统职责与支柱挂靠

### 1.1 一句话职责

> **把"扔掉死重"这个赌博，做成一次有明确收益、有明确代价、有 0.35 秒顿帧的强反馈节拍。**

### 1.2 支柱闸门校验

| 支柱 | 本系统如何服务 | 判定 |
|---|---|---|
| **P1 · 过程即内容** | 分离是玩家**手动触发**的动词（V4），不是自动事件。且它在概念 v0.3 中被明确降级为「段内节拍」——**分离前后玩家的键位（A/D 配平）与视线目标（轨道预测标记条）保持不变**，操作连续性不被切断 | ✅ 挂靠 |
| **P2 · 可解读的深度** | 分离的收益（质量 −7000 kg ⇒ 加速度跃升）与代价（过早分离 ⇒ 一级燃料未烧完，Δv 白扔）都是**可直接读出**的量：Δv 余量读数在分离瞬间会**跳变下降**，这是玩家学习"我分早了"的唯一信标 | ✅ 挂靠 |
| **P3 · 一次发射，六十秒** | 分离时机直接影响总时长。早分离缩短一级段、拉长二级段（净效果接近零），但**过早分离会让二级带不动** ⇒ 任务失败。**分离是 60–90 s 窗口内的主要风险节点之一** | ✅ 挂靠 |
| **P4 · 失败也好看** | 分离失败（在动压过高时分离 ⇒ 箭体碰撞 / 姿态失控）有专属演出 | ✅ 挂靠 |

**闸门结论：S3 挂靠全部四根支柱。**

### 1.3 明确不属于 S3

- 分离后的下级箭体坠落物理（翻滚、下落、坠地）→ **视觉表现由美术 §6.4 定义，物理上 MVP 内简化为"无碰撞的运动学抛体"**，不参与任何判定
- 整流罩抛离（美术 §6.5）→ **不进 MVP**（概念 §4.3，抛罩属核心体验层）
- 三级火箭 → **不进 MVP**（单构型两级）

## 2. 核心状态与数据结构

### 2.1 状态枚举

```ts
export const StageState = Object.freeze({
  ARMED_1:     'ARMED_1',      // 一级在工作，分离可触发
  SEPARATING:  'SEPARATING',   // 分离动画/顿帧中（0.35 s hit-stop），物理暂停
  ARMED_2:     'ARMED_2',      // 二级在工作（MVP 内无第二次分离）
  BURNT_2:     'BURNT_2',      // 二级燃料耗尽
});
```

### 2.2 数据结构

```ts
interface StagingState {
  state:          StageState;
  tSep:           number;      // 分离发生时的 S1 局内时刻 s（未发生为 null）
  hSep:           number;      // 分离高度 m
  vSep:           number;      // 分离速度 m/s
  qSep:           number;      // 分离瞬间动压 Pa（失败归因用）
  fuel1AtSep:     number;      // 分离时一级剩余燃料 kg（= 浪费的 Δv 的直接证据）
  dvWasted:       number;      // 分离时浪费的 Δv m/s = ISP_G0 · ln(m_sep / (m_sep − fuel1AtSep))
  sepValid:       boolean;     // 分离是否满足安全条件（用于 S6 归因）
  hitStopRemain:  number;      // 顿帧剩余时间 s
  debris:         DebrisState; // 下级箭体的纯视觉状态
}

interface DebrisState {
  active:    boolean;
  rx, ry:    number;   // m
  vx, vy:    number;   // m/s
  angle:     number;   // rad
  angVel:    number;   // rad/s
  aliveFor:  number;   // s（超过 DESPAWN_T 后移除）
}
```

### 2.3 常量

| 常量 | 值 | 量纲 | 说明 |
|---|---|---|---|
| `S1_DRY` | 7000 | kg | 分离时抛掉的质量 |
| `HITSTOP` | 0.35 | s | 顿帧时长（美术 §6.4） |
| `Q_SEP_SAFE` | 5000 | Pa | **安全分离动压上限**（5 kPa） |
| `SEP_DELAY` | 0.15 | s | 上级发动机预热闪烁时长（美术 §6.4） |
| `DEBRIS_SPIN` | 0.785 | rad/s | 下级翻滚角速度（45 °/s，美术 §6.4） |
| `DEBRIS_COAST` | 0.30 | s | 下级失去动力后继续上升的时长（美术 §6.4） |
| `DESPAWN_T` | 6.0 | s | 残骸对象回收时限 |
| `T_SEP_BASELINE` | 60.00 | s | 基准弹道的分离时刻（一级燃尽） |

## 3. 规则与公式

### 3.1 分离的触发条件

**MVP 内分离只有一个触发源：玩家按 `Shift`。** 系统**不自动分离**（否则 P1 违规——玩家会问"刚才发生了什么"）。

```
IF (state === ARMED_1) AND (input.stage) THEN
    q = S4.getQ()
    IF q <= Q_SEP_SAFE THEN
        sepValid = true
        → 执行分离（§3.2）
    ELSE
        sepValid = false
        → 执行分离，但立即向 S6 抛出 SEP_HIGHQ 失败码（§3.4）
```

> **设计说明（为什么允许在高动压下分离）**：
> 不允许 = 剥夺玩家犯错的权利 = 削弱自主性（概念 §5.1 自主保障 1）。
> 允许但惩罚 = 玩家能"作死"，且死因可归因（"你在 16 kPa 时分离，箭体撞上了自己的一级"）。**这更符合 P2 与 P4。**

### 3.2 分离执行序列（总时长 0.50 s）

| 时刻 | 事件 | 归属 |
|---|---|---|
| **t = 0.000** | 触发分离。`state = SEPARATING`。**顿帧开始**（`hitStopRemain = 0.35`） | S3 |
| t = 0.000 | 分离面出现 2px 白色闪光线，横向贯穿箭体，持续 **3 帧** | 美术 §6.4 |
| t = 0.000 | 震屏 **8px / 0.25 s** | 美术 §6.4 |
| t = 0.000 | 分离碎片 **12 个**小矩形硬边（带独立旋转），**不用柔和粒子** | 美术 §6.4 |
| t = 0.000 | 记录 `tSep / hSep / vSep / qSep / fuel1AtSep / dvWasted` | S3 → S6 |
| **t = 0.000（顿帧内）** | **S1 的物理积分暂停**（顿帧属于时序层，与震屏正交，不占震屏名额） | S1 |
| t = 0.000 | 质量跳变：`m −= (S1_DRY + fuel1AtSep)`；`stage = 2`；`fuel1` 冻结（剩余一级燃料随残骸一起抛弃） | S1 |
| t = 0.000 | 创建 `DebrisState`：继承分离瞬间的 `r, v`，`angVel = DEBRIS_SPIN` | S3 |
| **t = 0.150** | 上级发动机**预热闪烁**（3 次明暗，2 Hz，持续 `SEP_DELAY = 0.15 s`） | 美术 §6.4 |
| **t = 0.350** | 顿帧结束，S1 恢复积分 | S1 |
| **t = 0.350** | 上级发动机点火，推力在 0.10 s 内爬升至 `T2` | S1 |
| t = 0.350+0.300 | 下级残骸失去动力后继续上升 0.3 s，然后开始翻滚下落 | 美术 §6.4 |

> **顿帧期间"物理暂停"的严格定义**：S1 的 `step(DT)` 不被调用，但**渲染插值、相机、粒子、UI 动画继续**。这是标准 hit-stop 实现，玩家感知为"时间停了但画面还在动"。

### 3.3 质量跳变与 Δv 记账（P2 的核心）

分离瞬间，**被抛弃的是「一级干重 + 剩余一级燃料」两者之和**：

```
m_before = m
m_after  = m_before − S1_DRY − fuel1AtSep
         = S2_DRY + S2_FUEL + M_PAYLOAD
         = 16500 kg        ← 与分离时刻无关，恒为常量
```

> **这是一个必须记住的恒等式**：无论何时分离，分离后的质量**恒为 16500 kg**。
> 因为"剩下的东西"永远是二级 + 载荷，与一级还剩多少油无关。

**Δv 余量的跳变**（这是玩家读懂"我分早了"的唯一信标）。沿用 S1 §3.2-⑥ 的分段公式：

```
分离前（一级燃烧中）：dvRemain_1 = 2900·ln(m_before / 23500) + 923
分离后（二级燃烧中）：dvRemain_2 = 2900·ln(16500 / 12000)    = 923       ← 常量
```

**关键性质（必须验证）**：
- 若 `fuel1 == 0`（正好燃尽分离）⇒ `dvRemain` **连续，跳变 0**。
- 若 `fuel1 > 0`（提前分离）⇒ `dvRemain` **下降**，下降量恰为：
  ```
  dvWasted = 2900 · ln( m_before / 23500 )      // = 2900·ln(m/(m − fuel1AtSep))
  ```

**数值示例（RT-1 标定）**：

| 分离时刻 | 一级余油 | 分离前 m | 分离后 m | dvRemain 前 | dvRemain 后 | **跳变 = −dvWasted** |
|---|---|---|---|---|---|---|
| **T+60.00（基准）** | 0 kg | 23500 | 16500 | 923 m/s | 923 m/s | **0**（连续 ✅） |
| T+55.00（早 5 s） | 1575 kg | 25075 | 16500 | 1111 m/s | 923 m/s | **−188 m/s** ❌ |
| T+50.00（早 10 s） | 3150 kg | 26650 | 16500 | 1288 m/s | 923 m/s | **−365 m/s** ❌ |
| T+40.00（早 20 s） | 6300 kg | 29800 | 16500 | 1659 m/s | 923 m/s | **−689 m/s** ❌ |

> 以上数值已由 `tests/c1/dv-accounting-check.mjs` 逐项验证。

> **读法**：在 T+40 → T+60 区间，每提前 1 秒分离约损失 **35 m/s** Δv（近似线性）。
> 基准弹道的 Δv 损失预算是 **548 m/s**（RT-1）。解 `2900·ln(m/23500) = 548` 得 `m = 28 388 kg`，
> 即 `fuel1 已烧 14 012 kg` ⇒ **T+44.5 s**。也就是说 **T+44.5 s 之前分离，Δv 赤字就吃掉全部损失预算，入轨在数学上不可能**。
>
> 与 §3.4 的「安全分离动压门槛 ⇒ 最早 T+40 s」取交集，**真正的有效决策窗口是 T+44.5 → T+60，约 15.5 秒宽**（此处 Δv 约束是绑定约束，动压约束不绑定）。
> 窗口够宽（不是唯一解），也够窄（早分离有真实且可读的代价）。

**S7 的处理要求**：分离瞬间，Δv 余量读数**不得**只做数字跳变，必须同时显示一行赤字提示（持续 1.2 s）：
```
−188 m/s  抛弃 1,575 kg 未燃燃料
```
这才是玩家真正损失的量。**这是 S7 的必做项，不是可选项。**

### 3.4 高动压分离的后果

若 `qSep > Q_SEP_SAFE (5 kPa)`：
1. 分离照常执行（保留玩家自主性）
2. 立即向 S6 抛出失败码 `SEP_HIGHQ`
3. S6 播放**级间碰撞**演出：上级箭体被下级追尾，姿态 `theta` 加一个随机扰动 `±0.35 rad`，随后大概率进入 TUMBLE → DESTRUCT

**数值背景（RT-1 实测）**：

| 时刻 | 动压 | 能否安全分离 |
|---|---|---|
| T+19.16（Max-Q） | 16.47 kPa | ❌ 高危 |
| T+33.36（hTurn） | 7.05 kPa | ❌ 仍超限 |
| T+47.61（大气顶） | 0.00 kPa | ✅ 安全 |
| **T+60.00（基准分离）** | 0.00 kPa | ✅ 安全 |

> **这意味着：`Q_SEP_SAFE = 5 kPa` 对应的最早安全分离时刻约为 `T+40 s`**（动压降到 5 kPa 以下）。结合 §3.3 的 Δv 损失表，**分离时机的有效决策窗口约为 T+40 → T+60，共 20 秒**。这个窗口宽度合理——够宽（不是唯一解），也够窄（早分离有真实代价）。

### 3.5 下级残骸（纯视觉，无判定）

```
// 0 → 0.30 s：无动力上升，保持分离瞬间速度，受重力
vx += ax_g · dt;  vy += ay_g · dt;  rx += vx·dt;  ry += vy·dt;
// 0.30 s 后：加入翻滚
angle += DEBRIS_SPIN · dt;
// 无阻力（简化：残骸在 T+60 分离时已在大气顶之上 2.98 km，大气阻力为 0）
// 落到 h <= 0 或 aliveFor > DESPAWN_T ⇒ 移除
```

> **简化声明（P4 不受损）**：残骸**不参与碰撞检测、不影响任何其他系统、不产生失败**。它的唯一职责是**视觉上的"死重被扔掉了"**（美术 §6.4：火焰 0.2 s 内 alpha→0 → 继续上升 0.3 s → 翻转下落，旋转 45°/s + 轻微 tumble）。

## 4. 玩家输入映射（键鼠）

| 动词 | 键位 | 行为 |
|---|---|---|
| **V4 分离 Stage** | `Shift`（左或右，任一） | 触发分离（仅 `ARMED_1` 状态下有效） |

### 4.1 输入细则

1. **去抖**：`Shift` 为**边沿触发**（按下沿），长按不重复触发。需 200 ms 的重复抑制窗口，防止玩家紧张时连按导致"分离两次"（MVP 内第二次分离无定义）。
2. **无效状态下的按键反馈**：
   - `ARMED_2` / `BURNT_2` 状态下按 Shift ⇒ 控制台分离按钮进入 **Disabled 态闪一下**（美术 §5.3：45° 斜纹叠加 + 描边转 `P2`），**不播放任何音效**。
   - `SEPARATING` 期间按 Shift ⇒ 完全忽略。
3. **可重映射**：同其他动词（美术 §9.4）。
4. **键鼠唯一性**：MVP 内**不提供鼠标点击分离**。理由：分离是飞行中的高频紧张操作，鼠标要从画面移到底部按钮会丢失对轨道标记条的视线追踪（违反 A3 遥测可读性优先）。**但控制台上仍绘制分离按钮**（美术 §5.1.2），作为"可发现性"提示，标注快捷键 `SHIFT`。

> ⚠️ **加速度跃升的设计问题（诚实记录）**：
> 基准弹道下分离**前**的加速度（31.6 m/s²）**高于**分离**后**（30.4 m/s²）——因为一级推力 913.5 kN 远大于二级 621.4 kN，抵消了减重收益（23500 → 16500 kg）。
>
> **这与概念 §4.1 写的"分离 = 加速度跃升"直觉相反。**
>
> **处理方案（S7 必做）**：分离瞬间的加速度指针**不做"跃升"演出**，改为**换挡演出**——指针先快速回落（推力下降），再缓慢回升（质量持续下降 ⇒ 加速度持续上升）。这更真实，且给玩家一个"现在进入耐力段"的正确信号。
>
> **若主理人希望保留"跃升"手感**，唯一办法是上调 `T2`（增大二级推力）或下调 `T1`——**两者都要重跑 RT-1 标定**。我建议 **接受真实曲线**，不做参数改动。见 §9-C9。

## 6. 边缘情况（≥3 条，含数值退化与除零防护）

### 6.1 `dvWasted` 的对数退化

`dvWasted = ISP_G0 · ln(m_before / (m_before − fuel1AtSep))`。若 `fuel1AtSep == 0`（正好燃尽分离），则 `ln(1) = 0` ✅ 无退化。
但若浮点误差使 `m_before − fuel1AtSep` 略小于 `M_DRY_PATH_1`，则 `ln` 参数仍 > 1，安全。
**真正的退化点**：若 `fuel1AtSep` 因浮点变为极小负数（如 `−1e-12`），则 `m_before/(m_before + 1e-12) < 1` ⇒ `ln < 0` ⇒ **负的"浪费 Δv"**。

**防护**：
```
fuel1AtSep = Math.max(0, fuel1AtSep);
dvWasted   = (fuel1AtSep <= 1e-6) ? 0 : ISP_G0 * Math.log(m_before / (m_before - fuel1AtSep));
dvWasted   = Number.isFinite(dvWasted) ? Math.max(0, dvWasted) : 0;
```

### 6.2 顿帧期间的重复触发

顿帧的 0.35 s 内 S1 不推进，若玩家在这期间再按 `Shift`：
- `state` 已为 `SEPARATING`，输入被忽略 ✅（§4.1-1）
- 但**累加器会累积这 0.35 s 的真实时间**，顿帧结束后若不做处理，S1 会一次性补跑 21 步 ⇒ 火箭瞬移。

**防护**：顿帧期间**不向 S1 的累加器喂时间**（`accumulator` 冻结）。顿帧结束时 `accumulator = 0`。

### 6.3 在 `h < 0` 或极低速时分离

理论上玩家可在起飞后 1 s 内按 Shift（此时 `h ≈ 0.1 km`，`q` 很小）。按 §3.2 与 §3.3，剩余一级燃料随残骸一起抛弃：

```
fuel1AtSep = 18900 − 315·1 = 18585 kg
m_before   = 42400 − 315   = 42085 kg
m_after    = 42085 − 7000 − 18585 = 16500 kg        ← 恒等式成立
dvWasted   = 2900 · ln(42085 / 23500) = 1690 m/s
```

分离后 TWR = `621429 / (16500 · 8.0)` = **4.71** —— 火箭会飞得很猛，但 **Δv 只剩 923 m/s ≪ 入轨所需**，必然以 `INSUFFICIENT_DV` 失败。

**这是正确行为，不需要特殊防护。** 但 S6 必须能给出明确归因："你在 T+1.0 s 分离，扔掉了 18,585 kg 未燃烧的一级燃料（−1,690 m/s Δv）。"

**验收**：S6 的归因文案必须包含 `燃料质量` 与 `浪费 Δv` 两个数字。

> ⚠️ **注意**：若实现时只扣 `S1_DRY`（7000 kg）而**不扣 `fuel1AtSep`**，则 `m_after = 35085 kg`，
> 火箭会带着 18.6 t 幽灵燃料继续飞，**Δv 余量读数会严重虚高**（`2900·ln(35085/12000) = 3117 m/s`，超过总 Δv 2635）。
> 见 §9-C16——参考实现 `tests/c1/final.mjs` 正是只扣 `s1.dry`。

### 6.4 分离后 `fuel1` 的残留读取

分离后 `fuel1` 应保持分离瞬间的值（用于归因），**不得清零、不得归零后再被 S1 消耗**。

**防护**：S1 的推进逻辑为 `if (stage === 1 && fuel1 > 0)`，分离后 `stage = 2`，该分支永不进入。`fuel1` 成为只读的归因数据。

### 6.5 残骸对象的生命周期泄漏

`DESPAWN_T = 6.0 s` 后移除。若残骸在真空中（无阻力）永远不落地，6 s 后必须强制回收，否则每局泄漏一个对象。

**防护**：`aliveFor > DESPAWN_T` ⇒ 回收，**同时** `h <= 0` ⇒ 回收。两个条件取先满足者。重开时 `reset()` 无条件清空 `debris`。

### 6.6 顿帧与「减少动效」模式

美术 §9.3：「减少动效模式：震屏幅度 ×0、粒子 ×0.3、闪烁改静态高亮」。**顿帧未被提及。**

**决策**：顿帧在「减少动效」模式下**保留**（它不是闪烁，不涉光敏风险），但震屏 8px 归零、碎片粒子 ×0.3（12 → 4）。

## 9. 冲突与待裁决项

### C16【高 · 已判定为实现 bug，需程基岩修】参考实现分离时未扣除一级剩余燃料

`tests/c1/final.mjs` 第 59 行：

```js
if (stage === 1 && fuel1 <= 0 && !staged) { m -= rk.s1.dry; stage = 2; staged = true; }
```

只扣了 `s1.dry`（7000 kg），**没有扣 `fuel1`**。在参考实现里这不会出错——因为分离只在 `fuel1 <= 0` 时触发，此时 `fuel1 === 0`，两式等价。

**但 S3 允许玩家手动提前分离**（`fuel1 > 0`），此时该行会产生 **18585 kg 级的幽灵质量**：

| 项 | 正确（本 GDD） | 参考实现 | 偏差 |
|---|---|---|---|
| T+1 s 分离后质量 | 16500 kg | 35085 kg | **+113%** |
| T+1 s 分离后 Δv 余量 | 923 m/s | `2900·ln(35085/12000)` = 3117 m/s | **+219%（且超过总 Δv 2635，物理上不可能）** |

**影响**：Δv 余量是第 5 读数的核心数值，虚高会直接击穿 P2。

**修复**：`m -= (rk.s1.dry + fuel1); fuel1 = 0;`（并保留 `fuel1AtSep` 副本供 S6 归因）。
**验收**：A3-1b（分离后质量恒等式）与 A3-3b（Δv 余量不虚高）两条断言。

### C9【中】分离不产生"加速度跃升"，与概念 §4.1 的反馈描述相反

见 §5.2 的数值分析：基准弹道下分离前 `a ≈ 30.9 m/s²`，分离后 `a ≈ 29.7 m/s²`，**加速度下降**。

概念 §4.1 把 V4 分离的反馈写为"爆螺栓闪光、分离级翻滚坠落、**加速度表跃升**"。这一描述源自真实火箭（Saturn V 一级分离后 TWR 上升），但**在 RT-1 的标定下不成立**——因为一级推力（913.5 kN）远大于二级（621.4 kN）。

**三种解法（待裁决）**：

| 方案 | 内容 | 代价 |
|---|---|---|
| **A（建议）** | **接受真实曲线**，把反馈从"跃升"改为"换挡"（指针先落再缓慢回升），并更新概念 §4.1 文案 | 零实现成本、零物理改动。牺牲一个直觉爽点，换来物理诚实（P2） |
| **B** | 上调 `T2` 使分离后加速度上升（需 `T2 > 913500 · 16500/23500 = 641.5 kN`，即二级燃时 < 20.3 s） | 改变 Δv₂ 与燃时 ⇒ **必须重跑 RT-1 全部标定**。且二级燃时缩短会压低 Δv 余量 |
| **C** | 下调 `T1` 使分离前加速度更低（需 `T1 < 621429 · 23500/16500 = 885.2 kN`，即一级燃时 > 61.9 s） | 同上，且一级燃时拉长会击穿 90 s 上限 |

**我的建议：A。** 理由：B/C 都会动摇 RT-1 的验收基础，而 A 只改一行文案和一个动画曲线。"分离后加速度略降，但质量轻了所以后续爬升更快"——这本身就是可教学的知识，是 P2 的素材而非损失。

### C6【低】分离发生在大气顶之上仅 2.98 km

基准分离 `h = 14.98 km`，大气顶 `12 km`。即**分离时已在真空**，残骸无气动阻力、无动压风险。

这使 §3.4 的"高动压分离"风险只在**提前分离**（T+40 之前）时存在，而提前分离本身已被 §3.3 的 Δv 赤字惩罚。**两个惩罚叠加可能过重。**

**建议**：保留两者，但将 `Q_SEP_SAFE` 从 5 kPa 上调至 **8 kPa**（对应最早安全分离时刻 ≈ T+31 s），给"早分离但不太早"的打法留出生存空间。这不改变基准弹道（基准在 T+60 分离，动压 0）。
