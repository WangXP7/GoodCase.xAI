## 1. 系统职责与支柱挂靠

### 1.1 一句话职责

> **把"第 47 次发射"变成一个有意义的说法。** S8 拥有会话生命周期、跨局持久化、新手引导（辅助线）与全部解锁逻辑。

### 1.2 支柱闸门校验 —— **逐子系统过闸**

S8 是一个容器系统，内部 5 个子系统**必须分别过闸**。凡是挂靠不了任何支柱的，**我建议不进 MVP**。

| # | 子系统 | P1 过程即内容 | P2 可解读的深度 | P3 六十秒 | P4 失败也好看 | 闸门结论 |
|---|---|---|---|---|---|---|
| **8.1** | **会话管理**（重开 / 暂停 / 会话状态） | ⚠️ 弱 | — | ✅ **3 s 重开硬上限的唯一执行者** | ✅ 重开是失败环的闭环 | ✅ **进 MVP**（P3 硬指标） |
| **8.2** | **发射档案室**（历史记录 + 跨局趋势） | — | ✅ **进步可量化**（概念 §5.1 胜任保障 3） | — | ✅ 失败码分布即学习曲线 | ✅ **进 MVP**（P2 + P4） |
| **8.3** | **解锁：跳过倒计时** | — | — | ✅ **78 s 打法的必要条件** | — | ✅ **进 MVP**（P3） |
| **8.4** | **辅助线（Guidance Line）** | — | ✅ 隐形教学，让新手能"读懂"该往哪打杆 | ✅ 减压阀，缩短试错成本 | — | ✅ **进 MVP**（概念 §5.2 减压阀） |
| **8.5** | **键位重映射** | — | — | — | — | ⚠️ **无挂靠** |
| **8.6** | **设置（色盲 / 减少动效 / 文本缩放）** | — | — | — | — | ⚠️ **无挂靠** |

**闸门结论**：

| 子系统 | 处置 |
|---|---|
| 8.1 – 8.4 | ✅ 进 MVP |
| **8.5 键位重映射** | ⚠️ **无挂靠——但美术 §9.4 已将其列为 Standard 分级的必做项（✅）**。这是**跨成员冲突**：我的支柱闸门判它出局，美术的可访问性分级判它必做。**需主理人裁决**。我倾向**保留**（成本极低，且可访问性属于"不服务支柱但必须做"的合规项，与支柱是并列关系而非从属） |
| **8.6 设置** | ⚠️ 同上。且美术 §9.3 的光敏安全（震屏 / 闪烁 / 扫描线三独立开关）属**安全合规**，不是可选特性 |

> **裁决请求（见 §9-C14）**：请明确"可访问性 / 安全合规项"是否**豁免支柱闸门**。我的建议是**豁免**——支柱是设计取舍工具，不是合规审查工具；把安全项硬塞进支柱闸门会得出"光敏保护不服务任何支柱所以砍掉"的荒谬结论。

### 1.3 明确不属于 S8（MVP）

概念 §7.2 核心体验层的以下条目**全部不进 MVP**，此处仅登记以防后期误纳入：

- 多档目标轨道递进（LEO → SSO → GTO）
- 异步排行榜 + 成绩分享卡
- 本地存档与解锁进度树（**例外**：8.3 的单一解锁条件需极简持久化）
- 交互式新手教学（改为 HUD 高亮 + 辅助线隐形引导，见 8.4）
- 飞行数据回放（概念 §4.3「分析 Analyse」）—— **S6 的归因面板是它的 MVP 缩减版**
- 天气 / 风切变、三级分离、抛罩

## 2. 核心状态与数据结构

### 2.1 会话状态

```ts
export const SessionState = Object.freeze({
  BOOT:       'BOOT',        // 首屏加载
  BRIEFING:   'BRIEFING',    // 任务简报（MVP 内为极简一屏，见 8.1.2）
  LAUNCH:     'LAUNCH',      // S2 序列 + 飞行
  DEBRIEF:    'DEBRIEF',     // 结算（成功）或归因（失败）
  ARCHIVE:    'ARCHIVE',     // 发射档案室
  SETTINGS:   'SETTINGS',    // 设置
  PAUSED:     'PAUSED',      // 暂停（美术 §9.4「无限时 / 可暂停模式」✅）
});
```

### 2.2 持久化数据（localStorage，单一 key）

```ts
interface MetaSave {
  version:        1;
  missionNo:      number;      // 累计发射次数（含失败与中止）
  successCount:   number;      // 累计成功入轨次数
  abortCount:     number;      // 累计主动中止次数
  best: {
    judgement:    Judgement;   // 最好评级
    accuracyM:    number;      // 最佳精度（绝对值最小）
    flightTimeS:  number;      // 最短局时
    dvLoss:       number;      // 最小 Δv 损失
  };
  failureCounts:  Record<FailureCode, number>;   // 失败码分布
  history:        FlightRecord[];                // 最近 30 局，环形缓冲
  unlocks: {
    skipCountdown: boolean;    // 跳过倒计时
  };
  settings: {
    colorblind:   boolean;
    reduceMotion: boolean;
    shake:        boolean;
    flash:        boolean;
    scanline:     boolean;     // 默认 false
    textScale:    100 | 125 | 150;
    highContrast: boolean;
    showGuidance: boolean;     // 辅助线开关
    keybinds:     Record<string, string>;
  };
}

interface FlightRecord {
  missionNo:    number;
  t:            number;      // 局时 s
  judgement:    Judgement;
  code:         FailureCode | null;
  periapsisM:   number;
  apoapsisM:    number;      // 可能 Infinity
  accuracyM:    number;
  dvRemain:     number;
  dvLoss:       number;
  maxQPa:       number;
  maxAlphaDeg:  number;
  hTurnAchievedM: number;     // 实际倾倒完成高度（玩家弹道的特征量）
}
```

### 2.3 常量

| 常量 | 值 | 说明 |
|---|---|---|
| `T_RETRY_HARD_MAX` | 3.00 s | **P3 硬上限**：从失败/结算到可再次操作 |
| `HISTORY_MAX` | 30 | 档案室保留局数（环形缓冲） |
| `UNLOCK_SKIP_SUCCESS` | 3 | 跳过倒计时的解锁条件之一：累计成功 3 次 |
| `UNLOCK_SKIP_ATTEMPTS` | 10 | 解锁条件之二：累计发射 10 次 |
| `SAVE_KEY` | `'rls_meta_v1'` | localStorage key |
| `GUIDANCE_SAMPLES` | 24 | 辅助线的采样点数 |

## 3. 规则与公式

### 3.1 会话管理（8.1）

#### 3.1.1 会话状态转移

```
BOOT ──► BRIEFING ──► LAUNCH ──► DEBRIEF ──┬─► BRIEFING（重开）
                        ▲                   ├─► ARCHIVE（查看档案）
                        │                   └─► SETTINGS
                        └───────────────────────┘
        任意状态 ──Esc──► PAUSED ──► 返回 / 重开
```

#### 3.1.2 任务简报（BRIEFING）

> **MVP 内为极简一屏，不是概念 §7.2 的"任务简报界面"**（那是核心体验层）。

内容仅三项，全部来自 S5 已明示的评级标准（保证 P2 的一致性）：
```
任务 {missionNo}  ·  目标轨道 15.0 KM  ·  入轨门槛 13.5 KM  ·  精确 14.25–15.75 KM
```
按 `Space` 进入 `LAUNCH`。

> **红线校验（P3）**：简报屏**不得**包含任何需要阅读超过 3 秒的内容。它存在的唯一理由是"让玩家知道第几次发射"。

#### 3.1.3 重开时序（**P3 的硬指标，本系统最重要的一条**）

| 路径 | 时序 |
|---|---|
| **失败路径** | `t_failure` → 演出 1.70 s → 归因面板 → **玩家按 `R` / `Space` 立即重开** |
| **成功路径** | `t_judge` → 演出 1.40 s → 结算面板 → **玩家按 `R` / `Space` 立即重开** |
| **中止路径** | `t_abort` → 演出 1.20 s → 归因面板 → 同上 |

**硬上限校验**：`t_failure + 3.00 s` 时，无论玩家是否读完，`R` 键必须已生效。
- 失败路径：1.70 s < 3.00 s ✅
- 成功路径：1.40 s < 3.00 s ✅
- **余量 1.30 s / 1.60 s**，用于吸收加载与动画抖动。

**重开的原子操作**（顺序固定）：
```
1. S8.meta.finalize()        写入本局 FlightRecord（失败也写）
2. S1.reset()  S3.reset()  S4.reset()  S5.reset()  S6.reset()  S7.reset()
3. S2.resetToIdle()
4. missionNo += 1
5. sessionState = BRIEFING  →  LAUNCH（若玩家在 DEBRIEF 直接按 R，跳过 BRIEFING 的展示延迟）
```

> **第 5 步的取舍**：P3 要求"3 秒内可再来"，但"第 N 次发射"的仪式感（概念 §5.1 关联）要求显示编号。**解法**：`missionNo` 在**任务带常驻显示**（不需要单独的简报屏），重开直接进 `LAUNCH`，编号在任务带跳变。**这样 BRIEFING 屏只在首次进入时出现一次。**

#### 3.1.4 暂停

美术 §9.4 已列「无限时 / 可暂停模式」为 ✅ 必做。
- `Esc` 在 `LAUNCH` 状态下**触发 ABORT（S6），不是暂停**——这两个语义必须分开。
- **暂停键为 `P`**（重映射可改）。暂停时：物理积分冻结、累加器清零、HUD 保留、显示 `PAUSED` 浮层。
- 暂停**不破坏仪式感**，反而增强"控制权"（美术 §9.4 原注）。

### 3.2 发射档案室（8.2）

> **存在理由（P2 + P4）**：概念 §5.1 胜任保障 3「进步可量化……并在跨局之间保留趋势」；关联：「任务编号计数器（"你的第 47 次发射"）、发射档案室（历史飞行记录）。低成本，不依赖后端。」

#### 3.2.1 呈现内容（三块）

| 区块 | 内容 | 视觉层级 |
|---|---|---|
| **① 生涯概览** | `第 47 次发射 · 入轨 12 次 · 中止 3 次` | L2 |
| **② 最佳成绩** | 最佳评级 / 最佳精度 / 最短局时 / 最小 Δv 损失（4 个数） | L2 |
| **③ 近 30 局列表** | 表格：局号 / 时长 / 评级 / 失败码 / 精度 / Δv 损失 | L3 |

#### 3.2.2 **失败码分布图（本系统的设计亮点）**

把 `failureCounts` 渲染为一张**横向条形图**（各失败码的累计次数）：

```
失败归因分布
气动解体      ████████░░░░░░░░  9
Δv 不足       ██████████████░░  17
撞地          ███░░░░░░░░░░░░░  4
攻角折断      ██░░░░░░░░░░░░░░  2
甩出引力场    █░░░░░░░░░░░░░░░  1
```

**为什么它服务 P2/P4**：玩家一眼看到"我死得最多的是 Δv 不足"，这就是**跨局的失败归因**——概念 §3.2-4「失败归因学习环」在元层面的兑现。成本极低（一张静态条形图），价值极高。

> **视觉合规**：这是**静态图表**，不是装饰性动画，不违反美术 §9.2 T2（禁止音乐可视化式特效）。条形图填充色用 `A2` 冰蓝（信息语义），**不用 `A1`**（`A1-BOUND` 黑名单：进度条常态填充禁用 `A1`）。

#### 3.2.3 跨局趋势（P2 的"进步可量化"）

**三项趋势曲线，横轴为局号**：
1. **入轨精度** `accuracyM`（越接近 0 越好）
2. **Δv 损失** `dvLoss`（越小越好）
3. **局时** `flightTimeS`（越短越好）

用 **SVG polyline 或 Phaser Graphics 静态绘制**（美术 §10.4：禁止每帧重绘 Graphics ⇒ **仅在打开档案室时绘制一次**）。

> **验收**：打开档案室时 Graphics 重绘次数 = **1**，不是每帧。

### 3.3 解锁：跳过倒计时（8.3）

```
skipCountdown = (successCount >= 3) || (missionNo >= 10)
```

- 解锁后，S2 §3.3 的 3 s 压缩倒计时生效。
- **解锁提示**：达成条件时，在结算面板显示一行 `已解锁：按住 SPACE 加速倒计时`。
- **MVP 内仅此一个解锁项**。概念 §7.2 的「解锁式科技树」不进 MVP。

> **红线校验（认知过载）**：解锁不增加任何新动词、新读数。它只改变一个已有流程的时长。✅

### 3.4 辅助线（Guidance Line）（8.4）

> **概念 §5.2 原文**：「减压阀：**辅助线（Guidance Line）**——为新手显示建议弹道曲线，可关闭。关闭后评级加成。这是让 A 和 B 两类受众共存于同一局的关键设计。」

#### 3.4.1 辅助线画什么

**辅助线画的是建议的目标俯仰角曲线 `theta_cmd_ref(h)`，画进场景层**（不是 HUD）。即 S1 §3.5 的幂律程序：

```
hStart = 150 m      (1% H)
hTurn  = 7500 m     (50% H)
p      = 0.8

theta_cmd_ref(h) = (h < hStart) ? π/2
                 : (π/2) · [ 1 − clamp( (h − hStart)/(hTurn − hStart), 0, 1 ) ]^0.8
```

**渲染**：`GUIDANCE_SAMPLES = 24` 个采样点，连成一条**虚线**（1px，`A2` alpha 0.35），从火箭当前位置向前绘制，覆盖未来约 8 s 的弹道。

#### 3.4.2 关键设计约束：**辅助线必须画"目标角"，不能画"轨迹线"**

| 方案 | 问题 |
|---|---|
| ❌ 画出预测轨迹（如果保持当前姿态，火箭会飞到哪） | 这是**答案**，不是引导。玩家只需跟着线走，技能归零，且违反概念 §5.1 自主保障 3「不提供最优解提示。可以显示数据，不显示答案」 |
| ✅ 画出建议的 `theta_cmd` 曲线 | 玩家仍需**自己操作** A/D 去跟随这条线。**引导的是意图，不是结果** |

#### 3.4.3 关闭辅助线的评级加成

**我建议取消这个加成。** 理由：

1. **概念 §5.2 写的是「关闭后评级加成」**，但 MVP 的三档评级（S5）**没有给"加成"留出结构**——它只有 `INCOMPLETE / ORBITAL / PRECISE` 三档，加成就意味着要么插一个新档（破坏三档结构），要么把 `PRECISE` 的门槛对关闭者放宽（那 `PRECISE` 就不是同一个成就了，跨局不可比）。
2. **加成会制造主导策略的反面**：它逼迫所有追求 `PRECISE` 的玩家都关闭辅助线，反而让辅助线变成"只有新手才用的拐杖"，加剧 A/B 两类受众的分裂，与概念 §5.2 的原意（"让 A 和 B 共存"）相反。
3. **更好的替代**：在档案室与结算面板记录一个**独立的、不影响评级的标记**——`辅助线：开 / 关`。让 Achiever 自己给自己设挑战，而不是由系统施加评级压力。

**裁决请求（§9-C15）**：请确认是否取消「关闭辅助线的评级加成」，改为「独立记录开关状态，不影响评级」。

#### 3.4.4 隐形引导（首局，替代教学关）

概念 §7.1：「教学关（**改为在首局中用 HUD 高亮与辅助线做隐形引导**）」。

| 阶段 | 引导 |
|---|---|
| 首局（`missionNo === 1`） | 辅助线**默认开启** |
| 首局，到达 `hStart`（T+4.7 s） | 姿态指示器（读数 4）外圈出现一次 `A2` 呼吸高亮（2 个周期，≤2 Hz）+ 文字事件提示 `重力转弯 GRAVITY TURN` |
| 首局，分离窗口（T+40 s） | 控制台 `SEPARATE [SHIFT]` 按钮进入 Hover 态描边（`A1`），持续 3 s |
| 首局，Ω 模态切换 | 标签切换时额外停留 0.6 s（总时长 1.2 s），确保玩家看到"读数性质变了" |
| 第 2 局起 | 辅助线保持玩家上次的选择，不再有高亮提示 |

> **红线校验（P1）**：引导全部是**高亮 + 文字事件提示**，不是"播放一段动画"。玩家可随时按键继续操作，无强制等待。✅

## 4. 玩家输入映射（键鼠）

| 输入 | 状态 | 行为 |
|---|---|---|
| **`Space`** | `BRIEFING` | 进入 `LAUNCH` |
| **`Space`** | `DEBRIEF` | 重开（等同 `R`） |
| **`R`** | `DEBRIEF`（面板已弹出） | 重开 |
| **`P`** | `LAUNCH` | 暂停 / 继续 |
| **`Esc`** | 非 `LAUNCH` | 返回上一屏 / 打开暂停菜单 |
| **`A`** | `ARCHIVE` | 打开档案室 |
| **`Tab`** | `DEBRIEF` | 切到档案室（**预留**，MVP 内可省略） |

### 4.1 输入细则

1. **`R` 与 `Space` 在 DEBRIEF 等价**：降低"找键"成本，服务 P3。
2. **演出期间锁定**：S8 必须与 S6 的 `lockInput()` 协同，演出未完成前 `R`/`Space` 无效（S6 §4.1）。
3. **重开去抖**：200 ms，防连按跳过两局。
4. **`Esc` 在 `LAUNCH` 是 ABORT 不是暂停**——这两个语义必须在设置界面显式说明，否则玩家会在飞行中误按 `Esc` 想暂停却中止了任务。

## 6. 边缘情况（≥3 条，含数值退化与除零防护）

### 6.1 localStorage 不可用（隐私模式 / 配额满 / 跨域 iframe）

**防护**：`meta` 全部读写包一层 `safeStorage`：
```js
function load() { try { return JSON.parse(localStorage.getItem(SAVE_KEY)) ?? defaults(); }
                  catch { return defaults(); } }
function save(d) { try { localStorage.setItem(SAVE_KEY, JSON.stringify(d)); } catch { /* 静默降级 */ } }
```
**降级行为**：内存态运行，本局一切正常，关闭页面后丢失。**不弹错误、不阻塞游戏。**

### 6.2 存档版本迁移与字段缺失

`MetaSave.version` 从 1 开始。读取时若版本不符或字段缺失 ⇒ **逐字段 fallback 到默认值**，不整份丢弃（玩家的历史比格式重要）。

**防护**：
```js
const merged = { ...defaults(), ...parsed, settings: { ...defaults().settings, ...(parsed.settings ?? {}) } };
```

### 6.3 `best` 的比较在首局的未定义值

首局时 `best.accuracyM` 未定义，与 `undefined` 比较会得 `false`，导致最佳成绩永不更新。

**防护**：初始化 `best = { judgement: null, accuracyM: null, flightTimeS: null, dvLoss: null }`，比较时：
```js
const better = (a, b) => (b === null) || (Math.abs(a) < Math.abs(b));
```

### 6.4 环形缓冲溢出与除零

`history` 上限 30。写入时 `history.push(rec); if (history.length > HISTORY_MAX) history.shift();`
**除零**：趋势图的横轴归一化 `(i) / (n − 1)` 在 `n === 1`（仅 1 局）时除零 ⇒ `NaN` ⇒ polyline 绘制失败。

**防护**：`const x = (n > 1) ? (i / (n - 1)) : 0.5;`（单局时曲线退化为一个居中的点）。

### 6.5 趋势图的数值退化（全部相同 / 全部失败）

若 30 局的 `accuracyM` 全部相同（或全部为失败局的 `null`），纵轴范围 `max − min = 0` ⇒ 归一化除零。

**防护**：
```js
const span = (max - min) || 1;      // 0 或 NaN ⇒ 退化为 1
const y = (v) => clamp((v - min) / span, 0, 1);
```
且失败局（`accuracyM === null`）**在趋势曲线上跳过该点**（折线断开，而不是连线到 0）。

### 6.6 `apoapsisM = Infinity` 的持久化

`JSON.stringify(Infinity)` ⇒ `null`。若直接存取，档案室会显示 `远地点 null`。

**防护**：写入前 `apoapsisM = Number.isFinite(x) ? x : null`，读取与显示时 `renderAs: 'INFINITY'`（S5 §6.7 / S7 §5.7）。

### 6.7 重开时的重置顺序竞态

S8 的 `reset()` 若先于 S6 的碎片清理执行，残留碎片可能在下一局开局瞬间可见。

**防护**：重置顺序固定（§3.1.3 第 2 步已列出），且**全部 `reset()` 在同一个同步块内完成**，不跨帧。

**验收**：连续重开 20 次，每局 T+0 时活跃粒子 = 0、残骸对象 = 0、Ω = 0 %、HUD 无残留告警。

## 9. 冲突与待裁决项

### C14【中 · 需裁决】可访问性 / 安全合规项是否豁免支柱闸门？

S8 的 8.5（键位重映射）与 8.6（设置）在支柱闸门前**无挂靠**——它们不服务 P1/P2/P3/P4 中任何一根。按闸门规则应判出局。

但美术 v1.1 §9.4 已把两者列为 **Standard 分级的必做项（✅）**，§9.3 的光敏安全规格更属 **Comprehensive 级**。

**这是"支柱闸门"与"合规底线"的工具边界问题。** 我的建议：

> **可访问性与安全项豁免支柱闸门。** 支柱是**设计取舍工具**（决定"做什么内容"），合规是**准入门槛**（决定"能不能上线"）。把安全项硬塞进支柱闸门，会得出"光敏保护不服务任何支柱所以砍掉"的荒谬结论。
>
> 建议在 PHASE1-SUMMARY §9 的评审闸门原文后补一句：「**本闸门适用于玩法特性提案；可访问性、光敏安全、性能预算等合规项不适用本闸门，按各自的验收清单独立判定。**」

### C15【低 · 需裁决】取消「关闭辅助线的评级加成」？

概念 §5.2 写「关闭辅助线后评级加成」。我建议**取消**，改为独立记录开关状态、不影响评级。三条理由见 §3.4.3：

1. MVP 的三档评级没有给"加成"留结构；
2. 加成会逼迫所有追求 `PRECISE` 的玩家关闭辅助线，反而加剧 A/B 受众分裂；
3. "自己给自己设挑战"比"系统施加评级压力"更符合 Achiever 的动机模型（概念 §5.3）。

### C2【关联】P3 的 60 / 70 / 90 应改为 78 / 81 / 90

见 S2 §9-C2 与 S5 §9-C2。S8 的档案室"最短局时"记录会直接反映这一变化，**无额外实现成本**。

### C10【关联】失败循环时长的表述冲突

见 S6 §9-C10。S8 的 `flightTimeS` 记录口径为"从松绑到判定"，**不含结算/归因面板的停留时间**——这样跨局可比。需与 S6 的表述修正保持一致。
