## 1. 阻塞项裁决

### BLK-1 · 24h 光照循环实现方案 → **裁定：方案 B（四时段淡入）**

**裁决内容**：

| 项 | 裁定 |
|---|---|
| lightmap 套数 | **4 套**（晨 / 午 / 昏 / 夜），时段间交叉淡入淡出 |
| 季节 | **不走 lightmap**。改用实时主光参数 + Color Grading LUT + 少量实时补光 |
| 天气 | **不走 lightmap**。同上 |
| 动态光上限 | 移动端 ≤4 个，推荐 2 个；桌面端 ≤8 个 |

**裁决理由**：
1. 策划将"24 小时真实光照循环"列为氛围支柱，其**实质内容是阴影随时间移动**。方案 A（单套 + 调色）会把这个实质削掉，只剩色调变化——那不是裁决，是阉割。
2. 方案 C（48 套）已被技术判定为移动端内存与下载量双重爆炸，属不可行项，不予采纳。
3. 方案 B 是唯一能保住支柱实质、又不突破技术边界的解。

**附条件**：技术要求程基岩在 Phase 3 架构文档中**核算 4 套 2048² lightmap 在移动端中低端机的实际显存占用**，给出具体数字。若核算结果仍超标，则授权其降级至方案 A，并同步通知策划调整氛围预期。**此核算为 Phase 3 硬性交付项**。

### BLK-2 · 资产精度基线 → **裁定：采纳技术修正，但设桌面/移动双档**

**裁决内容**：

| 项目 | 移动端档 | 桌面端档 | 说明 |
|---|---|---|---|
| 猫三角面 | ≤ 20,000 | **≤ 35,000** | 桌面端保留更高精度以兑现"3D 高模"观感 |
| A 档视口内总量 | ≤ 48k | ≤ 100k | 沿用技术给出的桌面档位 |
| 沙发三角面 | ≤ 12,000 | ≤ 18,000 | 近景家具 |
| 猫形态 blendshapes | ≤ 8 morph + 其余走骨骼 | 同 | 表情丰富度由**姿态库 + 骨骼**补足，不靠 morph 数量 |
| MVP 毛发 | 纯法线烘焙（1024² 法线 + 512² SSS） | 同 | 采纳美术方案 |
| Standard 毛发卡片 | ≤ 40 张 alpha-hash（头+尾） | ≤ 60 张 | 采纳技术修正 |

**裁决理由**：
用户明确要求"3D 高模"。若全面采纳移动端口径（猫 ≤20k 面），桌面端会明显达不到"高模"观感，等于变相阉割需求。技术自己在可行性报告中给出过桌面端 ≤100k 的档位，说明桌面端有富余。**双档制既尊重用户诉求，又不突破技术边界**。

**对美术的附加要求**：MVP 资产清单须**按桌面档制作、运行时按设备档位加载对应 LOD**，不得为了省事只做移动端档。

### U3 · 游戏命名 → **裁定：《檐下 · UNDER THE EAVES》**

**裁决理由**：
三个备选中，《小满》偏节气文艺、《归巢》偏乡愁，而本作的核心支柱是"**同住感**"——玩家与猫共处一个屋檐下，彼此独立又互相陪伴。"檐下"同时包含**空间（屋檐下的房间）**与**关系（庇护与被庇护）**两层含义，与支柱咬合最紧。英文名 UNDER THE EAVES 语感自然，便于后续网页分发。

**保留**：《小满 PETIT JOUR》《归巢 HOMING》记为备选，若后续品牌注册或平台命名冲突时启用。
