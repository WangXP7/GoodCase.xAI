## 一、阻塞项裁决（6 项，全部结清）

### RUL-1 · 24 小时光照实现方案（原 U1）

| 项 | 内容 |
|---|---|
| **议题** | 美术计划 48 套 lightmap；技术判定移动端显存与下载量必炸，主张 MVP 仅 1 套 |
| **裁决** | **采纳方案 B · 四时段淡入（晨 / 午 / 昏 / 夜）** |
| **执行要求** | ① 4 套 lightmap，时段间 0.8s 交叉淡入淡出，禁止硬切<br>② 程基岩在 Phase 3 核算 4 套 2048² lightmap 在中端移动端的实际显存占用，**若超过预算 60% 则降为 2 套（昼 / 夜）+ Color Grading LUT 补足中间态**<br>③ 季节与天气**一律不走 lightmap**，只允许改实时主光色温/强度 + 全屏 LUT |
| **理由** | 支柱二「时间的双层刻度」的实质内容是"光会移动"。方案 A 让阴影永久静止，等于把支柱抽空；方案 C 在当前技术评估下不可行。B 是唯一既保住支柱又不炸内存的解。 |
| **影响面** | 美术圣经 §5（场景规格）光照节需按 4 时段重写；技术 Phase 3 光照管线据此设计 |

### RUL-2 · 猫的模型精度基线（原 U2）

| 项 | 内容 |
|---|---|
| **议题** | 美术预算 50,000 面；技术修正为 ≤20,000 面 |
| **裁决** | **采纳技术修正 ≤20,000 面**，但**验收标准改为"视觉精度"而非"面数"** |
| **执行要求** | ① MVP 按 20k 面 + 高质量烘焙法线 + SSS 制作<br>② **移动端与桌面端共用同一模型**，不做双版本（省资产管线成本）<br>③ 若 playtest 中反馈"不像高模"，**允许上探到 30k 面**，但必须同步提交被削减的其他资产清单<br>④ A 档视口内总和仍守 ≤48k（移动）/ ≤100k（桌面） |
| **理由** | 技术给了设备档位与实测依据，经验估算应当让位。但用户明确要的是"3D 高模"，这是需求层的诉求——因此把验收权从"面数"转移到"观感"，并保留上探通道，防止精度被砍后需求落空。 |
| **影响面** | 美术圣经 §3（资产规格）与 §4（角色规格）需按新预算修订 |

### RUL-3 · 游戏命名（原 U3）

| 项 | 内容 |
|---|---|
| **议题** | 《檐下 UNDER THE EAVES》/《小满 PETIT JOUR》/《归巢 HOMING》 |
| **裁决** | **《檐下 · UNDER THE EAVES》** |
| **理由** | 三个候选里只有它精确命中支柱一。「檐下」= 一个庇护性的共处空间，玩家与猫是**同在一个屋檐下的室友**，语义与"同住感"完全对齐。<br>《小满》是节气，偏文艺但与养猫无内在关联；<br>《归巢》暗示"离开—回归"的循环，**与本作"不做惩罚性回访"的核心裁决精神冲突**——它会在潜意识里把"回来"框定为一种补偿行为。 |
| **影响面** | 全部文档标题、UI 文案、截图水印统一采用此名 |

### RUL-4 · 时间压缩比 ×12（原 P-1，裁决 D-3 的批准）

| 项 | 内容 |
|---|---|
| **议题** | 1:1 真实时间会让只在固定时段上线的玩家永远看不到其他时段的光照；美术已把「晨光」定为首图锚点 |
| **裁决** | **采纳。三段式时间模型即刻生效** |
| **执行要求** | ① 进入时锚定真实时刻（保住"我晚上打开，屋里就是晚上"的真实性）<br>② 会话内加速 **×12**<br>③ 离线 1:1 推进<br>④ **单次会话最多推进 6 游戏小时**（防 AFK 挂机跑完一天）<br>⑤ 设置项「时间流速：真实 / 加速」，**默认加速**，但真实档必须可用 |
| **理由** | 这不是体验优化，是缺陷修复。一个把「晨光」定为首图锚点的游戏，不能让相当一部分玩家永远看不到晨光。 |
| **影响面** | 策划 §5.4 定稿；程序需在架构中明确游戏时钟与真实时钟的分离 |

---

### RUL-5 · 亲密度「暖机」模型替代「−2/周」（原 P-2，裁决 D-4 的批准）

| 项 | 内容 |
|---|---|
| **议题** | Phase 1 原设「长期不在线 −2/周」与主理人 U4「正向奖励、不做惩罚」在**精神**上冲突 |
| **裁决** | **采纳暖机模型。亲密度本体永不主动衰减** |
| **执行要求** | ① 亲密度 `AFF` 永不主动衰减<br>② 新增独立记忆温度值 `warmth`：离线下降、共处上升<br>③ 仅当 `warmth` 低于阈值时 `AFF` 才缓慢下降，且**有地板**（历史峰值 60%，且不低于 10）<br>④ 回归后 3–5 次正向互动可追回（沙盘验证：停玩 90 天 AFF 90→69.2，回归 30 天恢复到 80，恢复度 89%） |
| **语义差别** | 旧：你离开了 → 猫对你的感情减少了（**惩罚**）<br>新：你离开了 → 猫对你的记忆温度降低了，需要几分钟重新热起来（**中性 + 暖机叙事**） |
| **理由** | U4 的措辞是"不做惩罚"，而单向衰减无论包装成什么数值，本质仍是惩罚。这里认可策划对"精神 vs 文字"的辨析——裁决按精神执行。 |
| **影响面** | 策划 §3.3.1 / §5.6.4 定稿；文案层禁止出现"等了你很久"一类表述（已列入风险 S-3） |

---

### RUL-6 · 拒绝率从 10% 上调到 20%（原 P-3）

| 项 | 内容 |
|---|---|
| **议题** | Phase 1 定拒绝率 10%；策划沙盘显示 10% 太罕见，玩家永远学不会读猫的肢体语言 |
| **裁决** | **采纳 20%** |
| **执行要求** | ① 拒绝率 20%<br>② 必须配套 D-5 的两级保底：软保底（连续无反应时 P 递减 0.15×n）+ **硬保底（连续 4 次无反应后第 5 次必定有反应）**<br>③ **"无反应"不等于"什么都不发生"**——物件层必给反馈，70% 概率给猫层「耳语确认 Ear-ack」 |
| **理由** | 三态反应是本作表达"猫性"的核心机制。若拒绝几乎不发生，三态就退化为二态，猫的脾气无从体现。但保底机制是这条裁决成立的**前提**，二者不可分割。 |
| **影响面** | 策划 §4.3.2 / §4.3.3 定稿；UX 文档 §6 交互反馈规格对接 |

### RUL-8 · 数据安全为最高优先级（对应 TECH-2 / 风险 S-4）

| 项 | 内容 |
|---|---|
| **问题** | iOS Safari 在 `visibilitychange → hidden` 回调返回后会**立即冻结页面**。若存档写入是异步的，玩家的进度会静默丢失。策划已标为 🔴 P0，且注明"技术上无策划侧缓解"。 |
| **裁决** | **同步写入 + 双槽 + CRC32 校验，三条同时做，不允许为工期削减任何一条。** |
| **理由** | 本作是长线养成，存档是玩家投入的唯一载体。一个养了 60 天的猫因为切后台丢失，是不可接受的失败——它比任何画面缺陷都更致命，且**不可挽回**。这是本项目唯一的"零容忍"项。 |

### RUL-9 · 回放功能：MVP 不做，但架构必须预留

| 项 | 内容 |
|---|---|
| **议题** | 潮线项目中程序提出"回放现在做 +200 LOC，以后做要返工"（要求全项目 RNG 种子化 + 固定步长） |
| **裁决** | **MVP 不实现回放功能，但架构层必须做好两件事**：① 全局 RNG 种子化 ② 逻辑固定步长（与渲染帧率解耦） |
| **理由** | 这两件事本身就是好架构（对养成游戏的确定性模拟有独立价值），且成本几乎为零。做了它们，将来加回放不必返工；不做，将来要重写。这是"现在免费、以后昂贵"的典型。 |
