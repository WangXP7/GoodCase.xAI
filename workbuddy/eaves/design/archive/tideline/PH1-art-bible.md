## 1. 视觉身份摘要（Visual Identity Statement）

### 1.1 视觉 DNA

本作是一款**以「灰调深海压迫感」为底、「高饱和街机反馈」为刃的横向卷轴鲨鱼街机游戏**。

我们让整片海洋保持低饱和的深蓝与灰——压抑、冷、缺少生机——玩家在其中是一只只能依靠**轮廓、光柱与运动**辨认世界的掠食者。而每当捕食成功、连击累积、稀有物入手的瞬间，屏幕会以街机时代特有的粗粝方式炸开：描边粗重的洋红溅射、跳动的大号像素数字、色差撕裂的扫描线、4 像素的屏幕震动。

**冷与热、静与爆、灰与彩之间的一次次剧烈反差，就是本作的核心视觉节奏。** 我们不是在还原海洋，我们是在用街机的语言重新发明一个海洋。

### 1.2 三个风格形容词

> **粗粝 · 紧张 · 怀旧**
> （Gritty · Tense · Nostalgic）

| 形容词 | 具体含义 | 可验证的落地标准 |
|--------|---------|-----------------|
| **粗粝** | 像素硬边、有限色阶、可见的硬件痕迹 | 禁用抗锯齿柔边；描边 ≥2px；强制 CRT 后期；像素必须整数倍缩放 |
| **紧张** | 信息密度高、威胁即时可辨、反馈强烈 | 玩家须在 0.3 秒内判断"可食/威胁/收集物"；捕食必带屏幕震动 |
| **怀旧** | 8-bit/16-bit 街机语汇、刻意保留的"过时感" | 角色动画锁定 12fps；分数用像素字；扫描线常驻（可关） |

### 1.3 两张参考图的调和方案 ⚠️ 关键决策

用户提供的两张参考图存在**配色方向冲突**，本文档给出明确裁决：

| 参考图 | 采纳什么 | 不采纳什么 |
|--------|---------|-----------|
| **上图**：AI 彩色海滩原型 | **场景元素构成与布局**（沙滩、散落道具、棕榈树、圆环/星星/瓶子） | ❌ 其高饱和全彩配色 |
| **下图**：复古灰调街机鲨鱼 | **整体美学与配色逻辑**（灰背景、卡通鲨鱼、像素分数、COMBO 字、笑脸太阳、CRT） | ❌ 其元素匮乏（需按上图补充密度） |

**裁决结论**：
> **采用下图的"眼睛"，装上上图的"身体"。**
> 保留灰调暗色基底（深蓝/黑/灰），把彩色海滩的元素**全部去饱和**铺进场景，**仅让可交互物（收集物、危险物、鲨鱼本体的关键部位）保留高饱和色**。

**这一决策直接服务玩法**：在灰调场景中，高饱和 = "这个东西可以吃/可以拿"的通用视觉契约。玩家不需要教学就能理解规则。同时它也解决了副循环的可读性问题——沙滩上散落的道具会自动"跳"出来。

**量化约束**：高饱和色（调色板索引 09–15）在任意一帧的**屏幕面积占比 ≤ 8%**。超过即视为配色失控。

## 2. 色彩规范（Color Palette）

### 2.0 ⭐⭐ 色彩总则：饱和度 = 可能性（v1.3 新增 · 全章最高原则）

> **主理人指示**：把 D4 搁浅的配色例外规则提升为 §2 开头的色彩总则。
> **理由**：它不是一条配色规定，而是**一套配色语义理论**——可推广到任意新场景，无需每次重新判断。

#### 2.0.1 原则

> ## **饱和度 = 可能性（Saturation = Agency）**
>
> 在本作中，**颜色的饱和度不是美学参数，而是信息参数**。它编码的是：
>
> ## 「**这个东西，玩家现在能对它做什么**」

| 饱和度 | 含义 | 玩家读到的是 | 出现位置 |
|--------|------|-------------|---------|
| **高饱和** | 这里有**可选择的东西** | "我可以吃 / 拿 / 躲" | 可交互物（收集物、目标、危险物） |
| **低饱和 / 灰阶** | 这里**没有选择** | "这是环境" | 全部环境、背景、天空 |

**这条总则的源头**：§1.3 已建立视觉契约「灰调场景中，高饱和 = 这个东西可以吃/可以拿」。本总则把它从**一条契约**上升为**一部可推导的法**——§1.3 说的是"高饱和意味着什么"，§2.0 说的是"**什么时候该给高饱和、给多少**"。

#### 2.0.2 核心推论

> **当玩家的选择权归零时，强调色必须归零。**

这是全章唯一不可协商的推论。它直接产出 §6.8 搁浅演出的配色例外规则：搁浅时玩家没有任何选择（只剩一个机械的 QTE），因此强调色失去全部功能，必须被抽干；**唯一例外是 QTE 圆环**——它是那一帧里仅剩的"可能性"，它的颜色梯度就是"剩余可能性的量表"。

#### 2.0.3 推导工具（任意新场景都用它，不要重新拍脑袋）

**三步走**：

1. **问**：在这一刻，玩家有什么选择？
2. **定**：选择多 → 配额高；选择少 → 配额低；**零选择 → 配额为零**
3. **配**：把配额分配给**承载那些选择的元素**（不是分配给"看起来重要"的元素）

**⚠️ 第 3 步是最容易错的**：配额要跟着**选择**走，不是跟着**重要性**走。ALARM 条很重要，但玩家对它没有"选择"——它获得配额是因为它**影响**玩家的选择，不是因为它重要。

#### 2.0.4 已确认场景的配额表（作为标杆）

| 场景 | 玩家的选择 | 高饱和配额 | 承载元素 |
|------|-----------|-----------|---------|
| **冲浪区**（副循环） | **高**：捡哪个、走哪条弧线 | **5%** | 收集物、浪线高光 |
| **深海潜行** | 中：选目标、选路线 | 2% | 目标高光、BANK 点标识 |

**用法**：新增任何场景/状态时，先在上表中定位它的"选择量级"，套用对应配额。**若某个新场景无法定位，说明它的玩法定位还不清晰——先回去问设计，不要先定颜色。**

#### 2.0.5 这条总则的额外收益：它同时是一条可访问性规则

因为"可能性"这个信息**同时被编码在饱和度与**下列不依赖色觉的通道里（见 §9.8 ④）：
- 可交互物有**描边**、有**尺寸**、有**动画**（脉冲/浮动）
- 环境元素没有

**因此灰度化后，"哪些东西可以交互"依然可读**——高饱和度的消失不会带走这条信息。这是 §2.0 与可访问性目标的天然一致，不是巧合：**两者都要求信息有多余的载体。**

### 2.3 血液替代方案 ⚠️ 重要决策

**不使用写实血液。** 采用 `#FF2E88` 溅射洋红粒子作为捕食反馈。

**理由**：
1. 网页游戏受众广，避免写实血腥带来的分级/平台审核风险
2. 洋红是 80 年代街机的经典"墨色"，比血红更符合复古调性
3. 洋红在深蓝背景上的**对比度优于红色**（红色与 `#FF3B3B` 危险警示会混淆语义）

**语义铁律**：`#FF3B3B` = 你自己有危险；`#FF2E88` = 你造成了伤害。**两者绝不混用。**

> **唯一合法用法**：洋红**只能**出现在"玩家对他人造成伤害"的那一瞬间。

**文策渊的提问**：系绳引入后，ALARM 75–100 会同时出现四个红色元素（ALARM 条 / 边缘箭头 / 系绳 / 血红太阳）。他粗算约 1.4%，在 ≤3% 配额内——**但他指出"配额问题总是死在叠加态上"，要我实测最坏情况。**

**他的直觉是对的，而且比他想的更值得做——因为验算暴露了一个度量问题。**

## 最坏情况实测（ALARM=100 + 两条系绳 + 屏幕边缘红晕，1440×864 = 1,244,160 px²）

**A. 离散红色元素（alpha 加权面积）**

| 元素 | 尺寸 | 面积 | alpha | 加权占比 |
|------|------|------|-------|---------|
| ALARM 条（满格红） | 320×20 | 6,400 | 1.0 | **0.51%** |
| 追捕箭头 ×4 | 16×16 三角 ×4 | 512 | 1.0 | **0.04%** |
| 系绳 · 直升机 | 2px × 1,679（满对角） | 3,358 | 0.85（呼吸均值） | **0.23%** |
| 系绳 · T4 | 3px × 1,679 | 5,037 | 0.85 | **0.34%** |
| 太阳（血红） | ⌀72 圆 | 4,072 | 1.0 | **0.33%** |
| **合计** | | | | **1.45%** ✅ |

> ✅ **文策渊估算的 1.4% 准确**（实测 1.45%），离散元素在 L0 ≤3% 配额内，**余量 1.55%**。

**B. 大气红色染色（暗角染红）—— 这里出了问题**

| alpha | alpha 加权占比 | 判读 |
|-------|--------------|------|
| 0.15（v1.1 原值） | **9.6%** | 单此项即为 L0 总配额的 **3.2 倍** |
| 0.08（v1.5 新值） | **5.1%** | 仍为总配额的 **1.7 倍** |
| 0.05 | 3.2% | 仍然超标 |

**结论：无论怎么调 alpha，按"面积"计量，大气染色都必然超标。** 这说明——

## ⚠️ 面积配额是大气染色的错误度量

**两类红色的失效模式根本不同，不能用同一把尺子量**：

| | **离散红色元素** | **大气红色染色** |
|---|---|---|
| 例子 | ALARM 条、箭头、系绳、太阳 | 暗角染红 |
| 失效方式 | **因"过多"而失效**——红点到处都是 → 失去稀缺性 → 不再抓眼 | **因"降低对比"而失效**——整屏泛红 → 离散红元素与背景的反差被稀释 → 反而更不显眼 |
| 正确的度量 | **面积配额**（≤3%） | **对比度**（离散元素 vs 紧邻背景） |

**所以：分成两个预算，各用各的尺子。**

## 双预算模型（v1.5 定稿）

| 预算 | 覆盖范围 | 度量 | 阈值 |
|------|---------|------|------|
| **预算 A · 离散红（L0）** | ALARM 条 / 追捕箭头 / 锁定系绳 / 血红太阳 / 搁浅 QTE 环 | **alpha 加权面积** | **≤3%**（实测 1.45% ✅） |
| **预算 B · 大气红** | 仅暗角染红 | **对比度**（见下），**不计入预算 A** | 见对比度测试 |

**暗角染红 alpha 定为 `0.08`**（v1.5 新值，原 v1.1 值 0.15 被我在 v1.2 误删后一直缺失）。

## 📐 新增验收：对比度测试（这才是大气染色该过的测试）

> **在 ALARM=100 的最坏叠加状态下，测量 ALARM 条（血红 `#FF3B3B`）与其紧邻背景的：**
> - **明度差 ≥ 30%**
> - **色度差 ≥ 0.15**
>
> **若不达标 → 降低暗角染红 alpha，直到达标。**
>
> 这条测试直接测"**那一抹血色还抓不抓眼**"，而面积配额测的是"**红点多不多**"。**两者测的是同一件事的两个方面，缺一不可。**

### 2.7 ⭐ 血红 / 洋红的语义分离（v1.2 新增 · 修复亮度撞车）

**发现（文策渊测算）**：血红 `#FF3B3B` 与洋红 `#FF2E88` 的 WCAG 相对亮度**同为 25%**，且同属红色系——**红绿色盲最难区分的一对**。这意味着 §2.3 那条最核心的语义铁律，**在灰度化后彻底失效**。

| 色 | 相对亮度 |
|---|---------|
| 炽白 `#F2F5F8` | 90% |
| 金 `#FFD23F` | 68% |
| 电光蓝 `#00C2FF` | 46% |
| 琥珀 `#FF8A3D` | 40% |
| **血红 `#FF3B3B`** | **25%** |
| **洋红 `#FF2E88`** | **25%** |
| 史诗紫 `#B14CFF` | 22% |

**✅ 同时确认的好消息**：ALARM 三级梯度（炽白 90% → 琥珀 40% → 血红 25%）是**单调递减**的亮度序列，灰度下完全可辨；色盲模式（炽白 90% → 金 68% → 电光蓝 46%）同样单调。**这两条设计成立。**

#### 我的裁决：加双通道，**但拒绝调亮洋红**

文策渊给了三个选项，我的取舍：

| 方案 | 裁决 | 理由 |
|------|------|------|
| **① 形态通道** | ✅ **采纳（强制）** | 洋红**永远**是"**径向运动的粒子爆发**"（动）；血红**永远**是"**静态填充 / 条 / 描边**"（静）。一动一静，灰度下也能分 |
| **② 位置通道** | ✅ **采纳（强制）** | 洋红**只**出现在**鲨鱼嘴部 / 捕食点**（画面中央的活动区）；血红**只**出现在 **HUD / 屏幕边缘 / 实体配色**（画面的框架区） |
| **③ 调亮洋红至 `#FF6EB4`（36%）** | ❌ **拒绝** | 见下 |

**为什么拒绝调亮**：
1. **破坏调性**：洋红现在 25% 的暗度正是"80 年代街机墨色"的质感。调亮成粉色，视觉上会滑向"可爱"，与 **D3 黑色喜剧**的锋利感直接冲突
2. **收益有限且不可靠**：11% 的亮度差对红绿色盲玩家帮助很小——他们区分不了色相，亮度差在运动中也很难被感知。而**形态（动/静）与位置（中央/边缘）是全通道可靠的**，不依赖任何色觉
3. **引入新颜色违反调色板纪律**：§2.5 明确"新增颜色须走申请流程"，为修一个已有通道能解决的问题而扩表，不划算

**验收测试（新增，与"灰度化后稀有度仍可辨"并列）**：
> 将捕食瞬间与 ALARM 告警瞬间**同时去色并排**播放，测试者须能仅凭"动/静"与"中央/边缘"区分"我在造成伤害"与"我有危险"。5 名测试者中 ≥4 人判断正确方为通过。

### 2.8 救生员的红色语义拆分（v1.2 新增 · 修复语义撞车）

**发现（文策渊）**：§4.3 规定救生员用红白条纹，但救生员在 ALARM **25–49** 就出现，而 L0 血红按定义是"ALARM 高段/最高危"才用的——**语义撞车**。

**裁决：红在「状态」与「对象」上分开计量，靠位置区分语义。**

| 类型 | 含义 | 出现位置 | 配额归属 |
|------|------|---------|---------|
| **状态红** | "**你**处境危险" | ALARM 条 / 屏幕边缘 / 搁浅 QTE 环 / 追捕箭头 | 计入 **L0 配额（≤3%）** |
| **对象红** | "**这个目标会反击**" | 救生员 / 高危敌人的**条纹等小面积配色** | 计入 **L1**，且**屏幕占比 ≤1%** |

**理由**：红白条纹是"禁止/危险"的通用符号学，**不能放弃**——放弃它等于放弃一个零学习成本的识别符。但只要位置清晰，玩家不会混淆"我危险"和"它危险"。

### 3.2 ⚠️ 中文字体加载策略（关键技术美术决策）

**问题**：中文像素字体（Zpix 等）普遍 2–10MB，直接引入会严重拖慢网页首屏。

**解决方案 —— 分离策略**：

```
拉丁/数字  → Press Start 2P（woff2, ~30KB）  → 像素质感，全部 HUD 数字
中文文本   → Noto Sans SC 子集（woff2, ~80KB）→ 清晰可读，非像素
```

- **子集化**：仅打包实际用到的汉字（预计 300–800 字），用 `fonttools pyftsubset` 生成
- **预加载**：`<link rel="preload" as="font" crossorigin>` + `font-display: swap`
- **回退栈**：`'Press Start 2P', 'Noto Sans SC', monospace`
- 若用户强烈要求中文也必须像素化，则**仅对标题做图片化处理**（把中文标题烘成 sprite），正文仍用非像素字体

### 3.3 字号层级（8px 网格系统）

复古像素字体必须按 **8 的整数倍** 取字号，否则会出现像素错位。

| 层级 | 字号 | 字体 | 颜色 | 用途 |
|------|------|------|------|------|
| **H0** | 64px | Press Start 2P | `#FFD23F` + `#0A0E17` 3px 描边 | 游戏 Logo、结算评级字母 |
| **H1** | 48px | Press Start 2P | `#FF8A3D` / `#B14CFF` | COMBO 数字、大事件提示 |
| **H2** | 32px | Press Start 2P | `#F2F5F8` + 2px 描边 | 分数、面板标题 |
| **H3** | 24px | Press Start 2P | `#C7CFD8` | 菜单选项（选中态 `#FFD23F`） |
| **Body** | 16px | VT323 / Noto Sans SC | `#C7CFD8` | 说明文本、道具描述 |
| **Caption** | 12px | VT323 | `#8A97A8` | 版本号、提示小字、HI-SCORE |

**文本可读性规则**：所有 HUD 文字必须带 `#0A0E17` 描边（H2/H1 用 2–3px，Body 用 1px）。海洋背景亮度变化剧烈，无描边文字会在浅滩区消失。

### 3.4 字距与排版

- Press Start 2P 自带宽字距，**无需额外 letter-spacing**
- 中文文本 `letter-spacing: 0.05em`，`line-height: 1.6`
- 数字分数使用**等宽对齐**（`font-variant-numeric: tabular-nums`），避免跳动时数字抖动
- **禁止**对像素字体做非整数倍缩放或 CSS 旋转

#### 4.1.6 携带态（Carry）视觉规范（v1.1 新增）

概念文档支柱一：*「你手里的战利品同时是你的通缉令。」* 携带态是身份反转的具象化，必须有**独立且明确**的视觉语言。

| 通道 | 表现 | 参数 |
|------|------|------|
| **姿态** | 身体下沉 4px，尾摆幅度 −30%，头部上仰 8° | 读得出"负重" |
| **嘴部** | 叼住游客，游客四肢**像素级高频抖动**（4 帧循环 @20fps，幅度 ±2px） | 概念文档 §3.3：*「抖就对了」*，不需要精细动画 |
| **水花拖尾** ⭐ | 携带时**持续**产生水花，在暗色海面连成一条**显眼的亮线** | 6 粒子/秒，`#F2F5F8`，寿命 1.2s。**这就是"你自己的暴露轨迹"，也是主动引怪的诱饵**（概念文档 §3.2 高阶技巧） |

**设计理由**：携带态的所有视觉变化集中在**轨迹（水花）+ 界面（HUD）**，而非角色本体的夸张变形。这样即使在 CRT + 扫描线 + 震屏叠加的情况下，玩家仍能一眼读出"我现在是猎物"。

| 漂浮物 | 泳圈 / 冲浪板 / 无 | 3 |

**素材量**：躯干 3 套 × 头饰 4 种 + 漂浮物 3 种 = **约 15 张图**，可组合出 **144 种**视觉组合。

**⚠️ 核心可读性规则**：游客剪影**必须包含"举起的手臂"或"泳圈"**，这是"人类"的通用识别符。玩家需要在 0.3 秒内判断"这是可捕食目标"而非障碍物。手臂动作做成 2 帧（上举/划水）。

#### 4.2.1 ⭐ 游客表情系统（v1.2 新增 · 落实 D3 黑色喜剧）

用户已锁定基调为**黑色喜剧**（非写实掠食、非萌系）。游客必须**惊恐但滑稽**——玩家要笑出来，不是被吓到，也不是感到不适。

**实现方式**：游客只有 ~40–56px 高（体型 168px 的鲨鱼叼着他们），面部只有 **8×8px** 左右。因此表情只能靠 **3 个像素级通道**：眼睛（2 点或 2 线）、嘴（1 条弧线或方孔）、四肢姿态。

| 状态 | 眼 | 嘴 | 姿态 | 触发 |
|------|-----|-----|------|------|
| **悠闲** Idle | 两个 1px 点 | 1px 短横（平直） | 正常划水，2 帧 | 未察觉鲨鱼 |
| **察觉** Notice | 两个 1px 点，间距拉大 | 1px 短横 → 小 "o" | 停住，头部转向鲨鱼 | 鲨鱼进入警戒半径 |
| **惊恐** Panic ⭐ | **两个 2px 竖线**（瞪大的眼白） | **3×3px 方孔**（张大嘴） | **四肢高频扑腾**（4 帧 @15fps，幅度 ±3px），身体上浮 | 鲨鱼冲刺接近 |
| **被叼** Carried ⭐ | 两个 1px 点（因抖动而重影） | 方孔保持 | **四肢像素级高频抖动**（4 帧 @20fps，幅度 ±2px）——概念文档：*「抖就对了」* | 被咬住 |
| **飞在空中** Airborne ⭐ | 两个 2px 竖线 | 方孔 | **四肢完全张开呈"大"字**，缓慢旋转（锚点 02 的喜剧爆点） | 被抛出水面瞬间 |
| **围观** Gawking ⭐ | 两个 1px 点 | 1px 短横 | **静止、滑稽、不构成威胁**，围成半圆（搁浅场景专用，见 §6.8） | 搁浅演出 |

**喜剧的四条执行准则**：

1. **夸张 > 精细**：8×8px 的脸做不出微表情。用**姿态的夸张**（大字型、高频抖动）而不是**面部的精细**来传达情绪。这也更像素、更街机。
2. **慌乱 ≠ 痛苦**：Panic 是"手忙脚乱的滑稽"，不是"受苦"。**禁止**流泪、痛苦扭曲的五官、求饶手势。
3. **抖动是免费的喜剧**：高频小幅抖动在像素动画里天然好笑（因为它"廉价"）。这是本作喜剧感的主要来源，成本几乎为零。
4. **被叼走的人没有受伤表现**：不出现淤青、伤痕、血迹。**他们只是被一只鲨鱼叼着，仅此而已。**

**⚠️ 合规红线（全年龄网页分发）**：不出现血液、不出现断肢、不出现死亡特写。被叼的游客在整段演出中始终是**完整的人形剪影**。这条同时保护了平台分发与 D3 的喜剧基调——一旦滑向写实，喜剧立刻变成残忍。

**动画**：`swim` 4 帧 @10fps · `panic` 4 帧 @15fps · `carried` 4 帧 @20fps · `airborne` 3 帧 @12fps · `gawking` 1 帧（静止）+ 偶发 2 帧眨眼。

### 4.3 NPC：救生员（Lifeguard）

**设计原则：视觉上必须传达"不可食用"信号。**

| 属性 | 规范 |
|------|------|
| 配色 | `#FF3B3B` 危险红 + `#F2F5F8` 纸白 **高对比条纹**（通用"禁止/危险"符号学） |
| 剪影 | 直立姿态 + 望远镜/哨子，站在浮台或船上 |
| 尺寸 | 96×120，比游客大 20% |
| 行为反馈 | 发现鲨鱼时头顶弹出 `!` 图标（`#FF3B3B`，H1 字号，0.3s 弹出 + 0.5s 保持） |
| 语义 | 攻击救生员 = 高惩罚。红白条纹 + `!` + 大尺寸 = 三重"别碰"信号 |

### 4.4 敌人威胁等级视觉表达

**⚠️ 三重冗余编码原则**：威胁等级通过 **颜色 + 尺寸 + 频闪频率** 三个独立通道同时表达。任一通道失效（如色盲、低亮度屏幕）时，玩家仍能判断威胁。这是可访问性的硬性要求。

| 等级 | 类型 | 主色 | 尺寸 | 频闪 | **锁定系绳** | 附加特征 |
|------|------|------|------|------|---------|---------|
| **T1 低** | 漂浮垃圾、废弃泳圈 | `#4A5A6E` 雾灰（低饱和） | 32–48px | **无** | **无** | 静态/慢速漂移，无警示 |
| **T2 中** | 救生员、摩托艇 | `#2E3E54` 灰蓝 + `#FF8A3D` 暖橙警示条 | 96–144px | 1Hz（**呼吸式**） | **无**（在巡视） | 船尾持续白色尾流粒子（10/s） |
| **T3 高** | **直升机**、拖网渔船 | `#0A0E17` 深渊黑 + `#FF3B3B` 危险红 | 176–256px | **1.5Hz（呼吸式）** | **直升机：2px，1Hz** | 探照灯光锥（白色梯形，缓慢扫动） |
| **T4 致命** | 捕鲨队 | 黑色 + `#FF3B3B` 危险红 | ≥320px | **2Hz（呼吸式）** | **3px，0.7Hz** | 屏幕边缘红晕 + 专属入场动画 |

> **📌 v1.4 新增「锁定系绳」列** —— 因为系绳现在是**诱饵免疫规则的唯一判据**（§5.4.2.4），它必须与威胁等级一起被设计，不能事后再加。完整规格见 §5.4.3。

**通用规则**：
- 威胁等级 ↑ = 红色占比 ↑ + 尺寸 ↑ + 频闪频率 ↑
- ⭐ **有锁定系绳 = 免疫诱饵；没有 = 受诱饵影响**（§5.4.2.4）
- 所有 T2+ 敌人在进入屏幕前 **0.8 秒**必须有预警（屏幕边缘对应方向的箭头 + 低频蜂鸣，交阮和鸣）

**🔴 v1.2 修正（P0-1 · 安全红线）**：

v1.1 写的是「T4 = **3Hz**」「频闪频率上限 **3Hz**」——**3Hz 不满足 `<3Hz` 的硬要求，是我文档内部的自相矛盾**，且 T4 用硬 on/off 切换是光敏性风险最高的形式。已修正为：

> **① 频率降至 2Hz（T4 上限），全部威胁等级改为「呼吸式明暗渐变」**
>
> **② ⚠️ 禁用硬 on/off 闪烁，一律改用 smooth pulse（呼吸式明暗渐变）**
> 实现：`alpha = 0.6 + 0.4 × sin(2π × f × t)`，在**两级色阶间做亮度往复**，而非在"有/无"之间跳变。
>
> **为什么这条重要**：硬 on/off 切换产生的**亮度突变**才是光敏性癫痫的主要诱因，而不是频率本身。呼吸式渐变**视觉上一样急促、一样抓眼**（甚至更有压迫感），但亮度是连续变化的，风险大幅降低。
> **——这个冗余通道（频闪频率）由此得以保留，不必为了安全而砍掉。**

### 4.5 ⭐ 黑色喜剧视觉准则（v1.2 新增 · 落实 D3）

用户已锁定基调为**黑色喜剧**。这不是"萌系"也不是"写实掠食"——它是**让玩家的恶意变得好笑**。这节定下可执行边界，供原画与动画直接对照。

**三条正面准则**（要做什么）

1. **夸张的物理性**——大字型腾空、高频抖动、滑稽的翻滚、被抛出时的缓慢旋转。**喜剧来自物理，不来自表情**。像素动画做物理夸张极便宜（改几个关键帧），收益却最大。
2. **对比制造笑点**——凶猛的鲨鱼 vs 慌张的小人；肃杀的追捕 vs 沙滩上晒太阳的游客；紧张的 QTE vs 一圈静止围观的剪影。**笑点在"不对等"里**，美术要把这种不对等摆在同一帧里。
3. **冷漠的环境**——太阳照常微笑（甚至在大笑），云照常飘，海照常蓝。**世界对玩家的暴行毫无反应**，这种"无所谓"本身就是冷幽默。这也是 §5.3.5 把太阳做成情绪锚点的原因。

**四条负面红线**（不要做什么）

| ❌ 禁止 | 原因 |
|--------|------|
| 血液、伤口、淤青、断肢 | 滑向写实即滑向残忍，喜剧立刻失效；且违反全年龄网页分发合规 |
| 痛苦扭曲的五官、流泪、求饶手势 | 让玩家从"好笑"切换到"同情"，情绪断裂 |
| 死亡特写（咀嚼、撕咬、吞咽） | 概念文档 §3.3 情绪禁区：*「基调是《大白鲨》式的暗示与黑色幽默，不是 B 级片」* |
| 把鲨鱼画成虐待狂（狰狞、享受痛苦） | 鲨鱼是"明目张胆的坏蛋"，不是施虐者。**它应该贪吃、得意、滑稽，不应该邪恶** |

**一句话判断标准**：
> 如果这一帧被截图发出去，**配文会是笑话还是举报**？——必须是笑话。

**为什么这对业务重要**：概念文档 §1.2 定义的次级用户是"梗图传播者"，他们决定传播量。黑色喜剧 + 名场面 = 可分享资产。反之，任何一处越界都会让游戏从"好玩的坏"变成"不适合分享"，直接损失传播渠道。

## 5. 场景与环境（Environment）

### 5.0 🔒 方向锁定（v1.2 新增 · 落实 D1）

用户已锁定**横版侧视**。本节锁定唯一方向，**全项目不得反转**：

> ## **深海在左（安全）→ 沙滩在右（最险）**

```
        ◄──── 安全 ──────────────────────── 危险 ────►

        ┌──────────┬──────────┬──────────┬──────────┐
        │  深海    │   浅滩   │  冲浪区  │   沙滩   │
        │  DEEP    │  SHALLOW │   SURF   │  BEACH   │
        │  明度 8% │  明度28% │  明度55% │  明度82% │
        │  BANK点  │          │  副循环  │  搁浅区  │
        └──────────┴──────────┴──────────┴──────────┘
             ▲                                    ▲
             │                                    │
          安全区                              最暴露区
        （往左退）                          （往右冲）
```

**为什么必须锁死**：概念文档 D1 的核心论证是"侧视让危险梯度变成**屏幕上的左右**"。这个设计只有在**方向恒定**时才成立——玩家必须能形成肌肉记忆："**往右 = 深入险境，往左 = 撤回安全**"。若中途反转，玩家的空间直觉会崩塌，风险估值的手感（支柱二）随之瓦解。

**四条执行约束**：

1. **关卡永远从左向右推进**。摄像机主要右移；允许玩家往左撤退（这是核心操作），但**区域的空间顺序恒定不变**。
2. **明度梯度必须与方向严格对应**（§5.3.0）：越往右越亮 = 越危险。**禁止"右侧的暗区"**——那会直接违反玩家的直觉。
3. **冲浪为侧视水平表现**：水面切一条水平线，鲨鱼沿水面冲刺（§5.3.3）。
4. **鲨鱼剪影在深色海水中必须一眼可辨**——见 §4.1.2 剪影可读性测试，以及 §5.3.0 的「实体与背景明度差 ≥40%」规则。

**移动端**：视角方向不变，输入压缩到 **1.5 个自由度**（上下控制深度 + 可选冲刺）。方向锁定对移动端更重要——小屏上玩家更依赖空间记忆而非实时判断。

### 5.1 整体结构（v1.1：✅ 已确认）

**概念文档 D1 决策：横版侧视。** 本文档的「横向卷轴 + 垂直分层」假设**验证通过**，无需重做。

概念文档给出的理由，也是这个选择对美术的意义：

> *「核心循环是『深海 ↔ 沙滩』的向量，侧视让危险梯度变成屏幕上的左右，冲浪也天然是侧视活动；且复古像素在侧视下可读性最强。」*

**对美术的直接推论**：水平方向 = **危险梯度轴**（左深海 → 右沙滩），垂直方向 = **深度轴**（上天空 → 下海底）。玩家的处境可以仅用「屏幕上的位置」表达——这就是 §5.3.0 明度阶梯能成立的前提。**所有环境设计必须强化这条左右轴的可读性。**

### 5.2 视差分层结构（6 层）

| 层 | 名称 | 视差系数 | 内容 | 重绘频率 |
|----|------|---------|------|---------|
| **L0** | HUD 层 | 0.0（固定） | 分数、生命、COMBO、菜单 | 仅数据变化时 |
| **L1** | 天空层 | 0.05 | 天空渐变、云、笑脸太阳 | 极慢滚动 |
| **L2** | 海面层 | 0.15 | 波浪线、水面折射、浮动杂物 | 滚动时 |
| **L3** | 浅海层 | 0.35 | 光柱、鱼群剪影、珊瑚剪影 | 滚动时 |
| **L4** | **主玩法层** | 1.0 | 鲨鱼、NPC、敌人、收集物、VFX | 每帧 |
| **L5** | 前景层 | 1.6 | 气泡、漂浮颗粒、暗角遮挡物 | 每帧（低密度） |

**性能收益**：L0/L1 独立 canvas，仅在滚动时重绘，可减少约 **60% 填充率**。

### 5.3 区域视觉规范（v1.1 修订 · 四层水体）

#### 5.3.0 ⭐ 明度阶梯：危险度 = 亮度（v1.1 新增 · 核心设计装置）

概念文档 §2 支柱三给出了本项目最精巧的一个视觉设计：

> *「危险梯度直接映射为明度梯度——深海最暗（安全）、浅滩中灰、冲浪区亮、沙滩近乎纯白（最暴露）。玩家用**亮度**就能判断处境，不需要看 HUD。」*

**这意味着亮度不是一个审美选择，而是一个玩法信息通道。** 必须严格量化，否则该设计失效。

| 区域 | 平均亮度 | 基色 | 危险度 | 玩家应感到的 |
|------|---------|------|--------|-------------|
| **深海 DEEP** | **8%** | `#0A0E17` → `#141C2B` | 安全 | "我在暗处，我看得见他们，他们看不见我" |
| **浅滩 SHALLOW** | **28%** | `#2E3E54` → `#4A5A6E` | 低 | "我开始暴露了" |
| **冲浪区 SURF** | **55%** | `#6E7C8C` → `#8A97A8` | 中 | "我很显眼，但这里有钱" |
| **沙滩 BEACH** | **82%** | `#C7CFD8` → `#F2F5F8` | **最高** | "我完全暴露，无处可藏" |

**验收测试（强制）**：截取四个区域的代表性画面，**去色后**测量平均亮度。若实测值偏离上表 ±8% 以上，该区域配色须返工。

**三条执行约束**：
1. 相邻区域的亮度差 **≥ 20%**，否则层级感消失
2. **禁止**在任何区域使用与危险度不符的亮度（如"明亮的深海"是设计错误，不是美术自由）
3. 实体（鲨鱼、敌人）在每一区的**明度对比**必须保持恒定 —— 鲨鱼在深海是亮剪影，在沙滩是暗剪影，**永远与背景拉开 ≥40% 明度差**

**⚠️ 这条同时解决了可访问性**：亮度是一个不依赖色觉的通道。色盲玩家、低亮度屏幕玩家都能通过明暗判断处境。

#### 5.3.1 深海区（Deep Zone）— 明度 8%

| 项目 | 规范 |
|------|------|
| 主色调 | `#0A0E17` 深渊黑 → `#141C2B` 深海蓝 |
| 雾效 | 黑色雾 alpha 0.4（近）→ 0.75（远），`#0A0E17` |
| 能见度 | 低。距屏幕中心 >400px 的实体开始雾化 |
| 视觉引导 | **光柱**（god rays）：白色梯形，alpha 0.05–0.12，ADD 混合，从顶部斜射，2–4 道，缓慢摆动（周期 8s） |
| 生物发光 | 深海生物用 `#2EE6A8` 生命绿微光点（2–3px，1Hz 呼吸）作为可食提示（⚠️ Standard 色，MVP 用 `#F2F5F8` 替代） |
| 氛围元素 | 缓慢下沉的碎屑（1px，密度 8/屏）、稀疏的巨大生物剪影（仅 `#141C2B`，比背景深一档，不参与碰撞） |
| 特殊设施 | **BANK 结算点**——概念文档锚点：深海光柱 + 结算数字上浮动画。光柱在此处**加宽至 160px、alpha 提升至 0.2**，形成明确的"安全区/落袋区"地标 |
| 情绪目标 | **孤独、压迫、屏息。** 对应概念文档锚点 01「深蓝边境的静默」——玩家在安全时感受到"对岸的光"的吸引力。右侧远处一条极细的琥珀色横线 = 沙滩 = 诱惑也是死地 |

#### 5.3.2 海面过渡区 / 浅滩（Surface Transition / Shallow Zone）— 明度 28%

| 项目 | 规范 |
|------|------|
| 主色调 | `#141C2B` → `#1E2A3D` → `#2E3E54` 三段垂直渐变（用 3 条硬边色阶带，非平滑渐变） |

### 5.4.1 ⭐ 水花两级规格（v1.2 新增 · 承接 DECOY BREACH）

**背景**：我在 v1.1 向文策渊提出 Q3——他设计的"引蛇出洞"高阶技巧中，水花是**被动**产生的，被动的 debuff 玩家无法主动操控，构不成技巧。他认领了这个缺陷，并补出完整机制 **DECOY BREACH（声东击西）**：**冲刺状态中穿出水面**（复合输入，不增加输入维度）触发一次大范围炸水，强制重定向附近敌人 2.5 秒。

**因此水花必须有两级，且必须一眼可辨。**

| | **L1 · 携带拖尾（被动）** | **L2 · 炸水 DECOY BREACH（主动）** |
|---|---|---|
| **触发** | 携带状态持续 | **冲刺 + 穿出水面**（复合输入） |
| **半径** | **40px** | **160px（4×）** |
| **粒子数** | 6/秒，2–3px 方块 | **25–40**，3–5px 方块，径向爆发 |
| **寿命** | 1.2s（沿路径拖尾） | 0.6s（瞬时爆发） |
| **运动** | 沿鲨鱼路径持续生成 | 径向 + 重力抛物线 |
| **附加** | 无 | **环形冲击波**：1px 硬边圆环，0.4s 内 0→180px，抖动淡出 |
| **颜色** | `#F2F5F8` 炽白 | `#F2F5F8` 炽白（**同色，靠规模区分**） |
| **功能** | 给追兵"大致方向"（**debuff**） | **强制重定向**半径内敌人至爆点，持续 **2.5s**（**主动工具**） |

**可辨识性设计（关键）**：**4× 半径差 + 5× 粒子量差**。两级刻意使用**同一颜色**——因为它们的区别是"规模"而非"性质"，玩家需要学会的是"看到大水花 = 那边刚炸过"，颜色相同反而强化了这个认知。

**敌人响应 VFX（新增，归美术）**：被吸引的敌人头顶弹出 `!` 并转向爆点。**复用 §4.3 的 `!` 规格**（`#FF3B3B`，0.3s 弹出 + 0.5s 保持）——**零新素材**。

**代价的视觉表达**（没有代价的技巧会退化成无脑最优解，美术必须让代价**可见**）：

| 代价 | 值 | 视觉表现 |
|------|-----|---------|
| 体力 | −1 格 | 左下体力槽**整格闪灭**（§6.1 已定义），让玩家看到自己失去了冲刺能力 |
| ALARM | +8 | ALARM 条**可见地跳增**一格——玩家必须看到"这一炸让我更危险了" |
| 暴露 | 出水瞬间无遮蔽 | 若直升机在场，探照灯**立即锁定**（光锥收窄 + 变血红） |

**版本范围**：机制本身属 **Standard**，但**两级水花的视觉规格现在就定**，MVP 阶段按两级设计，无需返工。

**Phase 2 验收（文策渊定，美术配合）**：DECOY BREACH 期望收益 ≤ 直接突袭 × 1.2，否则它就是唯一解。美术需确保 L2 炸水的**视觉回报不夸大其收益**——它的反馈强度应低于捕食溅射（捕食是核心动词，炸水是战术工具）。

### 5.4.2 ⭐⭐ 诱饵免疫的视觉表达（v1.3 新增 · v1.4 修订）

**需求（主理人转达，源自 R1 沙盘验证的最终裁定）**：直升机免疫 DECOY BREACH 诱饵，水面单位受吸引。差异必须**一眼可辨**，主理人倾向给明确的"无视"反馈而非纯不响应（纯不响应易被读成 Bug）。

**v1.4 修订：免疫判据从「域」改为「锁定」。** 详见 §5.4.2.4 —— 这是文策渊的裁定，**我接受，因为我原本的方案有硬伤**（见该节）。

> ## **最终规则：炸水只能惊动「在巡视的」，惊动不了「已经盯上你的」。**

| 单位状态 | 例子 | 受诱饵影响 |
|---------|------|-----------|
| **未锁定**（在巡视） | 救生员、摩托艇、拖网渔船 | ✅ 受影响 |
| **已锁定**（有锁定系绳连着鲨鱼） | 直升机、**T4 捕鲨队** | ❌ **免疫** |

**两条支撑理由，各自有独立的视觉证据，互不冲突**：

| 理由 | 视觉证据 | 解释了什么 |
|------|---------|-----------|
| **已锁定的根本没在听噪音** | **锁定系绳**（§5.4.3）——从单位连向鲨鱼的细光束 | 水面上的 T4 为何也免疫 |
| **空中的够不到水花** | **冲击波在水面线截断**（§5.4.2.1） | 空中单位为何免疫 |

**我同意主理人的倾向，并且认为问题可以解决得更好：免疫不该靠"特殊反馈"来表达，应该靠几何 + 状态来表达。**

#### 5.4.2.1 第一层：结构性表达 —— 让水花自己说明它够不到天上 ⭐ 核心设计

这是我认为**最重要的一层**，它让免疫在玩家触发之前就是可预见的。

> **L2 炸水的冲击波环，在水面线处被截断。**

| 表现 | 规范 |
|------|------|
| **冲击波环** | 从爆点扩散，半径 0→160px（0.4s）。**当环的上缘触及水面线时，被裁剪并"摊平"**——不再继续向上，而是沿水面横向铺开、碎成泡沫后消散 |
| **实现** | Canvas `clip()` 到水面线以下；或绘制后由水面层覆盖。**成本近乎为零** |
| **水花粒子** | 全部受重力约束，最高点不超过水面线上方 **60px**。**没有粒子能到达直升机的飞行高度** |
| **爆点位置** | 炸水发生在**水面**，因此其视觉能量天然向上衰减 |

**为什么这层最重要**：

玩家在学习"直升机免疫"之前，先会看到**水花是一个被水面封顶的事件**。于是当直升机无视它时，玩家的反应不是"规则说我不能骗飞机"，而是**"当然——水花根本够不到它"**。

> **这把「教学」变成了「确认」。**
>
> 纯靠"特殊图标提示免疫"，玩家学到的是**个案**（"这种敌人不吃这招"）；
> 靠几何表达，玩家学到的是**原理**（"水花是水面的事"）——**而原理可以迁移到未来任何新单位**。

#### 5.4.2.2 第二层：确认性表达 —— 「瞥见—驳回」+ 系绳不偏移（v1.4 加层）

主理人担心纯不响应被读成 Bug，这个担心是对的。但解法不该是加一个 UI 图标，而该是给一个**有意图的动作**。

**设计：三拍微动画，表达"我看见了，我判断了，我不在乎"**

| 拍 | 时长 | 表现 | 玩家读到 |
|----|------|------|---------|
| **① 瞥见** Glance | 0.15s | 单位**偏航 ~15° 转向爆点**；探照灯/追踪标记**快速收窄并扫向爆点**（0.1s） | "它注意到我了" |
| **② 驳回** Dismiss | 0.25s | 头顶弹出 **`✕` 标记**（2px 描边 `#F2F5F8`，16×16），0.25s 后淡出；探照灯**散开、扫回原方向** | "它判断了，然后放弃了" |
| **③ 恢复** Resume | — | 偏航回正，**航向与速度完全不变**，继续原路径 | "我没有被它骗到" |

## ⭐ v1.4 新增第四拍：**锁定系绳纹丝不动**（文策渊建议，我采纳）

> **在这整个三拍过程中，锁定系绳一次都没有离开鲨鱼——连一帧都没有偏移。**

**这一拍把意思从"我不在乎"升级为"我在乎的不是那个"**：
> **「我听见了，但我的眼睛一直在你身上。」**

**为什么这一拍很关键**：
1. **单帧可读**——玩家不需要看完整个动画，任意截一帧都能看到"光束仍连着我"
2. **它同时是规则的第二条视觉证据**（§5.4.2 表格）：系绳的存在本身就预告了免疫，动画只是确认
3. **它把"免疫"从被动属性变成主动表达**——单位不是"没听见"，是"**选择不理**"

**实现**：系绳在 `Glance` 期间**不参与**单位的偏航变换（它是独立渲染的连线，始终锚定鲨鱼中心）。这个"不跟随"的技术实现，恰好就是这个设计的意义本身。

**黑色喜剧收益保留**：单位"看一眼然后懒得理你，眼睛还一直盯着你"——**玩家的得意技被敷衍了**。这既是功能反馈，也是 D3 要的笑点（§4.5）。

**动画成本**：直升机 3–4 帧（偏航）复用现有 `turn` 逻辑 + 1 个 16×16 的 `✕` 标记 sprite（可复用于所有免疫单位）。**零新素材级别的成本。**

**为什么用「瞥见—驳回」而不是「完全无视」**：
- **完全无视** = 玩家无法区分"没看见"和"游戏没做"，→ 读作 Bug ❌
- **瞥见—驳回** = 明确表达"这是一个**决定**"，→ 读作规则 ✅

**一个额外的黑色喜剧收益**：直升机"看一眼然后懒得理你"，本身就是 D3 黑色喜剧想要的东西——**玩家的得意技被敷衍了**。这个微动画既是功能反馈，也是笑点。（§4.5）

#### 5.4.2.3 第三层：对比表达 —— 同一帧里的两种反应 ⭐ 真正的教学时刻

**单独把每种反应做清楚，不如让它们同时发生。**

当一个水面单位与一个空中单位**同时在爆点范围内**时，同一帧里会出现两个**方向相反**的反应：

```
                    ☁
                 ✕  🚁 ──────────►  （瞥见—驳回，航向不变）
                    ↑ 探照灯扫回
   ──────────────── 水面线 ────────────────
              ↑ 冲击波在此截断
                 💥
              ╱ | ╲
                 │
        🛥️  ←────┘         （被吸引：! + 急转向爆点）
        救生员  !
```

| | **水面单位（受诱饵）** | **空中单位（免疫）** |
|---|---|---|
| **标记** | **`!`** `#FF3B3B` 危险红 | **`✕`** `#F2F5F8` 炽白 |
| **动作** | **急转向**爆点，加速 | 偏航 15° **后回正**，速度不变 |
| **探照灯** | — | 锁定 → 散开 → 扫回 |
| **结果** | 被调度到爆点 | 继续原路径 |

**⚠️ 关键实现要求**：当两种单位同时在范围内时，**两者的反应必须在同一帧内同时播放**（不要排队、不要因为性能降级而丢掉其中一个）。这一帧就是教学时刻，**丢掉任何一个，规则就教不会**。

**两个标记形成清晰的二元词汇**：
- `!` 红 = "**我冲你来了**"
- `✕` 白 = "**我不在乎**"

复用 §4.3 已有的 `!` 规格（0.3s 弹出 + 0.5s 保持），`✕` 用相同时序但更短（0.25s 保持）——**免疫是"更快被驳回"，这个时长差本身也在传递"它根本没当回事"**。

|---------|------|-----------|
| **未锁定**（在巡视） | 救生员、摩托艇、拖网渔船 | ✅ 受影响 |

## ⚠️ 为什么推翻我 v1.3 的方案（我的原方案有硬伤）

v1.3 我提了两个方案，都不成立：

**方案 A（T4 免疫，按"它太强了"解释）—— ❌ 违反我自己刚论证的原则**

我在 §5.4.2.4 上一版写的是「按域分类的规则可以被归纳；按等级分类的规则只能被背诵」。而"T4 太强了所以骗不了"**正是按个体属性的背诵型规则**。

**更致命的是：它会让我自己的测试 B 挂掉。** 测试 B 给一个没见过的新单位让测试者预测是否受影响。若玩家手里的规则是"水面的受影响 + 但特别大只的例外"，那么遇到一个**又大又在水面上**的新单位时，两个启发式打架，预测必然分裂。**我自己说了 B 才是真判据——方案 A 过不了 B。**

**方案 B（T4 受影响）—— ❌ 平衡不答应**

文策渊沙盘：DECOY BREACH 在 k=4（ALARM 79–100）算出 **1.25×**，超了 1.2 验收线。直升机免疫**不是**为了"让直升机显得酷"，而是因为**诱饵必须无法移除致命威胁，只能移除骚扰**。而 T4 在 §4.4 分级就是「致命」——若 T4 能被骗走，k=4 的 1.25× 原封不动地回来，**这个修复白做**。

## 为什么「锁定」三个维度全赢

| 维度 | 「锁定」的表现 |
|------|--------------|
| **规则可见**（可归纳不靠背诵） | 锁定系绳连着鲨鱼，**一眼可见** |
| **通过测试 B**（新单位可预测） | 有系绳 → 免疫；没有 → 受影响。**二元、无例外** |
| **一条规则，不是规则+例外** | ✅ 空中单位免疫只是**推论**（它们出场即带锁定），不是第二条规则 |
| **平衡**（致命单位不可被移除） | ✅ 直升机与 T4 都是锁定单位 |

**而且它比「域」更能通过测试 B**：判断"它在水上还是天上"需要玩家对物理空间做推断；判断"它身上有没有光束连着我"只需要认出一个**被明确画出来的符号**。后者更可靠。

## ✅ v1.5 定稿：系绳 = 身份，不是状态（采纳文策渊二次修正）

系绳不是"正在锁定你"的**状态指示**，而是"**这是一台在猎你的机器**"的**身份标记**。

### 我 v1.4 的方案错在哪（他把位置指出来了）

> - 按锁定判据：无系绳 → 未锁定 → **应受影响**
> - 按几何证据：在空中 → 水花够不到 → **免疫**
>
> **矛盾态原封不动地回来了，只是从"锁定中"挪到了"上场未锁定"。**

**我切的位置偏了一格。** 修「过程」不够，必须修「身份」——**把系绳从状态量改成常量。**

| **①** | **两条视觉证据永远一致** | 致命单位恒有系绳 → 空中免疫严格成为锁定免疫的推论 → **不存在例外区间** |

### 5.4.3 ⭐ 锁定系绳（Lock Tether）视觉规格（v1.4 新增）

**重要性提醒**：锁定系绳现在**不再只是装饰**——它是**诱饵免疫规则的唯一判据载体**（§5.4.2.4）。玩家要靠它判断"这一炸有没有用"。因此它的可读性优先级等同于 HUD 元素。

**⚠️ v1.5 关键定性**：系绳是**身份标记，不是状态指示**（§5.4.2.4）——它是"这是一台在猎你的机器"，不是"它正在锁定你"。**致命单位出场即带，恒常存在，不存在无系绳阶段。**

#### 5.4.3.1 基础规格

| 项目 | 规范 |
|------|------|
| **形态** | 从锁定单位连向鲨鱼中心的一道**细光束** |
| **线宽** | 直升机 **2px** ／ T4 **3px**（更粗更稳，体现级别差异） |
| **结构** | **1px `#0A0E17` 深色包边 + 核心色线** —— 保证在**任何背景明度**下可读（深海 8% 与沙滩 82% 都测过） |
| **颜色** | **血红 `#FF3B3B`** —— 语义正确：系绳 = "你正处于危险中"（§2.3） |
| **色盲模式** | → **电光蓝 `#00C2FF`**（沿用 §9.8 映射表，全项目一致） |
| **动画** | **1Hz 呼吸式明暗渐变**（`alpha = 0.7 + 0.3 × sin(2π·1·t)`）。⚠️ **禁止硬闪**（§9.9） |
| **端点** | 鲨鱼端画一个 **4px 十字准星**（2px 描边血红），明确"被瞄的是我" |
| **渲染层** | L4 主玩法层，**在实体之上、HUD 之下**；不参与视差 |
| **恒常性** ⭐ | **只要该单位在场，系绳就在**。不因"尚未开始追踪"而缺席，不因距离远近而消失 |
| **离屏表现** ⭐ | 单位部分或完全离屏时，**系绳仍绘制，延伸至屏幕边缘外**。见下 |

**为什么用红色**：§2.3 已定血红 = "你自己有危险"。锁定系绳正是这个语义的**最强载体**——它是唯一一个"直接连在你身上"的危险信号。红色在此处的作用不是装饰，是**语义复用**。

**⭐ 为什么离屏也要画系绳**：既然系绳是**身份**，玩家就必须**永远知道"有东西连着我"**。若单位飞出屏幕、系绳随之消失，玩家会误判"我安全了"——而实际上计时仍在走。
> 而且这在观感上很好：**一条红线从你身上延伸出画面外**。玩家看不见敌人，但能看见"线还在"。这比任何 HUD 箭头都更直接地传达"你仍被锁定"。

#### 5.4.3.2 与游戏中其他光束的区分（必须做到不混淆）

本作现在有四类"光束/线"，必须能被区分：

| 元素 | 颜色 | 形态 | 关键区分特征 |
|------|------|------|-------------|
| **锁定系绳** ⭐ | **血红** | 细直线 | ⭐ **唯一连接两个实体的线**（单位 ↔ 鲨鱼） |
| 直升机探照灯 | 炽白 | 宽锥形 | 是"视野"，不是"连接"；覆盖区域而非连线 |
| 深海光柱 | 白色，抖动 6–12% | 宽梯形，静态 | 从屏幕顶部斜射，不从实体出发 |
| 炸水冲击波 | 炽白 | 圆环 | 径向扩散，不连接任何东西 |

**核心区分逻辑**：**只有锁定系绳是"连接两个实体的线"**。这个形态特征不依赖颜色、不依赖亮度，因此在灰度化与色盲模式下同样成立——**这是它为规则载体所必须具备的性质。**

#### 5.4.3.3 直升机与 T4 的家族化处理（文策渊要求"同一视觉家族"）

| | 直升机 | T4 捕鲨队 |
|---|--------|-----------|
| 系绳线宽 | 2px | **3px** |
| 呼吸频率 | 1Hz | **0.7Hz**（更慢 = 更沉稳 = 更致命） |
| 准星 | 4px 十字 | **8px 六边形**（更重） |
| 附加 | 探照灯锥形（复用现有） | **追踪标记**：单位端画一个 6px 三角箭头，指向鲨鱼 |

**共同点（构成家族感）**：同色（血红）、同结构（深包边 + 核心线 + 端点准星）、同呼吸式动画、同"连接实体"形态。

#### 5.4.3.4 状态转换的可读性（v1.5 重写 · 改为身份模型）

系绳的**出现与消失**必须让玩家明确感知，否则玩家会误判诱饵是否有效、计时是否在走。

| 转换 | 表现 |
|------|------|
| **单位登场** | 系绳**从单位端向鲨鱼"射出"**（0.2s 线性延伸——§6.7 位移规则，非缓动）+ 准星在鲨鱼端**合拢**（0.1s）。**这是登场动画的一部分，不是独立事件** |
| **追踪持续** | 1Hz 呼吸 |
| **⭐ 接近断裂（张力预告）** | 见下——这是 v1.5 新增的关键设计 |
| **断裂（玩家脱离视线）** | **绷紧 → 断裂 → 回弹**，见 §5.4.3.5 |
| **重新捕获** | 系绳从单位端**重新射出**（0.15s，比登场更快——表达"它一直知道你在附近"） |

## ⭐ v1.5 新增：张力预告（Tension Telegraph）

**这是我在文策渊"断线必须是可感知事件"基础上的加层。**

他的要求是：断线要有明确的视觉事件（绷紧→断裂→回弹），让玩家知道自己做对了什么。**完全正确。但只做事件，玩家学不会「怎么」断线。**

> **如果断线是一个突然发生的事件，玩家只会归因于运气，不会归因于自己的操作。**

**所以我要在断裂之前加一段可感知的"张力累积"过程**：

| 阶段 | 触发 | 视觉表现 |
|------|------|---------|
| **① 松弛** | 正常追踪 | 系绳 1Hz 呼吸，无明显张力 |
| **② 拉紧** ⭐ | 玩家接近脱离条件（进入深水 / 接近遮挡物，**脱离进度 >50%**） | 系绳**呼吸频率升至 2Hz**、**线宽减细 1px**（视觉上"被拉长变细"）、准星**轻微抖动** |
| **③ 临界** ⭐ | 脱离进度 >80% | 系绳**颜色开始抖动淡出**（有序抖动密度降至 50%，§7.6），呼吸 3Hz（⚠️ 上限 2Hz——**改用视觉抖动密度变化表达紧迫，不靠频率**） |
| **④ 断裂** | 条件达成 | 见 §5.4.3.5 |

**⚠️ 频率约束修正**：③ 原本想用 3Hz 表达紧迫，但 §9.9 硬上限是 2Hz。**改用抖动密度（空间维度）表达紧迫，而不是频率（时间维度）**——这既守住了安全红线，又达成了表达目的。

**这段设计的价值**：
- **把"生路"从突发事件变成可追求的目标**——玩家看到系绳变细，就知道"再往深处游一点就能断"，于是主动去够
- **完全符合文策渊 §7 UX 铁律第 2 条（隐形教程）**：不加文字，靠反馈教会玩家
- **零新素材**——只改线宽、颜色抖动密度、呼吸频率三个参数

## 5.4.3.5 系绳断裂事件（Line Break）⭐

**这是玩家在 ALARM 75+ 的唯一生路，必须做成明确的、可铭记的事件。**

**触发**：脱离视线（潜入深水 / 被地形遮挡）持续 N 秒（数值归文策渊）

**三拍动画（0.6s）**：

| 拍 | 时长 | 表现 |
|----|------|------|
| **① 绷紧** Snap Taut | 0.15s | 系绳**瞬间绷直**（若有弧度则拉平）+ **闪白 1 帧**（`#F2F5F8`）+ 准星**缩至 2px** |
| **② 断裂** Snap | 0.1s | 系绳**从中断开**，断成两段；断点处**迸发 6 个碎片粒子**（2px `#FF3B3B` 方块，径向，寿命 0.3s）<br>+ **顿帧 0.05s**（短，只够被感知，不打断操作）<br>+ **震屏 3px**（轻微） |
| **③ 回弹** Recoil | 0.35s | 两段系绳**分别向两端回弹收回**（0.35s，线性），像断掉的橡皮筋；准星**张开消散** |

**配套**：
- **音效**（交阮和鸣）：短促的"失去目标"音——**断裂的听觉签名**，与捕食的厚重音形成对比（一个是"挣脱"，一个是"命中"）
- **单位转为 `?` 搜索状态**（见 §5.4.3.6）
- **追踪计时归零**——这是玩家真正得到的奖励，必须让他知道

**为什么断裂要做得这么重（相比 `✕` 驳回的轻）**：
- `✕` 驳回是"**诱饵无效**"，是**负面**信息 → 做得轻、快、敷衍 → 玩家感到挫败（这是对的）
- 断裂是"**我成功逃脱了**"，是**正面**信息 → 做得重、有仪式感 → 玩家感到**释然**

**两者情绪相反，所以反馈强度必须相反。** 这是同一套视觉语言里的情绪语法。

## 5.4.3.6 断裂后：`?` 搜索状态（v1.5 补入）

**文策渊的四词汇表没有覆盖"断裂之后"。我补上——因为它有明确的玩法必要性。**

**问题**：断裂后玩家不知道"它还在找我吗"。若无法判断，玩家要么一直躲（浪费时间），要么贸然行动（被重新捕获）。

**规格**：

| 项目 | 规范 |
|------|------|
| **标记** | **`?` 问号**（16×16，`#F2F5F8` 炽白，2px `#0A0E17` 描边），悬于单位头顶 |
| **动画** | 缓慢上下浮动（±2px，1Hz）+ 每 0.8s 轻微左右摆动（表达"四处张望"） |
| **单位行为视觉** | 在**最后已知位置**附近往返搜索，探照灯**无规律扫动**（区别于锁定时的稳定追踪） |
| **持续** | N 秒（文策渊定）后离开；期间若重新发现玩家 → 系绳**重新射出**（0.15s）+ `?` 变回系绳状态 |
| **对诱饵** | **受影响** —— 它失去了目标，正在搜索，噪音会吸引它。这是规则的自然推论，不是新规则 |

**设计收益**：
1. **制造第二段张力**——断裂不是"结束"，是"过渡"。玩家在 `?` 期间既要抓紧跑，又要避开它的搜索路径
2. **给诱饵一个新的战术用途**——断裂后可以用炸水把它**引向错误的方向**。这让 DECOY BREACH 在致命单位面前**并非完全无用**，只是不能直接救命。**这保住了技能的战术深度，又没有破坏平衡**

> **📌 这一条其实是文策渊"清路工具不是救命按钮"定位的完美落点**：诱饵对致命单位**不能用来自救，但可以用来清路**——哪怕是在你刚甩掉它之后。

#### 5.4.3.5 可访问性验证

| 检查 | 结果 |
|------|------|
| 灰度化后可读 | ✅ 系绳是**唯一连接两实体的线**，形态特征不依赖色觉 |
| 色盲模式 | ✅ 血红 → 电光蓝，沿用 §9.8 映射 |
| 明度对比 | ✅ 深色包边保证在任何背景（8%–82% 明度）下均可见 |
| 闪烁安全 | ✅ 1Hz 呼吸渐变，远低于 2Hz 上限（§9.9） |
| 不依赖颜色 | ✅ 形态（连线）+ 端点准星 + 动画（呼吸）三重通道 |

- **HUD 信息优先级**：ALARM > 体力 > COMBO > SCORE。屏幕紧张时（震屏/特效中）优先保证 ALARM 条可读

#### ⚠️ D5 约束：单局 90–150 秒对 HUD 的要求（v1.2 新增）

用户已锁定单局时长 **90–150 秒**。这个时长对 HUD 提出三条硬要求：

**① 零学习成本——HUD 元素总数 ≤5 个**
90 秒的局容不下"熟悉界面"的过程。玩家可能在等车时开一局，没有耐心读 UI。
> 当前 HUD 元素：**ALARM 条 / SCORE / 体力三格 / COMBO / 追捕箭头 = 5 个**。**已达上限，不得再增加。**
> 任何新增 HUD 元素的提案，必须同时说明要移除哪一个。

**② 扫视即可——每个元素的读取时间 ≤0.3 秒**
| 元素 | 读取方式 | 达标 |
|------|---------|------|
| ALARM 条 | 看**长度**（无需读数字） | ✅ |
| 体力 | 数**格子**（3 格，一眼数完） | ✅ |
| COMBO | 看**字号大小**（越大越赚） | ✅ |
| SCORE | 只需知道"在涨"，不需精确值 | ✅ |
| 追捕箭头 | 看**方向** | ✅ |

**③ 无文字教程——首次游玩不需要读任何说明**
- 所有 HUD 元素必须有**自解释的形状**（条=量、格=次数、箭头=方向）
- **只有 SCORE 是文字**，且它是最不需要理解的元素
- 概念文档 UX 铁律：靠场景引导，不靠文字墙

**④ 状态变化必须主动抓眼**（因为玩家不会主动去看 HUD）
- ALARM 跨阈值（25/50/75）时：**条闪一下 + 音效 + 太阳表情变化**——三重提示
- 体力耗尽最后一格：**持续脉动**
- **禁止**仅靠"数值缓慢变化"传达关键信息——在 90 秒的高压局里，玩家看不见

### 6.5 CRT 效果规范 ⚠️ 含安全约束

| 效果 | 参数 | 实现方式 |
|------|------|---------|
| **扫描线** | 每 2px 一条 1px 暗线，alpha **0.12**，`#000000`；以 8px/s 缓慢下滚 | 预生成 2×2 pattern 纹理平铺（**禁止每帧重绘**） |
| **屏幕弯曲** | 桶形畸变，曲率 **0.08–0.12**；边缘拉伸，中心不变 | WebGL 后期 shader（推荐）／Canvas2D 用 CSS `perspective()` + `border-radius` 近似 |
| **色差** | RGB 通道水平偏移：中心 0px → 边缘 **±3px**；红左偏、蓝右偏 | 后期 shader；或三次 drawImage + `globalCompositeOperation='lighter'`（性能较差，仅 LITE 档） |
| **暗角** | 径向渐变，内半径 60%，边缘 `#0A0E17` alpha **0.45** | 预渲染径向渐变图，静态叠加 |
| **荧光余晖** | 高亮像素外扩 1px，`#F2F5F8` alpha 0.3，ADD 混合 | 后期 shader（FULL 档） |
| **噪点** | alpha **0.03**，每 **3 帧**更新一次 | 预生成 4 张噪声图轮播（禁止每帧生成） |

**三档预设**（玩家可在 OPTIONS 中切换）：

| 档位 | 包含效果 | 目标设备 |
|------|---------|---------|
| **OFF** | 无 | 可访问性需求 / 极低端设备 |
| **LITE** | 扫描线 + 暗角 | 中低端设备 / 默认移动端 |
| **FULL** | 全部（含弯曲 + 色差 + 余晖 + 噪点） | 桌面端默认 |

**⚠️ 安全红线（可访问性强制项）**：
1. **禁止全屏高对比闪烁**（白/黑 或 红/黑 交替）
2. **任何闪烁频率必须 < 3Hz**（光敏性癫痫安全阈值；WCAG 2.3.1 要求 <3 flashes/second）
3. 系统在检测到 `prefers-reduced-motion: reduce` 时，**自动降级至 OFF 档**并关闭屏幕震动
4. 色差偏移 **≤3px**，过大会引发视觉疲劳与晕动症

**⚠️ v1.1 修订**：采纳概念文档 §6 更严格的约束（震屏 ≤6 帧 / ≤8px，顿帧 2–4 帧）。v1.0 的 12px Boss 震动已取消。

#### 🔴 v1.2 修正：顿帧的三条规则（P1-7）

v1.1 有三处错误，一并修正：

**① 顿帧时长恢复 0.08s（≈5 帧 @60fps）**
v1.0 定 0.08s，v1.1 误退为 4 帧（0.067s）。文策渊在 v1.1 轮次已明确采纳 0.08s——**这是他采纳我的值之后我又倒退了**。恢复为 **0.08s**。

**② 顿帧是「时序事件」，不是「视觉特效」——不占单屏特效名额**

v1.1 把顿帧列进"四选一"互斥表，但 §7.3 #3 捕食溅射又同时用了"顿帧 + 震屏"，**自相矛盾**。裁决：

> **顿帧不增加视觉信息量，它只是暂停逻辑**。因此它是**正交的时序层**，可与任一视觉特效共存。
>
> - **视觉特效三选一**：色闪 > 震屏 > 扫描线抖动
> - **顿帧**：可与上述任意一个同时发生
>
> 捕食 = 顿帧（0.08s）+ 震屏（4px），符合原设计意图。

**③ 顿帧的触发白名单 —— 受击时绝不触发**

| 场景 | 顿帧 | 理由 |
|------|------|------|
| 捕食成功 | ✅ 0.08s | 核心爽点 |
| 稀有/史诗拾取 | ✅ 0.08s | 高价值反馈 |
| COMBO 达成 | ✅ 0.05s | 节奏点 |
| **玩家受击 / 被眩晕** | ❌ **绝不触发** | ⚠️ **关键**：受击时顿帧会被玩家感知为**卡顿和输入延迟**，而不是打击感。逃生段是全游戏最需要操作流畅的时刻，任何输入延迟都会被放大成"游戏卡了" |
| 搁浅落地 | ✅ 0.08s | 招牌演出，需要"重量感" |

**⚠️ 顿帧是本作性价比最高的反馈手段** —— 0 额外素材，约 8 行代码，打击感提升显著。强烈建议程基岩优先实现。

### 6.7 ⭐ 复古反馈约束裁决（v1.1 新增 · 回应概念文档 §8.3）

> **概念文档提出的问题**：*「§6 UI 风格中的『禁止』清单需要与美术确认是否过严」*——清单为：❌ 柔和粒子系统 / ❌ 渐变发光 / ❌ 平滑缓动 / ❌ 半透明叠加。
>
> **我的答复：方向完全正确，但需要精确化。** 原文表述若被字面执行，会误伤必要手段；若被忽略，画面一定会"糊"。裁决如下：

| 禁止项 | 裁决 | 精确化规则 |
|--------|------|-----------|
| **柔和粒子系统** | ✅ **同意禁止"柔和"，保留"粗粒子"** | 粒子必须使用 **2–5px 硬边方块**，禁止圆形/羽化/径向渐变。概念文档自己要求的水花是「**大块的粗白像素方块**向外炸开，边缘锐利」——这正是我们要的。**禁止的是"柔和"，不是"粒子"** |
| **渐变发光** | ✅ **同意禁止** | 禁止任何径向渐变光晕、外发光。需要"发光"时用 **1px 硬边描边**或**色阶环**代替（例：稀有物光晕 = 2px 硬边外轮廓，非模糊光晕） |
| **平滑缓动** | ⚠️ **部分同意——区分属性** | **⚠️ 关键裁决：位移禁止缓动，缩放/旋转允许缓动。**<br>• **位置**：必须**量化到像素网格**（步进 2px 或整数倍），禁止亚像素插值。像素动画的位移一旦用 ease，会出现"像素在 1px 内抖动"的糊化现象<br>• **缩放 / 旋转**：允许 `ease-out` / `ease-out-back`（这些必然产生亚像素，但视觉上不糊，反而更有弹性）<br>• **alpha**：允许阶梯式衰减（0.75 → 0.5 → 0.25 → 0），禁止连续渐变 |
| **半透明叠加** | ⚠️ **部分同意——区分层级** | **sprite 本体禁止半透明**（实体必须 100% 不透明硬边）；**允许半透明的仅限三类全局后期层**：① 暗角 ② 遮罩 ③ 光柱/探照灯。<br>理由：这三类是"环境"而非"实体"，且去掉它们会让深海完全失去纵深 |

**新增一条 v1.0 未有的硬约束**（源自概念文档 R3 认知过载风险）：

> **同一时刻最多允许一个「屏幕级视觉特效」发生。**
> **视觉特效三选一**：**色闪 > 震屏 > 扫描线抖动**
> 若同时触发多个，按上述优先级执行，其余丢弃。
>
> ⚠️ **v1.2 修正（P1-7）：顿帧不在互斥表内** —— 它是正交的**时序层**，可与任一视觉特效共存（详见 §6.6）。
> 缩放脉冲同样移出互斥表（它作用于整层，不与其他特效争抢视觉带宽）。
>
> 这是概念文档 R3（*「CRT + 震屏 + 色闪 + 大数字叠加致画面糊」*）的直接缓解措施，**已写入程序验收项**。

**程序实现要求**：需要一个**中央特效调度器**（FX Dispatcher），所有特效请求经过它仲裁，同一帧只允许一个视觉特效生效。建议在程基岩的架构中预留。

### 6.8 ⭐⭐ 搁浅演出（Beached）完整美术规格（v1.2 升级 · 落实 D4）

> **用户决策 D4**：把原本的碰撞 Bug 设计化为**全游戏最有戏剧性的一帧演出**。
> **制作标准**：按「**名场面**」标准做，不按「失败提示」标准做。
> **验收标准**：这一帧必须**可截图、可传播**——玩家看到的第一反应是"我要发出去"，不是"我又死了"。

#### 6.8.1 配色例外规则 ⭐ —— 为什么这一帧可以是灰白？

这是本演出最需要解释的一条。本作平时就不是全彩（高饱和仅占 ≤5%），所以这不是"彩色 → 黑白"的切换，而是**"稀疏的强调色 → 零强调色"**。规则如下：

> ## **强调色 = 「可能性」的信号。**
>
> 在本作的语言里，高饱和色从来只出现在**可交互物**上（§1.3）：它意味着"这个东西你可以吃 / 可以拿 / 要躲开"。**强调色的存在 = 场上有你可选择的东西。**
>
> **而搁浅时，玩家没有任何选择。** 你动不了、逃不掉、攻不成，只剩下唯一一个机械的 QTE 输入。
> **因此强调色在这帧失去了它的全部功能——它必须被抽干。**

**三条支撑逻辑**：

1. **语义逻辑**：抽干强调色 = 抽干"可能性"。玩家会在意识到危险之前，**先本能地感到"这一帧不对劲"**。
2. **生理逻辑**：灰度 = 抽干生命力。视觉上等同于"屏住呼吸"，是本作唯一一次让画面"窒息"。
3. **处境逻辑**：搁浅发生在**沙滩区（明度 82%，全场最亮）**。**最亮的区域 + 最少的颜色 = 曝光过度、无处可藏**——这正是"暴露"的视觉本体。

**唯一的例外：QTE 圆环保留强调色。**

> 因为它是这一帧里**唯一还剩下"可能性"的元素**——玩家还能自救。
> 圆环的颜色梯度（炽白 → 琥珀 → 血红）**就是"剩余可能性"的量表**。
> **当圆环变成血红的那一刻，玩家读到的不是"要死了"，而是"可能性正在归零"。**

**可量化验收**：搁浅帧的**非圆环区域**，高饱和色占比 = **0%**。圆环本身不受此限。

#### 6.8.2 鲨鱼姿态（Beached Pose）

#### 6.8.3 游客围观构图（Gawking Composition）⭐

| 项目 | 规范 |
|------|------|
| **数量** | **6–8 个**剪影 |
| **颜色** | `#8A97A8` 亮灰（沙滩明度 82%，用中灰保证剪影可辨；**对比度验证见下**） |
| **排布** | 围成**半圆**，开口朝向画面左侧（深海方向 = 鲨鱼来的方向）。距离鲨鱼 **60–80px**，间距均匀（±10px 随机避免机械感） |
| **姿态** | **静止、滑稽、不构成威胁**。用 §4.2.1 的 `gawking` 表情：两个 1px 点 + 1px 短横嘴 + 直立姿态。**禁止**任何恐慌姿态——他们是来看热闹的，不是来受害的 |
| **高低错落** | 3 种身高（80/100/120px），随机分布。避免"一排同样高的人墙" |
| **偶发动效** | 每 2–3 秒随机一个游客**眨眼**（2 帧）或**微调站姿**。静止中的微小动静会让整个画面活起来，且成本极低 |
| **构图作用** | 半圆把观众视线**收拢到中心的鲨鱼**，同时形成"围观"的心理压迫——**被注视 = 更羞耻 = 更好笑** |

> **修正**：游客剪影改用 **`#6E7C8C` 中灰（约 38% 亮度）**，明度差提升至 **44%**。✅ 达标。

#### 6.8.4 QTE 圆环视觉语言 ⭐

| 项目 | 规范 |
|------|------|
| **位置** | 屏幕正中央（水平居中，垂直居中偏上 60px，避开鲨鱼本体） |
| **内环（目标环）** | 半径 **80px**，**2px `#0A0E17` 描边 + 1px `#F2F5F8` 内描边**（双描边保证在亮沙滩上可读） |
| **外环（收缩环）** ⭐ | 从半径 **140px 收缩至 80px**，耗时 **2.5s**（= QTE 窗口）。**这是"时间可视化"** |
| **颜色 = 剩余时间** | `>60%` 炽白 `#F2F5F8` → `30–60%` 琥珀 `#FF8A3D` → `<30%` **血红 `#FF3B3B` + 2Hz 呼吸式脉动**（非硬闪，见 §4.4 P0-1） |
| **进度填充** | 环内**扇形填充**表示已完成的输入进度（0→100%），颜色 `#F2F5F8` alpha 阶梯 0.25/0.5/0.75 |
| **输入反馈** ⭐ | 每次有效输入：圆环**外扩脉冲 8px（0.1s）** + `thrash` 动画播一次 + 沙尘爆发 8 粒子 + 扇形填充前进一格。**必须让玩家感到"每一次点击都推动了什么"** |
| **输入提示** | 环下方 16px 处显示连打提示图标（手指/空格键图形），2Hz 呼吸。**MVP 必须有，不能靠玩家猜** |

**⚠️ 可访问性**：圆环同时用 **颜色 + 半径（收缩）+ 扇形填充** 三重通道表达剩余时间。**灰度化后仍可辨**（半径与扇形是几何量，不依赖色觉）。这满足"颜色永不作为唯一信息通道"。

#### 6.8.6 为什么值得投入（名场面验收）

这是全游戏唯一一个**玩家主动造成、且被完全展示**的失败状态。它的传播价值在于：

> **看一眼截图就知道发生了什么。**

三者在**同一帧**里共同构成极强可读性：
1. **灰白的画面**（处境：无处可藏）
2. **中央收缩的血红圆环**（时间：正在归零）
3. **一圈静止的围观剪影 + 一只侧躺的瞪眼鲨鱼**（荒诞：黑色喜剧）

**名场面验收标准（新增）**：
> 将这一帧截图**去掉所有 UI 文字**，展示给未玩过本作的人。若 ≥4/5 的人能说出"鲨鱼搁浅了，旁边有人在围观，好像很紧急"——通过。
> 若有人问"这是不是游戏卡住了"——不通过（说明 QTE 圆环的紧迫感不足）。

### 7.4 VFX 通用规范

- **混合模式**：光效类统一 `ADD`（`globalCompositeOperation = 'lighter'`）；粒子类用 `SOURCE_OVER`
- **粒子形状**：一律使用 **2–5px 硬边方块**（不用圆形，保持像素风一致性）——**见 §7.6 裁决**
- **禁止**：径向渐变柔光、模糊、alpha 羽化边缘 —— 这些会破坏像素风
- **生命周期**：单体 VFX 存活 ≤ 1.5s（升级光柱 1.2s 为上限例外）
- **对象池**：所有粒子**预分配 + 复用**，禁止运行时 `new`
- **位移**：须**量化到像素网格**（见 §6.7），禁止亚像素插值
- **淡出**：⚠️ v1.2 改用**有序抖动（dither）**而非 alpha 渐变——见 §7.6

### 7.6 ⭐⭐ 粒子系统裁决（v1.2 新增 · 最终标准）

> **文策渊的提问**（经主理人转达）：他定了「**禁止柔和粒子系统**」以保像素锐利感，但担心这会卡死**水花**与**沙尘**的表现。
> **主理人指示：我的判断即为最终标准。**

## 裁决：**保留禁令，不开例外。**

**但更重要的是：这个担心建立在一个伪命题上——禁令与水花/沙尘根本不冲突。**

#### 理由一：文策渊自己已经写下了答案

概念文档锚点 02 的原文：

> *「水花**不是柔和的粒子**，而是**大块的粗白像素方块**向外炸开，**边缘锐利**。」*

他在一个地方写下了正确的规格，又在另一个地方担心这个规格做不到。**他担心的是"柔和的水花"，而他要求的是"锐利的方块"——两者从一开始就不是同一个东西。**

沙尘同理：§5.4 已规定为 **8×2px 硬边方块**，在明度 82% 的沙滩上用 `#C7CFD8` 硬边块，对比清晰、质感干脆。**不需要柔化。**

#### 理由二：真正需要解决的是"另外三件事"，而不是"柔化"

业界在这个问题上反复踩坑，是因为把三件不同的事混为一谈：

| 真正的议题 | 人们误以为的解法 | **正确解法** |
|-----------|----------------|-------------|
| **① 粒子形状** | 用柔和圆形"看起来更自然" | **必须是硬边方块**。圆的、羽化的在像素画面里会立刻"糊掉"，因为它引入了调色板外的中间色 |
| **② 粒子淡出** | 用 alpha 渐变"看起来更柔和" | **用有序抖动（dither）**。见下——这才是真复古做法 |
| **③ 粒子运动** | 用 ease 缓动"看起来更顺" | **量化到像素网格**。亚像素位移会让像素在 1px 内抖动，视觉上就是"糊" |

**所以："柔化"从来不是这三个问题的解法，它是一个会带来新问题的替代品。**

#### 理由三：硬边方块怎么做出"水"的感觉（给原画的具体技法）

如果有人担心硬边方块会像"彩色纸屑"，那是做法不对。让硬边粒子读起来像水，靠的是**物理与排布，不是柔化**：

1. **尺寸分层**——2/3/4/5px 混用（不要统一尺寸）。统一尺寸 = 纸屑感；尺寸分层 = 自然碎裂感
2. **重力 + 径向初速**——物理曲线承担"水"的动感。**是运动学在表达水，不是纹理**
3. **密度梯度靠数量，不靠 alpha**——冲击点密、边缘疏。**用粒子数量做浓淡，而不是用透明度**
4. **形状靠排布**——"水花冠"（splash crown）是**多个粒子按弧形排布形成的形状**，不是一张柔化的贴图
5. **消散用抖动**——见下

#### ⭐ 采纳文策渊的抖动提案（这是他这轮最有价值的建议）

> **真·复古硬件根本没有 alpha 混合。** NES / 街机基板用**有序抖动（ordered dithering）**模拟半透明——保留 100% 不透明的硬边像素，靠**网点密度**表达"半透过"。

**这彻底解决了"半透明 vs 硬边"的矛盾：我们根本不用 alpha。**

**抖动淡出的实现**：

```
粒子寿命剩余 100% → 抖动密度 100%（实心方块）
               75% → 75%（Bayer 4×4 矩阵，保留 12/16 像素）
               50% → 50%（保留 8/16，棋盘格）
               25% → 25%（保留 4/16，稀疏点阵）
                0% → 消失
```

用 **Bayer 4×4 有序抖动矩阵**，预生成 4 张（或 16 张）抖动图案，按寿命索引取用。**禁止每帧计算抖动**（性能）。

**适用位置（v1.2 统一规定）**：

| 元素 | 处理 | 理由 |
|------|------|------|
| **所有粒子淡出** | ✅ **抖动** | 原 alpha 阶梯衰减的全部替代 |
| **冲刺残影** | ✅ **抖动**（密度 60/45/30/15%） | 修复 P1-6 |
| **光柱 / 探照灯** | ✅ **优先抖动**（密度 6–12%） | 比 alpha 更街机、更统一 |
| **屏幕水珠残留** | ✅ **抖动**（密度 25%） | |
| **冲浪泡沫线** | ✅ **抖动** | |
| **屏幕暗角** | ⚠️ **保留真 alpha** | **唯一例外**：全屏暗角用抖动会产生可见网格纹（低分辨率下尤其明显），得不偿失 |
| **暂停/结算遮罩** | ⚠️ **保留真 alpha** | 同上，全屏后期层 |
| **实体 sprite** | ❌ **100% 不透明，硬边** | 绝不允许任何形式的半透明或抖动 |

#### 抖动的额外收益

1. **更符合街机 authenticity**——这是 1980 年代硬件的真实做法，不是我们"发明"的风格
2. **性能更好**——预生成的抖动图案是普通 sprite，无需 alpha 混合计算
3. **天然规避了"半透明破坏硬边"的全部矛盾**——因为像素始终 100% 不透明

**给程基岩的实现要求**：抖动图案**预生成为 4–16 张小 sprite**（如 4×4 或 8×8），打包进 `atlas_vfx`，运行时按粒子寿命索引取用。**禁止运行时逐像素计算 Bayer 矩阵。**

### 8.3 本作的「不可能三角」

在复古限制下，我们同时追求三者，但**任何两者强化都会挤压第三者**：

```
                    ▲
                   ╱ ╲
                  ╱   ╲
         可读性 ╱─────╲ 调色板克制
              ╱       ╲
             ╱  反馈   ╲
            ╱  强度     ╲
           ▼─────────────▼        · 追求 A：即时可读性（0.3s 判断敌我）
                                  · 追求 B：反馈强度与爽感（震屏/色差/爆发）
                                  · 追求 C：16 色调色板的克制美学
```

**冲突时的取舍优先级（决策规则）**：

> **A 可读性 > B 反馈强度 > C 调色板克制**

**具体裁决示例**：
- 若某个收集物在灰调背景下无法辨识 → **破例增加 1 个强调色**（牺牲 C，保 A）
- 若某反馈效果在低端设备掉帧 → **降低粒子数但保留顿帧与震屏**（牺牲 C/B 的表现规模，保 A 与核心手感）
- 若无，任何情况下**不得**为了调色板纯度牺牲可读性

**我们明确放弃的东西**：
- 环境的细节丰富度（放弃写实水体、复杂背景层次，用剪影 + 雾效 + 光柱代替）
- 角色的细腻表演（放弃 24/60fps 平滑动画，锁定 12fps 定格感）
- 色彩的丰富度（放弃平滑渐变，用 2–3 级色阶硬边）

## 9. 技术美术约束（Tech Art Constraints）

### 9.1 图集（Atlas）规范

| 项目 | 规范 |
|------|------|
| **单张尺寸** | 主力 **1024×1024**；单张上限 **2048×2048** |
| **图集数量** | 上限 **4 张**（`characters` / `environment` / `ui` / `vfx`） |
| **格式** | 像素资产用 **PNG-8 索引色**（体积降低 60–75%）；**仅**暗角/遮罩等真 alpha 后期层用 PNG-24（§7.6）。**v1.2：因改用抖动，PNG-24 用量大幅减少** |
| **打包工具** | TexturePacker / Free-tex-packer（开源），输出 JSON hash 格式 |
| **间距** | 图块间距 **2px**，边缘挤出 **2px**（防止缩放时采样撕裂） |
| **旋转** | **禁用**自动旋转打包（增加渲染复杂度，收益极低） |

**理由**：2048 在部分移动端 GPU 上受限；1024 广泛安全且便于分块加载与热更新。

### 9.2 动画帧率上限

| 类别 | 帧率 | 说明 |
|------|------|------|
| **角色主体动画** | **12fps** | ⚠️ **核心复古质感来源。** 用 24/60fps 做角色动画会彻底破坏像素动画的定格节奏 |
| **冲击类短动画**（冲刺/受击/咬合） | 20–24fps | 短时爆发，与 12fps 主体形成节奏对比 |
| **UI / 特效动画** | 30–60fps | UI 需要顺滑，不受复古限制 |
| **逻辑 / 物理更新** | **60fps（固定步长）** | 与渲染帧率**解耦**（见 §9.6） |

### 9.3 粒子预算（网页性能）

| 项目 | 预算 |
|------|------|
| **同屏活跃粒子上限** | **400**（目标 60fps @1444×880） |
| 单事件粒子数 | 拾取 3–8 / 捕食 25 / COMBO 爆发 40 / 冲刺残影 4 / 升级光柱 20 / 环境常驻 12 |
| **对象池预分配** | 512 个粒子对象，启动时一次性分配 |
| **降级策略** | 帧率 <50fps 持续 1s → 降至 **200**；<40fps 持续 2s → 降至 **100** 且自动关闭 CRT 后期至 LITE |
| **实现禁令** | 运行时禁止 `new` 粒子对象；禁止数组 `splice`（用标记 + 批量清理） |

### 9.4 分辨率适配策略 ⚠️ 需与程基岩对齐

**当前问题**：基准分辨率 1444×880 **不能被 3 整除**（1444/3 = 481.33，880/3 = 293.33），会导致像素缩放出现非整数倍，产生像素抖动。

**✅ 唯一推荐方案（v1.2 定稿）**：改为 **1440×864**
```
1440×864（16:9.6）
  1/2 = 720×432   ✔
  1/3 = 480×288   ✔
  1/4 = 360×216   ✔
  1/6 = 240×144   ✔
  1/8 = 180×108   ✔
```

> 🔴 **v1.2 修正（P2-1）：删除 1440×810 选项。**
> 810 **不能被 4 整除**（810/4 = 202.5），这会连丢 **1/4、1/8、1/16** 三档——而 **1/4 正是 §9.3 降级策略实际运行的区间**。只保留 1440×864。

**备选方案 B**：保持 1444×880，内部渲染缓冲用 **722×440**（1/2），放大 2×。可整除但**放弃 1/3 及以下所有档位**，降级空间不足。**不推荐。**

**推荐缩放流程**：
```
内部渲染缓冲（低分辨率，如 480×288 或 720×432）
        ↓ 整数倍放大（2× 或 3×）
Canvas 显示尺寸（1440×864 或 1444×880）
        ↓ CSS 适配
实际窗口（保持宽高比，letterbox 填充 #0A0E17）
```

**关键 CSS**：
```css
canvas {
  image-rendering: pixelated;      /* 必须，否则浏览器会做双线性插值 */
  image-rendering: crisp-edges;    /* Firefox 回退 */
}
```

**安全区**：所有 UI 距屏幕边缘 **≥48px**（CRT 弯曲会裁切边缘约 3–5%）。

### 9.5 骨骼动画 vs 帧动画 ⚠️ 决策

> **推荐：帧动画（frame-by-frame）为主，程序化叠加为辅。**

| 方案 | 评估 |
|------|------|
| **帧动画** ✅ **采用** | ① 复古街机质感要求"定格"节奏，帧动画天然契合<br>② 无需引入运行时（Spine 运行时 ~300KB + 商业授权）<br>③ 网页加载更快，渲染更简单<br>④ 帧数可控（鲨鱼总计 **83 帧**，见 §4.1.5）<br>⑤ 与固定调色板工作流天然兼容 |
| **骨骼动画** ❌ 不采用 | ① 商业授权成本（Spine 专业版 ~$349/席位）<br>② 骨骼插值产生的平滑变形与像素风格冲突<br>③ 运行时开销（顶点变换 + 批处理中断）<br>④ 对小团队是过度工程 |
| **程序化切段** ✅ 局部采用 | 用于**8 方向转向**与**身体 S 波**：将鲨鱼切为 头/身/尾 3 段 sprite，程序控制旋转与位移。成本远低于骨骼，效果足够 |

**若未来确需骨骼**：推荐 **DragonBones**（免费开源）而非 Spine（商业授权）。

**混合方案（推荐落地）**：
```
主体动作  → frame-by-frame sprite（8 帧 swim 循环等）
次级动态  → 程序化叠加层：
             · 冲刺残影（4 个半透明副本 + 位移）
             · 尾鳍延迟摆动（尾部单独 sprite，旋转 ±8°，相位滞后 2 帧）
             · 受击闪白（整体 tint 叠加）
             · 粒子系统（水花、气泡）
```

### 9.9 🔴 光敏性癫痫安全：三者独立开关方案（v1.2 新增 · 硬红线）

主理人指定的硬红线：*「CRT 扫描线抖动、色闪、震屏三种效果**必须可独立关闭**，闪烁频率 ≤3Hz，首次启动需提示。」*

**落实如下。**

#### 9.9.1 五个独立开关（不是三档预设）

v1.0/v1.1 的 CRT「OFF / LITE / FULL」三档是**打包预设，无法满足"独立关闭"**。已改为**正交的独立开关组**——CRT 三档仅作为快捷方式保留。

| # | 开关 | 默认值 | 关闭后的替代反馈 | 存储键 |
|---|------|--------|---------------|--------|
| 1 | **屏幕震动** Screen Shake | 开 | 以「**顿帧 + 色闪**」替代打击反馈（不损失手感） | `opt.shake` |
| 2 | **屏幕闪烁** Flash（色闪 / 闪白 / ALARM 脉动） | 开 | 所有闪烁改为**常亮**（保留信息，去掉闪变） | `opt.flash` |
| 3 | **扫描线抖动** Scanline Jitter | 开 | 扫描线保持**静态**（仍显示，但不抖动） | `opt.jitter` |
| 4 | **CRT 后期** CRT Post | FULL（桌面）/ LITE（移动） | → OFF（完全关闭） | `opt.crt` |
| 5 | **粒子密度** Particles | 100% | 100% / 50% / **0%** | `opt.particles` |

**⚠️ 关键要求**：这 5 个开关必须**两两正交**——任意组合都要能正常工作，且**组合后不能出现"关掉了震屏但打击感完全消失"**的退化。关闭震动时必须自动启用「顿帧 + 色闪」作为补偿（这是文策渊在 UX 规格中确认的）。

#### 9.9.2 频率硬上限：2Hz（比要求的 3Hz 更严）

| 效果 | v1.1 值 | **v1.2 值** | 说明 |
|------|---------|-----------|------|
| T4 敌人频闪 | 3Hz ❌ | **2Hz** | 3Hz 不满足 `<3Hz` |
| 全局频闪上限 | 3Hz ❌ | **2Hz** | |
| 扫描线抖动 | ≤3Hz | **≤2Hz** | |
| ALARM 条闪烁 | 2Hz | 2Hz ✅ | 无需改 |

**⚠️ 并且全部改用「呼吸式明暗渐变」，禁用硬 on/off 切换**（§4.4 P0-1）：

```js
// 呼吸式：亮度连续往复，无突变
alpha = 0.6 + 0.4 * Math.sin(2 * Math.PI * f * t);   // f ≤ 2Hz

// 禁止：硬切换（亮度突变是光敏性癫痫的主要诱因）
alpha = (t % period < half) ? 1.0 : 0.0;             // ❌
```

**为什么同时收频率和改形式**：硬 on/off 的**亮度突变**才是主要诱因，而非频率本身。呼吸式渐变**视觉上一样急促、一样抓眼**，但亮度连续变化，风险大幅降低。**——这样既守住了安全，又保住了威胁等级这个冗余通道（不必为安全而砍掉它）。**

