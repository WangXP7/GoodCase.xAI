## 1. 视觉身份定义（Visual Identity Statement）

### 1.1 一句话视觉主张

> **「这是一个被阳光偏爱过的、有人住着的家——你站在屋檐下，往里看一只正在过它自己小日子的猫。」**

我们做的不是"游戏场景"，是"被微缩成手办的、暖光浸润的、有生活痕迹的小屋"。**所有视觉决策都服务"同住感"**——玩家是室友，不是主人；视觉要让玩家相信"这间屋子真的住着一只猫"，而不是"这关卡叫 EAVES"。

### 1.2 三个视觉形容词

> **温 · 软 · 慢**
> （Warm · Soft · Slow）

| 形容词 | 具体含义 | 可验证的落地标准 |
|--------|---------|-----------------|
| **温** | 暖色调、柔光、生活温度 | 主光色温 3200–4500K（暖白）；任何"冷光"仅限窗外月光/雪夜；环境色温与时刻严格对应（§2.4） |
| **软** | 圆角、无硬切、轻微不规则的手作感 | **无锐边**：所有家具/猫的模型 100% 倒角（bevel）；**法线贴图有微噪点**（手捏感）；**禁用镜面金属**（仅允许高光偏弱漆面） |
| **慢** | 时间过得慢、动效不赶、节奏留白 | 关键动画缓动曲线偏 ease-out + 0.3–0.8s 时长；**禁止**任何 <0.1s 的瞬时反馈；24h 光照以真实秒级推进 |

### 1.3 不是什么（Negative Definition）⚠️ 关键

这是本作与市面 90% 养猫 / 治愈放置类游戏的分水岭。**任何以下风格元素出现一次即视为风格失控**：

| ❌ 不是什么 | 为什么 |
|------------|-------|
| ❌ **空泛套话式"治愈"**（粉色 + 浅蓝 + 满天星 + 卡通猫爪） | 概念文档 §1.2：用户**明确反感**空泛套话；要的是"有质感的手作"而非"二次元萌系" |
| ❌ **冷淡的技术演示风**（灰、白、纯几何体、breath-minimalism） | 概念文档 §1.2：用户**明确反感**冷淡风；本作要"家"不要"展厅" |
| ❌ **粒子堆砌 / 音乐可视化 / 强制爆点** | 概念文档 §1.3 反目标；本作无 IAP、无对战、无挑战，**不需要任何刺激元素** |
| ❌ **静态雕塑感**（猫摆在一个动作上一动不动） | 支柱三"猫性"：猫必须有自主行为；静态会立刻暴露"这是贴图" |
| ❌ **2D 像素 / 复古 LCD 屏模拟** | 用户已指定 3D 高模方向；2D 是其他项目（《潮线》即用） |
| ❌ **写实主义**（毛囊级皮肤、真实毛发 PBR） | 移动端 60fps 不允许；且与"微缩手办"的气质相违 |
| ❌ **Q 版二次元**（大头小身 / 黑眼豆豆眼 / 桃心嘴） | 与"handcrafted 黏土感"冲突；本作猫是"被手捏出来的"而非"被画出来的" |
| ❌ **真花真草**（高清照片纹理） | 违反"微缩感"——照片级纹理会让画面"破功"成现实照片 |
| ❌ **震屏 / 色闪 / 顿帧**作为反馈手段 | 概念文档硬约束；玩家被默认设置成"默认静音"——视觉也不能震 |

## 2. 色板系统（Color Palette）

### 2.0 色彩总则：「暖度 = 时间，灰度 = 距离」（全章最高原则）

> **色彩不是装饰参数，是信息通道。**
> 在本作中，色温编码"现在是什么时间"，饱和度编码"这个物体离玩家有多近"。

| 通道 | 编码什么 | 规则 |
|------|---------|------|
| **色温** | 当前时刻 | 晨光 = 4500K（冷白偏暖）→ 正午 = 5500K（中性白）→ 黄昏 = 3200K（深暖）→ 夜晚 = 2700K（极暖 / 含一点蓝） |
| **饱和度** | 距离 | 近景物件饱和度 60–80%；中景 40–60%；远景 20–40%；窗外 10–25%（越远越褪色） |
| **明度** | 视线焦点 | 玩家当前注视区域 ±15% 内的明度，比周围高 8–12%——**视觉无意识地把注意力引到该处** |

### 3.0 3D 高模在网页上的可行性判断 ⭐ 必读

> **主理人风险登记（必正面回应）**：「3D 高模」与「网页即时加载 + 移动端 60fps」存在直接冲突。

**我的最终判断**：**PASS（可行），但必须执行以下五项工程级取舍**——

| # | 取舍 | 落地 |
|---|------|------|
| **R1** | **不是"全高模"** | 资产分 A/B/C/Shell 四档精度（§3.1）。**仅"猫 + 5 件焦点家具"是 A 档**，且 **A 档视口内总和 ≤ 48k（移动）/ ≤ 100k（桌面）**（AR-1） |
| **R2** | **不是"全实时"** | 光照分两层：**实时动态光 ≤ 3 个**（1 directional + 1 hemisphere + 1 point，AR-7）；间接光 / 反射 / 软阴影**全部烘焙到 4 套 lightmap**（RUL-1 / AR-2） |
| **R3** | **不是"全 PBR 实时"** | 静态 / 远景 / 不需要动态光的物体，**材质烘焙到 Atlas 贴图**。v1.1 拆为 **三张**：Hero 2048²（P0）+ Deco 1024²（P1 懒加载）+ Shell trim 512²（P0）——见 §3.3.1 与 §3.7 的裁决 |
| **R4** | **不是"全毛发"** | 猫的毛发 **不实时计算**（§4.4）：MVP 用 **纯法线贴图烘焙**（方案 ④）；Standard 升级为 **≤ 40 张 alpha-hash 卡片**（AR-12），仅头 + 尾，仅近景档 |
| **R5** | **不是"全 60fps 全开"** | 移动端**至少 3 档降级**（§8.4），最低档降至 30fps + 砍光 + 降材质 |

**核心理念**：**"高模"指的是玩家目光所及之处**——猫、沙发、玩家当前在交互的物件。其余一律可以降级。这就是为什么本作**必须**做"等距微缩"——微缩的尺度感本身就在告诉玩家"这是模型不是真实世界"，**因此降级远景不会穿帮**。

### 3.4 材质策略（PBR 实时 vs 烘焙 vs 风格化）⭐ 主理人必读

> **回应文策渊问题**："手作黏土感"如何在 3D 引擎中通过材质实现？

**答案 = 三个通道的协同**：

| 通道 | 实现 | 对应美术感觉 |
|------|------|------------|
| **① 高 roughness + 零 metalness** | 全部材质 `roughness ≥ 0.6`，`metalness ≤ 0.05`。**禁用任何 metallic ≥ 0.5** | "不反光、不塑料"——黏土与毛线的基础 |
| **② 法线贴图微噪点** | A/B 档法线贴图叠加 5–10% 的**细碎高低起伏噪点**（程序生成，非手画） | "被手捏出来的"——参考图右半的黏土摆件表面那种不规则感 |
| **③ 边缘倒角 + 软阴影** | A 档所有硬切边 100% 倒角（bevel 0.5–2mm），**禁用任何 90° 直角** | "软"——不刺眼、不工业感 |

**烘焙 vs 实时光照取舍规则**：

| 物件类型 | 烘焙 / 实时 | 理由 |
|---------|-----------|------|
| 接受动态光（窗光、台灯光） | **实时** | 这些光会动（24h 循环 + 开关灯） |
| 仅受环境光（顶光、窗外漫射） | **烘焙到 lightmap** | 不动的光不花实时算力 |
| C 档（远景 / 装饰） | **完全烘焙到 Atlas 的 RGBA** | 一张图搞定，零实时成本 |
| 主角（猫） | **实时 PBR** + **额外 Subsurface Scattering**（次表面散射） | 猫的"有肉感"靠 SSS |
| **🆕 L4 局部补光（窗光带、灯罩内）** | **取消实时光** → 改 **emissive 材质 + 烘焙进 lightmap 的假光斑** | **AR-7**：实时光上限降到 3。美术侧在烘焙时手动补光斑，零运行时成本，且更符合"烘焙优先"（§3.0 R2） |

> ⚠️ **v1.1 · morph normals 关闭后的材质补偿**（反对 ② 的落地）
> AR-4 关闭 morph normals 后，耳朵压平 / 眼皮眯起的区域**法线不跟随形变**，在晨/昏斜射光下会出现"贴纸感"。三条补偿，**成本 ≈ 0.5 人日，0 显存**：
> 1. **shader uniform `faceShadowBias`**：`morphWeight > 0` 时同步下调该区域的 SSS 强度与 rim light 强度，让形变区在光照上"暗下去"，视觉上弥补法线不变
> 2. **顶点色 AO 预烘焙**：猫的 albedo 在耳内侧 / 眼周 / 嘴角预烘一层 AO，使形变区自带暗部（顶点色 R 通道）
> 3. **验收门槛**：Spike A 必须同时出「晨光下飞机耳 + 眯眼」的定妆图，与开 normals 版本并排；**ΔE > 5 或主理人肉眼可辨 → 重开 AR-4**

**风格化材质例外（仅 2 处）**：
- 窗外的雨滴 / 玻璃水雾：用 **Alpha 粒子叠加 + 折射 shader**（实时，不烘焙）
- 猫的瞳孔：用 **Emissive 自发光**（实时，但 emissive intensity ≤ 0.3，不刺眼）

### 3.7 🆕 AR-10 裁决 · 环境 Atlas 分辨率（必答 1）

> **程序的提问**：首屏余量仅 **6%**（3.3 MB / 3.5 MB）。若把环境 Atlas 从 2048² 降到 1024²，余量可提升到 **27%**（−0.75 MB）。
> **主理人的裁定**：这是美术的决策，不是程序的。**以下是我的裁决。**

#### 3.7.1 裁决结论

> ## **分级采纳。不整体降，也不整体留。**
>
> | Atlas | 裁决 | 首屏 |
> |-------|------|------|
> | **Hero（近景可辨识细节）** | **保持 2048²** | **P0** |
> | **Deco（中远景装饰）** | **降到 1024²** | **P1 懒加载** |
> | **Shell trim（墙/地/天花 tiling）** | **512²** | **P0** |
>
> **净效果：首屏 −1.04 MB（优于程序的 −0.75 MB），首屏余量从 6% → ≈ 35%，且近景物件反而比 v1.0 更清晰。**

#### 3.7.2 为什么不是"全降 1024²"——逐物件的模糊评测

v1.0 是一张 2048² 装 **30+ 件**，实测有效密度约 **334 px/m**（1 texel ≈ 3 mm）。若整体降到 1024²，密度跌到 **≈ 84 px/m**（1 texel ≈ **12 mm**）。在近景档（正交 viewSize 2.4 m，屏密度 533 px/m）下逐物件评测：

| 物件 | 细节尺度 | 1024² 下的 texel 数 | **判定** | 处置 |
|------|---------|------------------|---------|------|
| **书脊文字**（你问的） | 字高 ≈ 4 mm | **0.33 texel** | ❌ **完全不可读**，退化为一道色带 | 见 §3.7.3 的两条修正 |
| **地毯纤维**（你问的） | 纤维间距 ≈ 1.5 mm | 0.13 texel | ✅ **可接受** | 纤维本就是高频噪声，降采样后变低频斑驳，观感上"更柔"，不穿帮。**且玩家要看见的"单根猫毛"是 Line 几何（不进 Atlas），不受影响** |
| **木纹**（你问的） | 纹理周期 ≈ 8 mm | 0.67 texel | ✅ **不受影响** | 木纹只出现在 A 档（茶几 / 书架，各自独立贴图）与地板（Shell trim tiling）。**A 档与 Shell 都不在环境 Atlas 里** |
| **画框内容（3 幅手绘画）** | 笔触 ≈ 3 mm | 0.25 texel | ❌ **笔触全糊**，变成色块 | **进 Hero 2048²** |
| **挂钟刻度 / 日历数字** | 数字高 ≈ 5 mm | 0.42 texel | ❌ 不可读 | **日历走独立 512² 日期图集**（纹理 swap，本就不该进 Atlas）；挂钟进 Hero |
| **抱枕织物走线** | 线距 ≈ 2 mm | 0.17 texel | ✅ 可接受（走线可改由法线表达） | 进 Hero（因为它常与猫同框） |
| **盆栽叶片** | 叶脉 ≈ 2 mm | 0.17 texel | ⚠️ 边缘 | 进 Hero（近景常出现在沙发旁） |
| **小摆件 / 灯罩 / 墙挂 / 桌布褶** | ≥ 15 mm 的低频形 | ≥ 1.25 texel | ✅ **可接受** | **进 Deco 1024²** |
| **窗外树 / 鸟** | 剪影级 | — | ✅ 可接受 | **进 Deco 1024²**（本来就是 silhouette） |

**结论**：真正需要 2048² 的只有 **12–16 件**（书、画、钟、日历、碗、玩具、抱枕、地毯、盆栽）；其余 **25–30 件**是中远景的低频形状，1024² 完全够。

#### 3.7.3 两条必须同步落地的修正（否则 2048² 也救不回来）

| # | 修正 | 内容 |
|---|------|------|
| **M-1** | **书脊文字的验收标准改定义** | 在等距微缩尺度下，书脊文字**本就不应是可读的**。它是"暗示有字"的纹理，不是可读文本——要求它可读，等于要求一个 12 mm 宽的书脊承载 6 px 高的字，这在任何分辨率下都是错的。<br>**新验收标准**：能读出**横向的深浅条带**（暗示书名烫金 + 书脊压线），条带数 = 3–5 条，色取 `#C9A87C` 旧金 C06 / `#5C4030` 胡桃 E06 交替。**不要求可读字。** |
| **M-2** | **日历 / 挂钟走独立图集，不进 Atlas** | 日历是**每日 swap 的动态纹理**，挂钟是指针转动的动态 UV。它们**本就不该进静态 Atlas**（swap 会污染 batch）。独立 512² 日期图集（31 天 + 12 月），与墙 Shell 同 batch，**0 额外 draw call**。 |

### 4.1 品种方向与体型比例

**决策**：**单一品种方向 = 短毛家猫（Dsh，短毛家养猫）**，**体型中性**。理由：
- 短毛是**毛发技术最友好的品种**（长毛需要更多 Hair Cards，对移动端压力巨大）
- 家猫 vs 纯种：更"普通"、更像"家里那只"，契合"同住感"
- 中性体型：成年体长 **48cm / 高 28cm / 体重 4.5kg**（参考图右半的圆身猫，柔软不瘦削）

**体型比例（猫的"3:5:2"卡通化）**：

| 部位 | 比例 | 备注 |
|------|------|------|
| 头 : 身 : 尾 | **3 : 5 : 2** | 略放大头部为表情留空间 |
| 头 : 身（高） | **1 : 1.2** | 圆身、略矮、不瘦长 |
| 耳 : 头（高） | **1 : 2.5** | 耳朵大小适中（太大显凶，太小显弱） |

### 4.4 毛发技术方案 ⭐⭐ 主理人必读 · 关键工程决策

> **回应文策渊问题**：3D 高模猫在移动端的毛发方案是什么？

**对比与最终推荐**：

| 方案 | 视觉品质 | 性能（移动端 60fps） | 开发成本 | 推荐 |
|------|---------|-------------------|---------|------|
| **① 实时 Hair Cards**（几何毛发片 + Alpha 透贴） | ⭐⭐⭐⭐ | ❌ **不可行**——猫 + 4 件 A 档 + 4 个动态光，移动端三角面与 fill rate 双重爆炸 | 中 | ❌ |
| **② 实时 Shell Fur**（多层半透明壳） | ⭐⭐⭐ | ❌ 不可行——动辄 50+ 渲染层 | 中 | ❌ |
| **③ 体积渲染（Volumetric Fur）** | ⭐⭐⭐⭐⭐ | ❌ **绝对不可行**——仅桌面端 4K 才考虑 | 极高 | ❌ |
| **④ 纯法线贴图烘焙（Mesh + Normal）** ⭐ 选定 | ⭐⭐⭐ | ✅ **完美**——单张 1024² 法线贴图，零额外几何 | 低 | ✅ **MVP 推荐** |
| **⑤ 烘焙毛发卡片 + 动态法线（Hybrid）** ⭐ Standard 升级 | ⭐⭐⭐⭐ | ⚠️ **可接受**——仅在近景档启用，卡片 **≤ 40**（AR-12，v1.0 的 200 作废） | 中 | ✅ **Standard 升级方案** |
| **⑥ XGen / Houdini 程序化毛发** | ⭐⭐⭐⭐⭐ | ❌ 不可行——烘焙后即方案 ④/⑤ | 极高 | ❌ |

**最终推荐（双轨）**：

| 阶段 | 方案 | 理由 |
|------|------|------|
| **MVP** | **④ 纯法线贴图烘焙** | 零性能风险；视觉完全够用（参考图右半的猫就是"几乎平涂 + 强法线"的微缩感） |
| **Standard** | **⑤ 烘焙毛发卡片**（仅头部 + 尾巴） | 给"被摸"瞬间的毛发形变；身体仍用方案 ④ |

> ⚠️ **v1.1 · AR-12 收紧（反对 ④ 的落地）**
> v1.0 的「≤ 200 张卡片」作废，改为 **≤ 40 张 alpha-hash 卡片**。我的配套规定：
> - **全部 40 张给头 + 尾**（头 26 / 尾 14），**身体不给**——身体仍走方案 ④ 法线烘焙
> - **只在近景档（正交 viewSize ≤ 1.2 m）与日记快照（附录 A）启用**；中远景档与移动 L 档**完全不加载**
> - Atlas **512²** → 单卡 UV ≈ **81 × 81 px**。近景档屏密度 533 px/m，一根 8 cm 的耳后绒毛 ≈ 43 px 屏宽 → **超采样 1.9×，够用**
> - 启用时**同时开 alpha-hash 的 dither 抖动**，禁用 alpha blend（避免排序问题与 overdraw）
> - **性能红线**：启用后中端移动帧时间涨幅 **≤ 1.0 ms**，超出即自动降级回方案 ④

**方案 ④ 的具体实施**：
- 单张 1024² 法线贴图（细碎不规则起伏，模拟毛流）
- 单张 512² SSS 贴图（次表面散射，模拟"有肉感"）
- 身体使用 **单色 PBR（`#E8B894` 奶茶色）** + 弱 AO 卡斑（深浅不均，模拟"有几块深斑"）
- **关键约束**：猫的轮廓必须**有"软边"**——做法是模型边缘**微倒角** + 法线贴图边缘**微微不规则**（不能是刀切边）

### 4.5 眼球与瞳孔表现 ⭐ 情绪核心

> 猫的瞳孔变化是**重要情绪通道**——瞳孔大小受光线影响（强光收缩、暗光扩张），但也受情绪影响（兴奋扩张、害怕扩张）。本作必须**用瞳孔同时编码光线与情绪**。

**实现方案**：

| 通道 | 编码 | 实现 |
|------|------|------|
| **虹膜颜色** | 固定（按花色） | `#5A8F7A` 薄荷绿（黄绿猫）or `#3E5C7A` 牛仔蓝（蓝眼白猫） |
| **瞳孔大小** | 光线 + 情绪叠加 | Shader uniform：`pupil_dilate = base + emotion_offset + light_response` |
| **眼白比例** | 情绪（惊吓时眼白外露） | ⚠️ v1.1：不再是独立 blend shape —— 由 `m_Eye_Wide` 1.0 承担（见 §4.3.0） |
| **自发光** | 暗光下"眼睛会发光" | Emissive intensity = 0.1 + (1 - light_intensity) × 0.4 |
| **慢眨（Half-blink）** | 信任/满足 | 2 秒缓动（关键信任信号，**必须能被玩家注意到**） |

**MVP 锁定虹膜色 = 薄荷绿 `#5A8F7A`**（最"通用"的猫眼色，与本作整体暖调和谐）。

|---|---|
| **crossfade 时长** | **0.8 s 真实秒**（RUL-1 明文，不可调） |
| 插值曲线 | `smoothstep(0, 1, t / 0.8)`（**不是线性**，避免起止的"速度突变"被察觉） |
| 触发条件 | 过渡进度跨过 0.5 **且** `crossfadeDone == false`（保证每次过渡只播一次） |
| 边界情况 E-L1 | 玩家恰好在**中点 ±0.5 游戏分钟进入** → **不播放淡入**，直接设 `lightMapMix` 为按进度算出的静态混合值。理由：一进游戏就看到淡入，会被读成"加载完成动画" |

**美术侧的烘焙要求**（这是我给烘焙工序的硬规格）：

1. **4 套的曝光必须对齐**：同一像素在 4 套里的"漫反射基色"差异**不得超过 ±12%**。否则 crossfade 会被读成"整屋闪了一下亮度"，而不是"光在变"。
2. **禁止在 lightmap 里烘焙任何"会动的东西"**：猫、可移动家具、窗帘、玩具**一律不进 lightmap 的投影**（它们由实时 shadow 或 blob shadow 承担）。
3. **假光斑的手绘补光**：L4 取消后，窗光带与灯罩内的辉光由我**在烘焙后手动在 lightmap 上补一层柔和亮斑**（Photoshop 层，ADD 混合），再重新打包。这是"烘焙优先"的正确用法——**把实时成本换成美术的一次性劳动**。

#### 5.4.3 季节 / 天气（Standard 阶段，MVP 仅"无季节 + 晴"）· AR-3 落地

> ⛔ **v1.0 的「季节：4 套 lightmap × 4 套窗外景物 = 16 套」作废。**
> **季节与天气一律不改 lightmap。** 只允许两个通道：**实时主光（色温 / 强度）** + **全屏色彩分级 LUT**。

**通道一 · 主光**（参数见 §2.3.2 的完整表）

| 变量 | 实现方式 | lightmap 成本 |
|------|---------|--------------|
| 季节色温 | 主光 `colorTemp` 偏移（春 ±0 / 夏 +200 K / 秋 −100 K / 冬 −300 K） | **0** |
| 季节昼长 | **改变 4 个 slot 的时刻边界**（查表 + 7 天线性插值）——光"几点天亮"变了 | **0** |
| 天气强度 | 主光 `intensity` ×（晴 1.00 / 阴 0.55 / 雨 0.35） | **0** |
| 天气色温 | 主光 `colorTemp` +（0 / +300 / +200 K） | **0** |
| 天气投影 | **仅晴天开 shadow map**；阴/雨天关闭（漫射光本无投影）→ **反而省 0.5–1.0 ms** | **0** |

**通道二 · 色彩分级 LUT**（MVP 用参数化 lift/gamma/gain/sat/temp，**美术不产出 LUT 资产**；Standard 若需精确调色再上 32³ 3D LUT，0.14 MiB）

- 季节 4 组 × 天气 3 组 = **12 组常量 × 8 float = 384 B**
- 参数值见 §2.3.2

**其他仍走模型 swap 的季节资产**（不走 lightmap）

| 项 | 规格 |
|---|------|
| 季节窗外 | **4 套 C 档树**（各 ~1.5k tris / ~80 KB glb），按需加载当前季 1 套 + 预取下一季 |
| 季节可换道具 | **~12 件小道具**（各 ≤ 800 tris），合计 ~200 KB |
| 切换时机 | **必须在玩家离线时执行**（窗外模型 swap 有 ~15 ms hitch），GDD PH2b §3.5.4 / E-L3 |

#### 5.4.4 🆕 后处理管线顺序（AR 新增② · 不可调换）

```
scene render → [ACESFilmicToneMapping：Three.js 内置，在 material shader 末尾执行]
             → RT
             → tilt-shift（1/4 降采样模糊带 ×2 + 边缘暗角准备）
             → 色彩分级（季节 / 天气 LUT）        ★ 必须在 ACES 之后
             → vignette（边缘暗角 0.15）
             → screen
```

| # | 为什么这个顺序 | 违反的后果 |
|---|--------------|-----------|
| 1 | **色彩分级必须在 ACES 之后** | 若在 ACES 之前，季节/天气的调色会被 ACES 再压一遍：冬天要的"低饱和冷调"被 ACES 的对比曲线拉回，**美术在 DCC 里调好的参数与运行时不一致** |
| 2 | **tilt-shift 必须在色彩分级之前** | 若颠倒，模糊会把分级后的色彩边缘再混一次，**在模糊带与清晰区的交界处产生色边（color fringing）** |
| 3 | **vignette 放最后** | 暗角是对最终画面的裁切，必须在调色后，否则会被 LUT 拉回来 |

**各档后处理开关**（与 AR-9 的 DPR 联动，见 §5.5）

| 档 | tilt-shift | 色彩分级 | vignette | 后处理总预算 |
|---|-----------|---------|---------|------------|
| **H 高端** | ✅ 全开 | ✅ | ✅ | 1.91 ms |
| **M 中端** | ✅ 开（降采样从 1/4 改 1/8） | ✅ | ✅ | 0.79 ms |
| **L 低端** | **✅ 保留**（见反对 ③） | ✅（参数化，成本极低） | ❌ 关 | 0.35 ms |

> 🔴 **反对 ③ 的落地**：v1.0 §8.4 写「L 低端档后处理全部关」。**我要求 L 档保留 tilt-shift。**
> 理由：tilt-shift 是"等距微缩"这一视觉语言的**唯一载体**（§5.5）。关掉它，本作会退化成"一个普通的低模 3D 房间"。而 vignette 只是装饰，可以关。
> **代价**：L 档 DPR 已被压到 1.0，fill rate 紧张 → **补偿方案**：L 档 **不加载 Deco Atlas 1024²**（P1 也不加载）、**猫仍保持 LOD0**、**禁用毛发卡片**。省出的 fill rate 全部留给 tilt-shift。

### 5.5 相机与构图规格

| 参数 | 规范 |
|------|------|
| **投影** | **正交投影（Orthographic）**——保留微缩感（**禁用透视投影**，会破坏 tilt-shift） |
| **FOV 等效** | 35mm（正交下不适用，但作为参考） |
| **相机角度** | **俯视 30°**（俯角），**方位角 45°**（从东南角看） |
| **Tilt-shift 后处理** | **2 个模糊带**（顶部 + 底部各 15% 屏高的甜甜圈模糊）+ **边缘暗角**（vignette 0.15） |
| **DPR（设备像素比）** | ⚠️ v1.1：**由程序控制，美术不指定**。桌面 ≤ 2.0；移动端 **H 1.5 / M 1.25 / L 1.0**（**AR-9**，不接受 Retina 全分辨率） |

**为什么必须正交**：tilt-shift 的本质是"模拟微距镜头的浅景深"，但**纯 3D 场景下真正的 tilt-shift 极贵**。我们的做法 = **正交投影 + 后处理模糊带**——视觉上一样，**成本低 80%**。

> ⚠️ **v1.1 · AR-9 的连带说明**：v1.0 写"移动端 max 1.5"是美术越权。按 **AR-9**，DPR 由程序按设备档位控制（H 1.5 / M 1.25 / L 1.0），**美术不再指定数值**。我的唯一要求是 §5.4.4 的「L 档保留 tilt-shift + 猫保持 LOD0 + 不加载 Deco Atlas」三项补偿（反对 ③）。

> 🔴 **反对 ③ 的三条补偿（L 低端档专属）**：
> 1. **保留 tilt-shift**——它是"等距微缩"这一视觉语言的唯一载体，关掉它本作退化成普通低模 3D 房间
> 2. **猫仍保持 LOD0**（不降面、不降贴图）——猫是情感核心，任何降级都会破坏"被捏出来的"质感
> 3. **完全不加载 Deco Atlas**（P1 也不加载）——省出的 fill rate 全部回补给 tilt-shift 与主体
>
> v1.0 写「L 档后处理全部关」，**我推翻这一条**。vignette 可以关（它只是装饰），tilt-shift 不能关。

### 8.5 Three.js 关键技术约束

| 项 | 规范 |
|---|------|
| **渲染器** | `WebGLRenderer` + `antialias: true`（桌面）/ `false`（移动） |
| **色彩空间** | `THREE.SRGBColorSpace` 全部；texture 用 `colorSpace = SRGB` |
| **色调映射** | `ACESFilmicToneMapping`，exposure 1.0（在 material shader 末尾执行） |
| **🆕 后处理顺序** | **ACES → RT → tilt-shift → 色彩分级 → vignette → screen**。**色彩分级必须在 ACES 之后**（AR 新增②，见 §5.4.4） |
| **🆕 压缩格式** | **法线与 lightmap 强制 `UASTC → ASTC 4×4`**（KTX2 + zstd）；Android 兼容档 `ETC1S → ETC2`。**禁止 ETC1（无 alpha）**（AR 新增①） |
| **🆕 lightmap 采样** | 通过 `onBeforeCompile` 注入**双 sampler**（`lightMapA` / `lightMapB` + `lightMapMix`），锚定 `<lights_fragment_maps>` chunk。**稳态 `lightMapB` 指向 1×1 白纹理**（ADR-103 §2.5） |
| **🆕 CI 断言** | `lightmap.generateMipmaps === false`（ADR-103 V-103-6）；`LightmapManager.setSlot()` 只接受 1 个参数 |
| **阴影** | PCFSoftShadowMap（桌面）/ BasicShadowMap（移动） |
| **PBR** | `MeshPhysicalMaterial`（仅 A 档用 subsurface）；B 档用 `MeshStandardMaterial` |
| **抗锯齿** | SMAA（移动）/ FXAA（桌面） |

|---|------|--------|
| R1 | 资产分 A/B/C 三档 | 远景 70% 用 C 档烘焙，仅 5 件是 A 档高模 |
| R2 | 光照分实时/烘焙两层 | 仅 1 个主光 + 1–2 个室内灯实时，其余全烘焙 |
| R3 | 静态物件烘焙到 Atlas | 一张 2048² 装 30+ 物件，零运行时成本 |
| R4 | 猫毛发不实时计算 | MVP 用法线贴图烘焙，Standard 才上毛发卡片 |
| R5 | 移动端 3 档降级 | 最低档 30fps + 砍光 + 降材质，仍能跑 |

**核心理念**：等距微缩的尺度感 + 烘焙优先 + 仅主角高模 = 网页端 3D 高模**完全可以**做到。

### 11.5 整体建议

1. **MVP 6–8 周**（3 人美术 + TA）可完成；2 人则需 12–14 周
2. **优先做猫的 12 姿态 + 沙发 + 茶几 + 窗**——这 4 件撑起 80% 视觉印象
3. **MVP 阶段不做天气 / 季节**——这些是 Standard 的"氛围升级"，不影响玩法核心
4. **可访问性 = Standard 级**（已落定 §9）
5. **所有色值已给完整 HEX**（§2.1 共 28 色）；所有面数 / 贴图预算已给具体数字（§3.1 / §3.3 / §10）
