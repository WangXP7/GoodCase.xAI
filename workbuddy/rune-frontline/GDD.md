## 1. 项目概述

### 1.1 一句话

5 个英雄钉在三路固定点位上自动开火，用弹幕一格一格打穿对方的符文壁垒，抢在海克斯三选一里滚出一条 build，先把对方水晶打空的人赢。

### 1.2 高概念

| 项 | 内容 |
|---|---|
| 类型 | 竖版放置塔防 + 实时 PVP + Roguelite 局内成长 |
| 核心参考 | LOL 海克斯大乱斗（强化符文）、金铲铲（海克斯节点与档位）、皇室战争（分路施压）、王者荣耀（逐层推塔）、弹幕射击（弹道表现） |
| 平台 | **微信小游戏（主）**，H5 浏览器（调试 / 预览）。竖屏设计分辨率 750×1334 |
| 单局时长 | **20 秒部署 + 90 秒战斗**（加时最长 110 秒） |
| 付费模型 | 免费 + 英雄/皮肤/战令（不含战力直购，避免 PVP 失衡） |
| 目标用户 | 25-35 岁 LOL/金铲铲流失用户，想 3 分钟一局但要「有 build 深度」 |
| 差异点 | **三向共振**：英雄技能 × 装备 × 海克斯 三个独立乘区同向叠加，单点爆发可达 7 倍 DPS |

### 1.3 三条体验支柱

1. **每 25 秒一次心跳** —— 海克斯三选一。三张卡、一次免费刷新、8 秒倒计时，战场还在流血。选错卡这局就废了，选对卡这局就飞了。
2. **一条路开花的爽** —— 不是均匀变强，是把所有资源灌进一路，看着那一路的格子像玻璃一样连续碎掉，一路打穿直接赢。
3. **抢** —— 装备池是共享的、看得见的、有库存的。你犹豫 3 秒，对手就把「无尽之刃」拿走了。

### 1.4 反模式（明确不做）

| 不做 | 原因 |
|---|---|
| 小兵 / 补刀 | 用户明确要求无小兵；也让 90 秒节奏成立 |
| 英雄手动走位 | 用户明确要求「英雄不可动」，操作量归零，符合放置 |
| 手动点技能 | 全自动释放，玩家的手只用来做「决策」不用来做「操作」 |
| 纯数值对撞的自动战斗 | 必须有可见的弹幕、碎格、战线推移 |
| 抽卡数值堆叠致胜 | 长线养成只影响「可选内容广度」，不影响单场战力上限 |
| 三路平均分配资源 | 数值上要惩罚「雨露均沾」，奖励「集中突破」 |

### 1.5 与已有原型（《领界》v4.1）的关系

工作目录名 `wbDSv4.1F` 与参考站 `192.144.170.61:18086` 的《领界 · HEXFRONT》同源。原型已跑通：单路格子争夺、3 英雄局内招募、基地等级 + 经验、4 次海克斯（Lv1/7/11/15）、3 手动大招、装备材料合成、复活 8-24s、领地落后的防拖掉血。

**本作是原型的「三路 + 5 英雄 + 微信小游戏」升级版，不是从零重做。** 可直接复用的资产：配色体系、六边形符文语汇、装备/海克斯数据表结构、单路战斗循环。**必须重写的部分**：战场从 1 路扩到 3 路（渲染、AI、平衡全变）、UI 从 DOM 改为全 Canvas、5 英雄的站位与切人交互。

### 2.2 关键结论

- **海克斯是骨架不是点缀**。LOL 把它做成「每局 4-5 次的随机强化」，金铲铲把它做成「3 个固定节点的质量博弈」。两者共同点：**节点固定、品质分档、可刷新**。本作必须保留这三点，否则失去「赌+算」的张力。
- **皇室战争不是三路**（左右两条桥 + 中央王塔）。三路的真实来源是 MOBA 上中下分路。本作用三路，是因为竖屏下三列布局天然成立，且「5 人分三路」直接产生资源分配难题 —— 这是策略的来源。
- **无小兵 = 必须有别的推进载体**。MOBA 靠小兵推线，本作靠**打碎格子**。格子必须是有 HP、有归属色、会翻转的实体，而不是一根进度条，否则 90 秒会变成看血条。

## 3. 核心玩法

> ⚠️ **实现版已调整**：按「格子要很多很多」的要求，战场从「每路 10 格」改为
> **每路 11 列 × 36 行 = 396 格，三路 1188 格**，并加入「伤害溢出连打（打砖块）」与
> 「纵向相邻约束」。落地后的实际数值见本文末尾 **第 17 章 实现记录**，本章为原始设计意图。

### 3.1 战场结构

竖屏 1080×1920。战场区 `y ∈ [300, 1560]`，高 1260px。

- **3 条纵向通道（Lane）**，宽 300px，间距 30px，左起 `x = 45`。
- 每条通道 **10 格**，每格 126×126。
- 自下而上（己方在下，敌方在上）：

```
格 9  ┌──────┐  敌方水晶（HP 2400）
格 8  │ 壁垒 │  HP 300   ← 敌方最外格（紧邻中线）
格 7  │ 壁垒 │  HP 420
格 6  │ 壁垒 │  HP 560
格 5  │ 壁垒 │  HP 720   ← 敌方最内格（贴水晶）
      ├──────┤  ── 中线 ──
格 4  │ 壁垒 │  HP 720   ← 己方最内格
格 3  │ 壁垒 │  HP 560   ◆ 前哨位（Front）在格 4 中心
格 2  │ 壁垒 │  HP 420   ◆ 主阵位（Rear）在格 2 中心
格 1  │ 壁垒 │  HP 300
格 0  └──────┘  己方水晶（HP 2400）
```

**为什么越靠内越硬**：靠水晶的格子是最后防线，硬；靠中线的格子是前沿哨所，脆。这让「打穿」的节奏是先快后慢，前 4 秒有反馈，后 20 秒有压力。

### 3.2 格子（Hex Tile）规则

| 属性 | 说明 |
|---|---|
| HP | 见上表（**Lv.1 基础值**），随己方基地等级成长。全场不回复。 |
| 归属 | 己方 / 敌方。被打碎后**翻转**为对方颜色，但**不再生成新格**（战线不会反向移动） |
| 符文增益 | 每格带 1 条词缀，为己方全体提供 buff。**格子存活才生效，碎掉即失效** |
| 视觉 | 六边形符文砖，带阵营色发光边框、HP 刻度线。碎裂时炸成 6-10 片碎片 + 闪光 |

**格子词缀池（每路 4 格各随机 1 条，开局可见，可被海克斯改写）**

| 词缀 | 效果 | 出现在 |
|---|---|---|
| 疾行符文 | 该路己方英雄 +8% 攻速 | 格 1-4 随机 |
| 坚韧符文 | 该路己方英雄 +10% 最大生命 | 格 1-4 随机 |
| 锐利符文 | 该路己方英雄 +8% 伤害 | 格 1-4 随机 |
| 丰饶符文 | 该路击碎敌格时 +20% 金币 | 格 1-4 随机 |
| 荆棘符文 | 攻击该格的敌人受到 3% 反伤 | 格 1-2（内圈） |
| 静滞符文 | 命中该格的弹道 5% 概率被弹开 | 格 1-2（内圈） |

📌 设计意图：格子不只是血条，是「可被剥夺的 buff 区」。对手打碎你的「锐利符文」格，你就真的变弱了 —— 这给了防守方「必须救场」的动机。

### 3.3 点位（Slot）与站位

每条通道 **2 个固定点位**，共 **6 个**：

| 点位 | 位置 | 特性 |
|---|---|---|
| **前哨位 Front** | 格 4 中心（贴中线） | ① 弹道飞行距离短，命中快（等效 +5% DPS）<br>② **拦截本路敌方弹道**：敌方子弹先打它，溢出伤害才到后排<br>③ 承受 100% 伤害，最容易死 |
| **主阵位 Rear** | 格 2 中心（贴水晶） | ① 安全，被前排挡住<br>② 弹道飞行距离长（等效 -5% DPS）<br>③ 前排空了就直接暴露 |

**5 个英雄 / 6 个点位**：必然留 1 个空位。

- 空位所在路 = 该路只有 1 人，输出腰斩、且没有第二层拦截。
- **第 6 个点位靠「海克斯造物」补**：部分海克斯/英雄技能会生成可放置的召唤物（提莫蘑菇、黑默丁格炮台、安妮提伯斯、亚索风墙）。这是把海克斯价值做高的关键设计 —— **海克斯不只是数值，是「第六个人」**。

📌 这让「海克斯选什么」直接决定「阵型完不完整」，决策权重远高于纯数值卡。

### 3.4 弹道与伤害流向

```
[主阵位英雄] ──弹道向上──▶ [前哨位英雄(己方)] 穿过（不伤害友军）
                            │
                            ▼
                    [敌方前哨位英雄] ← 若有人，先吃伤害
                            │ 打穿后
                            ▼
                    [敌方最外格 格8] ← 打碎后
                            │
                            ▼
                    [格7] → [格6] → [格5] → [敌方水晶]
```

规则：

1. 弹道垂直向上，**不跨路**（三路完全隔离）。
2. 命中**第一个敌方实体**停止（弹道有穿透属性则继续）。
3. 友军不阻挡弹道（否则前排英雄会挡住后排输出）。
4. **目标优先级默认 = 格子**（推进为纲）。部分英雄/海克斯可切换为「优先英雄」（斩首流）。
5. 敌方英雄站在前哨位时，弹道会先打英雄 —— 所以「前哨位放坦克」是天然的护盾。

### 3.5 英雄死亡与复活

| 项 | 值 |
|---|---|
| 基础复活时间 | 15 秒 |
| 可缩短 | 装备「中娅沙漏」-3s；海克斯「俯冲炸弹」-40% |
| 死亡惩罚 | 该点位空置 15s → 该路输出下降 / 失去拦截层 |
| 击杀奖励 | 击杀者 +100 金 + 对方 5 秒内不能再买装备 |

📌 保留死亡机制，是为了让「斩首流」成为一条真实可行的 build，而不是只有推塔一条路。

### 3.6 胜负判定

| 情况 | 判定 |
|---|---|
| 任一路打空对方水晶（HP 归 0） | **立即胜** |
| 90 秒结束，三路水晶均在 | 进入 **加时 20 秒** |
| 加时期间 | 双方水晶每秒流失 1% 最大生命（**双方同时掉**，先归零者负） |
| 110 秒仍双方存活 | 比较**三路水晶剩余 HP 总和百分比**，高者胜；差 < 2% 判平局 |
| 双方水晶同一帧归零 | 平局（不加星、不扣星） |

**防拖设计**（继承原型思路，压缩到本作节奏）：

| 时间点 | 触发 | 目的 |
|---|---|---|
| 60s | 三路水晶总血量**落后 25% 以上**一方，格子的双抗 -20% | 给优势方一个「破局窗口」，避免僵持 |
| 90s | 强制加时，双方水晶开始同步流血 | 保证 2 分钟内必结束，适配小游戏「一局 3 分钟」 |
| 110s | 血量百分比裁决 | 兜底 |

🔴 **决策点**：任一路破即胜 vs 三路汇入一个主水晶。**我建议前者**（集中一路是最爽体验），但后者容错更高、更适合休闲用户。见第 14 章 D1。

### 3.7 单局时间轴

```
T+0s   战前部署 20s（可跳过；5 英雄归位、首发装备已锁）
T+20s  战斗开始（基地 Lv.1，海克斯 #1 自动弹出）
        │  夺格 → 经验 → 基地升级
T+?s   Lv.7  → 海克斯 #2（黄金档，手动开启）
T+?s   Lv.11 → 海克斯 #3（黄金 / 棱彩）
T+?s   Lv.15 → 海克斯 #4（棱彩档）
T+110s 战斗强制结束 → 结算（正常 75-95s 结束）
```

**海克斯由基地等级驱动，不由时间驱动。** 这是从原型继承的最重要一条：打得好 → 夺格多 → 升级快 → 更早拿到海克斯 → 滚雪球。

时间兜底：**每 30 秒，双方基地无条件 +1 级**（防止被压制方永远拿不到海克斯）。

| 节点 | 优势方到达 | 均势到达 | 落后方到达（兜底） |
|---|---|---|---|
| Lv.7 → 海克斯 #2 | 20-24s | 28s | 40s |
| Lv.11 → 海克斯 #3 | 42-48s | 55s | 70s |
| Lv.15 → 海克斯 #4 | 65-72s | 80s | 95s |

**海克斯选择时的战场处理** 🔴：

| 方案 | 说明 | 优劣 |
|---|---|---|
| A. 完全暂停 | 3 秒，战场静止 | 清晰，但破坏「紧张感」，也让 PVP 同步变复杂 |
| **B. 减速 50% + 8 秒倒计时（建议）** | 子弹时间，仍可看到自己在挨打 | 最有戏剧性；倒计时压迫决策 |
| C. 不暂停 | 纯浮层 | 手忙脚乱，容易误选，差评 |

超时未选 → 自动选第一张（不允许「不选」）。

### 3.8 基地等级与经验

基地（水晶）不攻击，但**是本局唯一的等级系统**，驱动三件事：海克斯节点、格子强度、经济产出。

| 项 | 规则 |
|---|---|
| 等级上限 | 20 级 |
| 经验来源 | 夺格 **+7**；失格 **+3**；每秒被动 **+4**；击碎敌格 **+12** |
| 重复产经验限制 | 同一格 5 秒内被同一方反复易手，不重复给经验 |
| 落后补偿 | 每落后 1 级，经验获取 **+25%**，最高 +100%（翻倍） |
| 格子成长 | 基地每升 1 级，**己方全部壁垒格 +1 生命上限、+0.75 双抗** |
| 防御等级差 | 格子防御效果最多按「领先对手 2 级」计算（防滚雪球过猛） |
| 经济成长 | 每 5 级，被动金币 +2/秒 |

**为什么格子要跟着长**：格子固定 HP 会导致「前期伤害溢出、后期打不动」或反之。跟着等级长，能自动把对局拉长到 90 秒左右，同时给「升级」一个直观的战场表现 —— 每升一级，己方格子的边框会亮一档。

### 3.9 核心循环（单局内）

```
金币 ──▶ 升技能 / 买装备 / 刷海克斯
  ▲                    │
  │                    ▼
  └──── 打碎格子 ◀── 战力提升（三向共振）
```

每 5-8 秒玩家要做一次「花不花、花在哪」的决策。90 秒内约 **10-14 次决策**，其中 4 次是海克斯（最高权重）。

### 5.3 三向共振（核心数值模型）

最终 DPS 由**三个独立乘区**相乘：

```
DPS = 基础DPS
    × (1 + Σ技能等级加成)        ← 乘区 A：加算，最高约 +120%
    × Π(1 + 装备加成)            ← 乘区 B：连乘，每件 1.15-1.35
    × Π(1 + 海克斯加成) × 特效    ← 乘区 C：连乘，每件 1.15-1.5
    × 暴击期望 × 敌方减伤
```

**关键设计：A 是加算、B 和 C 是连乘**。这让「三个方向同向堆」的收益远大于「分散投资」。

**算例（金克丝，90 秒后段）**

| 策略 | 技能 | 装备 | 海克斯 | 最终 DPS | 相对 |
|---|---|---|---|---|---|
| 均衡投资 | Q3（+30%）=1.3 | 2 件（1.15×1.15）=1.32 | 2 件（1.15×1.2）=1.38 | 100×1.3×1.32×1.38 = **237** | 1.00× |
| 全押技能 | Q5（+60%）=1.6 | 0 | 0 | 100×1.6 = **160** | 0.68× |
| 全押装备 | Q1 | 3 件（1.25×1.25×1.2）=1.875 | 0 | 100×1.875 = **188** | 0.79× |
| **三向共振** | Q5（1.6） | 3 件（1.875） | 3 件（1.3×1.3×1.4=2.366） | 100×1.6×1.875×2.366 = **710** | **3.00×** |

**结论：同向堆满 = 均衡投资的 3 倍、单押的 4 倍。** 这就是「最优解即最强战力」的数学基础，也是玩家愿意反复重开研究 build 的动力。

📌 平衡红线：必须保证「三向共振」需要**极其苛刻的条件**（海克斯抽卡随机、装备被抢、金币不够），否则每局都是同一套最优解，Roguelite 就死了。措施：
1. 海克斯三选一有随机性，凑不齐 4 件套
2. 装备池共享，对手会抢走你的核心装
3. 金币硬约束，无法同时满技能 + 满装备
4. 每赛季轮换 30% 海克斯池

## 6. 装备系统

### 6.1 共享装备池（抢夺机制）

**规则**：

1. 每局开局，系统从 40 件成装中随机抽 **10 件**组成公共池，双方看到**完全相同**的池子。
2. 每件成装有**库存 1-2 件**（总库存约 14 件）。
3. **先买先得**。一方买走最后一件 → 对方面板该装备立即变灰，标注「已被夺取」。
4. 成装**绑定英雄**，不可自由转移；可花 150 金拆除（回到池中，对手可抢）。
5. 每英雄 **3 个成装槽 + 4 格材料栏**（继承原型，6 格在竖屏太挤）。
6. **材料**（6 种小件）**不限量、不共享**，持有即生效，不占成装槽。
7. **合成**：2 个指定材料 + 差价 → 1 件成装，材料被消耗。
8. 出售成装返还 **70%** 金币，材料返还 50%。

**材料表（6 种，单价 70-90 金）**

| 材料 | 价格 | 属性 |
|---|---|---|
| 锋利碎刃 | 80 | 攻击 +4 |
| 奥术微晶 | 80 | 技能强度 +10% |
| 精密弹簧 | 80 | 攻速 +0.10/秒 |
| 生命晶片 | 70 | 生命 +40 |
| 铁质甲片 | 80 | 护甲 +12 |
| 抗魔纱布 | 80 | 魔抗 +12 |

📌 **材料的价值**：金币有多余时永远有地方花（不至于攒着等成装），且「先垫材料、再合成成装」的路径让早期就有成长感。合成让「抢成装」多了一层博弈：你抢走了成装，我还能用材料凑出 70% 的效果。

**为什么这是核心乐趣**：装备池是公开信息，双方都知道对方要什么。你在攒钱买「无尽之刃」，对手 600 金时直接抢走 —— 这一瞬间的挫败感和下一局的复仇欲，是留存引擎。

**异步 PVP 下如何实现**：对手是 AI 镜像，它的购买行为按预设时间轴执行（带上真实玩家的决策记录）。你慢 5 秒，AI 就买走了。效果与实时一致。

📌 **平衡目标**：至少 3 条 T0 路线互相克制（速攻克控制、控制克爆发、爆发克速攻），形成石头剪刀布。

### 7.5 海克斯 UI（最关键的一屏）

```
┌─────────────────────────────────┐

│ │ 每次 │ │ 每10s │ │ 金币 │     │  ← 效果描述（14px，3 行内）
```

**设计要点**：

1. **套装进度必须显示在卡上**（`⚔ 2/4`）—— 玩家不需要心算，一眼看出「选这张能凑 3 件套」。
2. **三张卡横排**，竖屏下每张 300×420，卡片顶部派系色条 + 图标。
3. **点击即选，无二次确认**（有 0.3s 的按下反馈 + 卡片放大动画）。
4. **刷新按钮在下方**，左手拇指可达。
5. 背景战场**变暗 40% 但仍可见**（能看到自己水晶在掉血，制造紧迫感）。

### 7.6 英雄觉醒（第 5 章新增，解决 5 人上场的 build 深度）

**为什么需要它**：5 个英雄全部上场后，「海克斯只有 4 次」不够撑起 5 条 build 线。每个英雄需要一次「自己的三选一」，让玩家在开局就定下这局的主 C。

| 项 | 规则 |
|---|---|
| 次数 | 每场上阵英雄各 1 次，共 **5 次** |
| 时机 | 战前部署 20 秒内，5 张英雄卡内联三选一（无需弹窗，直接点） |
| 选项 | 该英雄**专属**的 3 条分支，固定不随机 |
| 默认 | 未选则默认分支 ①，开战后 15 秒内仍可改（未出战过才可改） |
| 费用 | 免费；付 200 金可重选 1 次 |
| 派系 | 每条分支带 1 个派系标签，**影响该英雄与海克斯的协同**（但**不计入**套装件数，套装只算海克斯，保证 4 件套仍是极限追求） |

**示例（4 个英雄，其余 16 个同构）**

| 英雄 | 分支 ① | 分支 ② | 分支 ③ |
|---|---|---|---|
| 金克丝 | ⚔ **弹幕**：弹道 +1（散射 60%） | ⚔ **爆破**：对格子伤害 +35% | ⚙ **过载**：攻速 +30%，最大生命 -15% |
| 盖伦 | 🛡 **壁垒**：最大生命 +500，且优先被弹道命中 | ⚔ **审判**：旋转范围 +1 格，伤害 +20% | 🛡 **处决**：对 HP<30% 的格 +60% 伤害 |
| 拉克丝 | ✦ **穿透**：激光贯穿 +1 格 | ✦ **爆发**：技能伤害 +40%，CD +10% | ✦ **回响**：技能 20% 概率释放两次 |
| 提莫 | ☠ **剧毒**：毒伤 +60%，可叠 4 层 | ☠ **蘑菇园**：蘑菇上限 +3，爆炸范围 +1 格 | ⚔ **游击**：攻速 +35%，射程 -1 格 |

**总选择数：9 次/局（5 觉醒 + 4 海克斯）**

| 阶段 | 次数 | 决策性质 |
|---|---|---|
| 战前 20s | 5 次觉醒 | 定阵容流派（信息完整，可慢慢想） |
| 战斗中 | 4 次海克斯 | 应变（信息不完整，有倒计时压力） |

📌 这是本作相对原型最大的玩法增量：原型是「3 英雄 + 4 海克斯 = 7 次」，本作是「5 英雄 + 5 觉醒 + 4 海克斯 = 9 次」，且觉醒让每个英雄都有「我要走哪条路」的取舍。

## 8. PVP 与放置循环

### 8.1 主循环

```
挂机产出（12h 上限）
   ↓ 上线领取
大厅 → 选模式 → 战前编队（5 英雄 + 6 点位）
   ↓
对局（20s 部署 + 90s 战斗）
   ↓
结算（胜负 / 数据 / 海克斯组合回放）
   ↓
段位分 / 金币 / 图鉴解锁 → 回到大厅
```

单次会话目标 **3-5 分钟**（1-2 局），符合小游戏「碎片时间」定位。

### 8.2 模式

| 模式 | 说明 | 开放 |
|---|---|---|
| **排位赛** | 1v1 异步镜像，段位分，赛季 30 天 | 首发 |
| 休闲场 | 1v1 异步，无段位，练 build | 首发 |
| **PVE 推图** | 三路关卡，解锁英雄 / 装备 / 海克斯 | 首发 |
| 好友约战 | 分享链接 → 对方挑战你的镜像 | v1.1 |
| 实时对战 | WebSocket 同房间 | v2（成本高，见 12.7） |
| 副本 / 远征 | 特殊规则（如「只能用 3 个点位」） | v1.2 |

### 8.3 异步 PVP 是本作的最优解

**为什么不做实时**：

| 项 | 实时 PVP | 异步镜像 |
|---|---|---|
| 服务器 | 长连接 + 帧同步 + 权威校验，成本高 | 静态快照 JSON，可 CDN |
| 匹配等待 | 需要同段位同时在线 | 秒匹配 |
| 断线 | 判负，体验差 | 无影响 |
| 作弊 | 需服务端反外挂 | 快照可校验（见下） |
| 「抢装备」体验 | 真实同时 | **时间轴回放，心理效果一致** |

**快照内容**（约 2-4KB JSON）：

```
{ ver, seed, lineup[5], awaken[5], augmentSeq[], buyTimeline[{t, itemId, heroIdx}], skillTimeline[], result }
```

**校验**：本地模拟必须**确定性**（固定步长 + 种子随机），同样输入必然同样输出。服务端只做「快照合法性校验」（金币不超上限、时间轴单调递增），不做逐帧重算。

📌 这也意味着：**战斗逻辑必须是纯函数 + 固定时间步**，不能依赖 `requestAnimationFrame` 的 dt。这是架构红线，从第一行代码就要遵守。

### 8.4 挂机产出

| 项 | 值 |
|---|---|
| 产出 | 金币 60/h、英雄碎片 2/h、海克斯尘埃 1/h |
| 上限 | 12h（激励视频 +4h，月卡 +8h） |
| 领取 | 大厅「领取」按钮，一键领 + 10% 概率暴击 ×2 |
| 快速战斗 | PVE 已通关关卡可扫荡，即时结算 |

### 8.5 PVE 推图（教学 + 解锁）

- 章节 1-5，每章 12 关，共 60 关
- 前 3 关为教学（分别教：放英雄 / 打格子 / 选海克斯）
- 第 4 关起引入敌方英雄与装备抢夺
- 每章末关为 Boss（特殊规则，如「敌方水晶 2 倍血量」）
- 通关奖励：英雄 / 装备图鉴 / 海克斯解锁

### 9.8 英雄形象（程序化几何小人）

不做写实 3D，做**六边形符文小人**：

- 底座：六边形符文盘（派系色发光）
- 躯干：2-3 个几何体（梯形 + 圆 + 三角），按定位区分（坦克宽、射手细、法师带尖顶）
- 武器：1 个标志性剪影（弓 / 剑 / 法杖 / 枪），指向朝上
- 头部：圆形 + 单点发光眼（低成本、辨识度高）
- 待机：0.8Hz 上下浮动 2px
- 攻击：躯干后仰 3° + 武器前推 4px（0.1s）
- 死亡：碎成 6 片 + 底座熄灭，复活时底座先亮再重组

📌 这套做法与原型 SVG 塔的风格一致，且**纯代码绘制，零图片资源**，包体友好。

## 10. 数值框架

### 10.1 伤害公式

```
物理伤害 = 攻击力 × (1 + 增伤%) × 暴击倍率 × 护甲减免
护甲减免 = 100 / (100 + 有效护甲)
有效护甲 = (护甲 × (1 - 百分比穿透) - 固定穿透)，最低 0

法术伤害 = 技能强度 × (1 + 技能增伤%) × 暴击倍率 × 魔抗减免
魔抗减免 = 100 / (100 + 有效魔抗)
```

| 护甲 | 减免 |
|---|---|
| 20 | 16.7% |
| 45 | 31.0% |
| 80 | 44.4% |
| 120 | 54.5% |

### 10.2 TTK 目标（关键平衡锚点）

| 场景 | 目标时间 | 说明 |
|---|---|---|
| 单英雄清 1 格（最外，300HP） | 8-10s | 有反馈但不廉价 |
| 双英雄清 1 路 4 格（2000HP） | 38-42s | 均势节奏 |
| 双英雄破水晶（1800HP） | 34-38s | 合计 72-80s，留 10-18s 容错 |
| **三向共振双英雄破一路** | **18-24s** | 天胡局的爽感上限 |
| 均匀分兵（每路 1.67 人）破一路 | > 110s | **打不穿 → 逼玩家集中** |
| 英雄互杀（同级别） | 6-9s | 斩首流可行但不无脑 |

### 10.3 经济曲线

| 时间 | 累计金币（均势） | 关键消费 |
|---|---|---|
| 0s | 200 | — |
| 20s | 520 | 第一件材料 / 首次技能升级 |
| 40s | 980 | 第一件成装 |
| 60s | 1480 | 第二件成装 或 Q 满级 |
| 80s | 1980 | 第三件成装 / R 升级 |
| 90s | 2200 | 终局 |

📌 全程只能支撑「1 个英雄满配 + 1 个英雄半配」。这就是「主 C 只有 1 个」的硬约束。

### 10.4 平衡自检指标（每次改数值必跑）

| 指标 | 目标区间 | 超标处理 |
|---|---|---|
| 平均对局时长 | 78-92s | 短了加格子 HP，长了加水晶伤害 |
| 一路被破比例 | 55-70%（其余按血量判） | 低了降水晶 HP |
| 海克斯 4 件套达成率 | 3-8% | 高了提高抽卡随机性 |
| 单英雄使用率 | 每英雄 3-15% | 超 20% 削，低于 2% 加强 |
| 先手胜率 | 48-52% | 偏差大则给后手 +50 初始金币 |
| 投降率 | < 5% | 高了检查雪球是否过强 |

### 10.5 确定性要求（架构红线）

- 战斗逻辑用**固定步长 1/60s**积分，不用可变 dt
- 随机数用**种子 PRNG**（xorshift128），种子来自对局 ID
- 所有对象按固定顺序更新（路 1→2→3，点位 Front→Rear）
- 浮点结果**不允许依赖遍历顺序**（Map 迭代顺序固定）
- 目的：同一份快照在任何设备上重放结果一致 → 异步 PVP 可校验、可回放、可复盘

## 12. 微信小游戏技术方案

### 12.1 技术选型

| 方案 | 包体 | 开发速度 | 性能 | 结论 |
|---|---|---|---|---|
| **原生 Canvas 2D + 自研 UI 层（建议）** | < 1MB | 中 | 好 | ✅ 采用 |
| minigame-canvas-engine | < 1MB | 快 | 中 | UI 框架受限，动效难做 |
| Cocos Creator 3.x | 3-5MB | 快 | 好 | ❌ 包体吃紧，且本项目不需要场景编辑器 |
| LayaAir | 2-3MB | 中 | 好 | ❌ 生态弱 |

**理由**：本作 UI 形态固定（卡片 / 条 / 按钮 / 文本），不需要通用 UI 框架；战场是 2D 弹幕，Canvas 2D 足够；包体越小冷启动越快，对小游戏留存影响极大。

### 12.2 为什么不能直接搬 H5

微信小游戏**没有 DOM / BOM**：

- ❌ 不能用 `document`、`window`、`<canvas>` 标签、CSS
- ✅ 只有 `wx.createCanvas()` 得到的 canvas 和 `wx.*` API
- ✅ 有 `requestAnimationFrame`（由 adapter 提供）

**做法**：写一层渲染抽象 `gfx.js`（`rect / roundRect / text / sprite / gradient`），H5 与小游戏共用；平台差异用 `adapter.js` 抹平（`canvas` 获取、`storage`、`audio`、`input`）。

📌 这样本地用浏览器调试（快），发布时只换 adapter，业务代码零改动。

### 12.4 包体与分包

| 项 | 限制 | 本作目标 |
|---|---|---|
| 主包 | ≤ 4MB（以官方最新为准） | **≤ 1.2MB** |
| 分包总计 | ≤ 20MB | 不用（内容全塞主包也够） |
| 首次加载 | ≤ 3s（4G） | ≤ 1.5s |

**省包体手段**：全程序化绘制（无英雄图、无背景图）、图标合成 1 张 atlas、音频用 8-bit 短音效、数据表用紧凑数组而非 JSON 对象。

### 12.5 渲染与性能预算

| 项 | 预算 |
|---|---|
| 帧时间 | ≤ 8ms（60fps）/ ≤ 16ms（30fps 兜底） |
| 同屏弹幕 | ≤ 120（三路合计） |
| 粒子 | ≤ 200 |
| 每帧文本绘制 | ≤ 40 次（文本最贵，伤害数字合并绘制） |
| 每帧 drawImage | ≤ 200 |
| 渐变对象 | 缓存，禁止每帧 `createLinearGradient` |

**优化手段**：

1. **静态层离屏渲染**：背景 + 格子底纹画到离屏 canvas，仅在格子状态变化时重绘
2. **对象池**：弹幕、粒子、伤害数字全部预分配
3. **伤害数字合并**：同一格 0.2s 内的多次伤害合并显示
4. **dpr cap 2**：iPhone 3x 屏按 2x 渲染，肉眼差异小，性能省 55%
5. **后台降频**：`wx.onHide` 暂停循环，`wx.onShow` 恢复

### 12.6 存档与数据

| 数据 | 位置 | 说明 |
|---|---|---|
| 设置 / 编队 / 引导进度 | `wx.setStorageSync` | 本地，≤ 10MB |
| 英雄 / 装备 / 海克斯解锁 | 本地 + 云端备份 | 防清缓存丢失 |
| 段位 / 战绩 / 赛季 | 云开发数据库 | 需防作弊校验 |
| 对局快照 | 云存储（JSON） | 用于异步 PVP |

**云开发**（`wx.cloud`）足够支撑 MVP，无需自建服务器：云函数做匹配、云数据库存快照、云存储放静态配置。

### 12.7 网络方案

| 阶段 | 方案 | 成本 |
|---|---|---|
| MVP | 纯本地，AI 对手 | 0 |
| v0.4 | **异步镜像**：上传快照 JSON → 云数据库 → 匹配时拉取 | 极低（无长连接） |
| v2 | 实时对战：`wx.connectSocket` + 服务端权威 | 高（需服务器 + 备案域名 + 反外挂） |

**异步快照的关键约束**（前面已提，这里是实现）：

- 战斗必须确定性（固定步长 + 种子随机）
- 快照只存「输入」（阵容、觉醒、购买时间轴、海克斯选择、大招时机），不存「结果」
- 客户端本地模拟，服务端只校验合法性
- 快照体积 2-4KB，云数据库单条上限内

### 12.8 音频

| 类型 | 方案 | 预算 |
|---|---|---|
| 音效 | `wx.createInnerAudioContext` 池（8 个复用） | 10 个 × ≤20KB |
| BGM | 1 个循环，`loop=true` | ≤ 400KB（或省略） |
| 静音 | 首次进入询问，默认开启音效关 BGM | — |

📌 小游戏音频是内存大户，`InnerAudioContext` 不销毁会泄漏，必须池化复用。

### 12.9 平台能力

| 能力 | API | 用途 |
|---|---|---|
| 登录 | `wx.login` → 云函数换 openid | 账号 |
| 分享 | `wx.shareAppMessage` | 战绩、约战链接 |
| 激励视频 | `wx.createRewardedVideoAd` | 双倍挂机、复活、免费刷新海克斯 |
| 排行榜 | 开放数据域 + `sharedCanvas` | 段位榜、连胜榜 |
| 震动 | `wx.vibrateShort` | 破格、水晶受击 |
| 录屏 | `wx.getGameRecorderManager` | 分享高光（v1.1） |

### 12.10 机型适配

| 项 | 处理 |
|---|---|
| 分辨率 | 750×1334 逻辑坐标 + 等比缩放，超宽屏左右留边 |
| 安全区 | 顶部 / 底部按 `safeArea` 内缩 |
| 低端机 | 检测 `benchmarkLevel`（`wx.getDeviceBenchmarkInfo`），< 20 自动降画质（关粒子、弹幕简化） |

## 13. 合规与商业化

### 13.1 上线硬门槛

| 项 | 要求 | 风险 |
|---|---|---|
| **游戏版号（ISBN）** | 国内小游戏上线运营必须 | 🔴 **最高风险，周期 6-12 个月** |
| 主体资质 | 企业主体 + 网络文化经营许可证 | 高 |
| 实名认证 | 接入微信实名 / 防沉迷 | 必须 |
| 未成年人保护 | 时长限制、消费限制 | 必须 |
| 隐私政策 | 收集信息需明示 | 必须 |

🔴 **决策点**：如果没有版号，只能做「不收费、不联网、纯单机」的 demo 或走海外（微信小游戏海外版 / H5）。这会直接改变商业化设计。

### 13.2 iOS 虚拟支付限制

- iOS 小游戏**不允许虚拟支付**（不能卖金币、皮肤、战令）
- 安卓可走 `wx.requestMidasPayment`
- **结论**：iOS 只能靠**广告**变现；安卓可广告 + 内购

这决定了商业化模型必须「广告优先」：

| 变现点 | 形式 | 预估 |
|---|---|---|
| 双倍挂机收益 | 激励视频 | 高频 |
| 战斗复活（PVE） | 激励视频 | 中频 |
| 免费刷新海克斯（每局 1 次） | 激励视频 | 高频，且不破坏平衡（海克斯本身随机） |
| 战令 | 内购（安卓） | 低频高价 |
| 皮肤 | 内购（安卓） | 低频 |

⚠️ **不能卖「战力」**。PVP 公平是本作口碑根基，一旦卖战力，评价必崩。

### 13.3 IP 风险（必须处理）

「英雄完全参考 LOL」在**内部原型**阶段没问题，但**公开发行必须替换**：

| 风险项 | 处理 |
|---|---|
| 英雄名（盖伦 / 金克丝…） | 改为原创名（如「铁卫 · 加兰」「爆破手 · 金克」），技能机制保留、名称改写 |
| 英雄形象 | 本作本来就是几何小人，不与 LOL 原画相似，风险低 |
| 技能名（审判 / 终极闪光…） | 改为描述性名称（「旋刃风暴」「贯穿光束」） |
| 装备名（无尽之刃…） | 改为原创（「无尽锋刃」——原型已这么做） |
| 海克斯 / 强化符文 | 「海克斯」是 LOL 专有名词，需改为「符文」「强化」等通用词 |

📌 **建议从开发第一天就用原创名**，避免后期大规模改名（数据表、UI、文案全要动）。原型《领界》已经这么做了（雷霆哨卫 / 辉光术士 / 磐岩守卫…），本作应沿用这个策略。

### 13.4 商业化红线

| 不做 | 原因 |
|---|---|
| 卖战力 / 卖英雄强度 | PVP 公平性崩塌 |
| 抽卡保底不公示 | 违规 |
| 强制广告（不可跳过） | 审核不过 + 差评 |
| 首充弹窗轰炸 | 小游戏审核敏感 |

### 17.2 三个必须记录的机制改动

**① 伤害溢出 = 穿透打砖块**

一发子弹打碎一格后，**剩余伤害继续打下一格**（同列）。这是「弹幕感」的核心：

```
金克丝单发 18 伤害 → 打 24HP 格（不足）→ 停
海克斯后单发 45 → 碎 24HP 格（余 21）→ 再碎 2 格（余 3）→ 停
```

伤害加成不再是「数字变大」，而是**一次扫掉几格**，视觉反馈极强。

**② 纵向相邻约束（`canAttack`）**

只能打「后方相邻是己方」的格子。没有这条约束时，双方会互相穿插成"跳岛"，
战线永远是锯齿状死锁（实测 110 秒双方水晶满血）。加上后战线变成清晰的推进面。

```js
const back = owner > 0 ? row + 1 : row - 1;   // 己方向下看，敌方向上看了
return getCell(lane, back, col).owner === owner;
```

**③ 只按「净占领」给收益**

格子加 `rewarded` 标记，只有第一次被己方占领才给金币与经验。
否则反复易手会刷出天量经济（实测 110 秒刷到 3000+ 金）。

### 17.3 踩过的坑（会复现，写代码时直接避）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 110 秒双方水晶满血、格子数不变 | `targetCol` 里遇到己方格就 `break`，导致永远返回 -1，所有子弹打同一列 | 改成遍历全部格子找「最靠下的可攻击格」 |
| 2 | 25 秒就清空一整路 | 大招循环里边打边判断 `canAttack`，碎一格后上一格立刻可攻击 → 连锁清全路 | 先快照 `targets` 再统一结算 |
| 3 | 战线交错成锯齿，永远打不完 | 允许上下左右四向相邻 → 双方互相穿插 | 只保留纵向相邻 |
| 4 | 提高格子 HP 后反而更快结束 | 收益/经验按「翻转次数」给，反复易手刷爆经济 | 改成按净占领给 |
| 5 | 一切正常但打不动 | 英雄子弹被 `guard` 保护期吞掉，且返回值语义写错（不可攻击时返回全额伤害 = 免费穿透） | `damageCell` 返回值语义统一为「剩余伤害」 |

### 17.4 平衡实测（`node .sim.js`，8 局无头模拟）
