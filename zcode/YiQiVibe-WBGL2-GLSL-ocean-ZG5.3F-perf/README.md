*实测环境：Chrome / ANGLE，768×432，120 帧无垂直同步基准（页面内置 `__gpuBench`），不同 GPU 上比值会略有差异。*

## 实测锚点（核显，真实 60Hz 场景）

- 原版：75% 分辨率仅 40–50 FPS，GPU 占用高
- 版本一：60% 分辨率稳定 57–60 FPS（画面与原版一致）
- 版本四：100% 分辨率稳定 60 FPS，系统 GPU 监控实测占用约 11%

版本间相对 GPU 耗时（同一台机器、同一分辨率下经 GPU 完成时间同步测量的近似比值）：版本二 ≈ 版本一的 50%，版本三 ≈ 25%，版本四 ≈ 20%。弱核显上差距会更大（ALU 瓶颈更明显）。

## GPU 占用估算（与原版一致）

浏览器不暴露真实 GPU 占用率 API，页面显示的「GPU≈xx%」是估算值，按可靠性分三级：

1. **桩回读（主方案）**：GPU 队列按序执行——帧末往 1×1 RGBA8 桩帧缓冲提交 clear 再 `readPixels`，驱动必须等本帧全部绘制真正执行完才能返回，耗时即真实单帧 GPU 时间；减去启动时空队列标定的回读固定开销后除以 16.7ms 得到占用率。每 15 帧测一次（高负载降频到每 30 帧），EMA 平滑
2. **GPU 定时器查询**：`EXT_disjoint_timer_query_webgl2` 可用且数值合理时优先采用（部分驱动宣传该扩展但实际不可用，会自动落到桩回读）
3. **帧间隔兜底**：前两者都不可用时，帧间隔超过 18ms 说明 GPU 是瓶颈（间隔≈GPU 耗时）；锁在满帧率时保持上次读数

「GPU上限」滑杆（默认 80%）控制自动适配的升档行为：达到上限即停止提升分辨率/步数，只降不升。

## 技术要点（相对原版的改动）

- **★A 噪声查表**：256×256 RGBA16F 可平铺随机纹理，`vnoise` 从 4 次 hash + 双重插值改为 1 次硬件双线性采样，所有 FBM 成本约降 3 倍；查表噪声随机种子与原版不同，图案形态等同
- **★B 环境探针**：极光光线步进从逐像素（每帧 ~52 万像素 × 28 步）移到低分辨率全景缓冲（640×160 每 2 帧），主画面天空与海面反射改为一次双线性格纹采样；探针 x 向使用 REPEAT 平铺保证方位角 ±π 接缝连续
- **★C 时间累积**：RGBA16F ping-pong 双缓冲，相机静止/无参数变动时与上一帧按 0.12–0.75 混合（时间速度越快混合越保守防拖影），静止且时间速度为 0 时逐帧精化到超采样质量
- **② 空采样跳过**：极光步进先算垂直包络 `env`，低于 0.004 直接跳过整个 14 次噪声的密度计算
- **⑤ 域扭曲降频**：扭曲场是低频信号，改为每 2 步更新一次复用
- **⑧ 动态步数**：GLSL ES 3.0 循环上界用 uniform，自动适配先降步数（28→22→16→12）再降分辨率，升档顺序相反

## 运行

双击 `index.html`（需支持 WebGL2 的现代浏览器），或访问在线站点。按住鼠标拖动环视海面；面板可调分辨率、GPU 上限、极光强度、海浪高度、时间速度（版本四额外有帧率上限）。
